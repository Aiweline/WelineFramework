# 汉服独立站主题、编辑器与上线闭环设计

- 日期：2026-09-04
- 状态：已批准（2026-09-04）
- 目标站点：`https://p05113ef3.test.weline.com:9555/`
- 主题：云裳汉服 · Hanfu Atelier，默认水墨中国风
- 范围：Theme 页面类型、主题范围编辑、批量发布、活动页、商品 SEO、轮播无障碍、国际化内容治理与性能

## 1. 背景与已批准决策

目标不是制作一套脱离现有系统的静态皮肤，而是基于站点当前真实路由、商品、购物流程和 Weline Theme 可视化编辑器，完成可以上线运营的国际化汉服商城。用户已经批准架构第 2 节，并授权商品 SEO 与首页轮播无障碍修复；最终主题发布仍须在真实浏览器验收通过后单独即时确认。

当前真实页面和源码审计已经确认：

1. 首页水墨视觉方向成立，但导航密度偏高，轮播读屏标签仍输出“第%d张”。
2. 分类筛选公开了吊牌、领标、原始属性 slug 等采购侧字段；商品详情技术参数存在拼音字段名。
3. 商品详情缺少 Product、Offer 与 BreadcrumbList 结构化数据。
4. 活动页使用 Amazon Today's Deals 视觉语言、硬编码视觉值和公开演示商品，偏离 Theme Token 与水墨主题。
5. 编辑器前端脚本自行维护页面类型映射，与服务端 `ThemePageTypeResolver` 漂移；活动、帮助、关于、政策等页面被折叠成 `default` 或误判为 `cms_page`。
6. Theme 的 `theme_binding`、`layout`、`meta`、`appearance`、`i18n` 五类资源逐项发布；中途失败可能形成部分成功。
7. 真实日志显示动态慢请求主要耗费在控制器 `action_execute` 与后续 Query API 瀑布；路由匹配本身不是主因。

## 2. 成功标准

完成后必须同时满足：

- 默认主题呈现统一的水墨中国风，并在 375、768、1024 与宽桌面视口下保持可读、可操作和无双重横向边距。
- 首页、分类、商品、搜索、购物车、结账、账户、博客、活动、帮助、关于、联系、政策和 404 均有正确页面类型与 Theme 默认布局。
- 编辑器能在正确页面类型和范围内保存草稿、预览、切换页面、发布与回滚，不把独立页面错误折叠为 `default` 或 `cms_page`。
- 五类主题资源作为同一发布批次保持一致；失败时不得留下部分资源已发布的状态。
- 公开页面只展示真实商品或品牌化空状态，不出现内部占位说明、演示 SKU、采购字段或拼音属性键。
- 中英文核心转化链路完整；阿拉伯语按 RTL、币种和本地化格式展示，不混入仅适用于中国站的默认表达。
- 商品结构化数据可被解析，且只输出真实商品、价格、币种、库存、图片和面包屑信息，不伪造评分或评论。
- 首页轮播具备本地化标签、可辨识当前项、键盘操作和合理的自动播放控制。
- 性能验收同时覆盖冷动态请求、热缓存请求和浏览器 Core Web Vitals，不以单次 curl 或单测代替浏览器验收。

## 3. 非目标与授权边界

- 本设计不替换 Weline Theme、Weline UI 2.0、Weline.Api 或既有业务模块。
- 不引入第三方 UI 框架，不以 Bootstrap、Element、Ant 或 Amazon 风格组件替代 Weline 组件。
- 不在未获即时确认时执行最终主题发布。
- 不激活真实支付通道、不采购、不下单、不发消息，也不填写或保存用户凭据。
- 不伪造商品评价、销量、库存、折扣、产地、供应商或法律承诺。
- 不顺手重构与商城上线无关的框架代码，不覆盖工作区中的既有并行改动。

## 4. 总体架构

采用“一个页面类型真源 + 一个发布协调器 + 模块提供内容、Theme 提供布局”的方案。

1. `ThemePageTypeResolver` 成为运行时、编辑器导航、预览和布局选择的唯一页面类型真源。
2. Theme 为上线页面类型提供默认布局；业务模块通过既有模板、Widget、Hook 或 QueryProvider 注入真实内容。
3. 新增主题范围发布协调器，将五类资源组织成一个不可变批次，并生成可回读的发布回执。
4. 商品 SEO、轮播无障碍、活动页数据状态和国际化字段治理分别保持在各自归属模块，不把业务规则塞进 Theme 核心。
5. 所有视觉值使用 Weline Theme Token，共享内容版心使用 Theme 统一容器契约。

跨模块读取优先使用既有 QueryProvider、Interface 或 `w_query()`；视图扩展使用既有布局槽、Widget 或已声明 Hook。除非实现阶段发现现有契约无法表达需求，否则不新增 Event。

## 5. 页面类型与默认布局

### 5.1 页面类型真源

服务端解析器负责从规范 URI、显式 `page_type`、`theme_public_route` 和布局类型得到页面类型。编辑器 iframe 不再维护另一份硬编码 URL 判断表，而是消费服务端提供的页面类型清单或解析结果。

页面类型解析遵循：

1. 规范化语言、币种和站点前缀；
2. 优先使用控制器显式声明；
3. 其次按服务端路由解析；
4. 无法识别的内容页才退回 `cms_page`；
5. 真正的通用页面才退回 `default`。

编辑器导航、刷新、草稿预览和发布后的公开 URL 必须得到同一个页面类型。旧的不可达分支和重复映射删除，不保留双真源兼容层。

### 5.2 上线页面矩阵

以下页面类型必须保持独立，不得统一折叠成 `default`：

| 领域 | 页面类型 |
| --- | --- |
| 商城发现 | `homepage`、`category`、`product`、`search`、`promotion`、`activity` |
| 转化 | `cart`、`checkout`、`checkout_success`、规范名 `checkout_failure`（兼容既有 `checkout_failer`） |
| 客户 | `account`、`dashboard`；登录、注册、订单、地址和愿望清单沿用明确的账户子路由与同族布局 |
| 内容 | `blog`、`blog_category`、`cms_page`、`help`、`payment_guide`、`guide` |
| 信任 | `about`、`contact`、`review`、`qa`、`rma`、`policy`、`terms` |
| 系统 | `not_found`、`default` |

已有专用布局继续复用；缺失的页面类型在 `Weline_Theme` 默认布局中补齐。布局只定义页面骨架和空槽，业务模块内容通过 `default_injections` 或既有扩展点进入，禁止在布局 `<else/>` 中放演示业务文案。

## 6. 主题范围编辑与原子发布

### 6.1 草稿与预览

每个资源继续使用现有带范围的工作区：主题、区域、站点、语言、页面类型、布局选项和目标对象共同确定范围。草稿必须记录父发布版本与工作区 revision；保存冲突返回可理解的 revision 冲突，不静默覆盖。

预览严格读取同一范围的草稿快照；不存在草稿时按既有继承规则读取已发布资源。切换页面、语言、布局或目标对象时，未保存修改必须先明确刷新成功或保留在当前工作区。

### 6.2 批量发布协调器

发布顺序仍可按 `theme_binding`、`layout`、`meta`、`appearance`、`i18n` 排列，但所有资源先完成预检，再进入一个批次：

1. 解析待发布资源全集，冻结各自 revision、父发布版本和内容摘要；
2. 校验权限、范围、依赖关系和布局存在性；
3. 创建 `batch_release_id` 与批次状态；
4. 在一个协调器持有的单一数据库事务内创建不可变资源 release 并切换全部发布指针；
5. 任一资源失败时回滚整个批次，所有发布指针保持原值；
6. 提交成功后清理前台缓存并生成缓存；
7. 返回包含每类资源 release、摘要、范围、发布时间和缓存状态的发布回执。

显式目标资源及当前实现会同步派生的 descendant release 必须在预检阶段全部展开并纳入同一事务；协调器提交后不得再执行会改变发布指针的隐藏传播步骤。资源内容、revision、release 和当前指针均已由现有 Scoped Workspace 模型持久化到数据库，因此本章不引入跨数据库与文件系统的伪事务。

缓存生成失败发生在发布提交之后时，不把资源状态伪装成“发布失败”或尝试不安全的半回滚。批次保持一致并标记为 `published_cache_degraded`，公开读取走已清理后的冷构建路径；管理员可依据同一回执重试缓存生成。任何时候都不得出现“layout 新版、appearance 旧版”且没有批次状态可解释的组合。

### 6.3 回滚

回滚选择一个完整的历史 `batch_release_id`，再次创建新的批次指针，不修改既有不可变 release。回滚同样经过权限、范围、全集预检和缓存刷新，并生成新的回滚回执。

## 7. 活动页与水墨视觉

`promotion` 使用独立 Theme 默认布局，不再借用通用 `default` 页。活动业务模块仍拥有活动内容模板和商品查询，Theme 只提供统一页头、版心、内容槽和页脚。

活动页数据状态明确区分：

- `available`：展示真实可售商品；
- `empty`：展示水墨风品牌化空状态和返回商城入口；
- `unavailable`：记录查询故障并展示可恢复提示，不伪装成“没有商品”。

删除公开 stub 商品、内部接入说明和 Amazon 命名/样式。卡片、按钮、圆角、阴影、色彩、间距和版心全部使用 Weline UI 2.0 类与 Theme Token；活动页可使用宣纸、墨色、朱砂点色和真实汉服素材，但不得用手写 SVG、CSS 假图或拉伸占位图替代资产。

## 8. 商品 SEO 与公开数据治理

### 8.1 结构化数据

商品详情输出可解析的 JSON-LD：

- `Product`：真实名称、描述、规范 URL、图片、SKU 和品牌；
- `Offer`：当前真实价格、币种、库存状态和规范 URL；
- `BreadcrumbList`：首页、分类和当前商品层级。

多规格商品只输出当前选择或可证明的价格范围。缺失品牌、评分或评论时省略对应字段，不创建空壳或虚假值。JSON 使用安全序列化，测试必须实际解析输出而不是仅搜索字符串。

### 8.2 筛选与属性标签

前台筛选使用显式公开 allowlist。吊牌、领标、线头、供应商内部分类、原始 slug 和采购备注默认不公开；确有消费者价值的材质、版型、朝代、工艺、颜色、尺码和适用场景通过本地化标签解析器展示。

属性键与值按当前 locale 解析；找不到翻译时使用经过审核的可读名称，不直接展示 `hanfu_chao_dai`、`ao-qun` 或拼音标题化文本。列表页不以裸 SKU 作为视觉主信息；币种通过站点货币格式化器输出。

## 9. 首页轮播无障碍

轮播保留现有水墨视觉，但满足：

1. 每个指示器使用已格式化、本地化标签，例如“第 1 张，共 3 张”，不得把 `%d` 原样输出；
2. 当前项使用 `aria-current` 或等价状态；
3. 前后按钮有可读名称和足够点击区域；
4. 键盘可以移动到控制项并切换幻灯片；
5. 自动播放可暂停，并在键盘焦点或指针停留时不抢夺阅读；
6. `prefers-reduced-motion` 下禁用非必要运动；
7. 状态变化通过适度的可访问语义表达，不使用持续打扰的 live region。

移动端不让轮播控制覆盖标题、CTA 或商品图；桌面端保持视觉层级和安全裁切。

## 10. 国际化与内容一致性

核心上线语言先保证 `zh_Hans_CN`、`en_US`、`ar_SA` 的词典键一致，其他已启用语言不得因新增源串编译失败。前台模板用户可见文案使用 `<lang>` 或 `@lang()`，源串含逗号时使用安全形式。

英语不混入未翻译中文；阿拉伯语使用 RTL 排版、站点币种格式和适当的地址顺序。法律政策、支付说明、配送说明和退货承诺以站点实际能力为准，无法证实的指标、时效和社交链接不公开。

## 11. 性能设计

性能工作以真实日志和浏览器瀑布为依据：

1. 为首页、分类、商品、博客和活动页建立可重复的冷/热基线；
2. 在控制器、模板关键数据聚合和 QueryProvider 边界定位重复查询；
3. 同一页面对相同查询参数进行请求合并或复用，避免 Widget 各自触发等价 Query API；
4. 匿名公开页保持确定的 FPC eligibility，动态购物车、账户和地域信息不得无意使整个公共页面失去缓存；
5. 首屏必要数据优先在页面 ViewModel 聚合，非首屏内容延后但保留可访问的加载与错误状态；
6. 不以隐藏错误、延长超时或公开假数据换取“看起来更快”。

本地验收预算：热缓存 HTML 响应不高于 1 秒；核心公开页冷动态控制器不高于 3 秒；单个前台查询正常路径不高于 1 秒，首屏额外 API 瀑布总计不高于 2 秒。浏览器目标使用 Core Web Vitals 的良好阈值：LCP 不高于 2.5 秒、INP 不高于 200 毫秒、CLS 不高于 0.1。若本机环境噪声导致阈值波动，报告原始样本与瓶颈，不降低目标或把热缓存结果冒充冷启动。

## 12. 错误处理与可恢复性

- 页面类型未知：记录规范 URI 和解析输入，退回可解释页面，不写入错误范围。
- 草稿 revision 冲突：拒绝覆盖，返回最新 revision 与刷新建议。
- 发布预检失败：零资源发布，保留全部草稿。
- 批次中途失败：原子回滚发布指针与批次记录，返回失败资源。
- 缓存生成失败：批次保持一致，标记缓存降级并允许同回执重试。
- 商品查询失败：展示 `unavailable`，不回落到公开 stub。
- 商品确实为空：展示 `empty`，不把故障当空目录。
- 翻译缺失：测试失败并阻止该章节收口，不把源键或拼音键公开。

## 14. 测试与验收

### 14.1 自动化测试

最小测试集覆盖：

1. 已知路由解析为正确页面类型，语言/币种前缀不改变结果；
2. 编辑器导航使用服务端真源，没有独立硬编码漂移表；
3. 五资源批次成功时全部发布，模拟任一资源失败时全部保持原发布版本；
4. 缓存失败返回一致发布回执与降级状态；
5. 回滚以完整历史批次为单位；
6. 活动页可售、空目录和查询故障三态不混淆，源码中不再含公开 stub 文案；
7. 商品 JSON-LD 可解析，值与真实 ViewModel 一致；
8. 筛选 allowlist 不公开采购字段，属性键按 locale 解析；
9. 轮播标签格式化、当前项、键盘和 reduced-motion 契约；
10. 中英阿词典源键一致并完成 `i18n:collect`。

### 14.2 真实浏览器验收

使用用户指定的 Codex 本机内置浏览器，至少覆盖：

- 首页 → 分类 → 商品 → 加入购物车 → 购物车 → 结账；
- 搜索、博客、活动、帮助、关于、联系、政策和 404；
- 主题编辑器页面类型切换、范围保存、草稿预览、批次发布失败、成功发布和整批回滚；
- 中文、英文和阿拉伯文的导航、价格、属性、表单、错误与空状态；
- 375、768、1024 断点的内容版心、图片裁切、文字重排、CTA 和键盘焦点；
- JSON-LD 解析、轮播键盘控制和减少动画偏好；
- 冷动态、热缓存和页面 API 瀑布性能样本。

浏览器截图只能证明可见状态；键盘、读屏语义、发布一致性和性能仍须结合 DOM、接口回执、数据库回读和日志。最终发布不属于自动验收动作，必须等待用户即时确认。

## 15. 交付与证据

每章同步更新归属模块的 `doc/需求.md`、`doc/功能现状.md` 或 `doc/开发日志.md`，记录实际变更、测试命令、运行时结果、浏览器用例、截图路径和未完成项。

阶段汇报必须列出探活后的前台、后台与 API 地址。最终交付只有在全部章节、全部页面矩阵、主题范围编辑、批次发布与回滚、国际化、性能和浏览器验收都有直接证据时，才能称为“可上线”。
