# MCP 指令：产品分类修复

**触发词（任一即执行，无需再确认范围）**

- `产品分类修复`
- `分类修复`
- `商品分类修复`
- `category repair`
- `product category fix`

用户只要**提到**上述触发词，Agent 必须把本文件当作硬指令执行：对照主图 / 标题 / 适用性别 / 朝代 / 材质与**现有完整分类树**，为已发布商品做**一品多类**挂靠与错挂纠正，**不要**只口头解释、不要只修用户当前打开的单个 SKU（除非用户显式限制 `--product=`）。

会话内用户说「指令化」时：把**当前会话已验证的修复流程**沉淀为本目录下对应指令 md（本文件即本会话「产品分类修复」的指令化结果）。

## 缺陷定义（判定）

相对现有分类树（商业树 `女装/男装/童装/套装/配饰` + 汉服树 `形制/用途/材质`），存在任一：

1. **受众错挂**：女装主图/「汉服女」标题挂在男装；童装（女童/男童/儿童…）挂在成人男装或成人女装叶子（亲子/母女除外）
2. **分类过粗**：仅挂 1～2 个粗叶子（如只在「襦裙」「日常常服套装」），未追加受众根、形制、用途、材质等应属节点
3. **汉服树空洞**：已发布商品未挂 `/hanfu` 及形制/用途/材质
4. **形制未对齐**：标题含马面/齐胸/明制/唐制等，但未挂对应商业叶子或 `/hanfu/style/...` 叶子
5. **中性属性误扩**：源属性「中性/男女均可」把明确女装标题扩到男装

**典型根因**：1688 导入 `hanfu1688CategoryId` 只选一个粗叶子；后续受众追加未覆盖汉服树；`汉服女` 正则误匹配 `汉服女童`。

**不属于本指令：**

- 新建/删除/改名分类树节点（那是分类种子/后台编辑）
- 改商品主图、价格、规格轴、Offer
- 手改 `generated/`、店面模板
- 无标题/属性证据时强行填满所有空叶子（如无「真丝」证据不挂真丝桑蚕）

## Agent 必做流程

1. **工程会话（可选检索）**：需要规则/索引时可 `ensure-project-guidance` → `prepare_project` → 读 hard-constraints；**执行修复用宿主原生 Shell/编辑**。
2. **缺陷扫描**（仓库根，建议 `opcache.enable_cli=0`）：

```bash
php -d opcache.enable_cli=0 app/code/Weline/Product/scripts/remediate-product-category-audience-append.php --dry-run
```

关注 JSON：`append_links` / `unlink_conflicts` / `append_path_dist` / `items`。

3. **补充探针**（可选，SQL 或一次性 php）：确认  
   `women_title_on_men`、`kids_on_men`、`kids_on_women_no_parent`（排除亲子）、`missing_hanfu`、`too_few_links(<4)` 的数量。
4. **有变更则 apply**：

```bash
php -d opcache.enable_cli=0 app/code/Weline/Product/scripts/remediate-product-category-audience-append.php --apply
```

5. **再 dry-run**：期望 `changed` 接近 0，或仅剩合理例外（成人礼/老师款标题带「书童」仍挂女装等）。
6. **验收**：Browser 禁用缓存后打开至少：
   - `/category/men`（无女装主图卡）
   - `/category/kids`
   - 一个形制叶（如 `/category/hanfu/style/ming/mamian` 或 `/category/hanfu/style/tang`）  
   curl 探活交付 URL；关闭本回合验收 Browser。
7. **文档**：`app/code/Weline/Product/doc/开发日志.md` 记扫描/apply 数字与规则变更。
8. **汇报**：`changed` / `append_links` / `unlink_conflicts`；缺陷计数前后对比；交付 Markdown http(s) 分类页链接。

可选：

```bash
# 只修一个商品
php -d opcache.enable_cli=0 app/code/Weline/Product/scripts/remediate-product-category-audience-append.php \
  --product=320 --apply

# 指定 website / 限额
php ... --dry-run --website=0 --limit=50
```

## 脚本行为摘要

| 模式 | 作用 |
|------|------|
| `--dry-run` | 按标题+性别+朝代+材质生成 desired path 集；打印将追加/冲突 unlink 的项 |
| `--apply` | 幂等 `CategoryLinkRepository::link` 追加；受众冲突叶子 `unlink`；刷新店面分类缓存 |
| `--product=ID` | 单商品 |

**一品多类路径来源（可并存）：**

- 受众：`/women` `/men` `/kids`（及女童/男童）
- 商业形制：襦裙/马面/袄裙/褙子/圆领袍…
- 套装/配饰：`/sets/*` `/accessories/*`
- 汉服树：`/hanfu/style/{ming,tang,song}/…`、`/hanfu/occasion/…`、`/hanfu/material/…`

**硬规则摘录：**

- 童装标题不因「适用性别=男」挂成人男装
- 「汉服女」不匹配「汉服女童」；童装不挂成人 `/women*`（亲子/母女除外）
- 明确女装标题 + 中性属性 → 不挂男装
- 无证据不填空叶子

---

## 验收标准

- 男装列表无女装主图商品；童装不出现在成人男装
- 汉服形制/用途/材质有直链商品（不再全 0）
- 抽样商品同时出现在受众 + 形制 + 用途/材质等多类
- dry-run 后无大面积新增错挂
