# 指令：规格修复

**MCP：跳过**（`content_ops_skills_skip_mcp`）。勿 `prepare_project` / `get_skill`；宿主 Read 本文件并跑脚本。

**触发词（任一即执行，无需再确认范围）**

- `规格修复`
- `规格技术细节修复`
- `技术细节补全`
- `listing spec repair`

用户只要**提到**上述触发词，Agent 必须把本文件当作硬指令执行：自动查找「技术细节不对/缺失」的已发布商品，并从 1688 crawl 快照回填产品级 listing 属性（材质、领标、吊牌、货号等），**不要**只口头解释、不要只修单个用户当前打开的 SKU（除非用户显式限制 `--product-id=`）。

---

## 缺陷定义（判定）

已发布 configurable 商品，公开 EAV 中：

- `hanfu_%` / `material` 等产品级技术属性 **tech_n = 0**
- 通常仍有规格轴 `size` / `style_type`（或 color 族）
- 常有 `source_offer_id` + `var/hanfu-1688/**/crawl-snapshot.json` 里仍存完整 `specifications`

典型根因：导入报 `product_attribute_option_invalid`（历史上「货源类型」误入 `style_type`），产品级 listing 属性整单未写入；PDP「技术细节」只剩尺码/类型。

**不属于本指令：**

- 改可购规格轴矩阵 / combination_key / Offer SKU
- 手改 `generated/`、`view/tpl`
- 无快照、无 `source_offer_id` 的商品（记 skip，不要伪造属性）

## Agent 必做流程

1. **工程会话（可选检索）**：需要规则/索引时可 `ensure-project-guidance` → `prepare_project` → 读 hard-constraints；**执行修复用宿主原生 Shell/编辑**。
2. **先 dry-run 扫描**（仓库根）：

```bash
php app/code/Weline/Product/scripts/remediate-product-listing-spec-attrs.php --scan --dry-run
```

3. **有 deficient>0 则 apply**：

```bash
php app/code/Weline/Product/scripts/remediate-product-listing-spec-attrs.php --scan --apply
```

4. **再扫一遍确认** `deficient=0`（或仅剩无快照 skip）。
5. **验收**：对**每一个** `applied` 商品（过多时可抽样，但不少于 2 个且含本回合全部 fixed 时优先全覆盖）打开 PDP：Browser **禁用缓存** → 确认「技术细节」多于尺码/类型；对**每条交付 URL** `curl` 探活（与字面 URL 一致）。
6. **文档**：`Weline_Product` `doc/开发日志.md` / 必要时 `功能现状.md` 记一笔扫描结果与版本。
7. **汇报（硬）**：必须按下方「汇报模板」输出——**修复内容明细 + 交付地址**；禁止只写 `fixed=N` 而无清单、无链接。写完「交付地址」后关闭本回合验收 Browser。

可选：

```bash
# 只修一个
php app/code/Weline/Product/scripts/remediate-product-listing-spec-attrs.php \
  --product-id=84 --offer-id=896875413963 \
  --snapshot=var/hanfu-1688/.../crawl-snapshot.json --apply

# 指定 website / 快照根
php ... --scan --apply --website=0 --snapshot-root=var/hanfu-1688
```

## 汇报模板（硬，缺一不可）

面向用户的收口回复**必须**包含：

### 1. 摘要

- `deficient` 扫描数 / `fixed` / `skipped` / `failed`
- 若 `fixed=0`：写明「无缺陷可修」或 skip 原因；**仍可**省略交付地址，但须说明为何无链接

### 2. 修复内容明细（每个 fixed 商品一行或多行）

| # | product_id | 商品名（短） | source_offer_id | 回填属性摘要（code=值，可截断） | 条数 |
|---|------------|--------------|-----------------|----------------------------------|------|
| 1 | 84 | … | 896875413963 | material=涤纶；领标=…；吊牌=… | 13 |

- 属性摘要至少列出用户可见的关键项（材质 / 领标 / 吊牌 / 货号 / 适用场合等），不要只写「已回填」。
- `skipped` / `failed` 另列原因（无 offer_id / 无快照 / normalize 失败等）。

### 3. 交付地址（每个 fixed 商品一条）

主链 Host：`http://{project_hash}.test.weline.com:{port}/product/{slug}`  
（禁止主链用 `*.weline.test`；有 `*.test.weline.com` 时勿强行 `127.0.0.1`。）

写法（**每个 fixed 商品都要有**）：

```markdown
### 交付地址

- [#84 柒依阁学生表演服](http://p05113ef3.test.weline.com:9555/product/qi-yi-ge-zhong-guo-feng-han-fu-chu-gao-zhong-xue-sheng-yun-dong-hui-62364c3c)
  `http://p05113ef3.test.weline.com:9555/product/qi-yi-ge-zhong-guo-feng-han-fu-chu-gao-zhong-xue-sheng-yun-dong-hui-62364c3c`
```

- slug 取 EAV `slug`（website 分片）；探活 URL = 交付字面 URL。
- fixed 较多时：列表全给链接；Browser 可抽样打开，但**汇报链接不得省略**。
- 收口后：unlock + 关闭本回合验收 Browser（`browser_release_after_delivery`）。

## 脚本行为摘要

| 模式 | 作用 |
|------|------|
| `--scan --dry-run` | 列出 tech_n=0 的已发布商品；为每个 `source_offer_id` 选 listing 规格最多的 crawl-snapshot；打印将写入的非轴属性 |
| `--scan --apply` | 同上并写入 website shard attribute_value（`''` + `zh_Hans_CN`）；不改 axes / offers |
| 单商品三参数 | 定向回填，不扫全站 |

写入前会：`OfferEavMapper`（含货源类型→`hanfu_huo_yuan_lei_bie`、含量不并入 material）→ `ensureHanfuAttributeOptions` → `hanfu1688AlignProductValuesToSharedEav` → `normalizeRows`。

---

## 验收标准

- 扫描前后：`deficient` 下降；目标商品 EAV 出现 `material` / `hanfu_*` 等
- PDP「技术细节」可见材质、领标、吊牌等，而不仅是尺码/类型
- 规格轴与加购行为不变
- **汇报含修复明细表 + 每条 fixed 商品的 Markdown 交付地址**
