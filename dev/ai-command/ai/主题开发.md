## ⚠ 破坏性操作高压线（开篇必读）

以下**不是**清缓存、**不是**日常排障手段。误触 = 绿场级数据丢失。用户说「慎重」时，默认指本表：

| 操作 | 后果 | 允许条件 | 绝对禁止 |
|------|------|----------|----------|
| **Factory Reset**（Editor `factory-reset` / `ThemeFactoryResetService::resetAll('RESET')`） | 清空 scoped patch/revision/release/workspace、layout version、default_injection、`weline_theme`，并清相关 Meta/词典 | **仅绿场**；用户本回合**显式授权**；确认串精确 `RESET`；**先备份 DB** 并核验 | 生产；把 Reset 当「清缓存/修预览」；未备份；确认串近似（`reset`/`Reset` 都不行） |
| **自写 SQL 删/改** `theme_scope_*` / 旧 Scope 表 | 破坏继承链与 Release | **无**——`theme:scope:migrate` **未实现** | 猜删、手搓迁移、发明平行 CLI |
| **手改** `generated/` / `view/tpl/` / `pub/static` 当源 | 下次 compile/upgrade 覆盖；污染真源 | **无** | 排障「先改产物」 |
| **`clearNonGlobalCaches(null)`**（已知 typed Scope 时） | 跳过 `generated_theme_cache`；店面仍旧 | 仅未知 Scope 的遗留路径（尽量不用） | 已知 Scope 的发布后失效 |
| **生产** `theme:remove` / 未审卸载 | 主题卸载面含历史调试残留，勿当生产卸载器 | 本机绿场且已 Read Console 源 | 生产未备份卸载 |

**排障默认顺序**（未授权破坏性操作前）：禁缓存 Browser → 查 published binding / 发布回执 → `theme:upgrade` / disk:compile / scan-variables（按矩阵）→ 框架定向缓存失效。**仍不行再 escalate，禁止先 Reset。**

## § work_mode 开工门禁（硬）

**未声明 `work_mode` 禁止落任何 Theme / `app/design` 文件。**

合法取值（架构师冻结）：

| `work_mode` | 含义 |
|-------------|------|
| `default_theme` | 维护默认主题层 `Weline_Theme/view/theme` |
| `design_theme` | 新开或维护 `app/design/{Vendor}/{theme}` |
| `theme_module_runtime` | 维护 Theme 模块 PHP 运行时（非皮肤文件战） |

规则：

1. 开工首条回报必须写出 `work_mode=…`（或纪要/channel 同等声明）。  
2. **单波默认单 mode**；同一施工波禁止混改默认层 + design 皮肤。  
3. **跨 mode** 须单独 `justification`（为何同回合需要、影响面、回归范围），否则拆波。  
4. 领域探查 checklist（新主题）：`register` → `frontend/` 现代树 → `parent` 名正确 → palette（`colors/_` + `variables/_`）→ overlay（layout/模块模板）→ `theme:active` + published `theme_binding`。

## § Mode A — `default_theme`（维护默认主题）

**根**：`app/code/Weline/Theme/view/theme/{frontend|backend}/`

**改什么**：

- Token：`colors/_*.css`、`variables/_*.css`（语义色 / spacing / typography）  
- 基础 layout / partial / component  
- **仅本 mode** 可改 `assets/css/theme.css`、`assets/js/theme.js`（全局运行时入口）  
- Editor / 预览壳相关若属默认壳层  

**影响**：默认层变更影响**所有** design 子主题（继承链）。落盘前须写清回归提示：至少预览三态 + 1 个活跃 design（若有）+ 正式店面抽检。

**命令（适用时）**：

```text
php bin/w resource:compile welineModules
php bin/w frontend:check-theme-layout-widgets
php bin/w frontend:check-required-injection-sibling-fetch
# Browser：预览三态与正式态同构；Token 生效；禁私有 hex 调色盘
```

## § Mode B — `design_theme`（新开 / 维护 design 主题）

对照样例：`app/design/Weline/hanfu/`（register + `frontend/` 树）。**样例非第二权威**；冲突以 Theme 源码与 inheritance 文档为准。

### 逐步清单

1. **注册** `app/design/{Vendor}/{theme}/register.php`：

```php
Register::register(
    TypeInterface::type,
    'Weline_Hanfu', // module_name
    [
        'name' => 'hanfu',
        'parent' => 'Default 默认主题', // 或已存在主题 name
        'path' => __DIR__,
    ],
    '1.0.0',
    '描述'
);
```

样例链：[`app/design/Weline/hanfu/register.php`](../../../app/design/Weline/hanfu/register.php)。

2. **现代目录树（硬）**：必须含 `{frontend|backend}/`（否则 `themeSupportsArea` 失败）。  
   - **禁止照抄** `theme:create` 仍可能提示的旧 `view/templates` 树。  
   - **勿依赖** `theme:create` 作为唯一权威脚手架；以本 Mode B + hanfu 为准。生成器若过时，按本清单手建。

3. **安装 / 列表**：

```text
php bin/w setup:upgrade
# 或
php bin/w theme:install -t {name}
php bin/w theme:listing
```

核对 name / parent / path。

4. **激活（命令名硬）**：`php bin/w theme:active {name} frontend`  
   - **不是** `theme:activate`（旧文案错误）。  
   - 同时配置 Website / Scope。  
   - 正式店面 HTTP：**published `theme_binding`（scoped Release）优先于裸 `is_active` / `is_active_frontend`**。只改 `is_active` 而不发 binding，店面可能仍走旧主题。

5. **最小皮肤**：

   - `frontend/colors/_*.css`（文件名须 `_` 开头）  
   - `frontend/variables/_*.css`  
   - 独立 `frontend/assets/css/{brand}.css`（勿用 `theme.css` 同 key）  
   - head / partial 用 `<theme:css>` 挂盘（对照 hanfu `partials/head/hanfu-skin.phtml`）

6. **高压线（硬规则 `theme_design_must_not_override_core_runtime_assets`）**：  
   禁止同逻辑 key 覆盖 `assets/css/theme.css` / `assets/js/theme.js`（`ThemePathResolver::isCoreRuntimeAsset`）。品牌化只用 colors / variables / 独立 CSS。

7. **layout / 模块模板覆盖**：

   - layout：同 key **整份替换不合并**  
   - 模块模板：`app/design/.../Weline_Module/templates/{area}/...`  
   - **禁止** `frontend/templates/`（那不是模块模板覆盖协议）

8. **验收**：

   - 预览三态身份（preview / editor / runtime）不混  
   - 正式店面 binding 生效  
   - 父源槽位 / Hook 不丢（对照 inheritance + hanfu 继承研究）

## § 前后端主题 · 四层 · 公共组件库（HARD）

本席**必须**先分清 area、四层与「公共库」再落文件。权威展开：[`view/theme/README.md`](../../../app/code/Weline/Theme/view/theme/README.md)、[Theme开发总指南 §2](../../../app/code/Weline/Theme/doc/开发/Theme开发总指南.md)、[部件开发指南](../../../app/code/Weline/Theme/doc/部件开发指南.md)、[通用建站部件库](../../../app/code/Weline/Theme/doc/通用建站部件库.md)、[组件Meta信息格式规范](../../../app/code/Weline/Theme/doc/组件Meta信息格式规范.md)。

### 前后端主题怎么定义

| 概念 | 定义 |
|------|------|
| **area** | 主题树按 **`frontend` / `backend`** 分区，不是旧式 `design/frontend/default` |
| **默认主题** | `app/code/Weline/Theme/view/theme/{area}/`（平台基线；Mode A） |
| **design 主题** | `app/design/{Vendor}/{theme}/{area}/`（可**只做 frontend**；后台继续吃默认 backend；Mode B） |
| **控制器选壳** | 前台 `FrontendController` → area=`frontend`；后台 `BackendController` + `isBackend` → area=`backend`。后台 URL 的 `editor_area`/`preview_area` **只影响画布身份，不把后台壳改成 frontend layout** |
| **激活** | `php bin/w theme:active {name} frontend`（或 `backend`）；须带 area |

目录骨架（每个 area）：

```text
{area}/
├── layouts/{layoutType}/{option}.phtml
├── partials/{type}/{option}.phtml
├── components/*.phtml          ← 公共 UI 原语（SSR / Builder）
├── widgets/{type}/{code}/default.phtml  ← 可拖拽部件
├── colors/_*.css · variables/_*.css
├── assets/css/theme.css · assets/js/theme.js  ← 仅默认层可同 key 维护
└── config/modules.json
```

### 四层地图（勿混用）

| 层 | 一句话 | 路径 / 引用 |
|----|--------|-------------|
| **layout** | 页面骨架 + slot/hook/widget 挂点 | `layouts/{layoutType}/{option}.phtml` |
| **partial** | header/footer/head/sidebar 等可切换壳 | `partials/{type}/{option}.phtml`；`<w:block class="Weline\Theme\Block\Partials" area type default-option>` |
| **component** | **无业务**可组合 UI 原语（button/card/…） | `components/{name}.phtml`；`$this->fetch('Weline_Theme::theme/{area}/components/….phtml', $data)` |
| **widget** | 可视化可拖拽、带 `@widget.*`/`@param` 的运营块 | `widgets/{type}/{code}/default.phtml` + `extends/module/Weline_Widget/{Module}/widget.php` |

Taglib（`<w:…>`）是**领域控件**，不替代四层；能用四层就不要为普通片段新建 Taglib。

### 公共组件库 = 双层（不是单一 npm 包）

**① Theme `components/*.phtml`（主题内组件库）**

- 落点：`Weline_Theme/view/theme/{frontend|backend}/components/`
- 职责：Builder / SSR 原语；Meta 见 `组件Meta信息格式规范.md`
- 前后端差异：FE 另有 `divider`/`image`/`input`/`text`/…；BE 另有 `message`；共有 `button`/`card`/`alert`/`table`/`modal`/…
- **新后台页优先直接写 Weline UI 类名**（见下），不要依赖旧 Bootstrap `btn-*`

**② Weline UI 2.0（公共 chrome / 类名权威）**

| 资产 | 落点 |
|------|------|
| Foundation + `w-*` | `view/statics/ui/weline-foundation.css`（`.w-button` `.w-card` `.w-input` `.w-field` …） |
| 前台壳 | `weline-frontend.css` + `{area}/assets/css/theme.css` + `theme.js` |
| 后台壳 | `weline-backend.css`（`.w-backend-page` / `__heading`） |
| 运行时 | `weline-ui.js`；声明式 `data-w-component="menu\|dialog\|popover\|…"` |
| 懒加载高级件 | `view/statics/ui/components/*`（datatable、mega-menu、file-picker…） |

后台业务页：**必须** `w-backend-page` + `w-card` + `w-field`/`w-input`/`w-button`/`w-table`；对照 Marketing/Smtp。Token：`--weline-theme-*` / `--backend-color-*`；基础组件禁私写 hex。

### 部件怎么定义

| 类型 | 落点 | 本席 |
|------|------|------|
| **Theme 自有部件** | `view/theme/{area}/widgets/…` + `extends/.../Weline_Theme/widget.php` | 可施工（模板/内嵌） |
| **通用建站部件库** | 见 `通用建站部件库.md`（`section-heading`/`card-grid`/`hero-banner`/…）；样式 `statics/css/widgets/site-blocks.css` | Theme 自有范围内本席；跨模块注入交部件席 |
| **业务模块部件** | 各模块 `extends/module/Weline_Widget/Weline_{Module}/widget.php` | **禁止**代写外国 `default_injections` → **Team:部件开发工程师:** |

硬规则：Theme layout **仅可内嵌** `Weline_Theme` 部件；跨模块只走空 `<w:slot>` + 拥有模块 JSON；同身份 XOR（`theme_layout_widget_owner`）。

## § 编译矩阵（P0）

| 何时 | 命令 |
|------|------|
| 改 `weline.modules.js` / 模块 paths | `php bin/w resource:compile welineModules`（亦见 `theme:resource:compiler`） |
| 改 Theme Editor / UI bundle（`theme-editor.js`、`editor-mode.js`、`statics/ui` 入口） | `php bin/w resource:compile welineUi` |
| 色盘/变量 **Meta→Editor 目录** | `php bin/w theme:scan-variables`（可 `area=` / `theme_id=` / `force=true`；`setup:upgrade` 也会扫） |
| 色盘/变量 **店面 override CSS** | `php bin/w theme:disk:compile`（见下） |
| 主题静态搬迁到 `pub/static`（改 CSS/JS 店面仍旧） | `php bin/w theme:upgrade` |
| 改默认壳/多语后 404 静态页 | `php bin/w theme:publish-not-found-static`（`--force` / `--lang=xx_YY`）→ `pub/errors/storefront-not-found/` |
| 壳/后台 chrome 残留第三方 UI | `php bin/w theme:ui:audit`（可 `--format=json`；违规非 0） |
| 布局部件门禁 | `php bin/w frontend:check-theme-layout-widgets`（+ sibling-fetch） |
| section 身份 | `php bin/w frontend:check-section-code` |

**变量双轨（硬）**：`scan-variables` ≠ `disk:compile`。宣称 Token 生效须按需两者都跑 + 禁缓存 Browser。

**`theme:disk:compile` 实操**

- 产物：`generated/theme/disks`（整盘 override CSS，非手改目标）
- 参数：`t|theme_id`（可选，默认全部主题）、`a|area`（`frontend|backend`，默认两边）、`scope`（默认 `default`）
- 例：`php bin/w theme:disk:compile -t 1 -a frontend`
- 改磁盘 `colors/_` / `variables/_` 后走本命令；**不要**手改 `generated/`

**Toast**：`Weline.Toast` / `Weline.BackendToast`；禁止依赖 `window.Toast` / `AdminToast` / 裸 `Swal`/`bootstrap`（`theme:ui:audit` 亦扫）。

**禁止**只改源不 compile / 不 upgrade / 不 publish-not-found 却宣称 Editor/店面/404 已更新。

## § theme_binding · Scoped 发布（P0）

正式店面 HTTP 权威是 **published `theme_binding`（Scoped Release）**，不是裸 `is_active`。

| 动作 | 要点 |
|------|------|
| `php bin/w theme:active {name} frontend` | 经 `ThemeContextService`；**会 sync published theme_binding**（见 `Active.php`） |
| Theme Editor 发布 | 顶部先选 **作用范围 → 区域 → 主题**；Publish 生成不可变 Release；`r{published_release_id}` |
| 资源族 | `theme_binding`（绑主题）≠ layout 版本 ≠ appearance Brand；各发各的，勿混 |
| 结构冲突 | 父级删/移子级正在改的节点 → 后代服务最后有效 Release；用重置/重定位/重基线；`blocked` **不清缓存** |
| Scope 迁移 | **见下「幻影 CLI」**；禁止自写 SQL 猜删 |

权威：`visual-editor/scope-switching.md`。否决：只改 `is_active` / 只 `theme:listing` 却宣称店面已切主题。

### Scope 迁移 CLI 现状（硬 · 纠偏）

- 文档中的 `php bin/w theme:scope:migrate preflight|apply` **当前未实现**（`Console/Theme/Scope/` 为空；本机 `No matching command`）。
- **禁止**自写 SQL 猜删 `theme_scope_*` / 旧 Scope 表；歧义节点只告警不覆盖。
- 未挂载命令前：只走 Editor 规范 Scope 写入 + 发布路径；**禁止发明**平行迁移 CLI。

## § 发布后缓存失效（P0）

「改了看不见」优先查：FPC / chrome / generation / `theme_static_version`。权威：`runtime-cache-invalidation.md`。

| 场景 | 正确失效 | 禁 |
|------|----------|-----|
| Editor Scoped publish 成功 | 走框架 `clearAllThemeRelatedCaches` / Scope 定向 `clearScopedCaches` | 已知 typed Scope 却 `clearNonGlobalCaches(null)`（会跳过 `generated_theme_cache`） |
| publish `blocked`（结构冲突） | **不得**清缓存；HTTP `success=false` | 当成功发布 |
| 仅 CLI 改静态源 | `theme:upgrade` + 适用时 disk:compile；必要时 bump `theme_static_version` | 只清局部 forget 键 |
| 模板静态 URL | 由 Env `theme_static_version` / bump 注入 | `.phtml` 手写 `@static(...)?v=` / `&v=`；Preview injector 挂死 ASSET_VERSION |

人工排障：确认发布回执非空 → 禁缓存 Browser → 再查 Worker Env 是否 reload 磁盘 `theme_static_version`。

## § 语义色 · 店面度量 Token（P0）

权威：`theme-semantic-color-matrix.md` + `theme-storefront-token-consumption.md`。

## § 版心与 Head 挂盘顺序（P0）

版心契约：[`theme-layout-content-width.md`](../../../app/code/Weline/Theme/doc/theme-layout-content-width.md)。禁止自写第三套容器或字面量 `1440px` 版心；漏挂 `variables/_spacing.css` 会导致版心错位。

**前台 head 真序**（权威源：`view/theme/frontend/partials/head/default.phtml`）：

1. `weline-theme-prepaint.js`  
2. `Weline_Frontend::templates/public/head.phtml`（Frontend 模块公共 head）

5. `ui/weline-foundation.css` → `ui/weline-frontend.css`  
6. `assets/css/theme.css`（**仅默认层同 key**；design 禁覆盖）  
7. `css/widgets/site-blocks.css`  
8. `ui/weline-ui.js`（module）+ hook module-declarations  

design 品牌 CSS：独立文件名 + `<theme:css>`，插在 colors/variables 之后、**不要**顶替 `theme.css`。
