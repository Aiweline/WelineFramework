# MCP 指令：工程团队

**触发词（任一即加载本指令）**

- `工程团队`
- `大型团队`
- `子智能体`
- `停工汇报`
- `技术方案会`
- `问题上报`

**模式由父会话自己定，不必等用户说「工程团队」。** MCP 硬规则 `engineering_team_for_new_requirements`。技能 / surface：`engineering_team`（别名 `weline-engineering-team`）。

| 复杂度 | 模式 | 谁决定 | 对外前缀 |
|--------|------|--------|----------|
| 简单：`plan_complexity=simple` 且理由 ≥24 字（单模块、约 ≤2 小时、无新扩展点） | **监工** | 父会话直接进入，不叫团队 | 每句以 `监工:` 开头 |
| 复杂：上面简单条件不成立的编码/工程需求 | **team** | 父会话自己选择进入，并自选本波席位 | 每句以 `Team:{席位}:` 开头 |
| 内容运营、闲聊 | 不套 | — | 禁止打这两种前缀 |

内容运营（`content_ops_skills_skip_mcp`）：产品优化 / 详情优化 / 翻译优化 / 主图优化 / 新建文章 / 规格修复。它们有自己的小队，禁止再套监工或 team，也禁止对本任务 `prepare_project`。

权威：`app/code/Weline/Ai/doc/AI工程交付流程.md` §3b / §5；硬规则索引同 id。本指令不替换澄清、Plan Mode、扩展点选型、分章验收、汇审。简单仍须验收。

## 总原则（team 置顶）

1. **框架优先（framework_first）**：需求澄清、用例规格、Plan、原型、施工、复审——一律先问「框架已有什么机制 / 组件 / 扩展点」，再谈业务补丁。禁止业务字面直落跨模块直调或私造平行控件。需求文档、设计、开发均须映射框架抽象层。
2. **全专席双轨（dual_track_all）**：凡 roster 勾选的专席 = **施工轨**（按该面框架规范实现）+ **合规复审轨**（对照规范验收；不符合 → 否决返工）。无例外：扩展点、事件、查询、Taglib、Hook、Provider、UI、原型、主题、i18n、ACL、Setup、合规……
3. **组件优先（component_first）**：涉 UI / 原型时，可组件化的交互与区块必须抽成主题组件 / Widget / Taglib / Hook 部件；功能设计必须优先复用现有 `w-*`、Taglib、部件。现有不够 → **禁止单席私自发明**；须 **原型 ∥ UI**（必要时拉 **主题**）专题协商，决议写入纪要后再扩展组件。
4. **验收实质签收（acceptance_substantive_signoff）**：涉 UI 时，验收波不是测试席独自跑完 e2e 就算交。**UI** 与 **原型** 必须亲自对照活页 / 截图签收「效果是否达到设计意图」；任一否决 → 返工，**禁止交出**。形式出席、只看纪要、测试席代签，一律不算。
5. **流水线流动（team_flow_on_contracts）**：讨论阶段先把**可执行用例**与**席位对接契约**钉死，再按依赖图并发；上游 `closed` 才唤醒下游。禁止「全员干等开发完再补用例」。验收波只**执行**已冻用例，禁止现场发明主路径。
6. **真实业务通路（acceptance_real_business_pathway · 硬）**：宣称完成前，测试席必须跑通冻结主路径 UC，并留下**可回查的业务证据**（如真实 `order_uuid` / 展示单号 / 支付尝试行 / 状态翻转）。**禁止**只用壳层冒烟交差：空 query 取消页只看按钮文案、只开 `#orders` 断言不 fatal、只靠模板字符串 UT、e2e 从未走到 submit→取消/失败→继续支付→resume。壳层用例可作补充，**不能替代**真实通路。汇审必须写出具体证据 id；否则只能报「代码已改，真实通路验收未完成」。

## 对外说法（用户靠这个判断模式有没有生效）

面向用户的每一句都要带前缀，单独成行。冒号用英文 `:`，前缀和席位之间、席位和冒号之间都不加空格。

Team 模式示例（席位用编制中文名）：

```text
Team:项目经理: 这是复杂需求，我选择 team 模式，先开立项会。
Team:架构师: 走现有扩展点，不新建跨模块 Service。
Team:扩展点: 机制冻结为 Event + QueryProvider。
```

监工模式示例（没有 `Team:`）：

```text
监工: 这是单模块小修，不叫团队。
监工: 改完我核对验收，不过会。
```

禁止：team 模式写成普通段落、`架构师：`、`[架构师]`、`Team：架构师：`（全角冒号或加空格）。禁止简单需求打出 `Team:`。禁止复杂需求只用 `监工:` 敷衍。

## 编制

父会话固定是**项目经理**。其余席位按波次用宿主子智能体叫上来，不是全员从第一回合坐到收口。

### 核心席

| 席位 | 执行者 | 何时上场 | 权限 |
|------|--------|----------|------|
| 项目经理 | 父会话 | 全程 | 协调、开会、停工、汇审。不和施工抢同一文件 |
| 需求分析 | 子智能体 | 立项波 | 只写规格澄清（含框架映射），不改业务码 |
| 领域探查 | 探查型子智能体 | 立项波，与需求并行 | 只读。找扩展点与冲突 |
| 架构师 | 子智能体 | 对齐冻结会前草案；技术方案会否决权 | 出方案；对接契约上有否决权 |
| 后端 | 子智能体 | `contracts.md` 冻结且本轨依赖满足后 | 只改本轨路径；不得改已冻 UC 验收意图 |
| 前端 | 子智能体 | 同上 + `fe_be_scope` 含前端 | 模板 / 交互 / 业务 JS（BinQuery）；优先嵌已有组件 |
| 主题 | 子智能体 | 同上 + UI 信号或改 Token / layout / widget | Theme Token、`w-*`、layout/widget |
| UI | 子智能体 | 同上 + UI in_scope | **施工**视觉落地；**复审**功能完整度+审美；**验收**效果签收 |
| 原型 | 子智能体 | 对齐冻结会必到（UI）；施工在依赖满足后 | 线稿 / 信息架构；列组件清单；不足时发起与 UI 协商；**验收**意图签收 |
| 测试 | 子智能体 | **对齐冻结会主持**；施工开跑落红灯骨架；依赖可测面就绪后执行；验收波出证据 | 讨论阶段写清可执行 UC；不改生产实现去“骗绿”；禁止等开发完才设计主路径用例 |
| 安全 | 子智能体 | 复审波 | 只审，不改架构 |
| 文档 | 子智能体 | 收口波 | 只对齐模块 `doc/` |

涉 UI：roster 必须勾选 **原型 + 前端 + 主题 + UI**。禁止「只写后端不写 UI」或「写了 UI 却不复审 / 不签收」。

### 框架专席（触发即双轨）

对齐 [扩展点选型.md](../../../app/code/Weline/Framework/doc/3-开发/扩展点选型.md)。未触发写 `skip` + 一句理由；漏触发却 skip = 编制违规。

| 席位 | 强制触发 | 施工轨（守框架） | 合规复审轨（否决示例） |
|------|----------|------------------|------------------------|
| 扩展点 | 一切复杂 team | 选型表；`surfaces.md`；禁跨模块直调 | 机制与实现不一致；发明未文档化扩展 |
| 事件 | 机制含 Event，或改 `event.xml` / Observer | 文档化事件名；event.xml；Observer；dispatch 契约 | 未注册 / 未文档化事件；本该走 Event 却直调 |
| 查询 | 机制含 Query，或跨模块读列表 / 聚合 | QueryProvider / BinQuery 契约 | 跨模块读 Model；契约字段漂移 |
| Taglib | 机制含 Taglib，或改选择性控件 | 场景映射；无则在拥有模块新增标签 | 手写领域 select/input；标签属性内 PHP |
| Hook | 机制含 Hook，或新建 / 改 hook | `hook.php` + `doc/hook`；type 仅 `partials\|layouts` | 只有 phtml；type 发明功能名 |
| Provider | Payment / Dropship 等壳 SPI | 业务进 Extends Provider | 壳 Controller 重写供应商逻辑 |
| i18n | 新文案 / `i18n=in_scope` / 用户提翻译 | 源串简中；中英 CSV；`i18n:collect`；用户提翻译则默认站全语种 | 英文源串；裸字符串；未 collect；用法错误 |
| ACL | 新后台入口或改菜单 / 权限 | `menu.xml` / ACL 资源 | 入口无权限门；菜单与 ACL 不一致 |
| Setup | 改 Model / Controller / `event.xml` / `hook.php` / `register.php` | `etc/module.php` 升版 + `setup:upgrade` / `--route` | 改了注册面却未升版 / 未升级 |
| 合规 | 触及商品 / 结账 / 支付 / 站店渠 | 电商合规要点入方案 | 缺合规要点却上线电商面 |

并发只看依赖：文件或扩展点互不重叠，且 **`contracts.md` + 可执行 UC 已冻结**，才在同一回合启动多个子智能体。同一文件、同一扩展点、同一章验收只能有一个负责人。澄清、Plan Mode、**对齐冻结会**、技术方案会、停工确认、汇审必须串行。施工波内部按依赖图**唤醒式并发**（见下「流水线」）。

子智能体看不到父会话历史。父会话必须把下面的「提示词骨架」写进每个子任务，否则等于没制度。

## 本机开发环境测试账号（硬 · 禁止问用户）

**适用范围**：本仓库本机 / 开发环境（`*.test.weline.com`、WLS default 等）的 UT / RT / Browser WB-OP / Playwright e2e / 手工探活。

### 默认身份（直接用，禁止向用户索要账号密码）

| 面 | 账号 | 密码 | 用法 |
|----|------|------|------|
| **后台** | `admin` | `admin` | `loginAsAdmin(page)` 默认即此；或 `PLAYWRIGHT_ADMIN_USERNAME` / `PLAYWRIGHT_ADMIN_PASSWORD`；Browser 手填同此 |
| **前台** | 团队自建 | 团队自定 | 注册页自建，或 CLI（如 `user:create` / `customer:*` 等现成命令）；推荐固定邮箱 `e2e.customer@weline.local`、密码 `E2eTest!234`（不存在则本回合创建） |

环境变量若已设置，优先环境变量；**未设置时必须回落上表默认，不得停下来问用户要权限或密码。**

### 强制行为

1. **测试席 / 项目经理验收波**：自行登录、自行造前台用户、自行跑 e2e；失败只报证据与自修，不把「请提供账号」甩给用户。
2. **与 `forbid_user_manual_test_handoff` 同级**：禁止「请你登录试一下」「请给个测试账号」「开发环境没有权限」一类甩锅。缺账号 → 用默认或创建；缺权限 → 用 `admin` 或 CLI 赋权。
3. **子智能体提示词**必须带上本节省略版（见下方骨架），避免只读席 / 测试席再问用户。
4. **凭据不得写入**面向用户的交付文档正文、规格对外摘要、公开 README 大段复述以外；团队指令与 e2e 默认值内保留即可。

### 失败处理

- 默认 `admin`/`admin` 登不上：先查 WLS/路由/验证码/bootstrap，再 `user:reset:password` 等自愈；仍失败 → 验收记「未完成」+ 技术原因，**仍不向用户要密码**。
- 前台需要登录态：本回合创建测试顾客并在证据里写「已用自建账号」，不写明文密码到用户可见汇审以外的场合时可写「见团队默认前台测试账号约定」。

## 升级

1. **本轨闭环**。问题只在自己的文件里，且不改接口、不改扩展点。回报 `result=closed`。
2. **上报**。跨文件、跨前后端、或碰到硬规则。本轨立刻停手，回报 `result=escalate`。禁止猜着改。
3. **专题会**。项目经理只叫相关席位再开一轮。每人三选一：同意、异议（附替代）、否决（附硬规则或证据）。决议写入会议纪要。
4. **停工令**。会上没有人能拍板，或属于重大架构矛盾。全部写码席位停工，只交停工汇报，等用户确认。确认前禁止改 PHP、模板、CSS。

**重大架构矛盾（必须停工，不能当普通缺陷）**

- 两套扩展点都成立且互斥
- 只能靠跨模块直接调对方 Service / Model
- 方案违反已有硬规则，改规则才能继续
- 表结构或公开接口会不可逆
- 需求字面和框架审视结论冲突，必须用户选边

测试失败、文案、命名、单文件缺陷、专席合规复审 fail 走第 1、2、3 级返工，不发停工令（除非升格为重大架构矛盾）。

## 组件复用与双席协商（硬 · UI in_scope）

技术方案会与施工前强制：

1. **盘点**：对照 Theme 组件、`w-*`、Taglib 场景映射、现有 Widget/Hook，列出「本功能将复用的组件」→ 写入 `components.md`。
2. **复用**：功能设计与原型默认只组合现有组件；禁止平行再造。
3. **不足判定**：现有组件能力缺口须写清（缺哪种交互 / 字段 / 状态）。
4. **协商扩展**：项目经理同回合拉起 **原型** 与 **UI**（需要 Token / 部件落点时再拉 **主题**），各自表态：同意扩展 / 异议（给替代复用） / 否决（硬规则）。决议写入 `meetings/component-negotiate.md` 后，才允许新增 / 扩展组件。
5. **落点**：新组件归属主题体系或拥有模块 Taglib/Widget，并补文档；禁止只在业务页内联一套一次性 UI。

## 波次

```text
立项波（并行）需求分析 ∥ 领域探查
    → 立项会（串行）：初版 roster（核心 + 专席触发）+ 框架映射要点
    → 还有澄清项：停工，一次最多 5 个问题

对齐冻结波（串行 · 硬门禁 · 测试主持）
    → 参会：测试 + 架构师 + 已触发专席（涉 UI 须原型/前端/主题/UI）
    → 必须一次性钉死：
        1) 可执行 UC（升格 spec：步骤/前置/断言，可直接喂 Playwright / WB-OP）
        2) contracts.md（席位对接：输入 / 输出 / 状态 / 谁交付谁）
        3) deps.md（依赖边：谁可开干、谁 wait 谁）
    → 未冻结三者 → 禁止进技术方案定稿与施工
    → 改验收意图必须回本会，禁止施工中私改主路径用例

技术方案波（串行）架构师 + 扩展点出方案 / surfaces.md / components.md
    → 技术方案会：机制对齐已冻 UC 与 contracts（不得偷改验收意图）
    → 组件不足：原型 ∥ UI（±主题）协商会 → 再冻结
    → 同意才冻结机制落点；否决或无人能拍板 → 停工汇报

施工流水线（依赖唤醒 · 并发）
    → 项目经理按 deps.md 只拉「依赖已满足」的席位；禁止全员空转等终点
    → 测试：对齐冻结会后立刻落红灯骨架（失败测试 / e2e 草稿）；可测面就绪才执行，不重新设计主路径
    → 上游 closed → 唤醒下游；下游未轮到时不得改上游契约文件
    → 任一 escalate：该轨停，开专题会；专题会再拿不住 → 全员停工

复审波（并行）架构 ∥ 缺陷 ∥ 安全 ∥ 每个已触发专席合规复审
    → 任一否决：点名返工回施工，禁止进验收

验收波（串行证据 + 并行签收）
    → 测试：只执行已冻 UC — UT → RT → WB-OP/VIS → 章 e2e → e2e-plan-suite
    → 禁止验收波现场发明主路径用例（发现缺口 → 回对齐冻结会补订再测）
    → UI in_scope：UI 效果签收 ∥ 原型意图签收（实质对照活页，非形式出席）
    → 任一签收 fail 或证据缺：返工，禁止交出
    → 汇审会：纪要必须含「汇审」
```

### 流水线（team_flow_on_contracts）

| 规则 | 要求 |
|------|------|
| 先钉后干 | 无 `contracts.md` + 可执行 UC + `deps.md` → 禁止施工写码 |
| 唤醒式并发 | 只启动依赖边已满足的席位；其它席位待命，不假装「一起开会写码」 |
| 对接即验收契约 | `contracts.md` 每条边写清：交付物路径/形状、消费方、就绪条件、对应 UC id |
| 测试时序 | **设计**在对齐冻结会；**红灯落盘**在施工开跑；**执行**在可测面就绪 / 验收波 |
| 禁止反流 | 禁止「开发完了再想测什么」；禁止下游改上游已冻接口而不回冻结会 |

子智能体回报「做完了」不算交付。父会话不得据此开下一波写码，也不得向用户宣称完成。

### 复审轨（施工全部 closed 后）

| 复审轨 | 负责席 | 何时强制 | 产物 |
|--------|--------|----------|------|
| 架构复审 | 架构师 | 始终 | `meetings/架构-review.md` 或合并章节 |
| 缺陷复审 | 测试 | 始终 | 同上 |
| 安全复审 | 安全 | 始终 | 同上 |
| 各专席合规复审 | 该席自身 | 凡 roster 触发 | `meetings/{席位}-review.md`（可合并但每席须 pass/fail） |
| UI 复审 | UI（可拉原型 / 主题会签） | UI in_scope | 功能完整度 + 审美；截图路径 |
| i18n 复审 | i18n | 文案 / i18n in_scope | 用法 + CSV + collect 证据 |

**硬顺序**：全部已触发专席复审 pass → 才允许验收波开跑 e2e / 签收。

### 验收实质签收（涉 UI 强制）

| 席位 | 必须亲自做什么 | 产物 | 否决则 |
|------|----------------|------|--------|
| UI | 打开活页（禁缓存），对照功能完整度 + 审美是否达到想要的效果 | `meetings/acceptance-ui.md` | 返工，不得交出 |
| 原型 | 对照 `components.md` 与原型意图：信息架构、组件组合、关键状态是否落地 | `meetings/acceptance-prototype.md` | 返工，不得交出 |

硬规则：

- UI / 原型 **缺席、代签、只写「同意」无对照结论** = 验收未完成。
- 测试 e2e 全绿但 UI 或原型 fail → **禁止汇审通过、禁止把交付地址当完成**。
- 两席都 pass 且测试清单齐，才允许项目经理写汇审并交出。

验收测试清单（与交付流程 §6–§7 对齐）：UT → RT（含 Setup）→ WB-OP/VIS → 章通路 e2e → `e2e-plan-suite` → 审图 acceptance（UI）→ 交付地址 + 关 Browser → 汇审。

### 回报单

- `role`
- `paths_changed`（没有则写「无」）

父会话原样填空后交给子智能体：

```text
你是工程团队的「{席位}」。父会话是项目经理。你看不到父会话历史，只执行本提示。

本波：{波次}。轨：{施工|合规复审|验收签收}。允许路径：{paths}。禁止：改架构、跨模块直调 Service/Model、改其他席位文件、在停工或只读波里改 PHP/phtml/CSS。
服从 hard_constraints 与 dev/ai-command/ai/工程团队.md。框架优先：先映射机制/组件再改业务。
本机开发环境测试账号（硬）：后台默认 admin/admin（loginAsAdmin 默认）；前台自建（推荐 e2e.customer@weline.local / E2eTest!234，无则创建）。禁止向用户索要账号、密码或「请你登录验证」。
```

### 增量约束（按席粘贴）

**扩展点**：写码前完成扩展点选型；产出 / 核对 `surfaces.md`；禁止跨模块 `new` Service/Model。

**事件**：事件名须已文档化；改 `event.xml` / Observer / dispatch 必须与 `doc/event/` 一致。

**Taglib**：先查场景映射表；禁止手写领域 select/input；标签属性内禁止 `<?=` / `<?php`。

**Hook**：必须有 `hook.php` + `doc/hook`；type 段仅 `partials` 或 `layouts`。

**Provider**：业务只进 Extends Provider；壳 Controller 只编排。

**原型 / UI（组件）**：先写 `components.md` 复用清单；不足则必须先有 `component-negotiate.md` 再扩展。

**UI / 原型（验收签收）**：必须亲自对照活页；禁止代签；fail 则禁止交出。

**测试**：对齐冻结会主持并钉可执行 UC；施工开跑落红灯；可测面就绪 / 验收波只执行已冻用例；正式 Playwright runner；**必须产出真实业务证据 id**（`acceptance_real_business_pathway`）；禁止壳层冒烟冒充收口；禁止向用户甩测；禁止等开发完再设计主路径。

**流水线席位**：开工前读 `contracts.md` + `deps.md`；依赖未满足禁止改本轨；上游契约变更须 escalate 回对齐冻结会。

## 禁止

- 简单需求打 `Team:`，或复杂需求不打 `Team:{席位}:`
- 内容运营打 `监工:` / `Team:`
- 接口 / **contracts / 可执行 UC** 未冻结就并行改同一文件或开施工
- **开发完才补主路径用例**，或验收波现场发明主路径用例
- **全员空等终点**（不按 deps 唤醒，假装一起干）
- 子智能体直接向用户提问（提问只能经项目经理的停工汇报或澄清停工）
- **向用户索要本机开发环境账号/密码/「请你登录测一下」**（须用本节默认后台 `admin`/`admin` 或自建前台账号）
- 把安全席做成「仅用户点名才允许启动」的专员审查；安全席是复审波里的通用子智能体
- 停工期间继续写业务代码
- 用子智能体的 `closed` 代替汇审、e2e 或交付地址
- 触发专席却跳过合规复审进入验收
- 涉 UI 却无原型 / UI 实质签收就交出（含 e2e 全绿代签）
- **只用壳层/冒烟 e2e（空取消页 CTA、账户页不 fatal）冒充真实业务通路收口，却报不出 `order_uuid` 等证据**
- 可复用组件却私造平行 UI；未协商就扩展组件
