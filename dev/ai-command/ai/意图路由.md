## 找问题类意图 → 强制 debug 技能（`diagnosis_routes_to_debug_skill`，2026-10-31 用户指定）

**触发**（任一命中即进本支路，与上面的 lane 并行、不替代 lane）：找问题 / 查问题 / 找根因 / 为什么报错 / 为什么慢 / 定位 / 排查 / 诊断 / 超时 / 间歇失败 / 结果不对 / 线上 5xx / 「看日志找问题」。

**硬顺序（违反即停手重来）**：

1. 本回合**第一个动作是加载技能** `debug`（宿主技能 `~/.agents/skills/debug/SKILL.md`；`skill` 工具 `debug`），**不是**读代码，也**不是**先改任何东西。
2. 阶段 0 **先读日志**：`var/log/exception.log` / `php_error.log` / `runtime.log` / `timing*.log` / WLS `wls.log` / nginx `error.log` / 部署与发布日志，取三个事实（报错原文、类名+文件行号、首次出现时间）并贴原文。
3. **再审查代码定位**：只从日志给出的文件/行号/类名顺调用链读，判断根因是否已能从代码直接确定；**代码看不出**（多分支/Fiber/跨进程/需要运行期真实值）才进阶段 2 锚点调试。
4. **循环深入**：每轮都要「取新线索 → 定位一层 → 判是否到根因」；产出必须是根因三件套（`文件:行号` + 复现命令/脚本 + 观测值原文）。**禁止**在第一层症状（例如「上游连不上」）停下当结论；**禁止**跳过日志直接读代码；**禁止**未到根因就给修复方案。
5. 找问题支路的收口与本规则同时生效：`no_error_masking_or_patch_workaround`（禁打补丁）、`honesty_gate`（未验证必须标注）。

debug 技能自有预算（一轮 ≤3 文件、一个假设一个 `dev/debug/<问题>-<层级>.php` 脚本、修复验收同回合清场）照旧执行。
