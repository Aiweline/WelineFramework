│ Process Model (Cross-platform)                                                │
└─────────────────────────────────────────────────────────────────────────────┘

POSIX Auto Direct + Project-managed Nginx:
┌──────────────────────────────────────────────────────────────────────────┐
│                          Master Process (PID 1000)                        │
│  Role: Registry, policy/config digest, hot reload, orphan detection      │
└────┬─────────────────────────────────────────────────────────────────────┘
     │
     ├─▶ Managed Nginx ◀── TLS 1.3, h2/h1; HTTP/3-only WLS health gate or pending
     │        │ loopback plaintext h1 keep-alive
     │        ├─▶ READY Worker-1 (PID 1001)
     │        ├─▶ READY Worker-2 (PID 1002)
     │        └─▶ READY Worker-N (PID 100N)
     │
     ├─▶ SessionServer (PID 1101) ──▶ Shared Session storage
     └─▶ MemoryServer (PID 1102)  ──▶ Shared memory/cache/policy state

Direct means no WLS Dispatcher. Project-managed Nginx exclusively owns TLS,
ALPN, multiplexing and tickets; WorkerPolicyKernel owns all L7 rules/FPC.

Windows Auto Direct + Project-managed Nginx:
┌──────────────────────────────────────────────────────────────────────────┐
│                          Master Process (PID 2000)                        │
│  Role: Registry, policy/config digest, monitoring                        │
└────┬─────────────────────────────────────────────────────────────────────┘
     │
     ├─▶ Managed Nginx ◀── TLS 1.3, h2/h1; HTTP/3-only WLS health gate or pending
     │        │ loopback plaintext h1 keep-alive; Nginx upstream balancing
     │        ├─▶ READY Worker-1 (PID 2001, worker_port_1)
     │        ├─▶ READY Worker-2 (PID 2002, worker_port_2)
     │        └─▶ READY Worker-N (PID 200N, worker_port_N)
     │
     ├─▶ SessionServer (PID 2101)
     └─▶ MemoryServer (PID 2102)

WLS 2.0 edge choices are host Gateway Nginx and project-owned pure WLS TLS.
Pure WLS uses worker_ssl on a project-owned high port. The host gateway keeps
its native Launcher/Broker transport for platform recovery, peer identity and
privilege separation.

Managed Nginx ingress invariants:
  • H2/H1 runtime readiness requires separate fresh requests through Nginx to
    /_wls/health?detail=1, with exact HTTP version, owner/backend identity and
    config generation. TLS/ALPN or configuration alone is not runtime proof.
  • HTTP/3 readiness requires an owner-bound HTTP/3-only fresh QUIC request
    through Nginx to the same health endpoint. A local Nginx response or edge
    cache hit is invalid.
  • Upstream authority is $http_host, or $host:$server_port when HTTP/3 leaves
    $http_host empty; Host + X-Forwarded-Proto/Port reconstruct public origin.
  • RuntimePolicyBundle always trusts 127.0.0.0/8 and ::1/128 as proxy transport
    peers, never as business whitelist entries.
  • Only the loopback-allowlisted /_wls/ location propagates an exact client
    Connection: close for fresh H1 distribution gates. Business traffic keeps
    upstream connections reusable except an exact websocket Upgrade tunnel;
    WebSocket itself remains outside the current 101/frame release matrix.

┌─────────────────────────────────────────────────────────────────────────────┐
│ IPC Architecture (NDJSON over TCP)                                           │
└─────────────────────────────────────────────────────────────────────────────┘

Master (127.0.0.1:control_port)
   │
   │ ControlMessage Protocol (NDJSON format)
   │
   ├─▶ register        Child process registration (role, pid, processKind, moduleCode)
   ├─▶ heartbeat       Keepalive (every 30s)
   ├─▶ reload          Hot reload code
   ├─▶ restart         Restart process
   ├─▶ stop            Stop process
   ├─▶ config_update   Config update
   └─▶ status          Status query

Message format examples:
{"action":"register","role":"worker","pid":1001,"process_kind":"framework"}
{"action":"heartbeat","pid":1001,"timestamp":1234567890}
{"action":"config_update","epoch":42}

┌─────────────────────────────────────────────────────────────────────────────┐
│ Process Identity                                                              │
└─────────────────────────────────────────────────────────────────────────────┘

ProcessKind enum:
  • FRAMEWORK  → Framework-level processes (Worker, SessionServer, MemoryServer, etc.)
  • MODULE     → Module-level processes (e.g. Weline_Payment gateway)

Process naming convention:
  • Framework: weline-wls-{role}  (e.g. weline-wls-worker-1)
  • Module: weline-{moduleCode}-{name}  (e.g. weline-payment-gateway)

┌─────────────────────────────────────────────────────────────────────────────┐
│ State Management (StateManager)                                              │
└─────────────────────────────────────────────────────────────────────────────┘

Problem: In long-running Workers, static properties pollute across requests

Solution:
┌────────────────────────────────────────────────────────────────────────┐
│ class MyService {                                                       │
│     private static array $cache = [];  ← Request-level state           │
│                                                                         │
│     public function __construct(StateManager $stateManager) {          │
│         $stateManager->registerState(self::class, 'cache', []);        │
│     }                                                                   │
│ }                                                                       │
└────────────────────────────────────────────────────────────────────────┘

After each request, StateManager auto-resets all registered static properties

┌─────────────────────────────────────────────────────────────────────────────┐
│ Hot Reload Mechanism                                                          │
└─────────────────────────────────────────────────────────────────────────────┘

Code changes (business logic, Controller, Model):
  php bin/w server:reload
  → Master sends reload message to all Workers
  → Worker finishes current request then exits
  → Master auto-spawns new Worker (loads new code)

Master/Dispatcher/startup param changes:
  php bin/w server:restart -r
  → Stop all processes
  → Restart Master
  → Master spawns all child processes

┌─────────────────────────────────────────────────────────────────────────────┐
│ Orphan Detection (OrphanGuard)                                               │
└─────────────────────────────────────────────────────────────────────────────┘

Problem: Master crashes, child processes become orphans and keep running

Solution:
┌────────────────────────────────────────────────────────────────────────┐
│ On child process startup:                                              │
│   1. Record Master PID                                                  │
│   2. Start background thread, check Master alive every 5s              │
│   3. If Master not exists → Child self-terminates                      │
└────────────────────────────────────────────────────────────────────────┘

Implementation:
  • Framework\System\IPC\OrphanGuard (generic base class)
  • Server\IPC\MasterOrphanGuard (WLS implementation)

┌─────────────────────────────────────────────────────────────────────────────┐
│ Project-managed Nginx TLS Certificate Lifecycle                              │
└─────────────────────────────────────────────────────────────────────────────┘

Flow:
  1. Certificate files are published under app/etc/ssl/{domain}/
  2. ManagedNginxConfigWriter builds an isolated candidate config
  3. The installed Nginx binary must pass nginx -t
  4. Config is atomically published, then Nginx starts or reloads
  5. A certificate-bound TLS 1.3 handshake is verified
  6. Fresh H2 and H1 requests must reach owner-bound real WLS health
  7. H3, when verifier support exists, must reach real WLS health over HTTP/3-only
  8. A failed rollback stops Nginx unless the committed live generation is proven

Session boundary:
  • Shared session cache/tickets are enabled in Nginx
  • Proof model: fresh-share-two-connection-pair-v1
  • Each pair owns a new SSL share: one fresh issuer + one fresh-TCP probe
  • At least 8 valid probes, failed=0, resumed handshake P95 <= 50ms
  • Same/cross-worker results bind each issuer/probe PID pair; cross-worker is
    not_applicable only when the effective Nginx worker count is one
  • HTTP/3/QUIC session resumption remains unverified

Nginx-backed Workers never load certificates and never terminate public TLS.
In explicit/fallback pure WLS mode, worker_ssl loads the same project-owned
certificate generation and terminates TLS/H2/H1 on the project high port.

┌─────────────────────────────────────────────────────────────────────────────┐
│ Service Providers                                                             │
└─────────────────────────────────────────────────────────────────────────────┘

Current WLS child processes extend AbstractServiceProvider:

WorkerProvider          → HTTP Worker (handle requests)
DispatcherProvider      → Explicit compatibility/diagnostic loopback H1 Dispatcher
SessionServerProvider   → Session shared service
MemoryServerProvider    → Memory cache service
MaintenanceWorkerProvider → Cron tasks (cleanup, stats)

Managed Nginx is owned by ManagedNginxService, not a WLS child Provider.
worker_ssl is the pure WLS edge process. The host-level native Launcher/Broker
is part of the WLS 2.0 shared-gateway control and recovery boundary.

Each Provider implements:
  • start()           → Start service
  • stop()            → Stop service
  • reload()          → Hot reload
  • getProcessKind()  → Return ProcessKind::FRAMEWORK
  • getModuleCode()   → Return '' (framework-level)

┌─────────────────────────────────────────────────────────────────────────────┐
│ Critical Constraints                                                          │
└─────────────────────────────────────────────────────────────────────────────┘

NEVER use blocking functions:
  ✗ sleep() / usleep()  → Blocks Worker, impacts throughput
  ✗ die() / exit()      → Kills Worker process
  ✓ SchedulerSystem     → Async scheduling

Static properties MUST be registered:
  ✗ private static $cache = [];  → Cross-request pollution
  ✓ $stateManager->registerState(self::class, 'cache', []);

Code changes MUST reload:
  ✗ Direct access (uses old code)
  ✓ php bin/w server:reload
