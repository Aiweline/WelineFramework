## 3. 当前源码事实锚点

以下是本计划的实现约束，不是待讨论的推测。

### 3.1 Edge 与启动语义

- `Service/Edge/EdgeAdapterInterface.php`、`EdgeAdapterResolver.php`、
  `Service/Contract/ServiceContext.php` 和 `ServerInstanceManager.php`
  当前只接受 `nginx|wls`。
- `nginx` 适配器表示 WLS loopback 明文 H1 后端；WLS 自身不终止 TLS，
  且要求项目受管 Nginx 已安装并允许自动启动。
- `wls` 适配器表示 PHP Stream TLS，提供 H2/H1；当前不提供 H3。
- `Console/Server/Start.php` 默认选择项目受管 Nginx；普通启动不下载、
  不编译、不安装 Nginx。WLS READY 后才调用受管 Nginx启动。
- `--no-nginx` 当前是一次运行级的纯 WLS 选择；实例持久化仍把
  `edge_adapter` 写成 `nginx`，所以本计划必须补充独立的 mode/scope 持久化。
- `ManagedNginxPublicOrigin` 与 `PureWlsPublicOrigin` 已负责当前入口地址持久化。

### 3.2 当前受管 Nginx 已有的安全与活性能力

- `ManagedNginxInstaller` 锁定 Nginx 1.30.4，并校验平台、架构和 SHA 清单。
- `ManagedNginxPaths` 使用项目与平台身份隔离运行路径。
- `ManagedNginxConfigWriter` 已有候选配置、原子发布和失败回退。
- `ManagedNginxProcessManager` 已有生命周期锁、PID 与可执行文件身份验证。
- `ManagedNginxService` 已有后端身份检查、`nginx -t`、owner intent、
  config generation、证书绑定 TLS 1.3 探针、H2/H1 实际路由探针、
  H3 实际路由验证及失败关闭。
- `ManagedNginxTlsSessionResumptionVerifier` 已定义同 generation 双连接复用
  和跨 reload 连续性验证。
- `ManagedNginxPortAllocator` 当前默认以 `8080/8443 + projectPortOffset`
  分配项目入口；配置可显式使用 80/443。

共享网关必须提取或复用这些原语，不能降低当前项目 Nginx 的发布门禁。

### 3.3 状态、停止与退役实现

- endpoint schema 当前为严格 v4；允许增量字段，但不能改变已有字段语义。
- endpoint 已有 `edge_adapter`、`public_origin`、`runtime_selection`；
  旧 `gateway.enabled=true` 会被拒绝，保持退役防误启。
- `Console/Server/Stop.php` 当前先停止项目受管 Nginx，再停止 WLS。
  宿主网关模式必须改为只排空/注销当前项目，绝不能停止共享网关。
- 旧 `GatewayProvider`、`Console/Gateway/Start.php`、`bin/gateway.php`、
  `Service/WlsGateway.php`、`ProtocolEdgeProvider` 和 `bin/protocol_edge.php`
  均刻意 fail-closed。它们不得被复用或重新激活。
- 当前 `SupervisorServer` 是项目 Master 内的控制服务，不是
  launchd/systemd/Windows Service，不能承担宿主网关独立存活。

### 3.4 项目身份、域名与证书

- `MasterProcess::getProjectIdentityHash()` 是规范路径派生 SHA1，迁移目录后会变化；

- `Api/Tls/ActiveCertificateDomainSourceInterface.php` 是 Server 已发布的活动域名接口；

- `SslCertificateService` 已管理 `app/etc/ssl`、证书映射、导入、续签和匹配。
- 网关必须通过上述公开契约取事实，不能越过模块边界直接读取 Websites 内部模型。

## 5. 闭合架构决策

### 5.1 Mode 与 Adapter 分层

公共 CLI 仍为：

- `--edge=auto`
- `--edge=gateway`
- `--edge=wls`

内部解析结果采用两个正交字段：

| 用户/迁移模式 | `edge_adapter` | `edge_scope` | 行为 |
| --- | --- | --- | --- |
| `gateway` | `nginx` | `host_gateway` | WLS 是 loopback H1 后端，宿主网关终止 TLS |
| `wls` | `wls` | `native` | 当前 Master 直接运行 TLS/H2/H1 |
| 内部 `legacy-project-nginx` | `nginx` | `project_managed` | 保留当前项目受管 Nginx，不自动提升 |

`auto` 不是持久化 adapter，而是选择策略：

1. 已保存 legacy 项目继续 `project_managed`，除非显式 promote。
2. 已 enrollment 且可信宿主网关 ready：选择 `host_gateway`。
3. 宿主网关包已安装、平台守护可建立且公共端口可安全取得：
   允许建立后加入。
4. 其他情况选择 `native` 高端口回退，并报告确定的降级原因。

显式 `gateway` 不可用时退出；显式 `wls` 完全不操作宿主网关。
`--no-nginx` 保留为 `--edge=wls` 的兼容别名。优先级：

```text
CLI > 实例 edge_mode > 环境 edge_mode > auto
```

未知程序占用 80/443 时不询问、不停止、不修改；`auto` 进入稳定高端口，
`gateway` 明确失败，诊断状态为 `PORT_TAKEN`。

### 5.2 宿主网关是显式安装的独立产品

新增 `server:gateway:install`，职责是：

- 选择宿主目录并安装自包含 Controller 包。
- 安装 WLS 2.0 锁定的 Nginx 分发物和签名/摘要清单。
- 建立不可变 A/B 二进制槽。
- 安装 launchd、systemd 或 Windows Service。
- 创建仅宿主管理员可读的管理凭据和状态目录。
- 完成公共端口、IPv4/IPv6、控制端、健康端和平台自启动验证。

`server:start` 永不下载、编译、安装、升级或写平台服务。安装/升级失败时
不得将网关标记为 ready。

宿主包不能长期从引导项目执行 PHP 文件；项目删除、迁移或停止后，
Controller 与已有数据面仍必须独立运行。

### 5.3 项目稳定身份与授权

新增项目拥有的身份文件：

```text
app/etc/wls-project.json
```

规则：

- UUID v4，0600，临时文件 + fsync + atomic rename。
- enrollment 或首次显式网关初始化时创建。
- 项目迁移时随 `app/etc` 私有配置一起移动，因此能在新宿主保持身份。
- 同一宿主检测到相同 UUID、不同规范根目录时拒绝第二个 enrollment；
  复制项目必须使用 `server:gateway:enroll --rotate-identity`。
- 现有 path SHA1 继续用于本机端口与进程目录，不替代 UUID。

授权模型：

- 宿主管理凭据只存在宿主目录，普通项目不可读。
- `server:gateway:enroll` 使用管理员权限创建逐项目 capability token。
- token 绑定项目 UUID、规范根目录、OS 对等身份和允许的证书根目录。
- `register` 只接受已 enrollment 项目，不得自动 enrollment。
- POSIX 优先 Unix Socket、目录权限和 peer credentials。
- Windows 首版可使用 loopback TCP + 逐项目 token + 明确 ACL；若 ACL
  无法证明受限，则该宿主网关不得 ready。

### 5.4 WLS Edge Protocol 2

协议标识 `wls-edge/2`，操作：

- 项目面：`register`、`renew`、`heartbeat`、`drain`、`unregister`。
- 管理面：命令行通过独立管理员通道调用 status、repair、upgrade 等，
  不与项目 capability 混用。

注册信封必须包含：

- 项目 UUID、规范根目录、实例 ID、OS 身份。
- gateway epoch、项目 generation、幂等键、请求摘要。
- `routes[]`：route ID、规范化域名、后端列表、后端身份、
  证书源摘要和 certificate generation。

一致性规则：

- 同 generation + 同摘要：幂等成功。
- 同 generation + 不同摘要：冲突并拒绝。
- 更低 generation：拒绝。
- 更高 generation：按项目串行候选发布。
- `heartbeat` 只能续租，不能改变配置。
- `renew` 必须带 expected route generation。
- 网关发布协议 min/max；不兼容时明确失败，项目不得自行升级共享网关。
- 多项目更新批量合并并限速，避免 reload 风暴；单项目顺序不能被批处理打乱。

### 5.5 路由、域名与证书

状态机：

```text
PENDING_BACKEND
  → PENDING_CERTIFICATE
  → ACTIVE
  → DRAINING
  → STALE
  → REMOVED
```

路由规则：

- 域名转小写 IDNA ASCII，严格校验标签和通配符位置。
- 跨项目精确冲突、精确与通配覆盖冲突一律拒绝。
- 域名转移必须显式 revoke/transfer，不能靠最后写入获胜。
- 后端必须返回项目 UUID、实例 ID 和 generation，全部匹配才激活。
- 未知域名返回中性 404/421，绝不落到首个项目。
- HTTPS 的 SNI 与 Host 必须解析到同一项目，否则 421。
- `website_id=0/code=default` 是合法来源，不能用空值判断过滤。

证书规则：

- 项目是域名、证书源、续签状态和 generation 的唯一事实源。
- 域名通过 `ActiveCertificateDomainSourceInterface` 获取。
- 证书通过 `SslCertificateService`/新增公开桥接服务获取，不调用
  Websites 内部实现。
- 默认允许 `app/etc/ssl`；额外证书根必须在 enrollment 显式授权。
- no-follow 打开文件，拒绝符号链接穿越、权限异常和根目录逃逸。
- 校验证书/私钥匹配、SAN、有效期、算法、权限和摘要。
- 复制前后摘要不一致则拒绝新 generation，继续使用上一代。
- 校验后在宿主生成内容寻址快照；私钥 0600；Nginx 只引用快照。
- 首次 ACME 仅开放精确 challenge 路径，证书有效后才开放 443。
- 项目侧保存续签待确认队列；网关恢复后按 generation 幂等重放。
- 纯 WLS 与 host gateway 使用同一源 generation；无效证书不能替换当前 TLS 上下文。

路由发布门禁：

- 候选配置必须通过语法、端口、证书、后端身份和真实 H2/H1 路由探针。
- 本次变更涉及的 route 必须同步探测通过才提交。
- 所有 ACTIVE route 至少每 60 秒轮询一次。
- H3 只有真实 QUIC 客户端到真实 route 通过才可声明；H3 失败只从候选
  能力中移除，不影响 H2/H1 发布。

### 5.6 租约与生命周期

默认值：

- heartbeat：10 秒。
- 45 秒无续租：route 进入 `STALE`，新请求 503。
- 主动 stop：先 `DRAINING`，最长 300 秒。
- STALE 元数据保留 24 小时。
- 未被活动配置和最近两个 LKG 引用的证书快照：7 天后回收。

`server:stop {instance}` 在 `host_gateway` 下执行：

1. 请求 route drain。
2. 停止接收新请求并等待项目连接排空。
3. unregister 当前实例的 route。
4. 停止当前项目 WLS。

它绝不停止宿主 Controller 或共享 Nginx。只有显式
`server:gateway:stop` 能停止宿主网关，并且必须显示受影响租户。

### 5.7 自动恢复

运行层次：

1. 平台守护：launchd/systemd/Windows Service。
2. Host Gateway Controller：注册、状态、发布、恢复。
3. Nginx 数据面：公共 80/443、TLS、反向代理。

每 5 秒核心检查：

- Controller 控制端是否响应。
- Nginx PID、可执行摘要、槽位、命令行和 config generation 是否属于本网关。
- 本地健康端返回的 generation 是否匹配。
- IPv4/IPv6 80/443 是否可连接。
- 轮换选择 ACTIVE route，使用 SNI、Host 和期望证书摘要做端到端探测。

状态必须区分：

- `CONTROL_DEGRADED`：Controller 异常但 Nginx 数据面健康；保持流量，
  只恢复 Controller。
- `DATA_PLANE_DOWN`：公共入口或真实 route 数据面失败；进入完整恢复链。

恢复链：

1. **无中断接管**：Controller 重启后验证 PID、二进制清单、命令行、
   槽位和 generation；全部匹配则接管，不 reload。
2. **快速重启**：连续 3 次核心探针失败，只重启清单中身份完全匹配的 Nginx。
3. **配置回滚**：5 分钟内 3 次启动/探针失败，回退最近健康配置；
   保留 current + 最近两代 LKG。发布顺序固定为 candidate →
   `nginx -t` → atomic switch → 至少 15 秒 live probe。
4. **二进制回滚**：升级后 5 分钟崩溃循环，切回旧 A/B 槽；
   旧槽直到新槽健康 24 小时后才可回收。
5. **状态重建**：宿主状态使用带摘要原子快照 + append journal。
   损坏文件隔离留证，以 LKG 证书启动 TLS/503 隔离配置；
   gateway epoch 变化后项目重放完整期望状态，逐条恢复。
6. **熔断**：15 分钟累计 10 次恢复失败，停止高频重启；
   进入最大 5 分钟指数退避。状态显示阶段、原因、generation、槽位和下次重试。

恢复过程禁止：

- 按端口盲杀进程。
- 操作无法验证 owner 的 PID。
- 以 Controller 可响应代替真实 route 可用。
- 在 LKG 未通过证书/二进制兼容验证时强行启动。

### 5.8 项目最终降级：同一 Master 的补充入口

网关数据面持续不可用 90 秒，且项目仍处于期望运行状态时：

- 不启动第二个 WLS Master。
- 当前 Master 通过经过认证的 Orchestrator 控制操作，动态建立
  `gateway_fallback_worker`。
- POSIX 复用现有 `worker_ssl.php` 的证书与 H2/H1规则。
- Windows 复用现有纯 WLS Dispatcher + TLS worker 规则。
- 不重复创建 Session、Cron、Memory、sidecar 或应用主循环。

端口从 20000–29999 按项目 UUID 稳定派生，再用宿主锁和实际 bind 确认；
冲突时按确定性序列探测，多个项目必须获得不同地址。

降级条件：

- 只有 `DATA_PLANE_DOWN` 连续 90 秒触发。
- `CONTROL_DEGRADED` 且数据面健康时不得触发。
- 未知进程占用 80/443 时保留 fallback 并标记 `PORT_TAKEN`。
- gateway route 恢复 ACTIVE 且连续健康 30 秒后切回。
- fallback 保留 300 秒排空后关闭。
- 明确报告 URL、端口以及 DNS、防火墙和负载均衡无法自动切换的限制。

### 5.9 旧项目显式提升

WLS 1.x/现有项目受管 Nginx 不自动变成共享网关。

`server:gateway:promote` 仅允许当前已验证拥有 80/443 的项目执行：

1. 验证项目 Nginx owner、二进制、证书、配置 generation 和真实 route。
2. 在影子端口构建宿主网关候选并注册原项目自身。
3. 完成候选配置、证书、H2/H1、可选 H3 和恢复清单验证。
4. 记录项目 Nginx 的可恢复 owner intent 与 LKG。
5. 短暂排空并释放项目 80/443。
6. 宿主网关绑定 80/443，原项目成为普通租户。
7. 失败时停止宿主候选，重新绑定并恢复项目 Nginx LKG。

提升失败不能留下半安装 ready 状态，也不能影响未知端口所有者。

  完成一个任务才更新一个 todo。
- 每次修改后记录 Browser URL/路径、操作步骤、可见结果、console 和 WLS 状态。
- 自动验证完成后停止测试实例；若交给用户手工验收，则保留实例并明确
  URL、实例名、端口、状态和 stop 命令。

## 11. 回滚与发布策略

### 11.1 项目源码

- 任务按 TASK-000 → TASK-011 顺序交付，每一任务形成可独立回滚边界。
- mode/scope/schema 只做加法；回滚时旧 `edge_adapter` 仍可解释。
- host gateway 未 ready 前，不改变当前项目 Nginx/纯 WLS入口。

### 11.2 宿主网关

- 安装使用临时槽 + 摘要校验 + 原子激活。
- 配置 current + 2 LKG。
- 二进制 A/B；新槽健康 24 小时前不删除旧槽。
- promote 在端口交接前保存项目 owner/LKG；失败按事务恢复。
- uninstall/revoke 不删除项目证书或项目身份。

### 11.3 数据与迁移

- 项目 route/cert 是事实源；宿主 registry、journal、快照全是可重建派生状态。
- 项目迁移不携带宿主 enrollment/token；在新宿主重新 enrollment，
  或直接使用 `--edge=wls`。
- 项目身份 UUID 随项目私有配置迁移；复制项目用 rotate 生成新身份。

## 12. 风险与非目标

| 风险 | 控制 |
| --- | --- |
| 宿主单点 | 本期只做单机自动恢复；不承诺宿主宕机无感 |
| 权限提升面 | 安装/升级/stop 走显式管理员命令，项目 token 不能调用 |
| 多项目 reload 风暴 | generation 串行、批量合并、限速和 changed-route 同步探针 |
| 证书私钥泄漏 | no-follow、授权根、内容寻址、0600、宿主 ACL |
| 误杀系统 Nginx | owner manifest + PID + executable + generation 全匹配才操作 |
| fallback 被误认为公共入口 | 状态明确标注高端口与 DNS/防火墙限制 |
| Windows 本地传输弱于 UDS | 逐项目 token + ACL；ACL 不能保证则 fail closed |

本期非目标：

- 多宿主高可用、外部负载均衡或 DNS 自动切换。
- 跨项目路径路由。
- 自动接管系统 Nginx/未知 Nginx。
- 在应用启动时获取管理员权限或自动安装宿主服务。
- 让旧 `gateway:start` 或外置 ProtocolEdge 复活。

## 14. 完成门禁

只有同时满足以下条件，WLS 2.0 网关计划才可标记完成：

1. 所有 TASK todo 逐项有代码、运行证据和文档证据。
2. 当前项目级 Nginx 与纯 WLS 基线能力无回归。
3. 不存在第三种 Edge Adapter。
4. 不存在从普通项目启动隐式安装/升级宿主服务的路径。
5. 不存在全宿主共享项目 token 或 register 自动 enrollment。
6. fallback 不启动第二个完整 Master。
7. `server:stop` 不可能停止共享网关。
8. 证书活动配置不直接引用项目源路径。
9. 恢复不会操作无法证明身份的进程。
10. 隔离宿主矩阵中所有未阻塞项目通过；环境阻塞项明确列出，
    不以静态检查或 mock 冒充通过。

单机恢复无法解决宿主宕机、宿主网络故障或机房故障。真正无感的公共
80/443 高可用应作为后续 WLS 2.x 多宿主网关与外部负载均衡计划。
