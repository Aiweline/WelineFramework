## 2. 项目群目标

以 Website 目录、Store 独立经营和完整 Scope 为基础，分阶段交付通用商城内核。工程目标不是一次性“大爆炸”开发，而是让每个项目都满足以下条件：

1. 只有一个可验收结果和一个主责 Owner；
2. 上游契约冻结后才开工，跨模块只走正式契约；
3. 数据、权限、支付和迁移边界始终 fail-closed；
4. 每个 Gate 都有真实入口、数据不变量、Browser/WLS 或文档证据；
5. 可暂停、可恢复、可前向修复，不靠删除新事实回滚；
6. 执行者不必重新设计 R4，也不能绕过项目群变更控制。

| 能力范围 | P4 四能力（Vendor/Subscription/B2B/CustomerAsset）全量或指定子集 |
| token 策略 | `production_on_token` 的来源与保管人 |
| Owner | 执行责任人与回滚决策人 |

开工后的固定步骤（依据 `2026-07-25-1028-res-mig-prod-cutover-auth-gate` 已验证脚本与顺序）：
`preflight` → checkpoint/journal → 按能力 `allowlist` → 复核 → `mode=on`（带 token）→ fresh-connection `verify` → 回写证据。任一步失败即停，按各能力 MIG 卡回滚，不 fail-open。
