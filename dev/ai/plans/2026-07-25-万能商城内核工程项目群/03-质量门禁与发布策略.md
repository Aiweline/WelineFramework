## 1. 质量原则

1. 风险决定验证深度，不能把所有项目简化成“运行测试”；
2. Browser 可见功能必须由 Codex 内置 Browser 给出最终可见证据；
3. WLS 只用唯一 `ai-test-*` 和实际整数端口 `>=9502`，禁止 9501；
4. 默认不新增或修改测试产物；若现有入口无法验证 CRITICAL 故障窗，先取得明确测试产物授权；
5. 数据迁移必须 preflight → checkpoint → apply → fresh verify → cutover/rollback guard；
6. Payment、Refund、Inventory、Asset 的外部事实和 ledger 不允许通过删除记录回滚；
7. 任何 Gate 的证据不全都等同未通过；
8. PostgreSQL 是默认与正式验收数据库；SQLite 仅用于开发与补充测试，
   不得用 SQLite 结果替代 PostgreSQL schema、迁移、并发或数据守恒证据。

## 2. 风险到验证层映射

| 风险面 | 必须验证 | Gate 证据 | 禁止替代 |
|---|---|---|---|

| 公共接口/跨模块 | 精确签名、调用方、兼容 adapter、真实 Query/入口 | impact、静态/LSP、调用证据、文档 | 猜测接口名 |
| Schema/迁移 | additive schema、隔离 DB、幂等、守恒、fresh verify、恢复日志 | checkpoint manifest、计数/哈希、不变量 | apply 内存结果 |
| Scope/WLS | default/0、A/B/A 串行与并发、异常/SSE reset、缓存键 | HTTP、correlation、WLS status/log、Browser | 单请求 CLI |
| 权限/安全 | 未登录、低权限、跨 Scope IDOR、CSRF/Origin、重认证、脱敏 | HTTP/Browser、审计、拒绝状态、无部分写 | 只看菜单隐藏 |

## 3. Gate 审查包

每个 `PG-*` 使用相同结构：

1. 范围：本 Gate 接受哪些 Project/TASK；
2. 基线：代码、schema、配置、feature mode、数据库 fingerprint；
3. 通过项：对应 TEST/ACC 和实际证据链接；
4. 失败/未执行项：原因、风险、责任人、是否阻断；
5. 数据：checkpoint、水位、quarantine、orphan、不变量、对账；
6. 运行时：WLS/Queue/Cron/Provider/日志状态与清理；
7. 安全：ACL/Scope/CSRF/密钥/审计结果；
8. 回滚：触发点、已验证动作、必须继续的历史义务；
9. 决策：Go / Conditional Go / No-Go；
10. 签收：Project Owner、技术主管、QA Lead、Program Owner，C3 另需用户。

## 5. 环境与验证执行

### 自动验证

1. 选择唯一实例名 `ai-test-commerce-{project}-{id}`；
2. 选择实际空闲整数端口 `>=9502`；
3. 使用项目自己的隔离数据库/config，先 fingerprint；
4. 按变更类型执行 schema/route 同步；
5. code 变更 reload，Master/startup 变更使用实例名位置参数 restart 语义；
6. 运行有界 CLI/HTTP/Browser/日志/数据验证；
7. 完成后 stop，并在证据包记录停止状态。

### 人工验收

若必须保留实例，交付必须包含：URL、实例名、端口、PID/status、当前功能状态、登录前置、精确 stop 命令。用户确认后立即 stop 并补清理证据。

## 6. 迁移与切换

每个 MIG Task 的最小阶段：

| 阶段 | 要求 | 禁止 |
|---|---|---|
| preflight | 只读清点、版本/connector/fingerprint、冲突、容量、权限 | 猜测默认库或 Scope |
| checkpoint | immutable manifest、基线计数/哈希、水位、feature mode | 无 checkpoint apply |
| expand | additive schema、兼容 reader、writer guard，mode off | 删除旧列或立即切写 |
| apply | 幂等批次、journal、限速、可恢复中断 | 跨 connector 无原子保证却继续 |
| fresh verify | 新连接从 DB 重算双向计数/守恒/quarantine | 复用 apply 内存 |
| cutover | allowlist dev/test → canary → 扩大；人工批准 | 全量一次切换 |
| contract | 旧 writer=0、旧 reader稳定无调用、另立删除授权 | 在同批删 schema |

每个 MIG TASK 在 L4 必须实例化以下八张独立 Slice，不能把命令、数据映射、apply、verify 和 cutover 塞进同一张施工卡：

| Slice | 单一结果 |
|---|---|
| `M01-MAP` | 冻结源/目标、字段映射、唯一键、历史兼容和守恒公式 |
| `M02-COMMAND` | 只编排 preflight/checkpoint/apply/verify/rollback 的薄 CLI |
| `M03-GUARD` | 数据库 fingerprint、生产 denylist、clone allowlist、manifest 校验 |
| `M04-CHECKPOINT` | schema/config hash、行数/hash、水位和恢复引用 |
| `M05-APPLY` | 分批、幂等、可续跑、冲突 quarantine 和 journal |
| `M06-VERIFY` | 新连接从数据库重算双向计数、hash 和不变量 |
| `M07-RECOVERY` | rollback 安全判定、恢复演练和 continue-forward |
| `M08-CUTOVER` | shadow/allowlist/CAS 切换、观察窗口和证据归档 |

## 7. 统一发布波次

1. Local isolated：功能 mode off，完成 schema/静态/现有入口；
2. Dev/Test allowlist：只允许明确 Scope，normal/test 账户隔离；
3. Shadow：纯比较，不做 DML/锁/预占/outbox/Provider；
4. Canary：最小 Scope、最低样本与完整对账周期；
5. Allowlist expand：每次扩张后重新观察和 Gate；
6. On：满足 R4 观察窗口与阈值；
7. Contract：旧 writer/reader 稳定为零后另立授权任务。

未达到最低样本不能以“暂无异常”晋级。资金、库存、Scope、权限、重复副作用、未分类 mismatch 任一非零立即停止。

## 8. 回滚优先级

1. 受影响 Scope 维护/只读，停新交易 producer；
2. 保持 webhook、payment reconcile、已支付库存 commit、refund/invoice/fulfillment、资产 settle/return、分账 reversal、已扣订阅 refund consumer；
3. 冻结 checkpoint、队列水位、feature mode 和不变量报告；
4. 排空可安全完成的 outbox；
5. 回 UI/route/mode，但保留所有新事实 reader；
6. 不删 additive schema，不恢复旧 Order writer、短 Scope writer 或缺 Envelope writer；
7. fresh verify/reconcile/Browser 只读验收；
8. 差异归零后解除维护，否则前向修复。

## 9. 测试产物授权边界

当前用户要求的是工程计划，不等同于授权新增测试。实施时：

- 优先使用现有测试、真实入口、CLI、HTTP、Browser、WLS、日志和 DB 不变量；
- 若 CRITICAL 崩溃窗、并发窗或 Provider 重放无法由现有入口受控复现，项目 Owner 提交测试产物授权申请，列明文件、场景、数据、清理和收益；
- 未授权前，该 TEST 标为 `DEFERRED_BY_AUTH`，对应 Project/Gate 不得假装通过；
- 获授权后再把测试文件作为单独 L4 Slice，不与生产实现卡混写。

## 10. 跨项目集成场景

以下场景必须在相应最终 Gate 中验证；它们是验收场景，不代表已授权新增测试文件：

1. 多仓 Vendor 订单部分发货后按原仓退款，库存、分账和退款总额同时守恒；
2. B2B 价格 + Tax 快照 + Vendor 分单，Checkout 与 Order minor-unit 总额一致；
3. Vendor 分账订单使用 CustomerAsset+现金组合支付后部分退款，现金与资产各自原路并生成 reversal；
4. Subscription 使用资产+现金且 Provider unknown，重试不会创建第二个现金扣款或重复资产 reserve；
5. Search/B2B/Store Scope 组合查询不会泄漏专属商品、价格或索引文档；
6. 所有扩展 `mode=off` 后停止新交易，但继续既有结算、周期、退款、履约和资产返还。

同一发布窗口最多切换一个新的 CRITICAL writer/cutover；Tax、Vendor settlement、Subscription scheduler 和 CustomerAsset tender 不得在同一窗口同时开启。
