# P0/P1 基础平台项目计划

## 1. 阶段目标

把商城所需的项目治理、迁移底座、完整 Scope、异步上下文、四层配置和安全基线交付为稳定公共平台。P1 未通过 `PG-2` 前，P2 不得以临时 Scope、短配置键或缺 Envelope 方式先行开发。

## 2. 项目顺序

```text
PRJ-GOV-00
  ├─ PRJ-MIG-00 ────────────────────────────────┐
  └─ PRJ-SCOPE-10 → PRJ-ASYNC-11 → PRJ-CONFIG-12 → PRJ-SEC-13 → PG-2
```

`PRJ-MIG-00` 和 `PRJ-SCOPE-10` 只能在 `PRJ-GOV-00` 通过后受控并行；任何实际 MIG apply 都等待 `PRJ-MIG-00` 验收。

## 3. `PRJ-GOV-00` 项目治理与基线

### 目标

建立一个不覆盖当前用户工作、可恢复、可审计的商城内核实施环境，并完成 R4/项目群人工复核和授权冻结。

### 工作包

| 顺序 | TASK | 交付物 | 验证 |
|---:|---|---|---|
| 1 | `TASK-P0-001` | baseline/dirty 清单、人工计划复核、项目板、分支/worktree 方案、Owner/RACI、授权矩阵、文件锁表、首波 L4 卡 | `TEST-DOC-01`、`TEST-DOC-02`、`TEST-DOC-03` 与人工签收 |

### 项目特有 DoR

- 用户确认开始治理项目，而不是直接实现 P2；
- 当前所有 tracked/untracked 改动已分类为：本项目、其他任务、未知 Owner；
- 对未知 Owner 文件默认禁止触碰。

### 项目 DoD / `PG-0`

- R4 和项目群计划人工可视核对通过；
- 19 项目/76 TASK 唯一映射、授权、WIP、Gate 和升级链已签收；
- 干净集成基线来源明确，但当前步骤不擅自 commit/push；
- `PRJ-MIG-00`、`PRJ-SCOPE-10` 的 L4 卡和文件锁已准备。

### P0 必须关闭的计划细化缺口

以下不是执行者可自行决定的实现细节；对应项未关闭时，该 P1 TASK 不满足 DoR：

1. `TASK-P1A-002`：把泛化的 Backend controller/templates 补成精确文件、符号和读写模式；ACL 完成前写入口必须 `off` 或只读。
2. `TASK-P1B-001` / `TASK-P1B-002`：冻结 `MOD-P1B-002` 的文件所有权，前者只负责 Runtime/Queue 契约，后者只负责映射、preflight、quarantine 工具。
3. `TASK-P1D-004-MAINTENANCE`：补齐实际 HTTP ingress、调用点和维护/preview gate 的精确接入文件。
4. `TASK-P1D-004-RATE`：补齐 limiter 的 HTTP ingress、配置、注册点和 fail-closed 接入文件。
5. `TASK-P1D-004-CONSENT`：冻结正式 Hook/layout、模块注册、QueryProvider/浏览器业务请求入口；不得临场自建页面或直连接口。
6. P1A CRUD：在对象 Scope ACL 未完成前明确菜单/写能力关闭策略，禁止先暴露未鉴权写入口。
7. P1D：形成统一 HTTP ingress 文件锁表，避免安全头、SEO、维护和限流并行覆盖同一入口。

### 停止条件

无法区分现有用户改动、计划文件与真实路径不一致、需要清理/覆盖他人工作、用户要求改变路线 B、无法建立隔离 worktree。

## 4. `PRJ-MIG-00` 迁移与灰度底座

### 目标

所有后续 MIG 共用同一 checkpoint、数据库隔离、journal、fresh verify 和 rollout 契约，禁止每个模块自建不兼容迁移框架。

### 工作包顺序

| 顺序 | TASK | L4 建议切片 | 退出证据 |
|---:|---|---|---|
| 1 | `TASK-MIG-FOUNDATION` | manifest/fingerprint → journal/restore → mode/allowlist/env-lock → pure shadow API → dry-run/unsafe DB rejection | `TEST-MIG-FOUNDATION-01`、`TEST-MIG-FOUNDATION-02` |

文件/符号级执行卡：[`l4/PRJ-MIG-00-L4.md`](l4/PRJ-MIG-00-L4.md)。`TASK-MIG-FOUNDATION` 契约 + 隔离 clone + 持久化 journal + **按能力 shadow 适配（M00-E）** 均已 ACCEPTED（2026-07-25，`DEF-MIG-M00E-01`）；项目状态 **`ACCEPTED`**。生产 cutover 属 `RES-MIG-PROD-CUTOVER`，须独立授权。任何 MIG apply 仅允许在 `mig_clone_*` 上执行。

### 关键契约

- manifest 不可变并绑定 repo/branch/commit/connector/schema fingerprint；
- shared/prod 指纹 denylist，无法证明隔离即拒绝 apply；
- verify 必须新连接重算；
- mode 仅 `off|shadow|allowlist|on`，生产 `on` 必须人工授权；
- rollback 只允许安全 reader/mode 回退或 continue-forward，不删除新事实。

### DoD / `PG-1` 的迁移部分

两次 dry-run 结果确定一致；错库/坏 manifest 在零写入前拒绝；中断可按 journal 恢复；所有 feature mode 默认 off。
