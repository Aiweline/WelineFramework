# DeveloperWorkspace 开发需求

## 需求记录

### 2026-08-22 - API 文档完整调用测试工作台恢复

**背景**
Weline UI 迁移曾将历史 API 工作台替换为只支持 Worker JSON 调用的薄壳，普通 REST 请求编辑、认证、环境、国际化与响应诊断能力丢失。UI 统一不得精简产品功能。

**功能需求**
- REST 与 Frontend Worker 均可真实试调；SDK 文档保留下载与指南入口。
- REST 保留方法、URL、查询参数、Header、JSON Body、示例导入、登录 Token、沙盒/正式模式和语言/货币路径或参数模式。
- 响应必须展示状态、业务 Code/消息、耗时、大小、响应头和可复制/格式化响应体。
- 接口树保留区域切换、层级、搜索、URL 定位及桌面拖拽调整；手机自动单列且不得横向溢出。
- 只允许原生 DOM、Weline UI 与 Weline.Api，不恢复 jQuery、jsTree、Bootstrap、Prism 或字体图标。

**验收状态**
- 需求：已确认。
- 实现：进行中。
- 真实路径验收：待 9555 WLS 浏览器验证。

### 2026-01-31 - Framework/View/doc 扫描支持

**背景**
文档导入命令目前只扫描 `Framework/doc`，导致 `Framework/view/doc` 中的文档无法被收集与检索。

**功能需求**
- 文档导入命令需支持扫描 `Framework/view/doc` 下的文档。
- 所有来自 `Framework/view/doc` 的文档必须归属到 `Weline_Framework` 模块。
- 原有其他模块的文档扫描规则保持不变。
- 扫描统计需正确计入新增/更新数量。
- `Framework/view/doc` 不存在时，导入命令应跳过并继续执行。

**技术方案（概要）**
- 在文档扫描服务中为 `Weline_Framework` 增加额外的 `view/doc` 扫描入口。
- 扫描结果仍以 `Weline_Framework` 模块归属写入。

**测试计划**
- 单元/集成测试：新增覆盖 `view/doc` 扫描的用例，验证文档路径以 `view/doc/` 前缀保存且模块归属正确。
- 命令行验证：运行 `php bin/w doc:import` 确认扫描统计包含 `view/doc` 文档。
