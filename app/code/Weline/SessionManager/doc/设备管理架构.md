# 设备管理架构

## 目标与边界

`Weline_SessionManager` 为 Customer 前台身份和 Backend 管理员身份提供统一的认证设备登记、验证、单设备撤销与逐设备记住登录。它不枚举 File、Redis 或 WLS 的底层 Session，因此三种 Session 存储使用同一套业务语义。

第一版中的“设备”是一次浏览器配置文件里的认证设备会话。不同浏览器、隐私窗口分别计为设备；正常退出后再次登录会生成新设备。不提供物理指纹、定位、设备改名、数量限制、全局查看或批量下线。

## 分层职责

- Framework 发布 `AuthenticatedDeviceRegistryInterface`、`RememberedDeviceCredentialProviderInterface` 及中立 DTO；`AuthenticatedSession` 负责在登录、认证检查和退出时调用 Provider。
- SessionManager 实现 Provider、两张 ORM 表、设备元数据、列表/撤销业务和 QueryProvider。
- Customer 负责前台 `w_frontend_ut` 的签发、恢复、轮换、旧 `w_ut` 迁移与退出清理。
- Admin/Backend 负责后台 `w_backend_ut`、旧 Backend remember Token 迁移以及恢复后的 ACL Session 上下文。
- 前台页面通过 Customer 账户中心 Hook 注入；后台页面、菜单、Controller 和 Query 操作统一受 `Weline_SessionManager::device_manage_self` 控制。

## 认证生命周期

### 密码登录

1. `AuthenticatedSession::login()` 启动并重新生成 Session ID。
2. Framework 用 `RuntimeProviderResolver::resolveDetailed()` 解析设备 Provider。
3. Provider 未声明时沿用旧登录；Provider 已声明但不可用时登录失败关闭。
4. SessionManager 只持久化 Session ID 的 SHA-256 摘要，并返回随机公开 `device_id`。
5. Framework 把公开 `device_id` 写入当前区域的认证 Session，再写入身份键并保存。
6. 用户选择记住登录时，身份模块为当前设备签发原始 Token Cookie；数据库只保存 Token SHA-256 摘要。

### 认证请求

`isLoggedIn()` 每个请求最多校验一次。设备有效时，最近活动和元数据最多每分钟更新一次；设备已撤销、绑定不一致或已配置 Provider 异常时，Framework 清理当前区域的认证键。购物车等无关 Session 数据不会被删除。

上线前已有的有效 Session 没有公开设备绑定；首次认证请求会按区域、主体和 Session 摘要惰性登记。唯一索引保证并发请求收敛。已有公开绑定但对应设备行缺失时不会重新登记，以免删除或撤销状态被绕过。

### 记住登录恢复

1. 新 Cookie 存在时只验证新凭证，不回退旧 `w_ut`。
2. 凭证验证得到区域内主体和公开设备 ID。
3. 标准 `login(..., AuthenticatedLoginContext::remembered($deviceId))` 将新 Session 摘要绑定回原设备。
4. 恢复成功后在同一设备上轮换 Token；旧 Token 立即失效，其他设备凭证不变。
5. 新 Cookie 不存在时，身份模块才检查并确认旧 `w_ut` 的归属；成功后签发新凭证、删除已确认的旧行和 Cookie。
6. 已登录用户也会执行一次归属确认后的惰性迁移。迁移失败或旧 Token 属于其他身份区域时保留旧 Cookie。

### 下线与退出

远端下线只接受公开 `device_id`。服务端从当前认证 Session 推导区域和主体，跨区域、跨主体及不存在统一返回 `device_not_found`。当前设备返回 `current_device_logout_required`；重复下线成功且幂等。

设备撤销与关联记住凭证在同一事务中更新。目标浏览器下一次认证请求会清理本地身份，随后其已撤销 remember Token 也无法恢复。正常退出调用 `revokeCurrent()` 后清理本地认证键和新 Cookie。

## 数据模型

### `weline_authenticated_device`

- 内部自增主键仅供服务端关联，不进入浏览器接口。
- `public_id` 是 32 字节随机值的 Base64URL 表示。
- `auth_area` 归一为 `frontend` 或 `backend`；`principal_id` 只在区域内解释。
- `session_digest` 保存 SHA-256 摘要，`(auth_area, session_digest)` 唯一。
- 保存设备名称、浏览器、操作系统、最近 IP、首次/最近活动、Session/remember 到期和撤销审计字段。

### `weline_remembered_device_credential`

- `device_id` 唯一，因此每台设备最多一个当前凭证。
- `token_digest` 唯一且只保存 SHA-256 摘要。
- 保存到期、最近使用、撤销时间和原因。

撤销记录和完全过期记录保留 30 天后清理。原始 Session ID、原始 Token 及其摘要不得出现在接口响应或日志中。

## QueryProvider 契约

Provider 名为 `session_manager`：

- `listFrontendDevices(page = 1, page_size = 20)`：要求 Customer 身份。
- `revokeFrontendDevice(device_id)`：要求 Customer 身份。
- `listBackendDevices(page = 1, page_size = 20)`：要求 Backend 身份及专用 ACL。
- `revokeBackendDevice(device_id)`：要求 Backend 身份及专用 ACL。

`page_size` 最大 100。列表只显示仍有有效 Session 或记住凭证的设备，当前设备优先，其余按最近活动倒序。响应不包含主体 ID、区域、内部主键、Session 摘要或 Token 摘要。

## 故障与兼容策略

- Provider 没有声明：Framework、Customer 和 Admin 维持旧认证/remember 行为。
- Provider 已声明但构造、数据库或业务调用失败：认证失败关闭，不得回退旧 Token。
- 设备管理页面使用 `Weline.Api.resource('session_manager')`；不直接 `fetch`/XHR，不使用浏览器原生确认框。
- SessionFactory 的认证实例与验证缓存按请求/Fiber 隔离，不能使用进程级主体状态。
