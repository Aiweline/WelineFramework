# 设备管理运营说明

## 用户入口

- 前台：Customer 个人中心 → 安全相关导航 → **设备管理**。
- 后台：系统管理 → 用户与权限 → **设备管理**。

后台超级管理员默认可访问。其他角色需要显式授予 `Weline_SessionManager::device_manage_self`；该权限仅允许管理员管理自己的后台登录设备。

## 页面含义

- **本设备**：当前浏览器正在使用的认证设备，不显示“下线”按钮；需要退出时使用正常退出登录。
- **已登录**：该设备仍有有效 Session。
- **可自动登录**：Session 已过期或不再活跃，但记住登录凭证仍有效。
- 最近 IP、浏览器和系统来自请求元数据，只用于辅助识别，不应当作物理设备指纹或精确定位。

设备页仅展示仍能通过 Session 或 remember 凭证登录的设备。撤销和过期记录在数据库中保留 30 天用于审计，但不会继续显示。

## 下线行为

点击非当前设备的“下线”后，页面显示内联“确认下线/取消”。确认后：

1. 目标设备和关联记住凭证一起撤销。
2. 当前操作设备继续登录，不受影响。
3. 目标设备不会被主动推送到登录页；它在下一次访问需要认证的页面时退出。
4. 目标设备的旧 remember Cookie 不能恢复登录，并会在验证失败后清理。

重复下线同一设备按成功处理。无权操作和不存在的公开设备 ID 统一显示不可操作，避免泄露其他用户设备是否存在。

## 发布与升级

1. 确认 Framework 版本为 `2.4.0`，SessionManager 版本为 `1.1.0`，依赖模块版本与清单一致。
2. 通过定向 `setup:upgrade` 创建 `weline_authenticated_device` 和 `weline_remembered_device_credential`，并刷新路由、菜单和 Provider 注册表。
3. 使用独立 WLS 实例验证前台和后台登录、设备列表及双浏览器下线路径。
4. 上线不会统一踢出已有登录；旧有效 Session 在首次访问时自动登记。

不要手工写入设备表、公开设备 ID 或 Token 摘要，也不要用删除设备行代替下线。公开绑定存在而行缺失时会按安全策略拒绝认证。

## 故障排查

### 登录统一失败并提示设备服务不可用

- 检查 SessionManager 是否启用且 Provider 注册表已重新编译。
- 检查两张新表是否完成升级，数据库连接和事务是否可用。
- 检查模块版本/依赖是否一致，特别是 Framework `2.4.0`。
- 不要临时移除 Provider 映射来绕过已撤销状态；修复服务后重新登录。

### 设备页加载失败

- 前台确认 Customer 仍已登录；后台确认角色拥有专用 ACL。
- 检查 QueryProvider 描述中 `session_manager` 四个操作是否存在。
- 检查浏览器控制台和脱敏运行日志；不得记录或复制 Session ID、Token、摘要。

### 设备名称显示“未知设备”

User-Agent 缺失或无法识别时属于预期回退，不影响登录和下线。最近 IP 可能是代理链解析结果，不用于安全决策。

### 下线后目标设备短暂仍显示页面

下线按“下一次认证请求”生效。刷新或进入受保护页面后应返回登录页；静态页面或已经加载的前端内容不会被服务器主动移除。

## 隐私与日志

- 页面只显示当前身份自己的设备。
- 数据库不保存原始 Session ID 或原始 remember Token。
- API 不输出内部行 ID、身份 ID、区域或摘要。
- 日志不得记录原始值、前缀、后缀或摘要；排查时只使用公开 `device_id`、区域、状态码和非敏感主体 ID。
