## 当前有效需求

### `REQ-SESSIONMANAGER-0001` 存储无关的认证设备登记与撤销

- 来源与确认：用户于 2026-08-11 批准完整实施计划。
- 目标版本：`1.1.0`。
- 背景/问题：File、Redis、WLS Session 可并行登录，但不能通过底层存储一致地枚举或撤销某一登录设备。
- 业务逻辑：设备记录绑定认证域、主体和 Session 摘要；密码登录在同浏览器设备密钥下复用设备，记住登录恢复同一设备，旧有效 Session 首次请求惰性登记；撤销后目标设备下一次认证请求失败。
- 范围：frontend/backend 两个认证域、设备元数据、最近活动节流、幂等撤销、审计保留和过期清理、`install_key_digest` 合并。
- 非目标：枚举原始 Session 存储、全局查看他人设备、硬件序列号指纹、改名、地理定位、登录通知、数量上限。
- 数据/权限/安全：仅持久化 SHA-256 摘要和随机公开 ID，不输出内部主键或摘要；跨域、跨用户必须不可见不可写。
- 兼容/迁移：缺失设备行但已有可信认证 Session 时可惰性登记；撤销行不删除，避免重新登记绕过。
- 验收标准：同一主体两个 Session 同时有效，撤销其中一个不影响另一个；frontend/backend 完全隔离；并发登记收敛到唯一行。
- WebUI/E2E：前后台各用两个隔离浏览器上下文验证。
- 运营与支持影响：目标设备在下一次认证请求下线，不提供服务器推送；撤销/过期记录保留 30 天。
- 依赖与风险：认证热路径必须每请求最多验证一次，最近活动最多每分钟写一次。

### `REQ-SESSIONMANAGER-0002` 每设备独立记住登录凭证

- 来源与确认：同上。
- 目标版本：`1.1.0`。
- 业务逻辑：每个设备至多一个有效凭证；只保存 Token 摘要；自动登录成功后轮换；撤销设备与凭证在同一事务中完成。
- 范围：`w_frontend_ut`、`w_backend_ut`、新 Token 解析/签发/轮换/撤销，以及旧 `w_ut` 的归属确认后惰性迁移。
- 非目标：恢复或重新签发已撤销凭证、改变现有前台/后台 remember 有效期。
- 数据/权限/安全：原始 Token 只进入 HttpOnly Cookie；Provider 声明故障时禁止回退旧凭证。
- 兼容/迁移：新 Cookie 缺失时才尝试旧 Token；只清理已由 owning 模块确认归属的旧行/Cookie。
- 验收标准：新设备不覆盖其他设备 Token；撤销 B 后 B 不能自动恢复；旧 Token 可一次性迁移。
- WebUI/E2E：登录勾选 remember、远端下线、目标浏览器刷新/重开受保护页。

### `REQ-SESSIONMANAGER-0003` 前后台自助设备管理

- 来源与确认：同上。
- 目标版本：`1.1.0`。
- 用户与运营场景：Customer 在个人中心管理自己的前台设备；后台用户在“系统管理 → 用户与权限 → 设备管理”管理自己的后台设备。
- 业务逻辑：当前设备优先，其他设备按最近活动倒序；分页默认 20、最大 100；当前设备只显示“本设备”，其他设备以双击式内联确认下线。
- 范围：QueryProvider `session_manager` 四个操作、Customer Hook、后台页面、菜单、ACL、加载/空/错误/重试状态和 i18n。
- 非目标：批量下线、管理其他主体设备、原生 confirm/alert、直接 fetch/XHR。
- 数据/权限/安全：浏览器不得提交 user ID 或 area；后端从绑定 Session 推导；后台使用 `Weline_SessionManager::device_manage_self`，菜单、Controller、Query 操作一致。
- 验收标准：允许用户只能看到自己的设备；无权限后台角色菜单不可见且直达拒绝；当前设备 API 返回 `current_device_logout_required`。
- WebUI/E2E：真实 WLS 中覆盖成功、空、错误/重试、当前设备、权限和前后台隔离。

### `REQ-SESSIONMANAGER-0004` 浏览器设备密钥合并同一配置

- 来源与确认：用户于 2026-08-30 确认采用长期 Cookie 设备密钥合并，避免同一 Mac/Chrome 配置出现多条设备。
- 目标版本：`1.2.0`。
- 业务逻辑：签发 `w_frontend_dk` / `w_backend_dk`；仅存摘要；密码登录按密钥复用未撤销设备并改绑 Session；`relogin` 软过期 Session；`password_login_replaced` / `password_login_without_remember` 只吊销 remember 凭证；退出保留设备密钥 Cookie。
- 范围：Schema、`DeviceInstallKeyCookieService`、Registry 合并、单测与运营说明。
- 非目标：硬件序列号、跨浏览器合并、自动清理全部历史无密钥幽灵行。
- 验收标准：同密钥两次密码登录只保留一条；不同密钥仍为两条；凭证替换不撤销设备行。
