## 当前有效需求

### `REQ-BACKEND-0001` 后台三态主题偏好持久化

- 来源与确认：关联用户确认的 `REQ-THEME-0001`，由 Theme 作为需求 owner。
- 目标版本：`1.4.1`。
- 业务逻辑：用户主题配置只接受 `system|light|dark`；`system` 保存为偏好，页面属性在客户端预解析为实际 light/dark。旧 light/dark 与布尔字段继续可读；非法历史值回退 light，非法新写入明确拒绝。
- 范围：`BackendThemeConfigInterface` 现有实现、主题设置控制器和聚焦测试。
- 非目标：数据库迁移、跨模块具体类耦合、站点同步。
- 数据/权限/安全：继续使用当前用户级配置和既有授权路径；不新增请求端点。
- 验收标准：合法三态可持久化并在刷新后恢复；非法写入失败且不会污染用户配置。
- WebUI/E2E：由 Theme/Admin 的后台三态入口和 E2E 覆盖。

### `REQ-BACKEND-0002` 后台认证设备恢复上下文

- 来源与确认：用户于 2026-08-11 批准多端登录与设备管理计划。
- 目标版本：`1.4.2`。
- 业务逻辑：Backend 发布的交互认证接口允许 Admin 在记住登录恢复时传入中立 `AuthenticatedLoginContext`，并统一通过 `AuthenticatedSession::login()` 安装身份，禁止继续直接写认证键绕过设备登记。
- 范围：Backend 公开 auth Interface 与实现的向后兼容可选参数、ACL Session 上下文恢复。
- 非目标：Backend 保存设备记录、依赖 SessionManager 具体类或提供设备管理页面。
- 数据/权限/安全：仅依赖 Framework 中立契约；不得把原始 Session/Token 传入日志或业务 DTO。
- 兼容/迁移：旧调用方不传上下文时行为兼容；旧 BackendUserToken 仅作为 Provider 未配置或惰性迁移来源。
- 验收标准：密码登录与记住恢复均经过标准 Session 登录路径；恢复设备不创建重复逻辑设备；ACL 上下文保持可用。
- WebUI/E2E：后台两个隔离上下文完成登录、下线、被下线后的拒绝与 remember 不恢复。
