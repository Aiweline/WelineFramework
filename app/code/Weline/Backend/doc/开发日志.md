# Weline_Backend 开发日志

## 2026-09-03 — 删除 backend/logo 云裳残留文件并清空 Theme brand

- 现象：媒体库 `Media Files/backend/logo` 仍有 `yunshang-*.jpg`；选择确认时报「该资源尚未建立可选的文件实体，或当前语言的名称、alt、描述尚未审核。」
- 根因：文件为磁盘直写，无 FileAsset / 语言审核态，`asset_selectable!==true`，MediaManager `confirmSelection` 触发 `assetMetadataRequired` toast。
- 处理：删除三份文件；清空 `w_meta_config` brand_* 与 `w_theme_scope_release` appearance payload 中的 yunshang brand；清 Theme/WLS 缓存。登录页继续默认 Theme logo。


## 2026-09-03 — 后台登录 Logo 恢复默认（清 WLS system_config 脏缓存）

- 现象：管理面板登录页仍显示云裳黑底横幅 Logo（`/media/image/backend/logo/yunshang-logo-light.jpg`），与「已清理 Backend 外观 Logo」预期不符。
- 根因：`w_system_config` 中 `Weline_Backend` 的 `logo_light`/`logo_dark`/`site_icon` 已无行；CLI/文件缓存读到空值，但 WLS 共享内存 `system_config` 池仍残留旧 map（含 `/pub/media/backend/logo/yunshang-*`）。登录页 `Login` 读 Backend 配置后经 `MediaUrl::fromPath` 渲染。
- 处理：`WlsMemoryAdapter::clearAllMemory()` + `WorkerCachePoolResetter::clearFrameworkPools()`（含 `system_config`）；`BackendConfigStore::deleteConfig` 再次确认 logo 键为空。未改登录模板逻辑。
- 验收：登录页 `img.w-login-logo[src=/Weline/Theme/view/theme/backend/assets/images/theme/logo.png]`；默认 Logo 资源 200。前台 Theme brand（`theme.frontend` `brand_logo_*`）未动。


## 2026-08-30 — 页头面包屑对带 query 的菜单 action 失配

- 现象：支付等方式页布局标题退成模块名（如 `Weline_Payment`），右侧面包屑空白；内容区又手写同名页头，看起来「多余且没有面包导航」。
- 根因：`menu.xml` / 库内 `action` 可带 `?target_scope=…`，`PageHeaderResolver` 按完整 action 精确匹配路由路径失败。
- 修复：匹配时剥离 query；XML 索引与 DB `LIKE path?%` 回退；面包屑 URL 拆 path/query 生成。

## 2026-08-29 — BinQuery backend auth_error（SessionFactory 双实例）

- 现象：后台 Worker `eav_admin.adminRequest` 等 `auth: backend` 调用返回 403「不满足操作授权要求。」；同 Cookie 直连 HTTP 控制器正常，`backend-bootstrap` 可为 200。
- 根因：`FrontendWorkerBackendAttestationProvider` 用 `SessionFactory::getInstance()` 恢复登录态，而 `FrontendQueryGateway` 用 ObjectManager 注入的另一 `SessionFactory` 读 principal；QueryBin 已置 RequestContext 后 Gateway 跳过二次 restore，principal 为空触发 `denyAuthorization`。
- 修复：AttestationProvider 构造注入 `SessionFactory`，与 Gateway 共用同一请求级实例。

## 2026-08-29 — 通知下拉文字重叠像「重复」

- 现象：铃铛下拉多条标题/正文叠在同一视觉区域，像数据重复。
- 根因：`.w-notification-menu__list` 为 `display:grid` 且行高被压到 `min-height`（约 64px），条目内容实际更高且 `overflow:visible`，文字溢出叠到下一条；DOM 本身无双份数据。
- 修复：列表改为 `flex` 列、`height:auto`；标题/正文 `line-clamp`；同步源 `backend.css` 与发布态 `weline-backend.css`。

## 2026-08-29 — 全部已读后顶栏角标仍 99+

- 当前状态：`fixed`
- 根因：列表已落库已读，但顶栏 `@meta.cache.mode=chrome`（TTL≈300s）冻结了旧未读角标 HTML；Notification Block 还无条件读取 warmup 身份。
- 修复：`mark*` 后 bump session `backend_notification_inbox_rev`、清 Block/Partials 进程缓存；Partials auth key 纳入 inbox rev（跨 Worker 失效）；warmup 隔离；前端成功后乐观移除 badge。

## 2026-08-29 — 通知中心「全部已读」无响应
