# 事件：`Weline_Deploy::core_update_after`

`php bin/w core:update`（`Weline\Deploy\Console\Update\Core`）在核心文件同步、统计与最新 commit 打印完成后派发。

## 载荷

| 键 | 说明 |
|----|------|
| `branch` | 目标分支 |
| `force` | 是否 `-f` / `--force` |
| `tmp_dir` | 缓存仓路径 |
| `new_files` / `updated_files` / `deleted_files` | 同步统计 |
| `args` | 命令入参 |

## 典型观察者

- 截至 2026-10-31，`app/code` 下已无模块在本事件上注册观察者（`grep -rn "core_update_after" app/code --include=*.xml` 无命中）。Deploy 侧仍照常派发，便于二次开发挂载。

**核心更新不再触发主题布局固化**：`Weline_Theme::core_update_purge_layout_entities` 已于 2026-10-31 从 `Theme/etc/event.xml` 解绑（`Weline_Framework_Deploy::upgrade_after` 上的 `Weline_Theme::deploy_upgrade_purge_layout_entities` 同批解绑），
因此 `core:update` 收尾既不清 `var/runtime/theme-layout-entities/`，也不重固化主题产物。

主题产物由 **`php bin/w theme:update`** 构建，不再挂在本事件的收尾上。

本命令仍不算静态发布完成：仍须另跑 `setup:upgrade` / `deploy:upgrade` 完成静态双树铺平（`Deploy\Upgrade`）与 FPC deploy 世代；其中只有 `setup:upgrade` 收尾会跑主题观察者 `SetupUpgradeAfterPurgeLayoutEntities`（首次安装就地固化；已进代次机制时只写脏标记）。
