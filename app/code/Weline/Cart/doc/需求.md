## 当前有效需求

### `REQ-CART-0005` 商城购物车类型 SPI（`cart_type`）与分车

- 来源与确认：2026-09-07 ToC/ToB 一期；Cart 为万能车承载，不硬依赖 B2B。
- 目标：新增 CommerceCartType SPI + 内置 `toc` Registry；分车键 = Scope + owner + registered `cart_type`；旧键视为 toc 迁移；类型 mismatch fail closed；无游客 tob；摘要含 `cart_type`+`type_payload`；`presentLine` 必须带 `cart_type`。
- 范围：Cart 类型扩展、键与摘要合同、与 Checkout 冻结透传；B2B 可选注册 `tob` 见 `Weline_B2B` `REQ-B2B-0002`。
- 非目标：平行 B2B 购物车模块；会话直赋未注册类型；热路径探测 B2B。
- 验收标准：见 `doc/cart.md`「售卖类型 `cart_type`」节；未装 B2B 时仅 toc 且零探测税。

### `REQ-CART-0003` 商品详情所选 EAV 规格随加购提交并在购物车展示

- 来源与确认：2026-09-03 用户指出汉服规格必须来自 EAV，且购物车必须对应前台实际选中的颜色、尺码与短 SKU；2026-09-05 确认购物车/结账页须展示可读规格，而非仅 SKU。
- 业务逻辑：详情页加购脚本从当前商品根节点读取已选中的 `data-variant-axis` / `data-variant-value`，按轴名排序后作为 `selection` 交给 Cart `add`；Offer UUID、价格、库存与 SKU 仍由服务端权威解析。购物车行通过 `options` 展示 EAV 标签（轴名 + 选项文案）。
- 范围：`product-purchase-actions.js`、Cart 行 `options`、购物车页渲染；不引入或恢复商品规格 JSON。
- 验收标准：选择颜色和尺码后加入购物车，购物车行保存并显示相同 EAV 规格，SKU 为该 Offer 的短 SKU；无规格卡片加购仍提交空 selection。
- WebUI/E2E：真实 Weline 浏览器在汉服商品页切换规格、加购并打开 `/cart` 核验；结账页同步可见规格。

### `REQ-CART-0001` 服务端权威购物车身份与 Scope

- 来源与确认：现有 `cart.md`、`CartScopeResolver` 和本次正式商城闭环要求；用户于 2026-08-17 确认继续按建议实施。
- 目标版本：`1.2.1`
- 背景/问题：Cart、Checkout 和 QueryBin 必须解析到同一可信 Website/Store/Channel；跨模块不能依赖 Cart 内部具体 Service。
- 用户与运营场景：游客或登录顾客从商品页加入购物车并进入结账时，系统始终读取同一辆服务端权威购物车。
- 业务逻辑：浏览器只可携带不透明 guest token；客户身份与 Scope 由服务端请求上下文解析。Cart 发布稳定 Scope 解析接口供已声明依赖的模块使用，具体实现仍归 Cart 所有。客户端 Scope 与可信 Scope 冲突时 fail closed。
- 范围：公开 Scope 解析接口、Cart `provides` 绑定、Checkout 按接口消费、冲突行为回归测试。
- 非目标：不允许浏览器提供 `customer_id`、价格、币种或订单行作为可信事实；不改变多站点 Scope 语义。
- 数据/权限/安全：不得以跨模块具体类或 `ObjectManager` 获取 Cart 内部 Service；不得跨 Host 串车。
- 兼容/迁移：保留 `CartScopeResolver::fromParams()` 行为；无 Model Schema 变更。
- 验收标准：Checkout 源码不引用 `Weline\Cart\Service\CartScopeResolver`；QueryBin 与 HTML 请求解析同一 Scope；现有 Cart Scope 测试继续通过。
- WebUI/E2E：从当前 Host 加车后进入 `/USD/checkout`，商品、币种和 Scope 与购物车一致。
- 运营与支持影响：无新增配置；Scope 冲突继续返回稳定错误码。
- 依赖与风险：依赖 `RequestContext` 和 Frontend Worker 已安装的可信 Scope binding。

### `REQ-CART-0002` 公开结账快照边界

- 来源与确认：现有 `cart.md` 与 `CheckoutCartSnapshotInterface` 源码，2026-08-17 建立基线。
- 目标版本：`1.2.0`
- 背景/问题：结账不得信任浏览器传入的商品、数量和金额。
- 用户与运营场景：提交报价前，Checkout 从当前 Cart 重新解析 Offer、价格、可售状态和币种。
- 业务逻辑：`CheckoutCartSnapshotInterface` 输出重新校验后的服务端快照；`clear` 仅清理当前可信身份与 Scope 的购物车。
- 范围：冻结、重新定价、可售校验和受控清理。
- 非目标：Cart 不负责支付、订单状态或配送执行。
- 数据/权限/安全：所有成交事实由服务端读取；Provider 缺失或非法结果按既有契约 fail closed。
- 兼容/迁移：保持现有接口与 V2 行为。
- 验收标准：Checkout 不接收客户端行/金额，清理不会影响其它身份或 Scope。
- WebUI/E2E：加车、结账、成功下单后当前车为空，其他 Scope 不受影响。
- 运营与支持影响：无。
- 依赖与风险：依赖 Product 快照 Provider 和价格/可售 Gate。
