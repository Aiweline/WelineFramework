## 1. 问题（本席回答什么）

> 结账支付方式区如何展示「减多少」，使买家在**未选中时也能看见可选减免**、选中后摘要即时兑现，且视觉复用现有结账壳而非新造界面？

## 2. 信息架构（结账右栏 / 支付区）

### 2.1 区域拓扑（既有，不改骨架）

```
结账页
├── 主列：地址 / 配送 / …
└── 侧栏摘要（aside）
    ├── 商品回顾
    ├── 优惠与留言（券 slot 等）
    ├── totals 金额表          ← 激励摘要行插这里
    └── 提交
支付步骤内
└── .payment-methods           ← 列表「减 X」插这里
    └── .payment-methods__grid
        └── .payment-method-card × N
```

首期**不**在购物车/PDP 强制挂激励条（顾问：结账列表为主）。

### 2.2 支付方式卡片（一行一方式）

| 槽位 | 内容 | 状态规则 |
|------|------|----------|
| 左：radio + icon + name | 既有 title-row | 不变 |
| 次行：description | 既有简介 | 不变；**禁止**把「减 X」塞进长简介替代主提示 |
| **激励提示（新增）** | 主信息：「减 ¥X」或「减 X%（约 ¥Y）」 | 有发布激励且方式**可用**才渲染 |
| reason / disabled | 既有不可用文案 | 方式不可用 → **不展示**可点「可减」；可仅「当前不可用」 |

**未选中 vs 已选中**

| 态 | 文案语气 | 视觉层级（意图，不定色） |
|----|----------|--------------------------|
| 未选、有激励 | 「可选减 ¥X」/「选此再减 ¥X」 | 可见次强调；奖励感，不贬损他法 |
| 已选、有激励 | 「减 ¥X」（或百分比约价） | 相对未选略加重（字重/对比），与应付变化同步 |
| 无激励 | 不渲染激励槽 | 空白，勿占位「减 ¥0」 |
| 不可用 | 无激励主提示 | 跟 `__reason` |

百分比：列表展示「减 X%（约 ¥Y）」；**约 ¥Y 与选中后摘要行金额一致**（同一套后端算力 / payload），禁止列表写「最高」。

### 2.3 订单摘要 totals（分列）

建议行序（在既有表上增量；与叠加矩阵叙事一致）：

1. 商品小计  
2. 运费  
3. **优惠**（`data-checkout-discount-row` — 券/满减等既有语义，**不含**支付方式激励）  
4. （可选既有）定金 / 信用 / 税  
5. （既有）货到付款手续费 — 加价；与激励互斥叙事  
6. **支付方式优惠**（新增 `data-checkout-payment-incentive-row`）— 仅选中有激励的方式时显示；金额为负向「−¥X」  
7. 应付合计  

**切换支付方式**：列表提示 + 摘要激励行 + 应付 **同一帧语义更新**（允许轻量 loading，禁止「先高后低闪一下再改」的误导闪烁作为默认体验）。

### 2.4 文案面（交翻译工程师；本席钉 key 意图）

| source（简中） | 出现位置 |
|----------------|----------|
| 可选减 %1 | 未选卡片 |
| 减 %1 | 已选卡片 / 固定额 |
| 减 %1（约 %2） | 百分比卡片 |
| 支付方式优惠 | 摘要行标签 |
| 当前不可用 | 既有不可用（复用） |

禁止：「用卡多付」「原价仅限他法」「最高立减」。

## 4. 状态机（原型关心的可观察态）

| 事件 | 列表 | 摘要激励行 | 应付 |
|------|------|------------|------|
| 进入结账，默认无选 / 选无激励 | 有激励卡显示「可选减」 | hidden | 无激励扣减 |
| 选中激励方式 | 该卡「减 X」加重；他卡仍「可选减」 | 显示 −¥X | 下降 |
| 改选无激励 | 「减 X」回「可选减」；摘要行消失 | hidden | 回升 |
| 方式不可用 | 无「可减」主提示 | n/a | n/a |
| 激励未发布/未配 | 同无激励 | hidden | 不变 |

## 5. payload / 契约意图（供冻结会命名）

本席**推荐**（非最终类名）：

- 列表 method 项：`savings_minor`（int，可兑现扣减）、`incentive_display`（已格式化或 i18n 参数元组）、`incentive_type`: `fixed|percent`
- 摘要：独立行消费同一 `savings_minor`；与 `discount_lines[].source_type=payment_method_incentive` 对齐

开放点 §10.4：若架构/支付席定为 `incentive_discount` 亦可，**语义不变**。
