## stance

条件（对齐冻结前须写入规格「顾问约束」）：

1. **只做「激励折扣」叙事，禁止「选卡/选某方式加价」式 surcharge 主路径**（尤其 GB/EU 支付附加费限制；PayPal 商户协议禁对 PayPal 单独加收 surcharge）。

4. **首期支付方式范围收窄**：先 PayPal（+ 本机已可用的假卡/测试方式做对照）+ 通用「优惠明细透传」能力；其它 Provider 仅 capability 声明后配置启用，禁止默认全开。

## 要开发什么（产品/运营决策）

两块一体，缺一不可：

| # | 能力 | 客户价值 |
|---|------|----------|
| A | **支付方式激励折扣**：结账选择某支付方式时，订单应付可减免固定额或百分比（后台可配；未配置则无折扣） | 引导客户选用商家希望的支付方式（费率/转化/风控） |
| B | **优惠明细透传支付商**：购物车券、满减、运费优惠、支付方式激励等 `discount_lines` 传到 Provider（首期以 PayPal `amount.breakdown.discount` / 明细一致为目标） | 客户在 PayPal 等侧也能看到「减了什么」；对账可核 |

运营目标：转化率与支付方式 mix 优化，而非制造假折扣感。折扣幅度应小于等于商家因该方式节省的成本或可接受的获客补贴（运营自控；顾问不写实现）。

## 成功标准

**客户感知**

- 支付方式列表项旁清晰展示「选此方式减 ¥X / 减 X%」或「省 ¥X」；选中后订单摘要即时更新应付总额。
- 未选激励方式时，列表仍可见「可选减」提示，避免选中后才「惊喜变价」导致不信任。
- 切换支付方式时，应付金额与「减多少」同步变化；无金额跳变后不一致。

**对账 / 支付商侧**

- Provider 订单应付 = 站内最终应付（币种、精度一致）。
- PayPal（首期）可见 discount breakdown；优惠券与支付方式激励均能量化进透传明细（名称/金额可审计）。
- 后台订单/支付会话可回放 `discount_lines` 快照（含 funding source：商家/Provider/平台）。

**运营验收指标（建议 PM 写入验收）**

- 激励方式选用率相对基线提升（首期可观测即可）。
- 因金额不一致导致的支付失败/客诉 = 0（硬门禁）。

## 叠加规则建议（顾问约束 · 须进规格）

建议默认矩阵（可配置，但首期默认如下）：

| 顺序 | 优惠类型 | 规则 |
|------|----------|------|
| 1 | 购物车/商品级促销、满减 | 先算，形成「商品小计后金额」 |
| 2 | 优惠券 | 作用于可券基价；与券规则冲突时以券模块既有规则为准 |
| 3 | 运费优惠 / 包邮进度 | 仅作用于运费行；不与商品折扣混写同一行 |
| 4 | **支付方式激励折扣** | **最后一档现金应付前**应用；基数 = 已含券/满减后的应付（不含不可用资产抵扣）；同一订单**仅一种**支付方式激励 |
| 5 | 信用/积分/W币 | 仍按 Payment 既有「支付或折扣二选一」；**首期不与支付方式激励混推为「双重大额减」**（若叠加须显式运营开关，默认关） |

**税前 / 税后**

- **首期默认税前折扣**（对商品/应付小计折扣，再算税——若站点含税价则按现有税务模块口径，禁止顾问另开平行税逻辑）。
- 运费优惠与商品折扣分列；PayPal 侧 `shipping_discount` vs `discount` 分字段映射（施工归支付席）。

**禁止**

- 用「全站原价抬高 + 仅某支付方式打折」制造虚假划线对比（CN 促销/价格标示风险）。
- 把「其它方式价」标成原价、激励方式标成折扣，却对客户隐瞒「标价已含卡费」的实质 surcharge（GB 风险）。

## 首期范围 vs 后续

| | 首期（MVP） | 后续 |
|--|-------------|------|
| 支付方式 | **PayPal** 激励配置 + 透传；本机 **fake_card** 对照验收；配置模型支持「任意 method 可配」但**默认未配=0** | Stripe/本地钱包/支付宝等按 capability 逐个打开 |
| 折扣形态 | 固定额 + 百分比（二选一或按配置）；币种跟结账币 | 国家/客户组/首单限定、A/B、Provider 补贴分摊 UI |
| 透传 | 优惠券 + 支付方式激励进 `discount_lines` → PayPal breakdown | 多 Provider 明细字段映射、发票展示对齐 |
| 展示 | 结账支付列表「减 X」+ 摘要行 | 购物车/PDP 轻提示（可选） |
| 退款 | 全额/部分退按快照比例回退激励折扣与券 | 争议/拒付专项话术与 FAQ |

**是否所有方式可配折扣**：产品上 **是（可配置）**；运营上 **否（不全开）**——仅对费率更优或战略引导的方式开折扣，避免「处处有减」稀释激励。

## ops_notes

- **激励对象**：优先引导「费率更优 / 信任更高 / 争议更低」的方式（用户点名 PayPal → 首期主推）。
- **幅度**：整数友好（¥5 / 2% / 5%）；复杂规则增加放弃率。
- **触达点**：结账支付列表为主；可选购物车一行「部分支付方式可再减」——避免 PDP 过度承诺导致未满足条件的投诉。
- **活动运营**：折扣可开关、可设起止；停用后新单不再享，历史单保留快照。
- **指标**：支付方式选用率、激励方式 AOV、因金额不一致失败率、退款纠纷提及折扣次数。

## design_brief（结账列表如何展示「减多少」）

- **一列表一行一方式**：左侧方式名/图标，右侧主信息为「减 ¥X」或「减 X%（约 ¥Y）」；选中态加粗应付变化。
- **订单摘要**：独立一行「支付方式优惠 −¥X」，与「优惠券 −¥Z」分列，禁止合并成模糊「优惠」。
- **切换方式**：即时重算摘要与应付；无刷新闪烁成「先高后低」误导。
- **不可用方式**：若方式本身不可用，不展示激励或标注「当前不可用」；禁止灰态仍显示「可减」误导点击。
- **文案语气**：奖励感（「选 PayPal 再减」），禁止贬损其它方式（「用卡多付」）。
- **视觉**：跟现有结账主题 Token；顾问不定色板/CSS（交原型/UI/主题席）。

站内文案面若新增规则说明：政策页/FAQ Hub 勾选；可见串须翻译工程师。

## 退款原则（顾问）

1. 支付方式激励折扣随原支付成功快照绑定；全额退 → 激励一并回退记账；部分退 → 按金额比例或按行规则回退（规格定一种，默认比例）。
2. 优惠券与激励分列回退，禁止只退现金不还原折扣账导致毛利虚高。
3. 客户感知：退款到账说明可含「已含支付优惠回退」——话术准确，不承诺「退回未付的折扣现金」。
