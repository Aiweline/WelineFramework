## 1. 探查结论（一句话）

仓内已有「优惠行快照 / 营销动作×支付方式兼容 / 资产折扣 Event / COD fee」四类邻近机制，但**支付方式激励折扣（选此可减）**与**优惠明细透传支付商（PayPal breakdown 等）**均未落地；§5.2 surcharge 与 §24 叠加矩阵仍待定界，且易与 `supported_discount_actions` 概念混淆。

## 2. 必查项核对

### 2.1 `PaymentCheckoutSessionPersistenceService` — `discount_lines` / amount snapshot

**路径**：`app/code/Weline/Payment/Service/PaymentCheckoutSessionPersistenceService.php`

| 能力 | 现状 |
| --- | --- |
| 常量 | `CONTEXT_DISCOUNT_LINES = 'discount_lines'` |
| 写入 | `persistFromPaymentContext` → context snapshot + `setAmountSnapshot` |
| 归一化 | `normalizeDiscountLines`：优先 `orderData['discount_lines']`；否则用 `totals.discount_amount_minor` + `coupon_code` 合成单行 `{key,label,amount_minor}`（金额为负） |
| amount snapshot | `currency` / `subtotal_minor` / `shipping_amount_minor` / `tax_amount_minor` / `discount_amount_minor` / `grand_total_minor` / `discount_lines` |

**消费面**：`PaymentReturnPresentationService` 读 context / amount_snapshot / requestData 的 `discount_lines`，用于**回站展示**。

**缺口**：全仓仅 Payment 内读写 `discount_lines`；Checkout/Order 提交链路未见写入结构化多行；**未进入**任何 Provider `createOrder` / Checkout Session 请求体。

### 2.2 `DiscountActionSupportService` / `supported_discount_actions` / Marketing·Checkout 兼容

| 组件 | 路径 | 语义 |
| --- | --- | --- |
| DiscountActionSupportService | `Payment/Service/DiscountActionSupportService.php` | 从 Marketing `ActionCatalogInterface` 列举动作；按支付方式 allow-list 校验 |
| Provider capability | PayPal/Stripe/Fake `getCapabilities()['supported_discount_actions']` | 声明该方式**兼容哪些营销 Action code**（如 `discount_fixed_amount`） |
| PaymentMethod | `supportsDiscountAction()` | config 优先，否则回落 Provider；空 config + null provider = 全支持 |
| 结账闸门 | `CheckoutGroupSubmitService` → `Order\DiscountValidationService::validateDiscountForPayment` | 有折扣效果时校验 payment × action_payloads |

Marketing：`DiscountQuoteRequest` / Condition `PaymentMethod` 可带 `payment_method` 参与报价条件；**不是**「因选某支付方式而自动减免」的激励模型。

**概念冲突（严重）**：`supported_discount_actions` ≠ 支付方式活动/激励折扣。立项文案与能力字段同名风险高，规格必须拆开命名。

### 2.3 PayPal — `PayPalApiClient` / `PayPalProvider`

| API | 金额结构 |
| --- | --- |
| `createOrder` | `purchase_units[].amount = { currency_code, value }` **仅合计**；无 `breakdown` / `item_total` / `discount` / `shipping` / `tax_total` |
| `patchOrder` | replace 整段 `amount`（同样仅 value）；无 breakdown |
| Provider | `createPayment` 只传 `currency + amountMinor + referenceId + return/cancel` |

Capability 仅有 `supported_discount_actions`（营销兼容），无 `amount_breakdown` / `discount_passthrough` 类能力位。

### 2.4 Stripe 及其他 Provider

| Provider | 透传现状 |
| --- | --- |
| Stripe `createCheckoutSession` | 单条 `line_items[0]`，`unit_amount = amountMinor`（应付合计）；无 `discounts` / 多行明细 / coupon 对象 |
| Fake / COD 等 | 未见 line-items / discount passthrough |

**结论**：壳层统一把应付 minor 交给 Provider；**没有任何 Provider 接收 `discount_lines` 或 amount snapshot breakdown**。

### 2.5 后台支付方式配置 — fee / surcharge / discount

| 配置面 | 现状 |
| --- | --- |
| `paypal.phtml` / `stripe.phtml` | 启用、排序、图标、express、钱包开关等；**无** incentive / surcharge / fee 折扣字段 |
| `assets.phtml` | 信用/积分/W币 `allow_discount` + `max_discount_ratio`（资产角色，非支付方式激励） |
| COD | `CodFeeCalculator` 读 `PaymentMethod.config.fee` / `cod_fee` → **加价**手续费；结账经 `CheckoutCodFeeApplier` |

**缺口**：通用「支付方式激励折扣」SystemConfig schema **不存在**；唯一邻近的方式级金额调节是 COD fee（方向为加价，非减免）。

### 2.6 Ledger `discount`、asset discount quote、freeze quote enrich

| 层 | 需求文档 | 代码现状 |
| --- | --- | --- |
| Ledger 类型 | `需求.md` §4：`discount` / `surcharge` / `provider_fee` / `platform_fee` / … | `PaymentLedger` 仅 `payment` / `refund` / `adjustment` |
| Allocation role | 需求：应付 + surcharge − 折扣 | 常量已有 `ROLE_DISCOUNT` / `ROLE_SURCHARGE` / `ROLE_FEE`；surcharge 运行时未接线 |
| Asset quote | — | `AssetCheckoutDiscountQuote` + Event `Weline_Checkout::checkout::freeze_quote::enrich` / `asset_discount::apply`（B2B/资产额度，**非**支付方式激励） |

### 2.7 `需求.md` §5.2 surcharge 与 §24 定界

| 章节 | 内容 | 与本需求关系 |
| --- | --- | --- |
| §5.2 | 客户侧手续费/便利费/surcharge；入 session/intent；合规禁用；退款规则；前台明示 | **加价**方向；契约字段名 `surcharge` |
| §5.3 | available-methods 项含 `surcharge` | QueryProvider **当前 payload 未输出** `surcharge` / incentive |
| §13 | 「支付方式活动折扣独立建模」+ funding source（商家/Provider/平台/共同） | 与用户「选此可减」同域；**未实现** |
| §24 | 活动折扣叠加顺序矩阵未定；surcharge/fee/补贴税处理未定 | **阻塞对齐冻结**的关键待定界 |

**定界建议（给需求分析/顾问）**：

1. 激励折扣与 surcharge **反向分字段**（勿塞进同一 `surcharge`）。
2. 叠加矩阵至少覆盖：购物车/优惠券/资产折扣 × 支付方式激励 × Provider 补贴 × 税前税后。
3. funding source 与退款反向快照进 allocation/ledger 规格。

### 2.8 Checkout 支付方式列表 UI 数据契约

| 环节 | 现状 |
| --- | --- |
| `PaymentQueryProvider::paymentMethodPayload` | code/label/icon/guide/enabled/disabled_reason/dynamic_form/capabilities… **无** `surcharge`、**无** `incentive_discount` / `savings_minor` |
| `CheckoutHtmlRenderer::renderPaymentMethodOptions` | logo + title + description + 详情链；**无**「选此可减 ¥x」展示位 |
| `discount_preview` | 结账摘要侧**购物车/优惠券**预览，与方法列表无关 |

**缺口**：列表既无数据字段，也无 HTML 插槽；前端/主题席后续才需开工，须先冻 payload 契约。

## 3. 清单

### 3.1 可复用机制

1. **Session 金额快照骨架**：`discount_lines` + amount_snapshot 字段形状可扩展（增 `source`/`funding`/`method_code` 等），供展示与日后 Provider 映射。
2. **营销兼容闸门**：`DiscountActionSupportService` + Checkout submit 校验 — 激励折扣生效后仍需与现有优惠券/规则兼容矩阵协作。
3. **Event 旁路先例**：`freeze_quote::enrich` / `asset_discount::apply` — 跨模块贡献 quote 数据的正确范式（对齐扩展点选型：通知/旁路 → Event）。
4. **AvailabilityResult.FIELD_SURCHARGE**：可用性结果已预留（当前 Provider 未填；Query 未透出）— 可对称预留 `incentive_discount` 或统一 `price_adjustment`。
5. **Allocation ROLE_***：折扣/附加费角色常量可复用，避免再造平行模型。
6. **COD fee 配置模式**：`PaymentMethod.config` + Calculator — 激励折扣配置形态可参考（方向相反）。
7. **Marketing `payment_method` 条件**：规则引擎可把「仅某支付方式可享」作为 Condition；与「列表展示激励价」可组合，但展示价仍需 Payment 列表 enrich。

### 3.2 冲突

| ID | 冲突 | 影响 |
| --- | --- | --- |
| C1 | `supported_discount_actions` vs 支付方式激励折扣同名/近义 | 规格/能力位/后台文案易混；实现误改营销兼容 |
| C2 | §5.2 `surcharge`（加价）vs 激励（减免）共用可用性字段风险 | 前端/退款/对账符号与合规规则相反 |
| C3 | `discount_lines` 仅展示回站，Provider 只收净额 | 「必须传到支付商」与现 API 签名冲突 |
| C4 | 需求 Ledger 类型全集 vs 代码三类型 | 激励折扣入账无现成 `ledger_type=discount` |
| C5 | §24 叠加顺序未定 | 未冻结前施工会返工金额与透传 |
| C6 | Marketing 条件「指定支付方式」vs 列表「未选先展示可减」 | 报价时点：未选 method 时是否算激励、切换 method 是否重算 |

### 3.3 缺口

1. 支付方式激励折扣的**配置模型**（SystemConfig / method config / Marketing rule 归属）。
2. 列表 payload + HTML：**选此可减**展示位与 a11y。
3. Provider **amount breakdown / discounts** 透传（PayPal 优先；Stripe line items / discounts 次之）。
4. Checkout/Order → session 的**多行 discount_lines 生产者**（券 + 激励 + 资产）。
5. Ledger/allocation 写入激励折扣与 funding source。
6. 叠加矩阵、税、退款反向规则（§24）。
7. QueryProvider 对 `AvailabilityResult.surcharge`（及未来激励字段）的透出。

### 3.4 建议扩展点（按 `扩展点选型.md`）

决策顺序：归类 → 查索引 → 有则引用 → 无则 TaskContract 声明新建。

| 意图 | 优先机制 | 建议 | 禁止 |
| --- | --- | --- | --- |
| 结账列表旁路注入「可减金额」 | **Event** + Observer | 新建文档化事件，例如 `Weline_Payment::checkout::available_methods::enrich`（或 Checkout 侧等价 enrich），由 Payment/Marketing Observer 写入 `incentive_discount` | Checkout 直 new Marketing Service；改 core 模板硬算 |
| 读可用方式+激励价 | **QueryProvider** | 扩展 `PaymentQueryProvider::paymentMethodPayload` 契约字段 | 前端信任缓存跳过重算 |
| 激励折扣报价/应用（写业务状态） | 归属模块 **Interface/SPI** | `PaymentMethodIncentiveQuoteInterface`（类比 `AssetCheckoutDiscountQuote`）；Marketing 出规则、Payment 编排入 session/intent | 跨模块直调 Controller |
| Provider 是否支持明细透传 | **Provider capability** | 如 `amount_breakdown: true`、`discount_lines_passthrough: true`、`passthrough_formats: ['paypal_breakdown','stripe_line_items']` | 在壳里写死 PayPal JSON |
| 后台开关与额度 | **SystemConfig** 模板 | `payment/method/{code}/incentive_*` 或独立 group；复杂对象走 adapter | 手写等价配置表绕过 SystemConfig |
| 模板展示位 | **Hook** / checkout HTML 契约 | `renderPaymentMethodOptions` 增加可选 badge 插槽，数据来自 payload | 主题硬编码某 method 折扣 |

**SPI/Capability 草案（供架构冻结合约，非本席实现）**：

```text
capabilities.amount_breakdown: bool
capabilities.discount_passthrough: bool|enum
availability / method payload:
  incentive_discount?: {
    amount_minor: int,          # 减免（建议正数表示可减）
    currency_code: string,
    label: string,
    funding_source?: string,
    rule_code?: string,
    stack_policy_ref?: string
  }
  surcharge?: { ... }           # 保持 §5.2 加价语义，勿混用
```

### 3.5 风险

1. **金额不一致**：店面展示可减额 ≠ Provider breakdown 合计 ≠ ledger — 必须单一快照源（建议 checkout session amount_snapshot）。
2. **PayPal 校验**：breakdown 各分项之和必须等于 `value`；漏传税运费会导致 create/patch 失败。
3. **切换支付方式**：激励切换导致应付变化，须重算 Marketing quote + 失效旧 intent/attempt。
4. **合规**：部分地区对「支付方式折扣/附加费」限制；与 §5.2 区域规则表同源治理。
5. **双重优惠**：激励 + 券 + 资产 + Provider 补贴无矩阵时可能超扣。
6. **退款**：激励 funding source 未快照则无法按原分摊退。
7. **命名污染**：误改 `supported_discount_actions` 会破坏现有结账兼容闸门。
