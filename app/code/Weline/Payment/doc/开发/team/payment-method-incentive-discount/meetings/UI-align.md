## stance

**同意冻结**（附视觉硬约束；非否决）。

结账「选此减 X」可作为激励徽章进入主路径信息架构，前提是：**奖励感从属于应付真相**，不得用划线价/对比价制造「其它方式更贵」的虚假原价叙事。

---

## 1. 信息层级（硬）

| 层级 | 表面 | 角色 | 规则 |
|------|------|------|------|
| L0 | 订单应付总额（摘要底部） | **唯一价格真相** | 字号/字重最高；切换支付方式时即时更新；禁止激励徽章压过应付 |
| L1 | 支付方式名 + 图标 | 选择主标识 | 与现有结账列表一致；激励不得抢占名称位 |
| L2 | 「选此减 ¥X」/「减 X%（约 ¥Y）」 | **激励提示** | 行内次级；未选中亦可见「可选减」；选中后可略加强（字重/主题强调色），仍低于 L0 |
| L3 | 订单摘要「支付方式优惠 −¥X」 | 审计分列行 | 与「优惠券 −¥Z」同级分列；禁止合并模糊「优惠」；金额 = 列表「减 X」= 最终扣减 |
| L4 | 不可用 / 未配置 | 诚实空态 | 不可用方式：不展示可点「可减」；未配激励：无徽章（非「减 0」） |

**交互层级**

- 选中态：强化「本行已计入」反馈（边框/勾选/摘要行出现），**禁止**整行变成促销海报或大面积色块盖住方式名。
- 切换方式：摘要与应付同步；禁止先闪高价再降价的闪烁误导序列。
- 百分比：主文案「减 X%」+ 次文案「约 ¥Y」；「约」仅允许舍入显示差，数值仍须与可兑现扣减一致（规格 US-1.7）。

---

## 2. 对比度与可读性（硬）

1. **激励文案 vs 背景**：正文对比须满足 WCAG AA（正常字 ≥ 4.5:1）；禁止用浅灰/低对比把「减 X」做成几乎看不见的小字，也禁止用高饱和霓虹色把激励做成比应付更抢眼的 CTA。
2. **选中 vs 未选中**：对比靠结构（边框/勾选/摘要行），不靠「未选行划线价 vs 选中行促销价」二元对比。
3. **强调色**：仅主题 Token 语义色（如 success/accent）；本席不定色板；禁止硬编码促销红/绿字面色散落（主题席落地）。
4. **图标旁文字**：徽章不得遮挡 logo/方式名点击热区；移动端触控目标保持列表行可用高度。

---

## 3. 禁止误导划线价（硬 · 对齐顾问合规红线）

**本 feature 视觉叙事 =「选用可再减」奖励，≠「原价 vs 折扣价」促销对比。**

| 禁止 | 说明 |
|------|------|
| ❌ 行内划线「原价」 | 禁止在支付方式行展示划掉的应付/商品合计，再并排「激励价」 |
| ❌ 把无激励方式标成「原价」 | 禁止暗示其它方式的应付是「标价/市场价」 |
| ❌ 全站抬价 + 仅某方式打折的视觉伪装 | 顾问 CN/GB 红线；UI 不得用删除线补强该叙事 |
| ❌ 「最高减 / 低至」不可兑现文案样式 | 即使文案层拦截，UI 也不得预留划线+大折扣模板位 |
| ❌ 「用卡多付 / 其它方式更贵」贬损对比 | 禁止相对价差条、涨价箭头、红色「+¥」对非激励方式 |
| ❌ 摘要双应付（划线总额 + 激励总额） | 摘要只展示**一个**当前应付；减免以独立负向行呈现 |

**允许的减法视觉**

- ✅ 摘要行前缀「−」或主题约定的减免符号 + 金额（与优惠券行同构）。
- ✅ 列表徽章「减 ¥X」「选此再减」——正向奖励语气（翻译工程师定串；本席不定措辞细节）。
- ✅ 选中后 L0 应付数字更新（无划线过渡动画伪装降价）。

## 5. 冻结给 contracts 的 UI 门禁（建议原文写入）

1. 结账激励展示须遵守本纪要 **L0–L4 层级**；应付为唯一价格真相。
2. **禁止任何划线价 / 伪原价对比**用于支付方式激励；减免仅允许「减 X」徽章 + 摘要负向行。
3. 「减 X」展示值 = 可兑现最终扣减 = 摘要行 = 网关应付差（金额恒等由支付席保证；UI 不得展示第二套金额）。
4. 对比度 AA；激励视觉权重 **严格低于** 应付总额。
5. 可见串走翻译工程师；本席不锁中英以外措辞。
