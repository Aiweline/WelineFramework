## 1. 结论（一句话）

本 feature 的跨模块边界须按「旁路 Event · 读 QueryProvider · 写归属 SPI/Interface · Provider capability · SystemConfig · 模板 Hook/payload」落点；**否决一切跨模块直调**（`new` 对方 Service、依赖对方 Model、直调 Controller）。激励能力位**禁止**复用 `supported_discount_actions`。

### 2.1 决策顺序核对

```text

2. 查索引：Event 范式有；QueryProvider 有；incentive SPI / enrich 事件 / capability keys 无
3. 有 → 引用既有路径；无 → 本纪要声明「新建扩展点」+ 须补模块 doc（禁发明未文档化事件名即施工）

```

## 3. 契约草案（供 contracts / surfaces；非 PHP）

### 3.1 Payload / Availability（读面）

```text
method payload / availability（与 §5.2 surcharge 反向分字段）:
  incentive_discount?: {
    amount_minor: int,       # 可减额（建议正数表示减免）；展示「减 X」须=可兑现扣减
    currency_code: string,
    label: string,           # 可见串 → 翻译工程师
    funding_source?: string,
    rule_code?: string,
    stack_policy_ref?: string
  }
  surcharge?: { ... }        # 仅保留加价语义；本 feature 主路径禁止使用
```

正式字段名（`incentive_discount` vs `savings_minor` 等）→ **架构对齐冻结钉死**；机制类别不变。

### 3.2 Provider capability（Provider 面）

```text
capabilities.amount_breakdown: bool
capabilities.discount_passthrough: bool | enum
capabilities.passthrough_formats?: ['paypal_breakdown', ...]
# 禁止用 supported_discount_actions 表达 method incentive
```

### 3.3 SPI（写面）

```text
PaymentMethodIncentiveQuoteInterface（归属 Weline_Payment）
  - 输入：结账上下文 + method_code + 既有折扣后基数
  - 输出：incentive 行（可入 discount_lines）或 0
  - 调用方：Payment 编排；他模块经 Interface，禁止 new 实现类旁路
```

### 3.4 Event（旁路面）

| 草案名 | 用途 | 文档义务 |
|--------|------|----------|
| `Weline_Payment::checkout::available_methods::enrich`（或 Checkout 等价） | 列表项注入激励字段 | 新建 `Payment/doc/event/...`；注册 `event.xml` 后源码核对 |
| 既有 `Weline_Checkout::checkout::freeze_quote::enrich` | 快照旁路贡献（对齐资产折扣范式） | 复用；激励 Observer 挂载须文档化 |

**冻结前**：架构选定正式事件名；扩展点机制类别已冻，名称不得借机改成跨模块直调。

### 3.5 SystemConfig / discount_lines

- 配置：Website→Store；`method_code` 绑定；未配=0；funding / 开关 / 有效期见规格 §5。
- `discount_lines` 行：`source_type=payment_method_incentive` 与 `coupon`/`cart`/`shipping` 分列；可选 `funding_source`、`method_code`。

## 4. 硬否决（跨模块直调 + 命名污染）

| ID | 否决项 | 依据 |
|----|--------|------|
| X1 | 跨模块 `new` / 直依赖对方 **Service**（Checkout↔Payment↔Marketing） | 《扩展点选型》通知行 |
| X2 | 跨模块依赖对方 **Model** 读写激励/券/session | 选型「读→Query/Interface」 |
| X3 | 跨模块直调 **Controller** 写激励状态 | 选型「写→归属 Interface/Hook/Queue」 |
| X4 | 壳层写死某网关 JSON / 无 capability 伪造 breakdown | Provider capability 行 |
| X5 | 用 `supported_discount_actions` 表达支付方式激励 | 探查 C1；规格 Q5 |
| X6 | 激励与 `surcharge` 共用字段或主路径做加价叙事 | 顾问约束 1；探查 C2 |
| X7 | 平行计价引擎绕过 Payable / checkout_session 快照 | 规格非目标 |
| X8 | 发明未文档化事件名即施工 | 选型决策顺序第 4 步 |

## 5. 与顾问 / 规格对齐

| 顾问约束 | 扩展点落点 |
|----------|------------|
| 禁 surcharge 主路径 | E7/payload 反向分字段；X6 |
| 「减 X」可兑现且站内=网关 | E2+E9 单一 `discount_lines`/amount_snapshot 真相源 |
| 叠加矩阵 | 非扩展点机制；写入 contracts 业务规则；SPI 报价遵守矩阵顺序 |
| 首期 PayPal + fake；其它默认 0 | E5 capability 门禁 + E6 未配=0 |
| 可见串翻译工程师 | E7 label/文案；机制不替代翻译闭环 |

## 6. 开放点（不改机制类别）

1. 正式 Event 名与归属模块（Payment vs Checkout dispatch）。
2. payload 字段正式命名。
3. PayPal 多行 discount 映射粒度（金额守恒硬）。
4. Ledger `discount` 类型是否本波补齐（架构+支付；非机制选型否决项）。
