| 项 | 冻结内容 |

## 2. 现状锚点（证据）

| 事实 | 位置 |
|---|---|
| Checkout 非目标：不内嵌 PayPal SDK | `Weline_Checkout/doc/需求.md` → `REQ-CHECKOUT-0004` |
| 结账快捷槽只发现/派发，Payment 部件渲染 | `checkout-express-payment.phtml`；`payment-shell.md` §6.1 |
| 标准结账模板仅 redirect CTA，无 SDK | `Payment/view/templates/Frontend/checkout/paypal.phtml` |
| 后台配置无 Google/Apple 开关 | `extends/.../Config/backend/paypal.phtml` |

| CSP 已预留 SDK/frame/connect 主机 | `PayPalProvider::cspDirectives()`（含 `www.paypal.com` / sandbox / `paypalobjects.com`） |

**需求纠偏（轻）**：产品侧「结账出现 Google/Apple Pay」≠「Checkout 模块加载 SDK」。权威边界是 **Payment 呈现层** 加载；Checkout 继续只声明槽位 / 方法选择，与 `REQ-CHECKOUT-0004` 一致。

**耦合提示**：无新增 Checkout↔PayPal 硬编码耦合；禁止在 Checkout 模板或 Checkout 静态资源中引用 PayPal SDK。

## 3. 配置契约（问题 1）

### 3.1 键名 / 默认 / scope

| key | label（建议） | type | value-type | default | scope |
|---|---|---|---|---|---|
| `payment/method/paypal/google_pay_enabled` | 启用 Google Pay（PayPal） | switch | bool | **`1`** | **`global,website,store`** |
| `payment/method/paypal/apple_pay_enabled` | 启用 Apple Pay（PayPal） | switch | bool | **`1`** | **`global,website,store`** |

与现有 PayPal 方式字段一致（同 `enabled` / `express_enabled` 等）。

### 3.2 落盘与归一化（实施契约，本会只冻结）

- 后台：`paypal.phtml` 新 group 或挂在 `paypal_runtime`（建议紧挨 `express_enabled`）。
- `PaymentScopeConfigService::normalizeConfigValue`：将 `google_pay_enabled`、`apple_pay_enabled` 纳入既有 bool 键列表（与 `express_enabled` 同类）。
- 缺省语义：配置缺失时视为 **开启**（与 `express_enabled` 缺省 true 对齐）；模板 default=`1` 保证新建 scope 可见为开。
- 读配置：Payment 侧 view-model / SDK URL 构建器只读方式级 config map，不读 Checkout。

### 3.3 非目标配置

- 不新增壳级 `payment/general/google_pay_*`（本议题仅 PayPal funding）。
- 不新增 Stripe / 其它网关钱包开关。
- 不把 Google/Apple 拆成独立 `method_code`（仍挂在 `paypal` 方式下，由 SDK funding 呈现）。

## 4. SDK 加载边界（问题 2）

### 4.1 硬边界

```
Checkout 模块          Payment 模块
─────────────          ────────────────────────────
槽位 / 方法选择   →    checkout/paypal.phtml（方法模板）
express 槽发现    →    checkout-express-payment 部件（可扩展容器）
禁止 sdk 脚本     →    唯一允许加载 https://www.paypal.com/sdk/js?...
```

### 4.2 推荐加载点（Phase 1）

1. **主路径**：扩展 `Weline_Payment` 的 `checkout_template_code=paypal` 模板（`Frontend/checkout/paypal.phtml`）。
   - 仅在支付方式呈现为 PayPal 时由壳渲染该方法模板 → SDK 生命周期跟「选中 PayPal」绑定。
   - 模板内：`#paypal-button-container`（或等价）+ 可选保留现有 redirect CTA 作降级。
2. **可选辅路径**：若 express 槽也要露出 Google/Apple 按钮，仅允许在 **Payment 部件**（`checkout-express-payment` / 新 Payment 子 partial）加载同一 SDK URL 构建器；**禁止** Checkout layout/phtml 直引脚本。
3. 脚本策略：优先 `data-weline-load` 注册 Payment 自有小模块（如 `paypalButtons`），由该模块动态注入 `<script src="…paypal.com/sdk/js…">`；禁止 Checkout 的 `welineModules` 登记 PayPal SDK。

### 4.3 CSP

沿用 `PayPalProvider::cspDirectives()`；Phase 1 **不扩域**（现有 script/frame/connect 已覆盖 SDK）。若实测缺 `pay.google.com` / Apple Pay 相关 frame，再单开「CSP 增补」子任务，不阻塞配置契约冻结。

## 5. enable-funding / disable-funding（问题 3）

### 5.1 驱动规则（冻结）

服务端根据两开关生成 SDK query（funding token 官方小写）：

| google_pay_enabled | apple_pay_enabled | enable-funding | disable-funding |
|---|---|---|---|
| 1 | 1 | `googlepay,applepay`（可与其它已启用 funding 合并） | **不含** googlepay/applepay |
| 1 | 0 | `googlepay` | `applepay` |
| 0 | 1 | `applepay` | `googlepay` |
| 0 | 0 | （不强制 enable 二者） | `googlepay,applepay` |

补充约定：

- **显式 disable**：关闭时必须写入 `disable-funding`，避免 SDK 默认仍展示钱包按钮。
- **显式 enable**：开启时写入 `enable-funding`，提高在支持环境展示概率（官方推荐对可选 funding 使用 enable）。
- 其它 funding（如 `venmo` / `paylater`）本议题 **不改**；构建器只追加/剥离 googlepay、applepay，不重置整串。
- client-id / currency / intent 等仍由现有环境凭据与订单上下文决定；本契约只冻结 funding 两维。

### 5.2 单一构建器

建议新增 Payment 内纯函数/小服务（命名示例，实施可微调）：

`PayPalJsSdkUrlBuilder::build(array $config, array $context): string`

- 输入：runtime config（含两开关 + client_id + environment）
- 输出：完整 SDK URL（含 `enable-funding` / `disable-funding`）
- UT 直接断言 query 组合（见 §7）

前端 **禁止** 自行拼 funding 字符串；只消费服务端下发的 `data-paypal-sdk-src`（或等价）。

## 6. 与 redirect 主链并存（问题 4）

### 6.1 原则：最小侵入、主链不换轨

| 路径 | Phase 1 | Phase 2（超出则拆） |
|---|---|---|
| 经典 PayPal（账号/卡，redirect） | **保持**：`createPayment` → Orders v2 → `approve_url` redirect；模板可继续展示「Continue to PayPal」 | 不变或可选弱化 CTA |
| Google/Apple（JS Buttons + funding） | **配置契约 + SDK URL + Buttons 容器挂载**；`createOrder` 回调优先复用壳已有「创建支付 / 取 approve」API | 完整 `onApprove` → capture / 回跳与 redirect 同终态；必要时 Orders `payment_source` |
| Express 快捷（现有 redirect） | **不改** `express_modes=['redirect']`；不因本议题改成 JS-only | 若产品要求 express 槽也出钱包按钮，另开需求 |

### 6.2 Phase 1 交付边界（冻结）

**必做：**

1. 后台两开关 + 契约 UT（模板键名/default/scope）。
2. `PayPalJsSdkUrlBuilder`（或等价）+ funding 真值表 UT。
3. Payment `paypal.phtml`（方法模板）可输出：SDK src 数据属性、Buttons 容器、开关态；**不**要求本阶段钱包实付全绿。
4. redirect CTA 与 Buttons **可同屏并存**；关闭两开关时不得加载钱包 funding（disable），可不加载 SDK（实现可选：两关且无其它 JS 需求则跳过注入）。

**明确不做（Phase 2）：**

- Orders v2 请求体写入 `payment_source.google_pay` / `apple_pay`。
- Apple Pay 商户域关联 / `.well-known` 文件全链路生产验收。
- 将 `express_next_action` 从 redirect 改为 `js_sdk`。
- Stripe Payment Request / Google Pay / Apple Pay。
- Checkout 模块内任何 PayPal SDK 引用。

### 6.3 若 Phase 1 实装 Buttons 的 createOrder

允许最小桥接：Buttons `createOrder` → 既有 Payment/Checkout 支付创建接口 → 返回 PayPal `order_id`（token）；**失败则回落 redirect CTA**，不阻断主链。完整 `onApprove`/`confirmOrder` 若工作量超本迭代，记入 Phase 2，**不阻塞本方案冻结**。

## 7. 测试策略（问题 5）

### 7.1 UT 契约（必做、可 CI）

| 用例 | 断言 |
|---|---|
| `PayPalConfigTemplateContractTest` 扩展 | 模板含两 key、`default="1"`、`scope="global,website,store"`、switch/bool |
| 新建 `PayPalJsSdkFundingContractTest`（名可微调） | 四象限 enable/disable query；关闭必须出现对应 `disable-funding`；开启不得误 disable |
| bool 归一化（可选同测） | `PaymentScopeConfigService` 对两 key 的 `0/1/"false"` 归一 |
| 负向 | Checkout 模块源码契约：**不出现** `paypal.com/sdk`（可用轻量 grep 契约测挂在 Checkout 或跨模块） |

### 7.2 Sandbox / e2e 边界

| 层级 | 可执行内容 | 边界说明 |
|---|---|---|
| 浏览器契约 / e2e（本机） | 打开结账选 PayPal：容器存在；`data-paypal-sdk-src`（或 script src）含预期 funding；关开关后 src 含 disable | **不**强制真实 Google/Apple 钱包扣款 |
| Google Pay 实付 | 需 Chrome + 测试卡 + PayPal sandbox buyer 能力 | 记入手动/可选 sandbox checklist；非 CI 门禁 |
| Apple Pay 实付 | 需 Safari + 域校验 + 设备 | 同上；生产域校验属 Phase 2 |
| 既有 redirect e2e | 保持现有 PayPal sandbox approve 闭环绿 | Phase 1 回归门禁：redirect **不得**因加开关而红 |

### 7.3 验收口径（Phase 1）

- 配置页可见两开关，默认开。
- 关 Google → SDK URL `disable-funding` 含 `googlepay`；Apple 同理。
- Checkout 仓库路径无 SDK 引用。
- redirect 主链 e2e / 既有 UT 仍 PASS。

## 8. 架构矛盾与停工选项（问题 6）

### 8.1 已审查矛盾

| 候选矛盾 | 裁决 |
|---|---|
| Checkout「禁止内嵌 SDK」vs「要出 Google/Apple 按钮」 | **假矛盾**：SDK 归属 Payment 方法模板/部件即可 |
| redirect 主链 vs Buttons | **可并存**：Phase 分层，主链不换轨 |
| 无 `payment_source` vs 钱包 | **不阻塞 Phase 1**；完整 wallet 收单进 Phase 2 |
| Stripe 也无钱包 | **非矛盾**：本议题仅 PayPal funding |

### 8.2 停工选项（本会不启用）

仅当出现以下情况才停工并 escalate：

1. 产品强制要求 **Checkout 模块源码** 内嵌 `paypal.com/sdk`（直接违反 `REQ-CHECKOUT-0004`）。
2. 产品强制 Phase 1 必须完成 Apple 生产域校验 + 实付 e2e 绿，且排期不允许拆 Phase。
3. 要求把 Google/Apple 做成独立支付方式并改壳编排（超出 funding 控制）。

当前输入 **不满足** 停工条件 → **推荐方案可冻结**。
