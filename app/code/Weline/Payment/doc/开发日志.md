## 2026-09-25 — 指南 hub「不启用即隐藏」：可用性门闩下沉 Provider 层

- 背景：生产站关闭 `fake_card` 后，`/guide/payment` 仍列出「Local Test Payment」（除 FPC 1800s 缓存外，主因是指南注册表从不问 Provider）。
- 根因：`PaymentCustomerGuideRegistry::getEntries()` 只按「扩展文件存在 + 源模块启用 + 非 sticker」筛选，**完全不感知**支付方式可用性；`PaymentCustomerGuideInterface` 也没有任何可用性成员。指南 hub 因此无法表达「不启用就隐藏」。
- 修（门闩唯一在 Provider 层）：
  - `Service/PaymentMethodManager::getStorefrontAvailableMethodCodes()` 新增：与结账列表**同口径**（`isMethodActiveForScope()`：`enabled` + 测连通过），返回 `[method_code => true]`。店面各表面据此判定，禁止各处自建可用性规则。
  - `Service/PaymentCustomerGuideRegistry::listStorefrontPublishedEntries($forceReload, $context, $alwaysIncludeMethodCode)` 新增：只过滤**列表**；可用性不可判定（解析器返回 null / 异常）时**不过滤**，避免把 hub 变成空页（fail-open）。构造函数新增第三个可选 `$availableCodesResolver`（与既有 `$urlBuilder` 同风格的测试缝）。
  - `Controller/Frontend/Guide/Payment.php` — `index()` 改用 `listStorefrontPublishedEntries()`；详情页侧边导航同样过滤，但传 `alwaysIncludeMethodCode` 保留当前页。
- **关键不变式**：`getEntry()` 保持**不过滤** —— 供应商登记的 agreement URL 是法律链接（如 PayPal Developer 的 User agreement URL），必须始终可达，不得 404。
- 契约：新增 `Test/Unit/Service/PaymentCustomerGuideStorefrontFilterTest.php`（6 用例：不可用即隐藏／当前页保留／不可判定不过滤／详情仍可解析／hub 用过滤列表／门闩归 Provider 层）。
- 真机数据核验（本机 DB + 真实门闩，非注入桩）：`available_codes=["fake_card","paypal"]`、`guide_all=["paypal","stripe","fake_card"]`、`guide_visible=["paypal","fake_card"]`（`stripe` 因未启用被隐藏）、`getEntry('fake_card')` 仍可解析。
- 真实浏览器验收（WB）：新增 `Test/e2e/frontend/payment-guide-storefront-availability.spec.js`（3 用例，Chromium 全绿）——
  hub 侧栏/卡片不含未启用方式；未启用方式的详情页仍 HTTP 200 且侧栏保留其自身（含 policy/agreement 子链）；侧栏每个方式链接均可打开（无死链）。
  截图证据：`doc/evidence/ch1/guide-hub-sidebar.png`、`doc/evidence/ch1/guide-disabled-detail.png`（hub 显示「2 payment provider(s)」，Stripe 卡片与导航项均不出现）。
  注：本用例用显式 `WELINE_E2E_BASE_URL`（默认 `https://p05113ef3.test.weline.com:9555`）直连，不走 e2e DIRECT 模式的 `127.0.0.1` 目标源——后者因服务端要求 SNI 会 TLS reset。
- 未 bump 版本（无 Model/路由变更）。
- 部署提醒：指南页 `@Extra type=fpc ttl=1800`，上生产后须清 `/guide/payment` 的 FPC 缓存才见效。
