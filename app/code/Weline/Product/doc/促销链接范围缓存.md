# 促销链接范围缓存

## 2026-09-13：共享原始路由，公开结果按当前上下文生成 URL

实际双实例验收发现：同一站店渠在 19655 生成的商品促销地址被 9555 复用。模板编译目录已经分离，首页仍有两处 `promotion/weekend` 链接使用旧端口。源头是 `buildPublishedOffers()` 在范围缓存 loader 内把 PriceView 的绝对 `campaign_url` 写入商品行；该缓存按站店渠、语言、货币共享，因此不能保存生成请求的 origin。

`StorefrontPriceAdjustment` 末尾增加默认空的 `frontendRoute`，仅表示内部前台路由，不参与价格、排序、叠加或促销选择。Promotion 通过唯一的 `PromotionActivityThemeService::storefrontPath()` 提供 `promotion[/slug]`；原 `storefrontUrl()` 也复用此路径生成绝对地址。

Assembler 携带该路由。Catalog 缓存行对内部链接保留 `_campaign_frontend_route`，对应 `campaign_url` 为空；候选促销同样保留 `frontend_route`，不存请求 origin。没有内部路由的 provider 显式 URL 原样保存，外链不按 host 或端口替换。

列表、摘要、按 ID 查询和详情返回口通过现有 `Url::getFrontendUrl()` 生成当前请求地址，并移除内部路由字段，公开 `campaign_url` 和候选 `url` 保持绝对地址语义。重复路由复用 `StorefrontScopeHotCache::rememberForRequest()`；范围 L1/L2 只保留原始行，公开结果的数组修改不回写共享缓存。

旧绝对地址 payload 自然退出：listing 的详细/其他投影从 v4/v3 升至 v5/v4，summary 从 v2 升至 v3，targeted 的详细/摘要从 v2/v1 升至 v3/v2。沿用原 catalog/price/config/i18n changed 依赖及 TTL，不新增私有缓存、整库 origin 副本或全局清理。

定向验证使用真实 Assembler、Catalog 方法、ScopeHotCache、CachePool、Context 和 URL 生成；只有存储适配器、代次权威与锁使用内存 fixture。覆盖内部原始路由、外链保留、金额不变、三个缓存入口跨请求/模拟 peer L2 复用、重复路由仅生成一次和旧 key 迁移。命令：`vendor/bin/phpunit --bootstrap app/bootstrap_phpunit.php --colors=never app/code/Weline/Product/test/Unit/StorefrontCampaignRouteCacheTest.php`。

开发验证不替代整页验收：主任务统一编译/重载后以 19655→9555 交错访问核对两处实际促销链接及性能。

## 实际验收结果（2026-09-13）

源码经正常 framework:compile 和两个实例 managed reload 加载；旧输出仅沿现有 theme 精确叶子 81→82 失效，父代次未变。同一 H2/同 worker 的 19655→9555→19655 每页 186 个同站链接全部正确，默认另一 worker 也为 0/0/0 错误；HTML/footer 完整。浏览器禁缓存的首页、英文筛选、第二页及详情页实际通过来源与页脚检查，既有 category-menu 重复 ID 警告仍保留。本批定向 PHPUnit 合计 22 tests/182 assertions 通过。英文 MISS 2.296s/HIT 58–51ms，不能视为冷启动达到 70ms。
