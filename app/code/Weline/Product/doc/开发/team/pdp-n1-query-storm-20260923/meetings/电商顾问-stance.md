## Stance（运营 / 领域）

1. **PDP 首屏主职是当前 SKU 决策**（主图、标题、价、规格、加购/购买）。推荐货架、最近浏览、交叉销售是**辅转化位**，默认可低于折线 / 非阻塞，**不得**与主职抢同一次同步全量解析的优先级。
2. **同屏同步全量不算硬需求**。运营可接受：辅货架首屏占位（骨架或「加载中」静默区）→ 视口邻近或主内容就绪后再出真卡；空态短文案优于拖死整页。禁止把「首字节就出满货架」写成默认成功标准。
3. **体验上限（产品边界，非施工单）**：猜你喜欢 / 相关推荐建议 **≤8 卡**（优先 4～6）；最近浏览 **≤6**；交叉销售 / 经常一起买 **≤4 组或卡**。多卡≠更高转化；卡多而首屏卡顿会伤购买意愿。
4. **运营验收底线**：主路径（主图+购买区）可读可点、辅货架最终内容真实（非假价/假图/错语种）、延迟加载不得误导为「无推荐」永久空。壳层目录/搜索下拉属全局导航能力，**不得**拖慢当前商品决策区到「像坏站」——体验上应与 PDP 主职解耦感知。
5. **领域纠偏**：用户认定数百 span「不正常」——顾问同意：辅货架与导航不应表现为「详情页一打开就全店重算」。优化目标是**可售体验**（快、稳、可信），不是拆掉必装商机位；删/藏货架须先过本席运营验收，默认路径是**降同步成本 + 控 N + 可延迟**，而非砍转化位。
