# Hanfu Content and Visual Remediation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver release-ready bilingual Hanfu editorial, category, homepage and product content with FileManager-native assets and safe removal of replaced files.

**Architecture:** Existing public services remain the only mutation boundary. A reviewed manifest describes every asset and locale; FileManager imports it first, then Blog/Product/Theme migration scripts consume returned public paths. Content cleanup is deterministic and idempotent, and deletion runs only after a four-surface zero-reference audit.

**Tech Stack:** PHP 8.x, Weline ObjectManager/services, FileAssetLibraryInterface, EAV attribute repositories, Theme widgets, ImageGen, WebP/JPEG media, PHPUnit/Pest, WLS Browser.

**Spec:** `docs/superpowers/specs/2026-09-01-hanfu-content-visual-remediation-design.md`

## Global Constraints

- Branch must remain `dev`; preserve unrelated dirty workspace changes.
- New/replacement images are uploaded only through `FileAssetLibraryInterface`.
- Every asset requires reviewed/manual `zh_Hans_CN` and `en_US` metadata.
- Do not publish license-unclear external media or invented product/history claims.
- Generated/category imagery must pass the form-review rubric in the spec.
- UI must use Weline Theme tokens and pass 375/768/1024 responsive acceptance.
- Delete only exact zero-reference old files.
