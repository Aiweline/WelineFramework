# 万能产品 v1.0 完善计划

> 版本：v1.0
> 状态：IMPLEMENTING（只有 M6 五类产品与跨站真实验收全部通过后才能改为 ACCEPTED）
> 权威范围：Weline_Product 产品领域、后台运营面、跨 Website 目录能力和 Commerce 消费链
> 最后更新：2026-08-26

## 一、目标与确认结论

最终完成标准：任意 Website 的运营人员都能独立完成产品新建、编辑、校验、发布、下架、复制和归档；普通实体、多规格、虚拟/服务、下载、组合五类产品全部贯通后台、前台、Search、Cart、库存/配送及订单相关流程。

确认的领域规则：

- `Product` 是商品主体，具有系统自动生成的总货号；一个 Product 包含一个或多个 `Offer`。
- `Offer` 是可购买规格，每个 Offer 拥有全局唯一 SKU；简单商品自动创建一个默认 Offer。
- 每个 Website 都可创建产品，产品归属首次创建它的 Website。
- Website 保存目录和经营事实；Store 默认继承并可覆盖；Channel 只消费投影。
- 新建或复制时默认选中目标 Website 下全部活动 Store，允许取消个别 Store。
- 默认主站商品可被获授权子站复制；其他站自建商品默认私有，可显式分享。
- 跨 Website 复制保留同一全局身份，但目标站数据独立，不自动同步；后续通过预览手动更新。
- SKU、类型、规格结构仅归属站可改；复制站可改名称、普通属性、分类、媒体、价格、库存和 Store 可见性。
- Eav 管属性定义、类型、选项、属性集和分组；Product 管具体商品/规格的属性值与编辑体验。
- Product 只管理 Website/Store/币种基础价；促销、会员价、阶梯价和订阅价走扩展能力。
- 不完整数据可保存草稿；发布按 Provider 规则校验。零库存可发布但不可购买。
- 生命周期为 `draft → published ↔ disabled → archived`；运营端不物理删除，SKU 和别名永久保留。
- 类型仅在未发布、未复制、无订单引用的草稿阶段允许转换。
- 归属允许“原站发起、目标站确认”的审计转让。

## 二、领域模型、数据迁移与公共契约

### 2.1 身份与聚合

- 新增独立的全局 Product 身份注册表，保存 `global_product_uuid`、自动总货号、归属 Website、Provider/type、状态、版本和分享策略。
- 新增 Offer/SKU 身份注册表，保存 `global_offer_uuid`、所属 Product UUID、全局唯一 SKU、状态、版本和 SKU 别名，实现真正的 Product 1:N Offer。
- 保留现有 `SkuRegistry`、UUID 和别名作为兼容数据，不直接破坏其 1:1 约束；V2 完成迁移后停止旧表新写。
- Website 分片继续保存本地 Product/Offer 投影、生命周期、价格、属性、分类、媒体和 Store 选择；全局身份与 Website 经营数据不得混为一个事实源。
- 全局结构变更由归属站完成；复制站只实例化所选 Offer 的本地投影。SKU 重命名保留旧别名并通过全局身份生效。

V2 全局表：

| 表 | 事实 |
|---|---|
| `weline_product_identity_v2` | Product UUID、总货号、owner、Provider/type、生命周期、版本、分享策略 |
| `weline_offer_identity_v2` | Offer UUID、Product UUID、唯一 SKU、状态、版本 |
| `weline_offer_sku_alias_v2` | 永久 SKU 别名保留 |
| `weline_product_share_grant` | 非默认分享授权 |
| `weline_product_ownership_transfer` | 双方确认归属转让 |
| `weline_product_audit_log` | 稳定动作码、版本和脱敏载荷 |
| `weline_product_migration_conflict` | 迁移人工冲突清单 |

### 2.2 EAV、分类和媒体

- Eav 发布只读属性元数据目录接口，Product 根据属性集、分组、类型、选项和 Provider schema 生成编辑器。
- 实现边界：Eav 的 `AttributeMetadataCatalogInterface` 只返回不可变定义 DTO；Product 的 `ProductAttributeMetadataCatalog` 负责 `value_type`、选项校验、`explicit/cleared/inherit` 和未知迁移行保留，具体值只写 Product shard。
- Product shard 的 AttributeValue 成为商品值唯一事实源，支持字符串、数字、布尔、日期、单选、多选等类型，同时保留 Website/Store/locale、`explicit/cleared/inherit`。
- 现有 Eav 动态 Product 值只作为迁移输入；相同值合并、Eav-only 值导入 Product shard、冲突进入人工清单，禁止双写。
- 分类和媒体以 Website 数据为默认；Store 覆盖仅保存加入/排除、隐藏、排序、主图角色等差异，删除覆盖即恢复继承。
- 媒体改用 FileManager/Storage 的安全资产引用；保留旧 path/blob 兼容迁移。下载文件使用私有资产及独立访问策略，不能混入公开商品图片。

### 2.3 公共接口

- `ProductProviderV2Interface` 和不可变 `ProductTypeDefinition` 声明 Offer 基数、表单 schema、必填属性、发布规则及定价、库存、配送、数字交付、组合、渲染能力；V1 Provider 通过适配器继续工作。
- 分离 `ProductIdentityV2` / `OfferIdentityV2` 与 V2 resolver；现有 `ProductIdentityResolverInterface` 保持兼容读取。
- `ProductAdminCommandInterface` 统一承载 create/save/validate/publish/disable/archive/changeType/share/transfer，使用 request hash、版本和稳定错误码。
- `ProductAdminReadInterface` 一次聚合返回商品、Offer、属性、价格、分类、媒体、Store 覆盖、Provider schema、归属和发布诊断。
- 后台浏览器统一通过受 ACL/CSRF 保护的 `product_admin` Resource/QueryProvider 调用；Controller 只负责页面和 HTTP 映射。
- 创建、编辑和发布必须在同一 Website 连接上的业务事务内完成；失败不得留下孤立身份、Offer、价格、媒体或 Store 选择。

扩展点选择已经固定：

- Product 内部写入：Product-owned command interface。
- 跨模块读取：Interface / QueryProvider。
- Search current source：按 Store/Channel 输出 V2 `product_offer` 文档，`global_offer_uuid` 是可购买单元主键，并兼容清理旧 `product_id` 文档。
- 库存、订单和下载权益写入：对应归属模块能力接口或 Hook。
- 缓存、索引、审计等旁路副作用：Event。
- 后台浏览器交互：Weline.Api + Resource/QueryProvider，禁止 Controller 互调和 raw fetch。

## 三、五类产品与后台体验

| 内置类型 | 核心行为与发布要求 |
|---|---|
| 普通实体 `simple` | 自动一个默认 Offer；名称、SKU、基础价必需；接库存和配送；零库存时不可购买 |
| 多规格 `configurable` | EAV 属性定义规格轴；每个组合唯一 Offer/SKU；组合不得重复；前台必须解析明确 Offer |
| 虚拟/服务 `virtual` | 不配送；一个或多个服务方案；默认无限库存；预约/容量由扩展 Provider 提供 |
| 下载 `downloadable` | 不配送；至少一个私有下载资产；支付成功产生可审计权益；支持次数/期限 |
| 组合 `bundle` | 组件组引用已发布 Offer；固定/动态价；校验循环；库存检查必选组件；配送由组件推导 |

订阅、礼品卡、预约、租赁等不硬编码进 Product，由所属模块注册 Provider；Subscription 必须完成一次扩展接入证明。

后台交付：

- 商品列表支持 Website、Store、归属、类型、状态、名称、SKU、总货号筛选，并显示主图、Offer/价格摘要、Store 状态和更新时间。
- 新建采用短流程：当前 Website → 类型 → 名称/首个 SKU 或规格轴 → Store（默认全选）→ 创建真实 draft → 完整编辑器。
- 编辑器包含概览、基础信息、动态属性、规格与价格、分类、媒体、Store、库存/配送、类型专属配置、发布诊断和审计。
- 多规格编辑器提供规格矩阵生成、批量 SKU/价格/库存编辑、重复组合检查和删除影响预览。
- 保存草稿允许不完整；发布前按 Store、locale、币种和 Offer 分组展示阻断原因。
- 发布命令统一校验父商品和选中 Offer；任一目标 Store 有硬错误时整体阻止，可修复或取消该 Store。
- 主图默认不是统一必填项，由 Provider 决定；显式零价有效，缺价和 `cleared` 不等于零价。
- 后台必须在 375 / 768 / 1024 宽度可操作。

### 3.1 跨站复制

- 复制前检查归属、分享授权和目标 Website/Store。
- 默认主站目录对获授权子站可见；非主站商品只有分享目标可见。
- 预览显示即将创建、更新、跳过的 Product、Offer、属性、价格、分类、媒体和 Store。
- 目标站默认选择全部活动 Store；一次目标 Website 操作内目录与所选 Store 原子提交。
- 重新复制只更新勾选字段包，不删除目标站未选字段或本地覆盖。
- 库存默认初始化为零，只有明确勾选且具备权限时才复制数量。
- 归属转让需要双方确认、版本校验和审计；转让前后已有 Website 投影保持不变。
- 归属站归档只归档自身投影并停止继续分享，不自动下架其他站；全局身份在仍有引用时不得清除。

## 五、测试与完成门禁

必须覆盖：

- 五类产品分别执行新建、保存、刷新、编辑、发布、前台展示和加入购物车。
- 多规格选择准确落到唯一 Offer/SKU；重复组合、重复 SKU 和无效规格被拒绝。
- 虚拟商品不产生配送；下载商品支付后只能由有权益用户访问；组合商品价格、库存、配送和订单快照正确。
- 任意 Website 可创建并成为归属站；主站默认共享、其他站私有分享、复制站结构只读。
- 跨站复制保留身份但不自动同步；手动更新保留目标本地覆盖；全部 Store 默认选中。
- Store 属性、价格、分类、媒体覆盖的继承、cleared、隐藏和恢复继承正确。
- 草稿可不完整；发布规则按 Provider 生效；零库存可发布但 Cart 拒绝购买。
- 类型转换只允许无引用草稿；分享、转让、归档和 SKU rename 均有版本冲突与审计覆盖。
- 任一步骤失败后无孤立 Product、Offer、SKU、Price、Media、Store 或 Inventory 数据。
- 旧 1:1 数据、壳数据、Eav-only 数据和跨站副本迁移幂等；冲突不自动覆盖或删除。
- PostgreSQL 集成、真实 HTTP/ACL/CSRF、独立 WLS Browser 和数据库结果共同作为验收证据；字符串测试、SQLite 或静态页面不能代替运行验收。

## 六、默认假设与禁止项

- 不引入 Website 任意父子树。
- `website_id=0/default` 是平台主站。
- 不做自动跨站同步。
- 营销价格不进入 Product。
- 不执行生产部署或生产数据迁移，除非另行授权。
- 不使用默认 WLS 端口 9501。
