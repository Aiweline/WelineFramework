## 5. 关键流程

### 5.1 创建任务（F02）

```
POST weline_product/backend/ai-review/create
  website_id=0, uuids[]=..., tasks[]=copy, model_codes[copy]=deepseek-flash, scope=missing
```

1. ACL + CSRF 校验；`website_id` 与当前后台站点一致。
2. 逐商品检查：存在、未归档、属于该站（`ProductAdminReadInterface`）。
3. `ProductAiModelResolver::resolve('copy', $modelCode)` → 场景 `product_copy_optimize` + 模型；未绑定立即 422 `product_ai_model_unbound`，**不建任务**。
4. 快照 + `input_hash`；同商品同任务已有 `queued/running` 任务且 `input_hash` 相同 → 直接返回已有 `job_id`。
5. 冻结媒体上下文：`MediaFileAccessContextFactory::freeze($input, $actorId)` 存入 `params_json`（保证消费者能落图，事实 13）。
6. 写 job（queued），`IdempotentQueueAdmission::admit()` 入队（`biz_key='product-ai:'.$jobId`，`idempotency_scope='product_ai_optimize'`）。
7. 返回 `{ok:true, data:{job_ids:[...], review_url:'...ai-review/index?job_id=...'}}`。

### 5.2 消费执行

1. `queued → running`（条件更新，防重复消费）；写 `started_at`。
2. 取快照（字段、媒体、`local_version`、`identity_version`）。
3. 文案：`AiService::generate($prompt, $modelCode, 'product_copy_optimize', $locale, $params, $actorId, true)`（事实 10 的方法签名在 `AiService.php:446`）。
4. 图片：`AiService::generateImage($prompt, $modelCode, 'product_image_optimize', $params)`；取 `images[0]`（`url` 或 `b64_json` + `mime_type`，由 `ImageGenerationResponseNormalizer::normalize` 归一）。
5. 落图：`FileAssetLibraryInterface::upload($diskCode, $objectKey, $stream, $name, $mime, $locale, $access, $localeMetadata, 'public', ['ai_scenario'=>'product_image_optimize','ai_job_id'=>$jobId])`；返回 asset UUID（事实 12）。`objectKey` 由现有媒体目录规则生成；同一商品同角色加时间戳，避免覆盖。
6. 文案：解析 JSON（适配器内做修复/兜底，参照 `Ai/Adapter/ArticleGenerationAdapter.php:47-55`）；字段级裁剪到长度上限；与快照相同则跳过；写 `AiDraft`。
7. 任务置 `succeeded`/`failed`，写 `result_json`/`error_*`；`finished_at`。

### 5.3 审核列表（F03）

```
GET  .../ai-review/index?website_id=0&status=pending&task_type=all&job_id=...
GET  .../ai-review/detail?job_id=...
POST .../ai-review/reject  {job_id, note}
```

- 列表按 `website_id + status + created_at` 倒序；每条返回任务类型、模型标签、字段数、冲突标记、生成时间。
- 详情返回 `fields[]`（`before/after/diff`）、`media`（原图 + 候选，候选含资产 URL）、`local_version`、`identity_version`。
- diff 在服务端生成（`diff_json`），前端只负责高亮渲染；避免在浏览器里做 HTML diff 引入 XSS。
- 「重新生成单字段」「采纳」在 S1 只改前端选择态与草稿状态（`accepted`），真正写入在应用时一次性完成。
- 冲突：`before_hash` 与当前快照不一致的字段打 `conflict`，默认不勾选；「只重生成冲突字段」= 用当前快照新建一个 job（同一商品、同一字段集），S1 允许。

### 5.4 应用（F04）

```
POST .../ai-review/apply {job_id, accepted_field_keys[], image_draft_id, local_version}
```

1. ACL（`ai-review:apply`）+ CSRF；`job.status === succeeded`。
2. 逐字段重算当前快照哈希：与 `before_hash` 不一致 → 409 `product_ai_draft_conflict`，返回冲突字段与当前值，**不写入**。
3. `local_version` 必须等于请求值，否则 409 `product_ai_local_version_stale`（事实 2）。
4. 组装 payload：
   - 文案：仅被采纳的字段，顶层键 + `locale`（事实 4）。
   - 图片：先 `AiService` 产物已落成 asset；读取当前 `syncProductScope` 列表，替换 `role=main` 为新 asset，旧主图转 `gallery`，**整组**回传（事实 6/7）。
   - `local_version` = 当前值。
5. 直连命令服务：
   ```php
   $command = ProductAdminCommand::fromArray([
       'action' => ProductAdminCommand::ACTION_SAVE,
       'website_id' => $websiteId,
       'global_product_uuid' => $uuid,
       'actor_id' => $adminId,          // 不能用 w_query('product_admin','command')，见事实 8
       'request_hash' => hash('sha256', 'product-ai:'.$jobId.':'.$appliedHash),
       'payload' => $payload,            // 含 local_version
   ]);
   $result = $commands->execute($command);
   ```
6. 成功后写审计（事实 9）：`ProductAuditLog` action=`product_ai_apply`，`before_version`/`after_version` 取返回的 `local_version`，`payload_json` 记录 `job_id`、采纳字段、模型、候选图 asset、`actor_id`。
7. 草稿置 `applied`，保存 `rollback_json`（应用前字段值 + 媒体整组快照）与 `applied_version_after`；任务置 `applied`（或保留 `succeeded` + 全部草稿 applied）。
8. 返回 `{ok:true, data:{local_version:new, applied:[...], audit_event_id:...}}`。
9. 失败：命令服务的 `ProductV2ConflictException` 转 409 并返回 `error_code`；不做部分写入（命令服务内部事务）。

### 5.5 失败与重试

- 模型超时/限流：`error_code=product_ai_model_timeout|rate_limited`，任务 `failed`；审核中心提供「重试」= 新建 job（同参数），不复用旧 job。
- 队列消费异常：消费者捕获后写 job `failed` 并返回摘要；`TaskConsumerInterface` 的失败重试由队列机制处理，业务层不重复扣费。
- 取消：`queued` 直接 `cancelled`；`running` 只标记 `cancel_requested`（S1 不做强制中断，S2 补）。

## 7. 模型标签接线

| 任务 | 场景 code | 模态 | 未绑定时 |
|---|---|---|---|
| 文案优化 | `product_copy_optimize` | `text2text` | 创建任务即 422，不静默换模型 |
| 图片优化 | `product_image_optimize` | `text2image` | 同上；绝不回退 text2text（事实 10） |

- 后台选择器：`<w:ai:model:select service_type="text2text|text2image" />`（`Ai/Taglib/ModelSelect.php:214` 用法）。
- 每个任务的默认模型：场景适配器绑定；批次内可逐任务覆盖（覆盖值在创建时校验模态）。
- 适配器 `getDefaultModelBindings()` 返回 `[]`，由管理员在 AI 场景设置里绑定；这样多站点/多模型商不写死（对齐 `MediaManagerAiDrawAdapter.php:15-17`）。
- 能力门禁：`class_exists(\Weline\Ai\Service\AiService::class)` 为 false 时，入口按钮隐藏，控制器返回 503 `product_ai_ai_unavailable`。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 并发覆盖（R1） | 字段级 `before_hash` + `local_version` 双校验；冲突即 409，不写入 |
| AI 编造事实（R2） | Prompt 事实白名单 + 输出字段白名单 + 人工逐字段采纳；不自动发布 |
| 产图落库丢失媒体上下文（R3） | 创建时 `freeze()`，消费时 `fromFrozen()`；落库失败整任务失败，不写半套媒体 |
| i18n CSV 与其它会话冲突（R4） | 动手前 `git status` + 读当前文件尾；只追加、不重排；提交前 diff 复核 |
| 其它会话并发改 Product（R5） | 每文件改动前 `git diff -- <file>` 确认；出现交叉修改立即停手（沿用并发停手规则） |
| 图片成本（R3-PRD） | S1 单商品固定 3 候选；任务创建时显示预估；不做批量 |
