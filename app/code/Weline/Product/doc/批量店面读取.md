# 批量店面读取

## 实时商品首个 Offer

进程内调用：`w_query('product_storefront', 'liveOffersByProductIds', ['product_ids' => [12, 34]], 'frontend')`。

- 归属 Product；仅内部 Query，descriptor 明确 `frontend=false`、`external=false`、`graph=false`、`mode=read`；不新增 HTTP/REST 暴露，也不进入 CDN。
- 输入正整数商品 ID，去重；空批不读数据，每100项分块，不按24卡片接口截断。当前网站/店铺/渠道/语言/货币取运行时上下文，入参不能指定其他网站。
- 输出以商品 ID 为键的原始首个已发布 Offer；商品与 Offer 必须满足既有发布规则、顺序与范围。包含实时 `sellable`，`false` 也保留；不存在/未发布无返回项。
- 沿 Catalog 现有集合构建，商品/Offer/EAV/媒体/价格/库存使用原批量链；仅请求内 memo，维度包含 ID 集合与 scope/store/currency/locale，不复用共享目录缓存作为实时结果。
- 输出保留 Wishlist 使用的 name、sku、slug、image、description、价格 minor、currency、rating/review_count、sellable、global_offer_uuid 及 campaign 字段。PDP 供应商专用字段不在此读取接口的合同内。
- Wishlist `resolveMany` 统一读取后沿自身原 normalize 输出，按收藏 ID 顺序组装；`resolve` 保留单条兼容入口。缺少已发布商品时仍按原规则清理收藏，暂不可售不清理。旧读取失败视空结果的行为未新增限制。

Provider 修改后必须正式 `framework:compile` 并用 `query:help product_storefront liveOffersByProductIds` 核对发现性；源码单测不是已加载运行时证明。

## 评论身份映射

`ProductIdentityBatchResolverInterface` 是既有单条 resolver 的可选批量扩展。Compatible 与 legacy SKU resolver 实现按 Offer UUID/商品 UUID 的集合读取；返回键对应调用方输入 UUID，缺失不返回。

V2 优先、legacy fallback、registry ID/requestHash/refCount 兼容不变。V2 成功时按规范化 Offer UUID 读取 legacy 元数据，保留大写输入兼容。商品 UUID 回退批量取有效 Offer，并沿原 registryId/sku 排序选首个。每批读取一次 cutover，未将迁移状态缓存至全局或共享池；每500 UUID分块。

Review 的可选 `BatchReviewTypeProviderInterface` 优先使用这条边界；只有不支持批量接口的第三方 provider 才保留单条兼容。正常内置商品路径没有逐 UUID SQL。缺失对象的后续回退异常不丢弃已经成功解析的 Offer；未写永久负缓存。
