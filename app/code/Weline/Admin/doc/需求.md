## 当前有效需求

### `REQ-ADMIN-0001` 后台三态主题控制

- 来源与确认：关联用户确认的 `REQ-THEME-0001`，Theme 是颜色系统 owner。
- 目标版本：`1.0.2`。
- 业务逻辑：后台 topbar 和右侧设置提供可键盘操作、可翻译的 system/light/dark 控件；控件调用既有 `theme.setBackendThemeMode`，不新增 fetch/Ajax。
- 范围：后台 Head 预解析、topbar、右侧设置、Admin 运行时和对应测试。
- 非目标：新增后台主题样式副本、改动 ACL/登录或创建新端点。
- 数据/权限/安全：沿用 Backend 当前用户主题配置和现有授权；只接受三态值。
- 验收标准：三态选项可见、键盘可操作、页面刷新后保留，解析属性正确且无暗色白闪。
- WebUI/E2E：登录后台后依次切换三态并重载，由 Theme E2E 覆盖。

### `REQ-ADMIN-0002` 后台每设备记住登录编排

- 来源与确认：用户于 2026-08-11 批准多端登录与设备管理计划。
- 目标版本：`1.0.3`。
- 业务逻辑：密码登录在设备登记完成后按当前设备签发 `w_backend_ut`；自动恢复优先解析新凭证并恢复同一设备，成功后轮换；已登录时可迁移经 Backend 确认归属的旧 `w_ut`。
- 范围：Admin 登录 Controller、`BackendRememberLoginService`、退出 Cookie 清理和对应测试。
- 非目标：Admin 保存设备 ORM、渲染设备管理页面或直接依赖 SessionManager 具体实现。
- 数据/权限/安全：通过 Framework 发布的凭证 Provider；Provider 声明故障时不得回退旧 Token；Cookie 使用 HttpOnly、Secure（HTTPS）和 backend 隔离名。
- 兼容/迁移：Provider 未配置时继续现有 BackendUserToken；可用时归属确认后迁移并使旧 Token 失效。
- 验收标准：两台后台设备各自 remember；下线 B 后 B 不恢复，A 不受影响；ACL 上下文仍正确。
- WebUI/E2E：真实后台菜单和两个隔离上下文覆盖。
