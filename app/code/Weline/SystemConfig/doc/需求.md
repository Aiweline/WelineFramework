### `REQ-SYSTEMCONFIG-0002` 公共 Scope 层级契约与规范身份

- 来源与确认：用户于 2026-08-22 确认 Theme Editor Scope 优先与逐值继承框架计划，要求 Scope 规范化成为公共内核而非 Theme 私有实现。
- 目标版本：`1.1.0`。
- 业务逻辑：发布 `ScopeHierarchyInterface` 和不可变 `ScopeContext`，统一 `ScopeIdentity` 编解码、typed claims 校验、规范存储值和父链。规范三段为 Global `default.default.default`、默认 Website `default.__website__.default`、Website `shop.default.default`、默认 Store `shop.__store__.default`、Store `shop.cn.default`、Channel `shop.cn.retail`。
- 写入安全：新写入拒绝短 Scope、非规范 Scope、非法业务代码和客户端伪造的 ID/code 组合；`__website__`/`__store__` 只是非法业务代码哨兵。
- 责任边界：`SystemConfigScopeResolver` 是公共接口实现；Theme、Meta 只依赖接口。`SystemConfigTargetScopeService` 不直接依赖 Websites Model/具体目录或 `$_SESSION`；Website/Store/Channel 可选项由拥有 UI 的模块经官方 Catalog API 获取，Session 只可恢复 UI，不是写入目标。
- 兼容：历史短 Scope、`website.default.__store__`、`~test/~dev` 等仅可在显式兼容读取边界归一，不得产生新非规范写入；`store_mode` 必须与 Scope 独立存储。
- 验收标准：单元测试覆盖规范身份往返、默认 Website/Store 区分、Channel 父链、非法哨兵/短 Scope 拒绝和 typed claim 伪造。

### `REQ-SYSTEMCONFIG-0003` Scope 身份目录的单入口与可选贡献者

- 来源与确认：2026-08-22 框架完整路由升级暴露 `ScopeIdentityCatalogInterface` 被 SystemConfig 与 Websites 重复注册；用户要求缺少即修复。
- 业务逻辑：SystemConfig 始终是 `ScopeIdentityCatalogInterface` 的唯一 Provider；未安装身份所有者时仅允许 Global。拥有 Website/Store/Channel 身份的模块只能通过 `system_config.scope_identity_catalog.*` 能力前缀贡献一个权威目录，由 SystemConfig 入口校验类型后委托。
- 安全与失败语义：零个贡献者安全回退 Global-only；一个贡献者正常委托；多个贡献者、无效类型或自引用必须 fail-closed，不允许注册顺序覆盖。
- 范围：Scope 目录公共契约、Global-only 入口、模块 Provider 清单和聚焦测试。
- 非目标：不放宽 Framework 的重复 Provider 门禁，不让 SystemConfig 直接依赖 Websites 类，不增加 Scope Schema。
- 验收标准：模块 Provider 注册无冲突；Global-only、单贡献者委托和多贡献者拒绝均有自动化证据；`setup:upgrade --route` 可越过 Provider 编译阶段。
