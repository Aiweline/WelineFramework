# FlutterBuilder 对接说明（app-flutter 席 → Lead / 后端席）

> 权威模板源：`app/code/Weline/App/source/app-template/`
> 现状：T5 `FlutterBuilder::scaffold()` 用程序化字符串生成最简单页（Hello）到临时目录再 build。本模板是升级替换源。

## 占位符清单（打包时渲染）

| 占位符 | 注入方式（推荐 dart-define，不改源码文本） | 渲染值 | 用途 |
|---|---|---|---|
| `{{BASE_URL}}` | `--dart-define=WELINE_BASE_URL=…` | 站点域名（`Weline_App` 打包配置 domain；通用包=站点主域名） | 启动拉 config / version / download（`lib/services/app_config.dart` `kBaseUrl`） |
| `{{APP_NAME}}` | `--dart-define=WELINE_APP_NAME=…` | App 显示名（如 `长安汉服`） | MaterialApp title / AppBar |
| `{{VERSION}}` | 写入 `pubspec.yaml` 的 `version:` + `--dart-define=WELINE_APP_VERSION=…` | `1.0.1` 等（跟随系统+模块版本，与 AppArtifact.version 一致） | UC6 比对基准（Account 页展示） |
| `{{DOMAIN}}` | 无需注入——App 运行时从 config 响应 `domain` 取 | 打包目标域名 | 仅 `main.dart` 文案展示（V1 骨架未用；保留约定以防直接字符串渲染方案） |
| `{{THEME_PRIMARY}}` | 不注入——Token 已固化为 `lib/tokens.dart` 朱砂常量 | `rgb(177,63,60)` | V1 汉服主题色固定；若将来站点主题色可配置（contracts §1.1 `theme.primary_color`），V2 改为运行时从 config 读 |

**推荐对接方式（dart-define，零文本替换）**：
`flutter build web --release --dart-define=WELINE_BASE_URL=https://… --dart-define=WELINE_APP_NAME=长安汉服`
占位符常量用 `String.fromEnvironment` 实现：未传 dart-define 时 `{{BASE_URL}}` 等字面量就是默认值，打出的包首启 config 会失败但 App 壳仍可用（静默降级）——便于无配置冒烟。

**备选方式（文本渲染）**：scaffold 复制模板后对 `lib/services/app_config.dart` / `pubspec.yaml` 做字符串替换 `{{BASE_URL}}`→域名、`{{VERSION}}`→版本。两种方式二选一；**dart-define 优先**（模板源不碰即可多站点复用）。

## FlutterBuilder 对接步骤（改造 scaffold() 为独立原子任务）

1. 复制目录：递归 copy `app/code/Weline/App/source/app-template/*` → 临时工作目录 `$workDir`（现有逻辑改为复制而非字符串拼接）。
2. （可选，若选文本渲染方案）对 `$workDir/lib/services/app_config.dart`、`$workDir/pubspec.yaml` 做占位符替换。
3. `pubspec.yaml` 依赖从仅 flutter 变为 flutter + http + shared_preferences + url_launcher：**首次 build 需要联网拉 pub.dev**（cn 镜像注入逻辑已有，保留）；`flutter build` 前无需手动 `pub get`（build 会自动 resolve）。
4. `flutter build web --release --no-tree-shake-icons` + dart-define（见上）→ 产物 `build/web` → 现有 collect()/build.json 戳逻辑不变（L7）。
5. 版本一致性：`{{VERSION}}` 取值必须与 AppArtifact 登记行 `version` 同源（`etc/weline_app_versions.json` 的 module 字段），否则 UC6 比对逻辑错乱。
6. 平台目录：模板只含 `lib/` + `pubspec.yaml`（跨端共享）。**打 Android APK 前需 `flutter create --platforms=android .`**（在临时目录执行，生成 android/）；打 Web 不需要。建议 FlutterBuilder 在 platform=android 分支自动补这一步。

## 已知限制

- Android 打包需 JDK 17 + Android SDK（`app:doctor` 探测；本机当前缺，W3 测试席补）。
- iOS 打包需 macOS + 完整 Xcode（`xcode-select` 指向 Xcode.app 而非 CLT）；V1 云编译就绪前 iOS 产物只走 App Store 占位链接（UC6 iOS 跳商店）。
- 宋体 Android 侧资产（Noto Serif SC 子集）未打包：display/title 槽在 Android 回退系统 serif；资产到位后取消 `pubspec.yaml` fonts 注释。
- `url_launcher` 在 Android 打开 download 302 时由系统下载器接管 APK 安装；「未知来源安装」引导属 W3 测试席真机验证范围。
- 模板不含真实商品数据（Home/Shop 均占位）；商品契约接入是 V1 后续独立任务。
