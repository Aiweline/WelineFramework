# 本地协助编译与部署（App 产物）

> 用户 2026-10-28 指定：**App 只在本机编译，线上不做编译环境**；大部分情况是「本机编译 → 上传对应位置 → 线上登记」。
> 技能入口：宿主技能 `weline-app-build`（口令「app <网站>」）。本文是模块侧权威事实与 CLI 契约。

**交付口径（2026-10-28 补充）**：`app <网站>` = 该站 `w_weline_app_build.platforms` 里的**全部可用平台**
（当前 `android` / `ios` / `web`）逐平台编、传、登记、验收；只发 Android 不算完成。`web` 即站点自带的
**Web / PWA 入口包**（Flutter web 静态面 + `build.json`），没有它的 released 登记行时 `/app/download`
与下载部件只显示 Android。

## 1. 分工

| 位置 | 做什么 | 不做什么 |
|---|---|---|
| 本机（macOS + Flutter + JDK + Android SDK） | `app:build` 出包、写 `build.json`、落到 `pub/static/weline-app/<build_id>/` | —— |
| 站点应用根（生产） | 放产物目录 + `app:artifact:import` 登记一行 | 不装 Flutter/JDK/SDK，不跑 `app:build` |

`app:build` 在无工具链的机器上会尝试 `app:install-deps` 自动装依赖；因此**禁止**在线上跑它（`--dry-run` 除外，已改为完全不碰环境）。

## 2. CLI 契约

### 2.1 `app:build`

```text
php bin/w app:build --website=<本机站点id> --platform=android|ios|web \
    --base-url=https://<公网域名> [--dry-run] [--check-only] [--async] [--no-install]
```

| 参数 | 语义 |
|---|---|
| `--platform` | `android`（APK）/ `ios`（未签名 IPA）/ `web`（**Web / PWA 入口包**：Flutter web 静态面整目录，`index.html` 改写为跳店面，`entry.html` 同内容）。**省略或取 `all` = 站点 `w_weline_app_build.platforms` 的全部可用平台，逐个出包**；也可写 `android,web` 指定子集。每个平台各得一个 `build_id` |
| 多平台失败隔离 | 逐平台构建，单平台失败（如缺 CocoaPods）不阻断其余平台；末尾输出 `platforms_built=` / `platforms_failed=`，有失败时 exit=1。单平台时输出形状与旧版一致 |
| `--base-url`（别名 `--domain`） | 编译期站点基址，必须是 http(s) 绝对地址；优先进队列内容，队列重渲染时不丢 |
| 未给 `--base-url` 且站点未配 `domain` | **拒绝出包**：`缺少站点地址：本机协助编译必须显式指定线上域名`（曾静默回退到本机默认站测试域名，已移除） |
| `--dry-run` | 只渲染配置（含 `domain`/`base_url`/`universal`），**不再触发依赖检测与安装** |
| `--check-only` | 只报告本机工具链缺项与安装计划；多平台时末尾输出 `platforms_ready=`（未就绪的在 `platforms_failed=`，exit=1） |
| `--async` | 只投队列，不等待 |
| `--all` | 按 `w_weline_app_build` 中 enabled 站点批量投递（忽略 `--base-url`） |

**可用平台**由 `w_weline_app_build.platforms`（站点后台「App 打包配置」）定义；「app <网站>」应按该清单
全量交付。`web` 的 `sha256` 是目录内容哈希（非单文件），登记后下载接口对 `web` 一律 302 回店面 `/`。

同步出包以**队列登记结果**为准：只有 `released:<build_id>` 才算成功，失败时 exit≠0 且不打印 `build_id`。

### 2.2 `app:artifact:import`（目标机执行）

```text
php bin/w app:artifact:import --path=static/weline-app/<build_id> [--changelog='...'] [--dry-run]
```

- 只接受 `static/weline-app/<build_id>`；目录名必须与 `build.json.build_id` 一致。
- 校验：`platform` ∈ android/ios/web；`version` 非空；`build_ts > 0`；android/ios 的安装包必须存在且
  `sha256`、`size_bytes` 与 `build.json` 完全一致。
- 登记：按 `build_id` upsert，`status=released`，`path` 写相对路径；同构建同哈希同 changelog → `unchanged`。
- 产物权威仍是 `w_weline_app_artifact` + 构建期发布戳（L7）：**请求期不 stat 文件**，版本/下载接口只读登记行。

### 2.3 产物目录与 `build.json`

```text
pub/static/weline-app/<build_id>/
  app.apk | app.ipa | (web 静态面)
  build.json
```

`build.json` 字段：`base_url`（编译期站点地址）、`site_hosts`（壳内同站白名单，含裸域）、`app_name`、
`website_id`（本机 id）、`build_id`、`platform`、`version`、`build_ts`、`sha256`、`size_bytes`。

壳内域名与接口由编译期注入，代码不写死站点：

- `WELINE_BASE_URL` = `build.json.base_url`
- `WELINE_SITE_HOSTS` = `build.json.site_hosts`
- 接口固定为站内 `/api/weline_app/rest/v1/{config/config,version/version,download/download}`

## 3. 标准链路（本机 → 生产 · 按可用平台全量）

```bash
# 0) 盘点：该站可用平台 + 线上已登记产物
#    w_weline_app_build.platforms = 可用包清单；下面三端里缺 build_id 的平台就是缺口
curl -s 'https://www.<域名>/api/weline_app/rest/v1/version/version?platform=android'
curl -s 'https://www.<域名>/api/weline_app/rest/v1/version/version?platform=ios'
curl -s 'https://www.<域名>/api/weline_app/rest/v1/version/version?platform=web'

# 1) 本机：按缺口逐平台编译（示例站点 playinginchina；省略 --platform = 全平台）
php bin/w app:build --website=550 \
  --base-url=https://www.playinginchina.com --no-install
#   也可显式子集：--platform=android,web；单平台：--platform=web
#   每平台各出一个 build_id，输出以 platform=<x> 分段，末尾 platforms_built=/platforms_failed=

# 2) 本机：验包（域名进包 + 哈希一致 + web 目录齐全）
cat pub/static/weline-app/<build_id>/build.json
shasum -a 256 pub/static/weline-app/<build_id>/app.apk
test -f pub/static/weline-app/<web_build_id>/index.html && \
  test -f pub/static/weline-app/<web_build_id>/entry.html && echo web-ok

# 3) 生产：建父目录（首次）并逐平台整目录上传
ssh <Host> 'su -s /bin/sh weline -c "mkdir -p <应用根>/pub/static/weline-app"'
scp -r pub/static/weline-app/<build_id> <Host>:<应用根>/pub/static/weline-app/
ssh <Host> 'chown -R weline:weline <应用根>/pub/static/weline-app/<build_id>'
# macOS tar 通道会带 ._* AppleDouble；清理后核对文件数与本地一致（scp 也可能带）
ssh <Host> 'find <应用根>/pub/static/weline-app/<build_id> -type f -name "._*" -delete'

# 4) 生产：逐平台登记（线上 CLI 必须以 weline 跑）
ssh <Host> 'cd <应用根> && su -s /bin/sh weline -c \
  "php bin/w app:artifact:import --path=static/weline-app/<build_id> --dry-run"'
ssh <Host> 'cd <应用根> && su -s /bin/sh weline -c \
  "php bin/w app:artifact:import --path=static/weline-app/<build_id>"'
```

验收（公网 · 逐平台）：可用平台里每个 `version` 接口的 `build_id`/`sha256`/`size_bytes` 都与本地对应
`build.json` 一致；Android 下载落盘 sha256 一致；Web/PWA 的 `download?platform=web` 302 回 `/`，
`/app/download` 同时列出 Android 与 Web 卡片（英文 locale 标题为 `Web`，含 PWA 安装按钮/提示；
版本等于本地 web `build.json.version`）；`/manifest.webmanifest`、`/sw.js`、`/pwa-icon-192.png` 均 200。

## 4. 硬约束

1. **禁止在线上构建**：线上只登记，不装工具链。
2. **站点地址必须是公网域名**：`--base-url` 与站柜 `server.md` 公网一致；包内出现 `*.test.weline.com` 视为作废。
3. **整目录上传**：`app.apk`/`app.ipa` 或 web 静态面（`index.html`/`entry.html`/`main.dart.js`/assets）与
   `build.json` 一起，禁止只传安装包、禁止 `--delete`。web 登记不逐文件校验，漏文件不会被登记拦下。
4. **登记是唯一发布动作**：上传文件但没登记 = 版本/下载接口看不到；登记前必须过 sha256 校验。
5. **签名状态**：当前模板产出的是 debug 签名 APK（`CN=Android Debug`），仅内测/自签；
   正式分发前必须先落地 `w_weline_app_signing_profile`（见 `doc/开发计划.md` P0 #1），否则覆盖安装会因签名不一致失败。
6. **iOS**：产物是未签名 IPA，需用户自签侧载；上架仍走 App Store 链接（`app.ios_store_url`）。
7. **回滚**：暂无回滚命令；版本接口取 `build_ts` 最大者。要回退只能把新产物行置 `failed`，或重出更高 `build_ts` 的旧版本包。
