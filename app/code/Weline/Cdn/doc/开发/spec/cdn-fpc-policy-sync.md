# FPC 策略管理与 CDN 自动同步

## 背景

控制器的 FPC 声明是公共缓存资格的代码来源。管理后台允许在现有 Website → Store → Channel 范围内调整可缓存方法的启用状态和 TTL，并将同一有效策略用于源站 FPC 和 CDN。代码禁止公共缓存的方法不能通过后台开启；未声明的方法继续遵守框架既有资格判断，不生成可后台开启的策略。

## 策略契约

- 声明身份由模块、类、方法、类型构成，公开路径不参与身份。重新收集或修改路径不覆盖人工设置。
- 声明投影与后台覆盖独立保存。enabled 与 TTL 分别按 Channel → Store → Website → Global → 代码默认继承，沿用 test/normal 隔离。
- 恢复继承只移除当前范围的指定字段；未提交字段不修改。源声明 enabled=false 或 TTL=0 保持禁止。
- Framework 定义 FpcPolicySnapshotProviderInterface，由 Cdn 提供编译覆盖。Framework 不依赖 Cdn 模型；请求期不新增逐方法策略表查询。
- 有效策略同时约束源站读取、构建、发布、响应头、预热及 WLS 快速路径。策略指纹进入缓存键与回执，旧回执不能绕过新策略。
- 边缘 TTL 不超过策略 TTL 和源站缓存剩余新鲜寿命。STALE 不重新获得完整边缘缓存寿命。

## 后台管理

沿用 API 规则入口，顶部显示 FPC 策略、现有 CDN 注释规则、同步记录三个页签。使用现有 Scope 控件、Weline UI、后台权限和中英文文案。

FPC 列表按控制器方法展示公开路径、代码默认值、当前覆盖、字段来源、最终启用/TTL、源站版本与同步结果。支持停用、调整 TTL、分别恢复继承和同步重试。

业务操作归现有 cdn QueryProvider：listFpcPolicies、saveFpcPolicyOverride、restoreFpcPolicyInheritance、collectFpcPolicies、listFpcSyncRecords、retryFpcSync。保存成功表示变更已持久化并安排处理，不能据此表示线上缓存已经生效。

## 发布与自动同步

路由收集完成、后台保存/恢复、相关域名启用或绑定变更自动产生同步任务；现有定时任务补齐未完成任务。事务提交后通过现有 Queue 执行：发布有效源站策略 → 同步必要 CDN 默认规则 → 清理受影响缓存。

编译快照原子发布成功后更新 HotCache 依赖与 namespace generation。连续修改累计尚未清理的旧路径，新增、删除和路径迁移均参与差异比较。清理优先精确 URL；通配路径使用对应 Scope 的公共路径前缀，无法进一步缩小时使用该 Scope 的公共 host/base prefix。

云端同步以适配器、账户、Zone 合并并串行执行。完整受管期望规则集合包含同 Zone 各域名；cron/realtime 只决定触发时机。Weline 规则使用稳定标识，保留人工规则及相对顺序；首次接入仅认领唯一且完整匹配的旧规则。策略未变化时不重复提交云端规则。

分别记录期望版本、源站已确认版本（`origin_version`）、实际快照文件版本（`snapshot_version`）与修订标识（`snapshot_revision`）、CDN 接受结果、缓存清理回执和实际请求验证。源站已确认版本表示内容等价的期望版本高水位；有效内容未变时不重写快照文件，因此两种版本可以不同。失败保留具体原因和待处理版本，事件派发成功不计作云端成功。

## 验收要求

1. 声明新增/修改后收集，管理投影和实际源站/CDN TTL 一致。
2. 后台修改 TTL、禁用、恢复继承，两层一致，重新收集保留覆盖，代码禁止不可反转。
3. 已有 CDN HIT 后缩短 TTL/禁用，旧对象清除，后续请求符合新策略。
4. 删除声明、改路径及连续保存，所有未完成旧路径均被清理。
5. 两 Scope 与同 Zone 两域名互不覆盖，人工云端规则保留。
6. 多常驻 Worker、旧回执、STALE 与预热使用统一策略。
7. 云端失败与重复任务准确记录，无重复规则、无遗漏清理。
8. 登录、私有页面、语言和货币变体继续遵守既有公共缓存约束。

发布必须递增实际变更模块版本、完成数据库升级与路由编译；已有覆盖默认为空，保留现有声明和 CDN 配置。验收先完成本机实际后台操作与自动化用例，再在已绑定目标域名核对响应头、正文和缓存状态。线上生效需源站、云端处理和实际请求三类证据。
