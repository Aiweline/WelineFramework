## 2026-09-01 — iframe 多选选择器默认进入选择模式

- 当前状态：`implemented`
- 问题：商品主图等 `multi=1` 嵌入选择器虽已多选参数，但未进入 `SELECTION_MODE`，单击会覆盖选中，需 Ctrl/右键才能多选。
- 实现：`init`/`setupIframeMode` 在 `IFRAME_MODE && MULTI_SELECT` 时自动 `enterSelectionMode`；`exitSelectionMode`/`clearSelection` 保持多选模式；右键菜单隐藏「退出选择模式」；模块 `1.3.1`。
- 验收：打开商品「从媒体库添加」后文件项显示勾选框，单击可累加多选。

## 2026-08-27 — 嵌入式媒体管理器底部滚动修复

- 当前状态：`implemented_pending_runtime`
- 需求 ID：`REQ-MEDIA-0005`
- 根因：iframe 内 `html/body/main/.mmf-wrap` 被脚本写成按 `clientHeight` 测得的固定像素高度，外层 frame 又重复写入 body 测量高度；两次取整和弹窗头部变化会让底部状态栏或详情动作超出 iframe 后被裁。
- 实现：移除内外两层像素高度锁定，保留 CSS 的百分比 flex/grid 高度链；目录树、中央内容和详情信息独立滚动，状态栏与详情动作固定在各自布局末端；触控滚动启用惯性与边界隔离。
- 验证：JS/PHP 语法通过；`testEmbeddedPickerKeepsBottomContentReachableWithoutPixelHeightLocks` 为 `1 test / 11 assertions`，带项目 bootstrap 的完整视图契约为 `17 tests / 289 assertions`，均通过；真实登录态页面可读且路由可达，但浏览器控制连接在接管标签页时中断，375/768/1024/1440 交互验收待恢复后执行。

## 2026-08-22 — 后台 Global FileAccessContext 回归修复

- 当前状态：`implemented_validated`
- 需求 ID：`REQ-MEDIA-0001`、`REQ-THEME-0004`
- 根因：已认证的 backend Query/Controller 不经过 storefront Scope 冻结，但 ConnectorService 为文件浏览同样强制读取 `RequestContext::scopeIdentity()`，导致页面壳恢复后文件树仍报“媒体文件访问缺少冻结的 ScopeIdentity”。
- 实现：仅当没有 storefront identity 且适配器已提供正数后台用户 ID 时，使用框架正式的 `ScopeIdentity::global()` 构建 `FileAccessContext`；不写入 RequestContext。无 actor 继续 fail-closed，已有 website/store/channel identity 原样保留，私有资源继续校验 owner、allowed scope 与 role。
- 验收：新增回归 `2 tests / 10 assertions`；PHP 语法与差异检查通过；`default:9555` 四 Worker 滚动重载后，真实 Weline Chrome 中媒体管理器文件树、11 个根项目与 `image.png` 正常加载，嵌入式图片选择器完成类型过滤、预览和选择，连接器请求均为 200。
- 说明：用户提供的 127.0.0.1 URL 因后台登录 Cookie 绑定正式域名而跳转登录页；同一路由未再出现 500，完整已登录验收在 `p05113ef3.weline.test:9555` 完成。
