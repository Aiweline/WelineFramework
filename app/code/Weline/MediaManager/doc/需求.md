## 当前有效需求

### `REQ-MEDIA-0001` 媒体 Query 身份取自已证明的 backend Worker 上下文

- 来源与确认：用户于 2026-08-18 在媒体管理页看到两个 `Internal server error.` toast；同意修复，并明确「admin 应该叫 backend」。
- 目标版本：`1.2.1`
- 状态：implemented
- 背景/问题：`media_manager` 的 `config/connector` 借用了 `ResumableTaskOwnerResolver`。该解析器要求 Worker backend 证明指纹与当前 backend Session 完全一致；一旦不一致就抛 `ResumableTaskAccessDeniedException`，QueryBin 再包装成 500。改为直接 `Session->start()` 仍会按 API Cookie 另起空会话，已登录页会误报「请先登录后台」。
- 用户与运营场景：已登录 backend 的用户打开「文件管理」，目录树与文件列表必须能加载；身份一律称 backend，不称 admin。
- 业务逻辑：QueryBin 路径优先读取已证明的 `FrontendWorkerExecutionContext` backend 用户 ID，不得再 start 一套 PHP Session。无 Worker 上下文时才回退已登录 backend Session。未登录返回 QueryBin 可识别的 401，不得伪装成 500。runtime_task 的 owner/lease 校验仍只用于可恢复任务，不用于打开目录。
- 范围：`MediaManagerQueryProvider` 身份解析、媒体管理页 connector/config 调用。
- 非目标：不改 AI 作图模型绑定；不改 runtime_task 协议；不改文件存储路径校验。
- 数据/权限/安全：未登录不得执行 connector/config/save；ACL 仍由 Query 描述符 `backend_acl` 把关。
- 兼容/迁移：无 Schema 变更；不升 `etc/module.php` 安装版本。
- 验收标准：backend 用户打开媒体管理页，connector 与 config 不再返回 `Internal server error.` 或误报未登录；能列出 Media Files 目录。
- WebUI/E2E：backend 登录 → 打开文件管理 → 目录树与网格可见，无红色 Internal server error toast。
- 运营与支持影响：无新配置。
- 依赖与风险：依赖 QueryBin 已对 `ResumableTaskAccessDeniedException` 做 401 映射，作为其它 provider 的安全网。
