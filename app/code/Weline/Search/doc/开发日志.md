## `1.4.8` — 投影入队按 target+scope 合并（治本）

- 问题：批消费只治冷启动；一万次事件仍会建一万条 Queue。
- 方案：`SearchProjectionQueueAdmission` 以 `slot:{target}:{id}:{scope}` 合并；pending 刷新最新 `event_seq`；终态 reopen；running 走唯一 followup。
- 验收：`SearchProjectionQueueAdmissionContractTest` + 观察者构造契约。

## `1.4.7` — Search 投影增量批消费（治本 CPU）

- 问题：`Search Product 投影事件` 每事件 `queue:run` 冷启一次 PHP（~0.9s），批量改商品时本机 PHP CPU 尖峰。
- 方案：增量仍异步；`SearchIndexIncrementalQueue` 实现 `BatchDrainingQueueConsumerInterface`；调度单飞行 + 同进程 drain 兄弟 pending。
- 改动：`SearchProjectionPendingDrainer`、`SearchIndexIncrementalQueue::{applyEvent,batchDrainLimit,execute}`；依赖 `Weline_Queue` 1.2.4 类级派发门禁。
- 验收：`SearchIndexIncrementalBatchDrainContractTest` + `QueueDispatchServiceTest::testBatchDrainingClassesAreSingleFlightOnDispatch`；本机持 cron 锁后同进程 drain 清掉积压 `1742` 条投影 pending（failed=0）。

## `1.4.6` — 店面搜索性能（空词跳过 + 商品直读降耗）

- 问题：`/search?type=all&q=中国风套装` TTFB≈13–20s；`type=product`≈11s，`type=blog`≈1.7s；空 `q` 曾达 40s+。
- 根因：`rollout.search=off` 时商品走全量 `snapshotWebsite`；空 `q` 仍 fan-out；分页前全量 `prepareRows`；搜索布局默认同步 `bestsellers` 再触发全量 `publishedOffers()`。
- 改动：前台 `Index` / Hub 空关键词短路；商品侧投影快照缓存/批量选品与分页前置（见 `Weline_Product` 1.0.143–1.0.144）；Theme 搜索布局去掉默认同步 bestsellers（2.2.184）。
- 验收（reload 后 curl）：空 `q` ≈2.6s；`type=all&q=中国风套装` ≈2.7–3.2s（暖）；`type=product` 暖 ≈1.2–2.3s。冷 Worker 首次 `snapshotWebsite` 仍可能数秒。

## `1.4.4` — 默认站 store/channel ID=0 可搜索

- 基线/目标版本：`1.4.4`（`etc/module.php` 已为 1.4.4）
- 需求：storefront 搜索门禁对齐 Websites P1a，`store_id=0`/`channel_id=0` 合法
- 根因：`SearchParamGuard` 与查询直读用 `storeId < 1` 误拒已冻好的默认 channel
- 改动：`SearchParamGuard`、`SearchQueryService`、Product 直读 Reader、`HotWordsService`；单测覆盖 0/0 通过与 website-only/空 locale 失败
- 证据：探针 `/search` → channel + store_id=0/channel_id=0 + locale/currency 齐全，仅被 `>=1` 误杀
