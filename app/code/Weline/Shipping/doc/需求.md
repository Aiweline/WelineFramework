# Weline_Shipping 需求基线

## 当前范围

### SHIP-REGION-CATALOG-001 国家权威源为地址库

- 后台地区管理国家列表仅来自 Shipping `Region`（`TYPE_COUNTRY`），由 `shipping:addresscatalog:import` / `data/address-catalog/countries.tsv.gz` 写入。
- 禁止从 I18n `CountryRepository` 拉取或「从i18n同步国家」写入国家节点。
- 无国家数据时提示导入地址库，而非同步国际化模块。

### SHIP-REGION-LOCAL-001 地区名称 LocalModel

- `Region`（国家/省/市/区）、`Street`（街道）与 `PostalPlace`（邮编地点 `place_name`）各有 `LocalDescription`。
- 展示按当前 `local_code` 读 Local；缺翻译回退主表名。
- **翻译取源**：主表已有 `region_name`/`street_name`/`place_name` 时，即使 Local 无源语言行，也以主表名为源，经 `LocalModelTranslation` 补其它语言。不要求先写源语言 Local，也不单独为英语硬编码配置。
- `data/region-locals/*.tsv` 仅可选离线回填。
- 用户地址表（`DeliveryAddress`/`ShippingAddress`）的 `name` 为个人昵称，不做 LocalModel。

### SHIP-CHECKOUT-ADDR-001 结账收货地址部件

- 部件 `checkout-shipping-address` 经 `default_injections`（`layout_type=checkout`，`required=true`）注入结账页 `checkout-shipping-address` 槽。
- 目标槽由 Checkout `checkout-storefront-slots` 容器声明，保证 Theme 默认注入可发现；Checkout 页模板禁止裸拼国家/省/市 input。
- 模板提供已存地址选择与 `<w:theme:address code="checkout-shipping-address">` 级联。
- UX：有已存地址时默认只展示已选/默认地址并收起表单；点「更换地址」后再加载完整列表供 radio 单选；支持编辑与「使用新地址」；账单地址默认与收货一致，可取消勾选后单独填写（分段布局 + Amazon 卡片样式）。

### SHIP-FOOTER-HELP-001 页脚帮助中心配送/退换入口

- 前台提供配送说明页 `guide/shipping` 与退换政策页 `guide/returns`。
- 部件 `footer-shipping-info-link` / `footer-returns-policy-link` 经 `default_injections` 注入 Theme `footer-help-links`。
- 指南页默认正文须覆盖发货时效、配送范围、运费、物流跟踪、签收验收、异常赔付（配送）以及适用条件、不予退换、办理流程、运费、退款到账、换货与尺码建议（退换），不得仅保留三五句摘要。
- 指南页通过 Theme `layouts/guide/default` 页面包裹器渲染：主题内容宽度、亚马逊风格面板，并与页头/页脚拉开纵向间距。

### SHIP-ADDR-ACCOUNT-001 个人中心地址管理

- 已登录客户可在个人中心查看发货地址与收货地址两个独立区域。
- **顶部 Header「配送至 / 配送地址」与个人中心「收货地址」同源**（`DeliveryAddress`）；「发货地址」是店铺寄出地址（`ShippingAddress`），不得与顶部配送混为一谈。
- 账户菜单与侧栏地址入口须将「收货地址」置于「发货地址」之前，作为与顶部配送对齐的主入口。
- 发货地址空状态须提示：顶部配送地址请到收货地址查看，并提供跳转。
- **唯一地址自动默认**：客户仅有一条收货地址（或店铺仅有一条发货地址）时必须 `is_default=1`；创建首条、删除后仅剩一条、以及列表读取时的脏数据均须修复。
- 地址区域必须获得当前前台登录客户上下文，并且只允许读取和维护该客户自己的地址。
- 地址列表支持空状态、加载错误、地址卡片、新增与编辑表单，以及默认地址操作。
- 地址表单继续使用框架主题地址组件和表单组件，不在站点主题中复制字段实现。
- 模板标签的编译结果依赖模板对象上下文；包含 `<lang>`、`<w:form>`、`<w:theme:address>` 等标签的渲染闭包不得声明为 `static`。
- 含动态属性的 `<w:theme:address>`（如 `country="<?= ... ?>"`）会走 `renderRuntimeTag`；`Weline_Theme\Taglib\Address` 必须提供 `runtimeCallback` 直接输出 HTML，禁止把编译期 `<?php ... ?>` 片段当作运行期返回值（否则会污染 Header 并吞掉后续页面主内容）。
- 只修改 `view/hooks` 等源模板，禁止修改 `view/tpl` 编译产物。

### SHIP-CARRIER-COV-001 承运商覆盖与网站可售匹配

- 启用承运商必须配置支持范围（`w_shipping_carrier_regions`）；Provider 可提供默认可改覆盖。
- 后台编辑支持范围须有明显谨慎提示；缩减覆盖会导致对应目的地失去该承运商配送方式。
- 结账配送方式主路径：禁运否决 → 可售目的地（空则不限）∩ 承运商覆盖 → 按承运商 `sort_order` 推荐启用中的 ShippingService。
- 费用模板只提供计费公式，不参与到达地区判定；目的地差异化定价通过多条 ShippingService 配置，而非模板内地区矩阵。
- 网站/店铺/渠道可配置可售目的地白名单（与禁运并列）；覆盖命中支持国家优先与祖先命中。
- `<w:theme:address selection="multi">` 用于后台批量选国家/州省/区县。
- Zone/`zone_regions` **已删除**（2.4.18）：结账仅承运商覆盖 ∩ 可售/禁运；不再保留 Zone 兜底。

## 验收标准

- 发货地址与收货地址区域均可在个人中心正常加载。
- 账户菜单/侧栏中「收货地址」出现在「发货地址」之前；打开收货地址可见与顶部「配送至」同源的已登录地址。
- 仅有一条地址时自动为默认（显示默认徽章，无「设为默认」按钮）。
- 空发货地址时显示区分说明，并可跳转到收货地址；空收货地址时可打开新增表单。
- 请求不再出现 `Using $this when not in object context`、HTTP 500 或越权提示。
- 聚焦模板契约测试、PHP 语法检查和浏览器验收通过。
