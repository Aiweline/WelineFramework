### 关键实现

- 线索去重：邮箱 → 公司域名 → 来源 URL 的 SHA-256；重复命中合并证据、`seen_count+1`，不覆盖人工状态。
- 洲/国家：7 洲 + 未知；60+ 国家 ISO2/时区/近似经纬度；国家未知回退 `XX/UNKNOWN`。
- 成本：`ai_model.token_price_input/output`（CNY/1000 token）；运行前 min/typical/max 估算，运行后 token/成本累加，并写 `ai_usage_log`。
- 浏览器桥：ticket 32 字节 hex、2h、单运行；SSE 25s 分片 + 500ms 拉取 + 15s 心跳；POST 仅 JSON；模型参数白名单。
- 扩展：MV3、`<all_urls>` host 权限、无远程脚本/eval；ticket 只存内存、日志脱敏；WASM 负责打分/循环预算/检索槽位。

### 已知取舍

- **SchemaDiff 绕过**：当前框架 `DbSchemaReader::readTablesBatch()` 对“尚不存在的新表”返回空列集合，SchemaDiff 会生成 `add_column` 而不是 `create_table`。本模块 Model 标记 `SchemaDiffExcludedModelInterface`，由 `Setup/Install.php` 用同一个 `SchemaParser` 幂等建表，字段/索引仍只以 Model 注解为权威。后续若框架修复该批量读表行为，可移除排除接口并回归 SchemaDiff。
- 浏览器扩展需手动“加载已解压的扩展”；未做商店签名/自动更新。
- 自动发信、Cron 编排、邮箱验证不在本轮范围。

### 三种模型模式

- `ai_module`：后端 `/bridge/step` 调 AI 模块模型，按 token 计费。
- `local_computer`：扩展直接调本机 Ollama / OpenAI 兼容 `/v1/chat/completions`；本地模型不计费。
- `browser_local`：扩展调 Chrome 内置 Prompt API（Gemini Nano）；模型在浏览器内运行，不计费。
- `RunService::create()` 接受 `model_mode/local_endpoint/local_model/browser_model`，本地模式不再要求 AI 模块模型；`meta_json` 记录模式配置。
- `Bridge::getContext()` 返回模式配置；`postStep()` 对本地/浏览器模式接受 `local_result`（assistant/tool_calls/usage），只记账不调模型。
- 运行页新增三选一标签卡与对应配置面板；扩展 popup 显示模型方式。
- 扩展 manifest 升 1.1.0，新增 `aiLanguageModel` 权限；`host_permissions` 仍为 `<all_urls>`，本地服务需放行 CORS（Ollama 设置 `OLLAMA_ORIGINS`）。
