## 当前有效需求

### `REQ-CRON-0004` 计划任务 CPU 预算声明与 CPU 出让

- 来源与确认：用户要求 cron 允许出让 CPU，每个任务可声明 CPU 额度（默认 1 核 / 最多 30%），并可在后台配置默认值。
- 目标版本：`1.1.0`（`etc/module.php` 由 `1.0.10` 升为 `1.1.0`，requires 增加 `Weline_SystemConfig`）。
- 背景/问题：此前调度子进程对 CPU 无任何上限；多任务并行时单个重任务可长期吃满核，拖慢同机其它站点与常驻服务。既有的准入/容量门禁只管「同时跑几个」，不管「每个跑多猛」。
- 用户与运营场景：运维在后台统一配置中心设定默认额度并观察计量；确有需要的任务实现能力接口自行声明额度；不希望被限速时后台可关总开关，只保留计量观测。
- 业务逻辑（额度口径，唯一权威顺序）：任务行 `weline_cron_task.cpu_count` / `cpu_percent`（非 0 生效，`0 = 未声明`）> 统一配置中心 `cron/cpu/default_count` / `cron/cpu/default_percent` > 能力接口常量 `DEFAULT_CPU_COUNT=1` / `DEFAULT_CPU_PERCENT=30`。额度 = `cpu_count × cpu_percent / 100` 个 CPU 核当量，是「最多占多少」的上限，不是预留。
- 出让机制：`CronCpuGovernor` 以 1 秒 SIGALRM 节拍取 `getrusage(0)`（只算本进程）累计 CPU，按 `need = 已用CPU / budget - 已过墙钟` 判断越界，越界才 `usleep(min(need, cap))`，单次上限 `cap = max(5.0, 2.0 / budget)`。宿主已就绪闹钟先探测并避让，用完在 `finally` 内还原闹钟/handler/异步信号开关。`cron/cpu/enforce=0` 时只前后计量、不装闹钟不睡眠，仍记录「本可让出」时长。
- 范围：`CronTaskCpuBudgetInterface`（新增可选能力接口）、`Service/CronCpuBudgetPolicy`（配置解析与夹紧）、`Service/CronCpuGovernor`（计量与出让）、`Model/CronTask` 两个新列、`Console/Cron/Task/Collect` 落值、`Console/Cron/Task/Run` 包裹业务体、后台系统配置页与列表 CPU 上限列。
- 非目标：不做 CPU 预留/配额调度、不做 cgroup/核绑定、不统计任务内部再 fork 的子进程（计量只取本进程 `getrusage(0)`）、不改变既有「同时跑几个」的准入语义。
- 数据/权限/安全：新列默认值 `0`（来源：`Model/CronTask.php:68-71` 的 `#[Col('int', default: 0, …)]`）。存量行回填结果由项目经理实测（2026-10-29），输出原文如下：
  ```
  information_schema: cpu_count   | default='0' | nullable=YES
  information_schema: cpu_percent | default='0' | nullable=YES
  行分布: cpu_count=0 cpu_percent=0 rows=68
  ```
  即两列 DB 默认值确为 `0`，存量 68 行已全部为 `0/0`，存量任务一律「跟随统一配置」，不产生行为突变。复现途径：`php bin/w db:query` 在非 dev 模式被拒（原文 `This command is only available in development mode!`），故改为直连 PDO、从 `app/etc/env.php` 取 pgsql 连接参数查询（EXIT=0）。后台配置页类级 ACL 为 `Weline_Cron::cron_system_config`（父 `Weline_Cron::system_cron`）。
- 兼容/迁移：不实现能力接口的任务完全向后兼容（默认额度）；`pcntl_*` 或 `SIGALRM` 不可用（如 Windows）时降级为不限速执行并给出可见降级原因，不阻断调度。
- 验收标准：`CronTaskContractsTest` 67 assertions、`CronServiceContractsTest` 68 assertions 全过；列表页展示 CPU 上限列且未声明显示「跟随配置」；后台配置页可读可存三个 `cron/cpu/*` 键；`enforce=0` 只计量不睡眠。
- WebUI/E2E：列表页 CPU 上限列与后台配置页需真实后台复验（尚未执行，见「验收状态」）。
- 依赖与风险：`extends/module/Weline_SystemConfig/Config/backend/cron.phtml` 依赖 `Weline_SystemConfig`；不足 1 秒的任务在首个节拍前已结束，不受节流；实现者在 `execute()` 内自行安装 SIGALRM 会覆盖治理器节拍导致限速失效。

### `REQ-CRON-0003` 域名池/Query 安装状态与 CLI 项目级 cron scope 对齐

- 来源与确认：用户于 2026-10-08 反馈域名池黄条「cron未安装」与实际 crontab 不符。
- 目标版本：`1.0.7`。
- 背景/问题：CLI 以 `Weline_Cron@{BP}` 存 `CRON_SCHEDULE_NAME`，Query 用裸 `Weline_Cron` 回退 md5，名漂移误报；注释掉的 crontab 行也曾被当成已安装。
- 验收标准：`getInstallationStatus(scope=Weline_Cron)` 与 `cron:exist` 同一 cron_name；注释行不算已安装；本机 `cron:install` 后域名池不再误报。
