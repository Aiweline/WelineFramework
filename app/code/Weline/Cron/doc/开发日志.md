## 2026-10-29 — 计划任务 CPU 预算与 CPU 出让（1.1.0）

- **需求**：`REQ-CRON-0004`；用户要求 cron 允许出让 CPU、每任务可声明额度（默认 1 核 / 最多 30%）、后台可配默认值。
- **新增能力接口**：`CronTaskCpuBudgetInterface`（`DEFAULT_CPU_COUNT=1`、`DEFAULT_CPU_PERCENT=30`、`cpu_count()`、`cpu_percent()`）。不实现该接口 = 走默认额度，向后兼容；返回 0/负数/非法值按默认处理。
- **配置策略**：`Service/CronCpuBudgetPolicy` 拥有三键 `cron/cpu/default_count`、`cron/cpu/default_percent`、`cron/cpu/enforce`（`MAX_CPU_COUNT=64`）；`ConfigReader` 懒加载，读配置抛异常时回落默认常量，绝不因配置库不可用中断调度。解析优先级：任务行（非 0 生效）> 统一配置默认值 > 接口常量。
- **出让治理器**：`Service/CronCpuGovernor` 1 秒 SIGALRM 节拍，计量固定 `getrusage(0)`（只算本进程；`getrusage(1)` 会把子进程算进来，实测 30% 跑成 43.9%）；累计公式 `need = 已用CPU / budget - 已过墙钟`，越界才睡 `min(need, cap)`，`cap = max(5.0, 2.0 / budget)`。宿主闹钟先 `pcntl_alarm(0)` 探测、被占用则复原并降级，用完 `finally` 还原闹钟/handler/异步信号开关；`pcntl_*`/`SIGALRM` 不可用时降级为不限速并给可见原因。
- **只计量路径**：`cron/cpu/enforce=0` 时不装闹钟、不睡眠，仍前后取 `getrusage(0)` 与墙钟，`lastStats()` 回报 `cpu/wall/budget/wouldYaw`，让后台能说明「实际用了多少、本可让出多少」。
- **数据模型**：`Model/CronTask` 新增 `cpu_count` / `cpu_percent` 两列，`default: 0`（来源：`Model/CronTask.php:68-71` 的 `#[Col('int', default: 0, …)]`），语义 `0 = 跟随统一配置`；新行无声明即落默认 `0`，因此不会改变未声明任务的行为。存量行回填结果由项目经理实测（2026-10-29），输出原文如下：
  ```
  information_schema: cpu_count   | default='0' | nullable=YES
  information_schema: cpu_percent | default='0' | nullable=YES
  行分布: cpu_count=0 cpu_percent=0 rows=68
  ```
  即两列 DB 默认值确为 `0`，且存量 68 行已全部为 `0/0`，存量任务一律「跟随统一配置」，不产生行为突变。复现途径：`php bin/w db:query` 在非 dev 模式被拒（原文 `This command is only available in development mode!`），故改为直连 PDO、从 `app/etc/env.php` 取 pgsql 连接参数查询（EXIT=0）。
- **收集端**：`Console/Cron/Task/Collect` 未实现能力接口的任务写 `0`（未声明），实现接口的写声明值并夹紧 `1..64` / `1..100`。必须写 0 而不是接口常量：一旦落成行内值，后台 `cron/cpu/default_count` 会被行内值永久遮蔽。
- **执行端**：`Console/Cron/Task/Run::executeWithinCpuBudget()` 包裹业务体，额度按任务行 > 配置默认 > 接口常量解析；降级原因经 `printing->note()` 进 CLI/SSE 日志。顺带按 cron 表达式字符串缓存 `CronExpression`（同一轮多条任务常共用表达式）。
- **后台**：新增 `extends/module/Weline_SystemConfig/Config/backend/cron.phtml`（3 字段声明）、`Controller/Backend/Cron/Config`（类级 ACL `Weline_Cron::cron_system_config`）、`view/templates/backend/Cron/Config/index.phtml`（整模块 `w:config:embed`）；`etc/backend/menu.xml` 父 `Weline_Cron::system_cron` 改为纯分组，子项 `cron_task_listing` / `cron_system_config`；列表页新增 CPU 上限列（未声明显示「跟随配置」）。
- **契约**：`CronTaskContractsTest` 67 assertions、`CronServiceContractsTest` 68 assertions 本机全过。
- 版本：`1.0.10` → `1.1.0`；requires 增加 `Weline_SystemConfig`。
- **国际化边界（未验证项）**：本次新增词条已按库内约定写入 `i18n/zh_Hans_CN.csv` 与 `i18n/en_US.csv`（各 32 条，中文 source / `en_US` 英文 target，UTF-8 BOM 保持）。但这些词条**尚未进合并语言包**：`grep -c "CPU Cap" generated/language/en_US.php` 返回 `0`（exit 1），说明 `Framework/Phrase/DictionaryCompiler` 产出的 `generated/language/<locale>.php` 未包含本次新增 key。因此**英文站当前仍显示中文源串**；需重建语言包（`i18n:collect` / 字典编译）后 English 站才真正生效——该动作属发布动作、写入 `generated/language/**`，不在本次交付范围内，故此项保持**未验证**。
