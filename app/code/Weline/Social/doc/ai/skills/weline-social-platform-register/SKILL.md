# 融媒体口令

提到融媒体、社媒，或某个平台（含缩写），并且是在查号或注册时，先按本技能做。发帖、发图、发视频先读 `weline-social-content-publish`。

## 触发词

- `融媒体`
- `社媒`
- `媒体邮箱`
- `YouTube`
- `油管`
- `Facebook`
- `FB`
- `Instagram`
- `Ins`
- `IG`
- `TikTok`
- `抖音`
- `X`
- `Twitter`
- `LinkedIn`
- `Pinterest`
- `Snapchat`
- `注册社媒`
- `发布到社媒`（发内容时改读 `weline-social-content-publish`）

## 先分清两件事

口令里要有**哪个站**（站名或 code）。对不上站名就问用户，不要拿别的站的邮箱去注册。

**平台**可以点名，也可以不点：

| 口令里的平台 | 做什么 |
|--------------|--------|
| 点了具体平台 | 只处理这些平台。 |
| **没写平台**（只说「注册社媒 / 开号」） | **不要停下来问平台**。按下面「线上支持哪些」取出清单，对该站挨个处理。全部跑完再收口。 |

| 口令 | 做什么 |
|------|--------|
| 查找、用某站的 YouTube/FB 等 | 读该站已有社媒账户。在用且主页还在：反馈账户名和公开主页。被封或没有：按「注册」处理，不要只停在「还没有」。 |
| 发帖、发图、发视频 | 不在本技能里发。改读 `weline-social-content-publish`：只取这个站网站柜里在用的号，按柜中顺序逐个发。 |
| 注册 | 先过上线门槛。不过就停止。过了之后按平台集合逐个处理。 |

每个平台先判状态，再决定动作：

1. **在用**：线上该站已有同 `platform_code`，`status=active`，公开主页仍可打开 → 回报并跳过，不要再开一个。
2. **被封或已禁用**：`status=disabled`，或主页明确停用/封禁/不存在 → **用 `contact@{官网域名}` 新开一个号**。旧记录保持禁用，不要把旧行改成新号。新号成功后再「写入并激活」。
3. **站柜有主页、线上没有、主页没被封** → 不要去平台注册页。直接「写入并激活」。
4. **两边都没有** → 用 `contact@{官网域名}` 新开；成功后再「写入并激活」。

上面四条以「先打开后台看」里看到的范围社媒为准。接口没返回账户，不能当成范围里没有。

平台别名：youtube、facebook / fb、instagram / ins / ig、x / twitter、tiktok、linkedin、pinterest、snapchat、bluesky。线上注册表里的其它 code 以该站后台平台库页面上的 `code` 为准。

## 先打开后台看（硬）

判断「范围里有没有号」「开号清单是不是空的」「该不该再开」之前，必须打开**该站已登录的融媒体后台**看页面。`listPlatforms`、`getWebsiteDefaultAccounts` 和本机代码不能代替这一眼。

1. 上线门槛过了之后，用本机 Google Chrome（chrome-devtools）打开该站后台融媒体页。先开或复用标签组 **`AI·社媒注册`**，不抢焦点，不进隔离上下文。建不出组就停，不要改口说已经看过。
2. 页上的「当前配置范围」必须对上站柜里的这个站（用 `listWebsites` 的 `code` 对页面上的站点范围）。对不上就停，不要拿别的站的范围下结论。
3. 看「范围社媒」里实际勾选的账户：平台、账户名、是否勾选。这是该站范围里有没有号的依据。
4. 再看「平台库」上每个平台有没有注册按钮，以及按钮打开的地址。接口里 `account_signup_url` 为空，只说明接口没带出地址，不能据此说范围是空的，也不能据此说没有可开的平台。
5. 页面打不开、未登录、或标签组建不出来：停，并写明没看成。禁止写成「范围为空」或「没有可注册平台」。

## 线上支持哪些（不要写死清单）

口令没点名平台时，开号范围只来自**刚看过的该站后台平台库**，不要用本技能或记忆里的固定九个平台。

1. `welineSocial.listPlatforms` 只作对照，不能单独当结论。
2. 页面上有注册按钮、且地址是 `https` 的平台才进入开号清单。只配 bot token、webhook、api key、页面上没有注册按钮的不进。
3. 记下每条的 `code`、`title`、`auth_modes`、`supports_one_click_auth`、页面上的注册地址、`docs`。
4. 注册页或 `docs` 没写清**当前**要填的账号种类（邮箱、手机、用户名，还是跳到别的登录）时，再检索该平台官方帮助页，按当下页面操作。不要把某一次查到的点击步骤写进本技能。

`{email}` 换成下面的 contact 邮箱。只要 `https`。

## 上线门槛（注册必过）

1. 用口令里的站名对 `websites/README.md`，锁定 `websites/<site>/`。对不上就问用户，不要猜。
2. 读该柜 `server.md`。必须写有主用 SSH Host、应用根，以及官网域名。没有 `server.md`，或写明还没有生产站：告诉用户这站还没上线，停止。不要打开浏览器。
3. 官网从**源站**能通：SSH 到主用 Host，在机上请求 `127.0.0.1` 并带官网 `Host`。接受 200、302、308。禁止从本机对公网域名做 curl。不通就停止。
4. 邮箱域名必须是 `server.md` 里的官网域名，不是本机测试域名。

## 用哪只邮箱、密码放哪

新开和被封后重开，注册邮箱一律是 **`contact@{官网域名}`**。不要再为开号去建 `social-{网站code}@`。

读信身份在该应用根机器的 mail-reader 凭据里，只读 JSON 的 `username`（以及需要时的 `base_url`）。凭据在 `/etc/weline/mail-reader.credential`，或 `{应用根}/var/mail/mail-reader.credential`。`sealed_secret` 不要读、不要打印、不要复制。

`username` 为 `contact@{官网域名}` 时，验证信就在这只收件箱里，可以直接读。这不是故障。

账号和密码只给执行开号的这一步，落点只有站柜保险箱：

| 要填的东西 | 从哪拿 |
|------------|--------|
| 注册邮箱 | `contact@{官网域名}` |
| 这个平台的新登录密码 | 开号时生成一次，立刻写入 `websites/<site>/credentials/social-accounts.md`。填表只读这一份。 |
| 快捷注册所依赖的父账号 | 同一保险箱里该父身份的邮箱和密码。见下一节。 |

禁止把密码写进技能、源码、模块文档或会进 Git 的文件。禁止在对话里贴出密码。

## 快捷注册（依赖另一个账号时）

有些平台的开号页不是自己收邮箱，而是「用 Google / Apple / Facebook 继续」，或 `supports_one_click_auth=true` 且 `account_signup_url` 的主机不是这个平台自己。

1. 先看出注册页实际跳到哪个身份。YouTube 不走这条新开父账号的路，见下一节。
2. 开页之前，从站柜 `credentials/social-accounts.md`（或该站专门的登录保险箱）读出**那个父账号**的登录名和密码，用它完成快捷注册。
3. 保险箱里没有这个父账号：不要现编密码，不要改用别的站的账号。这是该平台卡住，按下一节继续清单里的下一个平台。Google 父身份不适用本条，不要为此去注册 Google。
4. 父账号本身已被封：用 contact 邮箱新开那个父身份，记入保险箱，再用它去开下游平台。父身份也开不下去时，同样只卡住这个平台。Google 不新开。

## YouTube：只建渠道，不新开 Google

YouTube 账号就是 Google 账号。**不要**为 YouTube 注册新的 Google 账号，也不要用 contact 邮箱走 `accounts.google.com` 的开号（含手机号、扫码、接码）。开号页如果落到新 Google 注册，停掉这一页，不要填下去。

改用本机 Chrome 里**已经登录的主 Google 账号**，只建立 YouTube 渠道：

1. 不要退出这个主账号，不要切换去新建 Google，不要改用 contact 再注册。
2. 主账号下已经有该站的渠道、公开主页还在：跳过，不要再开一个。
3. 还没有该站渠道：在这个主账号上新建渠道。渠道名、句柄、简介、官网、头像用「按站点资料填完整资料」里这一站的公开材料。
4. Chrome 里没有已登录的 Google：这个平台卡住。不要现开 Google，继续清单里的下一个平台。
5. 保险箱记下：依赖已登录的主 Google 建渠道。登录身份写这个主账号，不写成新开的 contact Google。密码栏写「沿用主账号，未新开」。

这条不把某一个站的邮箱写成所有站的主 Google。主账号是这次 Chrome 里已经登录的那一个，不是现场注册出来的。

## 人机验证：截图、认出、点

出现勾选框、图片题、滑块或「我不是机器人」时，不要停下来请用户，也不要用打码平台。当场做完再继续这个平台的开号，不要把整批停住。

1. 截这个验证区域的图。勾选框和图片题经常在跨域 iframe 里。页面脚本点 iframe 外壳，点不进里面的勾选。截图用浏览器这一层对这块区域的截图，并读这张图。不要只靠页面上的文字判断过不去。
2. 读图：题目要选什么，哪些块该点。
3. 用浏览器坐标点下去，不要用页面脚本去点 iframe 里面。勾选框点左侧方框。点开图片题后，再截图、再认、再点对应的块，然后点验证或下一张。
4. 点完看这一步有没有过去。换成新题，就再来一轮截图、认出、点击。不要中途停下来等用户。
5. 同一道题这样点过仍过不去：把这个平台记成卡住，立刻继续清单里的下一个。没有下一个，也只在收口写明，不要停在半路等人。不要把没截图、没点过的人机验证写成已经处理，也不要假装注册完成。

邮箱里的验证码不是人机验证，仍从 contact 收件箱读。

## 单平台卡住不中断整批

口令覆盖多个平台时（没点名平台，或点了多个），每个平台单独收口。某一个平台卡住，只把原因记到该平台的站柜草稿，然后立刻处理清单里的下一个。不要停下来等用户，也不要因为这一个没开成就结束本轮。

卡住包括：

- 人机验证已经按上一节截图、认出、点过，这一道题仍过不去。没截图就当卡住，不算处理完。
- 注册页写明要到手机应用上开，网页继续不了。
- 这个 Chrome 里该平台已经登录的是别人的号，不是本站 `contact@{官网域名}`。不要退出那个号，不要把它写成这个站的号。YouTube 除外：就用已登录的主 Google 建渠道，见「YouTube：只建渠道，不新开 Google」。
- 这个平台要快捷注册，但保险箱里没有它的父账号。
- 平台要求的资料项，这一站没有对应的公开材料。不要编。
- 这个平台资料已填完，但写入账户或并入范围失败。先按「写入并激活」把该平台的范围关系恢复好，再继续下一个平台。不要带着一份写坏的范围去开下一个号。

卡住的页留在标签组 `AI·社媒注册` 里。草稿写明：平台、卡在哪、没有写入生产。

全部待开平台都看过之后再收口。收口分开写：已在用并跳过、本轮开成并写入、卡住及原因。人机验证不放进「请用户协助」。

只有站点级门槛才整批停止：站没有 `server.md` 或还没上线、官网从源站不通、标签组建不出来、融媒体后台没看成、页面上的范围对不上这个站。这些不是某一个平台的问题。

口令只点了一个平台时，人机验证仍先截图、认出、点击，不要一出现就停下来请人。点过仍过不去，才在收口写明。其它卡住且没有下一个平台时，才停在该平台，请用户在这个 Chrome 窗口里协助。

## 开号

1. 用**本机 Google Chrome**（chrome-devtools）打开该平台的 `account_signup_url`。先开或复用标签组 **`AI·社媒注册`**，页只放进这一组，也只操作这一组。不要开到用户看不见的隔离上下文。不要用编辑器内置浏览器去填第三方注册页，不要用 AppleScript 把 Chrome 抢到前台。标签组何时删，见本节末尾。
2. 表单填 contact 邮箱，密码用保险箱里刚写下的那一次。要快捷注册时改填父账号。
3. 验证码从 contact 收件箱读，不要换邮箱。
4. 页面上普通人能点的按钮可以点。出现人机验证：不要用打码平台，按「人机验证：截图、认出、点」做完。不要停下来等用户，也不要把其余平台停掉。
5. 平台侧账号建出来之后，立刻做下一节「按站点资料填完整资料」。必填项没填完，不要写入，也不要说这个平台开成了。资料填完，或该平台没有资料页，再做「写入并激活」。这个平台写入并激活完成后，再开清单里的下一个。

## 按站点资料填完整资料

账号建出来不等于注册完成。邮箱或快捷登录通过之后，该平台当前页或向导里还要求填写的项（名称、用户名、头像、简介、官网、分类、语言、地区等），必须在同一轮用**这一站**的公开材料填完，再进入「写入并激活」。资料留空、留着平台默认占位，或填成别的站，都不算这个平台开成。

先收一份只属于这个站的资料，再对着平台当前要填的项填。不要先编再找出处。

| 平台要的 | 从这一站拿 |
|----------|------------|
| 显示名 / 品牌名 | 站柜 README 的站点名，或官网页头实际品牌名。两边不一致时以官网页头为准。 |
| 用户名 / 句柄 | 站柜对外清单或官网已经在用的品牌句柄。没有现成句柄时，用这个站公开使用的站点名，不要编成人名，也不要套别的站。被占用时，只加上官网域名里能区分这个站的那一段。 |
| 官网 / 网站 | `server.md` 的官网域名，写成 `https`。 |
| 简介 / 关于 | 官网关于页或首页上已经公开的介绍，按输入框长度截短。不要另写一套广告。 |
| 头像 / 横幅 | 该站柜里已有的社媒图或品牌 Logo。柜里没有，就用官网正在用的 Logo。不要现做另一套视觉，不要拿别的站的图。 |
| 分类 / 业务类型 | 按官网实际在卖、在讲的品类，选最接近的一项。 |
| 联系邮箱 | `contact@{官网域名}`。 |
| 语言 / 地区 | 官网默认店面的语言，和这个站对外经营的地区。 |

1. 当前这一屏标成必填、或不填就不能继续的项，必须用上表填上。某一项对不上来源：这个平台卡住，不要编，不要进入「写入并激活」。
2. 同一屏上的网址、简介、头像，资料里有就一并填上。资料里没有的选填项留空。
3. 填完再核对：名称、网址、头像、简介仍是这一站。串了别的站，先改回来。
4. 平台没有资料页，建号后就是主页：记下「该平台没有要求资料」，可以进入「写入并激活」。不要为了走本节去找一个不存在的表单。
5. 不要把某一次在某个平台上的点击顺序写进本技能。页面变了，就按当前页上的要求填。

## 写入并激活（资料填完后的闭环）

写入只发生在该站 `server.md` 的**应用根**上。调用 `welineSocial`。不要写到当前打开的本机框架库，也不要写到别的站。

用站柜里的网站 code 对 `listWebsites` 的 `code`，锁定 `website_id`。对不上就停，不要猜 `website_id`。

1. `saveCredentialAccount`。这一步就是写入该站后台「账户管理」。没有这条账户，不能做范围绑定，后台也无法按这个号操作或打开主页。
   - `platform_code`：与线上注册表 `code` 一致。
   - `account_name`：平台上的显示名或句柄。
   - `profile_url`：公开主页，必须是 `https`。账户列表靠这个地址打开社媒账户。
   - 已有公开主页：`widget_enabled=true`，`publish_enabled=false`。
   - 还没有公开主页：不要开 `widget_enabled`。告诉用户缺主页，先不要绑定范围。
   - 开号阶段不要开 `publish_enabled`。
   - 登录邮箱是 `contact@{官网域名}`。YouTube 渠道例外：登录身份是已登录的主 Google，不写成 contact 新开的 Google。密码不要放进这条接口的源码或仓库；平台口令只在站柜保险箱。
   - 写入后回读账户列表，必须能按平台和账户名找到这条，且主页是 `https`。找不到：不要绑范围，按「单平台卡住不中断整批」记下这个平台，再处理下一个。
2. 绑进这个站的范围，并且**并入**已有账户，不要覆盖。
   - 先 `getWebsiteDefaultAccounts`（`website_id`，不要 `publish_only`）。
   - 把上一步返回的 `account_id` 追加到已有 `account_id` 列表。被封的旧号不要放回这份列表。
   - 再 `saveWebsiteAccountDefaults`，传入这份**完整**列表。
3. 有公开主页时：`listWidgetAccounts` 里必须有这条，且 `profile_url` 对得上。
4. 回填站柜：
   - `credentials/social-accounts.md`：平台、账户名、公开主页、登录邮箱、密码、是否依赖快捷注册以及父账号名称。
   - 站柜 README 的对外清单只写公开 URL，不写密码。
5. 回读该站「范围社媒」。
   - 再调一次 `getWebsiteDefaultAccounts`（不要 `publish_only`）。
   - 返回的 `account_id` 必须仍包含写入前的全部在用 id，再加上新号。少了任何一个：先用写入前的备份恢复范围关系，再重写。
   - 账户管理里有这一行，并且当前范围勾上了它，才算写回完成。只有账户、没勾范围，还不能从该站范围里操作这个号。

向用户回报：站、每个平台的账户名、公开主页、要求的资料是否已按该站填完、账户管理里有没有、范围社媒是否勾选，以及卡住的平台和原因。密码只说「已写入站柜保险箱」。还有平台没跑完，或开成的号资料未填完、账户/范围缺一，结论写未完成。全部待开平台都已处理，且开成的号都填完该平台要求的资料、写入并勾上范围，才算这轮收口。

人机验证不留着等人点。还等用户处理的是别的卡住原因时，收口留下标签组 `AI·社媒注册`。没有待处理的页，再删掉该组。

## 权威

| 层 | 位置 |
|----|------|
| 范围里有哪些号 | 该站后台「范围社媒」页面上勾选的账户 |
| 平台清单 | 该站后台「平台库」页面；`listPlatforms` 只作对照 |
| 注册页 | 平台库按钮上的地址（`account_signup_url` 只是接口字段，空了不等于没有按钮） |
| 邮箱 | `contact@{官网域名}`；验证信走 mail-reader 的 contact 收件箱 |
| 密码 | `websites/<site>/credentials/social-accounts.md` |
| 站点资料 | 站柜 README 的站点名、`server.md` 的官网域名、官网页头/关于页/首页公开介绍、该站柜已有社媒图或官网正在用的 Logo |
| 填资料 | 账号建出来之后，按平台当前必填项用上一行的材料填完，再写入 |
| 写入并激活 | `saveCredentialAccount`（账户管理）→ 回读能找到该号和 https 主页 → `getWebsiteDefaultAccounts` → `saveWebsiteAccountDefaults` → 回读范围 id 不丢旧号且含新号 |
| 硬规则 | `social_scope_mailbox_for_platform_register` |

## 禁止

- 没打开该站融媒体后台页面，就说范围是空的，或说没有可开的平台。
- 账号建出来就收口，不填该平台要求的名称、简介、头像、官网等资料。
- 用别的站的名称、简介、Logo、网址填这个号，或站点没有的资料现场编造。
- 注册成功后不写入「账户管理」，或账户里没有可打开的 https 主页。
- 只写入账户、不并入当前范围，就说该站已经能操作这个号。
- 用一份写死的平台清单代替该站后台平台库页面。
- 每个平台各用一个邮箱，或把邮箱、密码写进源码、技能、会进 Git 的文件。
- 在用且主页还在的号再开一个。
- 被封之后仍只回报旧号、不去用 contact 邮箱新开。
- 口令没写平台时停下来问「注册哪个」。
- 遇到人机验证停下来请用户，或只用页面脚本点跨域验证框、不去截图再用浏览器坐标点。
- 一个平台卡住（人机验证点过仍过不去、已登录他人号、平台要求用手机开号、缺这个平台的父账号、这个平台写入失败）就停止其余平台。
- 把某一个站的邮箱或父账号当成所有站的默认。
- 站柜没有 `server.md`、或官网从源站不通，仍去注册。
- 快捷注册缺父账号时现编密码或借用别的站。
- 为 YouTube 新注册 Google 账号，或用接码平台应付手机验证。YouTube 只在已登录的主 Google 上建渠道。
- 平台号已经注册成功，却不写入该站线上后台、不回填站柜。
- `saveWebsiteAccountDefaults` 只提交新账户，把该站已有社媒绑定关掉。
- 开号阶段打开 `publish_enabled`，或把账户写到别的站、写到本机测试库。
