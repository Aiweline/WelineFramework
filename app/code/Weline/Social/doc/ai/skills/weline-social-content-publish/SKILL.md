# 按网站柜发布社媒内容

用户要发布内容、发帖、发图或发视频时，先确定是哪个站，再只使用这个站网站柜里已经在用的社媒账户，按柜中顺序逐个把这一次的图片或视频发出去。

查号、注册、补资料仍走 `weline-social-platform-register`。本技能不新开账号。

## 账号从哪来

1. 口令里要有哪个站。对不上站柜目录就问，不要拿另一个站的柜。
2. 读这个站的 `websites/<site>/README.md` 对外清单，和 `websites/<site>/credentials/social-accounts.md`。
3. 发布名单只收柜里已经在用的行：有 `https` 公开主页，并且不是「开号中 / 未开 / 别人的登录」。
4. 顺序按柜里的先后。不要另编平台，不要加入 `fake_browser`，不要把别的站的号插进来。
5. 密码留在保险箱。不要写进回复、帖子、源码或会进 Git 的文件。

融媒体后台的范围勾选用来核对这是不是这个站的号。柜里没有的平台，不要因为后台里还有别的行就拿去发。

## 逐个发布

一次任务只发一份内容。对名单里的每个账号做完再下一个。一个账号失败，记下原因，继续下一个。

1. 图片或视频只用这个站柜里已有的社媒图、品牌图，或用户这次给出的素材。没有素材就停在这一次，不要现做另一套视觉，也不要拿别的站的图。
2. 浏览器入口按下段口径（默认 ego；用户点名 Chrome 时才走本机 Chrome + 标签组 `AI·社媒发布`）。只操作本任务自己的页面，不要把窗口抢到前台。
3. 打开发这个账号自己的平台页，用这个号把图片或视频发出去。平台只收图就发图，只收视频就发视频，两者都收时跟用户这次给的素材走。
4. 浏览器里已是别人的号：记下并跳过，不要退出别人的号。
5. 这个号还没有登录页：记下并跳过，不要为了发这一条去注册。
6. 发出后记下该平台上的公开帖子地址。写回这个站的保险箱状态行，不写密码。

浏览器入口按仓规 `browser_automation_uses_ego`：默认 ego（CLI 写法与 shadow DOM 坑见 `app/code/Weline/Ai/doc/规则/00-MCP调用与会话.md` §8b / §8b.1）；用户点名 Chrome、或需要复用已登录会话时才走「本机 Chrome + 标签组 `AI·社媒发布`」。同一任务只用一种入口，不在两边来回切。

## 登录态判读（先证明提交真的发生过，再谈凭据对不对）

1. 判「登录失败」前必须分层排除：页面没加载好 → 填值没进 shadow DOM → 提交没触发 → 凭据错 → 平台挑战。前四层没排除完，不许写「密码失效」。
2. 填完先读回值（递归穿透 shadow root，读 `value` / `value.length`），再点提交；读回 `null` 是读法错，不是填失败。
3. 提交后的判据是**落到的 URL 与新出现的区块**（如落到 `/user/<name>/…`），不是「有没有红字」。**无错误文案 ≠ 密码错**——静默弹回登录页通常是平台挑战，不是凭据问题。
4. 回读长度要和柜里凭据的长度比一下；对不上说明柜里存在新旧两版密码，先定位是哪版，不要盲试。
5. 一个账号最多试 3 次（回读值 → 柜内凭据原文 → 账号名/邮箱两种形态）；三次都弹回就记 `blocked:平台挑战`，停手，不改柜内密码。
6. 凭据只从该站 `credentials/social-accounts.md` 读，不猜、不从别站搬。
7. 要清登录态只按 origin 清（`Storage.clearDataForOrigin` + `cookies`），一次一个站点；不要清整个 profile（全体站点一起掉登录）。
8. 结论里不许把「浏览器里已是别人的号」「登录页不存在」「平台挑战」合并写成「凭据失效」。

## 平台形态与社区边界（先读规则，再决定投不投）

1. 社区型渠道（Reddit 类）发布前**先读该社区规则**：`/r/<name>/about/rules.json` + 置顶的商家 / 买卖（BST）帖。原文写 `No ads or self-promotion`、或 `no shops, resellers, or drop-shippers` 的，**不投**——这类违规后果是删帖 + 封号 + 域名在整个 subreddit 被拉黑，不是「效果不好」。
2. 主页帖不等于社区帖：`/user/<name>/submit` 只触达关注者，不能当社区曝光算业绩；投过就在报告里如实写渠道性质。
3. 先验形态再填内容：逐个试 file input 并检查页面是否出现附件预览；无预览 = 该页收附件（Reddit 主页帖仅文本），改发「文案 + 链接」，不要反复重试。
4. 视频型平台（YouTube / TikTok / IG）与文本型平台（X / Mastodon / Reddit）分开对待：同一份成片，文本型只发「文案 + 链接」，不硬塞视频。
5. 内容里有落回本站页面的链接时，先确认本站动态路由不是维护模式（首页 200 可能是整页缓存静态命中，不能当站点正常）。

## 公开性复核（「看不见」不等于「被删」）

1. 发布后用该账号视角打开公开地址，或在页面内 `fetch(<permalink>.json?raw_json=1)` 读回，`removed_by_category`、`author`、`over_18`、`subreddit_type` 几项都要看。
2. 从本机 curl 平台页得到 403 / HTML 是反爬，**不能判成删帖或限流**；拿不到内容时不许写「已删除」。
3. 复核时把中文 slug 直接拼进 URL 会报 `'ascii' codec can't encode`，用短链（如 `redd.it/<id>`）或 ASCII 地址。
4. 验收脚本的 WARN（平台 400/403、编码告警）进报告作为已知限制，不改验收脚本去消警告。

## 不要做

- 不要在本技能里注册、开邮箱、改范围绑定，或打开 `publish_enabled`。
- 未开发布的账户不要送进 `createPublishBatch` 或发布队列。已开发布且凭据检测通过的账户，才可以走融媒体发布队列。
- 不要从本机对生产公网域名做 curl。
- 一个平台卡住时，不要停掉名单里其余账号。
- 不要把「平台挑战 / 未登录」写成「凭据失效」而停掉其余账号。
- 不要在禁自推广的社区投商家内容；不要用 curl 403 当删帖证据。

## 收口

按柜中顺序写出每个账号：已发出的公开地址，或跳过原因。还有账号没处理，结论写未完成。密码只说「在站柜保险箱」。

跳过原因只用这几类，不自创形容词：`未登录`（含平台挑战）、`无登录页` / `页面不收附件`、`社区禁自推广`、`浏览器已是别人的号`、`账号不存在`。每类附一句可复核的观察（落到的 URL、规则原文、`removed_by_category` 值、回读长度）。
