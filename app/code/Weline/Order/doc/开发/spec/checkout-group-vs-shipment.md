# 结账组 vs 发货记录：术语与边界

status: ready-for-ops  
owning_module: Weline_Order（组/子订单叙事）+ Weline_Shipping（本单发货槽）

## 术语表（全站钉死，禁止互叫「拆单」）

| 层级 | 对外名称 | 含义 |
|------|----------|------|
| CheckoutGroup | **结账组**（展示号 `G-` + uuid 前 8） | 顾客「这一笔」；财务/客服总入口 |
| Order | **子订单**（组内仅 1 张时可称「订单」；组 ≥2 必须标「子订单」） | 履约/库存责任原子 |
| OrderShipment | **发货记录** | 挂在子订单上；一单可多笔；追踪挂在发货行 |

## 何时拆子订单 vs 同单多发货

- **拆子订单**：分仓 / 分主体等责任切开（如 `split_key=wh:{仓}`）。运费挂在 `is_shipping_charge_owner` 那一张（DEC-015）。
- **同单多发货**：同一子订单多条 `OrderShipment`（分批发货、多运单）。能同单多发货就不要仅为「多运单」再拆子订单。

本规格**不改** `FulfillmentSplitPlan` 触发条件；只约束界面叙事与读模型投影。

## 读模型

- `CheckoutGroupSiblingPresenter`：组展示号、同组兄弟、子订单 x/N、运费归属、本单/组级发货计数。
- 后台列表/详情与账户列表共用同一字段语义。
- Shipping 发货槽标题：「本单发货记录」+「共 N 笔」；N≥2 时强调「同单多笔发货，非结账组其他子单」。

## 验收要点

- 2 子订单 × 各 1 发货：组导航 + 各自发货不串组。
- 同一子订单第 2 条运单：后台与个人中心均显示 2 行；组级发货计数含该增量。
