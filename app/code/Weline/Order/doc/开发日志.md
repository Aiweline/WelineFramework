## `REQ-ORDER-0001` — 通用订单支付后状态补全

- 默认 `OrderPostPaymentHookInterface` 已恢复为 `OrderPaidStateHook`，只依赖
  `OrderPaidContext` 与 Order 自有持久快照，不引用具体支付渠道 Model/Service。
- 首次支付成功按合法状态机推进 `pending → processing → paid`，并只派发一次
  `Weline_Order::order_paid`；重放保持 paid/version 不变。
- `AbstractModel::load()` 身份映射已按框架 request ID 分桶，并在对应
  `RequestContext` 清理时删除；CAS 后读取持久 post-image，避免 WLS Fiber
  跨请求串用陈旧订单。
- 确定性证据：Order Unit `94 tests / 593 assertions`（4 个既有 incomplete）；
  Facade DB Integration `3 / 50`；RequestContext Fiber `7 / 47`；聚焦通用支付、
  同事务连续 CAS、跨 request ID 隔离 `5 / 34`。
- 本次是后端契约修复，无新增 UI；`REQ-ORDER-0001` 的支付成功页到账户订单
  真实 WebUI 全链仍随既有 Browser 验收项执行，不以单元测试冒充。
