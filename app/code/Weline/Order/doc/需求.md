## 当前有效需求

### `REQ-ORDER-0001` 订单公开 Facade 与支付后通知

- 来源与确认：现有 `facade-api.md`、`OrderFacadeInterface` 和模块源码，2026-08-17 建立基线。
- 目标版本：`2.12.4`
- 背景/问题：Checkout/Payment 不得引用 Order 内部 Model/Service。
- 用户与运营场景：结账创建订单、读取投影并在支付成功后通知 Order 推进状态。
- 业务逻辑：`create` 是新 CheckoutGroup/Order 唯一 writer；`get` 按 UUID 返回只读投影；`notifyOrderPaid` 从持久事实推进支付后状态。
- 范围：Facade 接口、实现、幂等和只读投影。
- 非目标：不向跨模块调用方暴露 Order Model。
- 数据/权限/安全：金额、Scope 和 customer owner 来自持久快照。
- 兼容/迁移：保持现有公开接口。
- 验收标准：支付成功只通知一次且订单可在账户中读取。
- WebUI/E2E：支付成功页和账户订单显示同一订单状态/金额。
- 运营与支持影响：订单列表是支付后事实核对入口。
- 依赖与风险：依赖 Payment/Customer/Website 发布契约。

### `REQ-ORDER-0002` 个人中心订单隔离与 WLS 请求安全

- 来源与确认：用户要求个人中心闭环和正式商城审查；2026-08-17 继续执行。
- 目标版本：`2.12.5`
- 背景/问题：账户 Hook 必须只展示当前顾客与 Website 的订单，且 WLS 长进程不能用 `$GLOBALS` 保存一次请求渲染状态。
- 用户与运营场景：登录顾客进入个人中心订单列表/详情，只能看到自己的订单；并发请求不会互相污染渲染状态。
- 业务逻辑：订单列表以当前 customer+website 投影加载；详情 UUID 必须先属于该列表才解析；模板不写进程全局可变标记，重复渲染控制使用请求级 Gate/Context 或现有 Hook 生命周期。
- 范围：账户 Hook、详情 Resolver 调用和回归测试。
- 非目标：不创建第二套个人中心或主题专属订单数据源。
- 数据/权限/安全：越权 UUID 返回空/不可见；不得泄露其他顾客订单；不得使用 `$GLOBALS`、静态可变请求状态。
- 兼容/迁移：无数据迁移；保留既有 Hook 名和账户模板契约。
- 验收标准：源码无 `$GLOBALS['__weline_order_account_sidebar_content_rendered']`；当前账户列表/详情正确，越权详情不可见。
- WebUI/E2E：登录→订单列表→详情→返回；另一身份/无权限 UUID 不显示订单详情。
- 运营与支持影响：无新增配置。
- 依赖与风险：依赖 Customer 账户投影和主题 Hook 可见性控制。
