# 文档组织与入伍门禁（轮次收紧）

> **用法**：整理或新增文档时，**先过本门禁**再落盘。禁止先堆文件再事后分类。  
> 配套索引：[文档索引.md](./文档索引.md) · 橱窗说明：`dev/docs/README.md`

## 轮次策略（HARD）

| 轮次 | 目标 | 通过标准 |
|------|------|----------|
| **R1 高层入伍** | 钉死四层准入；错误类**禁止入仓/禁止入权威树** | 下文「准入表」生效；新稿先问属于哪一层 |
| **R2 橱窗层** | `dev/docs/` 只留导览/多语/guides/fix/部署/api | 无站点私案、无 team、无大全圣经、无 AI 流水账 |
| **R3 权威层** | `app/code/*/doc/` 只留契约与近窗日志 | 无 `doc/开发/team`；`开发日志` 遵守近窗；spec 在归属模块 |
| **R4 工作层** | `dev/session\|team\|tmp` 承接临时物 | 默认可丢；不入 Git 当规范 |
| **R5 引用收口** | 死链/旧路径清零；契约绿 | 索引与技能路径可解析 |

**递推规则**：上一轮未通过，不得开下一轮「大扫除」。每一轮先 **拒收/迁出违规入伍**，再整理该层存量。

## R1 准入表（先阻止错误入伍）

| 内容类型 | 允许落点 | **禁止**落点 |
|----------|----------|--------------|
| 模块需求/现状/开发日志/耐久 spec/指南 | `app/code/{V}/{M}/doc/` | `dev/docs/`、仓库根、`archive/` |
| AI 硬规则 / 交付流程 / 技能正文 | `Weline/Ai/doc/`、`doc/ai/skills/` | `dev/docs/ai`、`dev/docs/archive` |
| 宿主指令 | `dev/ai-command/` | 模块 `doc/`、橱窗根 |
| 对外入门、多语 README、架构导览 | `dev/docs/{weline,readme,assets}/` | 模块 doc |
| 通用操作/测试指南 | `dev/docs/guides/`、`dev/docs/fix/` | 写死某站域名的诊断长文 |
| 工程会话 / team 纪要 / channel | `dev/session`、`dev/team` | **`app/code/*/doc/开发/team`**、橱窗 |
| 截图证据 / 一次性 dig / 裁切旧日志 | `dev/tmp/` | 模块 doc、橱窗、Git 权威树 |
| 站点私有运维笔记 | `websites/<site>/` | `dev/docs/fix/`、框架模块 doc |
| AI 流水账、重复收口、实施总结草稿 | **不入伍**（或只进 `dev/tmp`） | 任意权威/橱窗路径 |
| 过期「框架大全」/旧版本计划堆 | **不入伍** | `dev/docs/`（含 archive 堆料） |

### 开发日志近窗（权威层附属门禁）

- `doc/开发日志.md` **只保留近窗**（建议 ≥ 最近 14～30 天，或按体积二次收紧）。
- 更早条目迁 `dev/tmp/devlog-archive/`（gitignore），**禁止**为「留痕」无限追加却从不裁剪。
- 自动快照 `AI-INDEX.md` / `功能现状.md`：可保留，**禁止**手改当需求正文。

### Agent / 文档工程师入伍检查（写前三问）

1. 这是**契约**还是**过程产物**？过程 → `dev/team|session|tmp`。  
2. 是否**绑定单一拥有模块**？是 → 该模块 `doc/`；跨模块导览 → 橱窗；AI 规则 → `Ai/doc`。  
3. 是否**站点私有**？是 → `websites/<site>/`，禁止进框架橱窗。

任一项答不上来 → **停笔**，先定层再写。

## 与既有硬规则的关系

- `module_doc_forbids_ephemeral_work_artifacts`：禁止临时资料进模块 doc（本门禁 R1/R3 具体化）。  
- `documentation_engineer_owns_durable_docs`：耐久正文只由文档工程师写模块 `doc/`。  
- 冲突时以 MCP `hard_constraints` 与本仓 `Ai/doc/规则/` 为准；本文件是**落盘分类操作门禁**，不另造工程流程。
