## 当前有效需求

### `REQ-AI-0001` 场景图像生成参考媒体契约

- 来源与确认：用户于 `2026-08-11` 确认 PageBuilder 应参考给定视觉样例生成高质、背景透明的 Logo，并确认把通用参考媒体边界同步到官方框架仓库。
- 目标版本：`1.1.3`
- 背景/问题：`ScenarioImageGenerationGateway` 的 provider-neutral media allowlist 会过滤调用方提交的 `image`，导致已在会话摄入层选择的参考图无法到达图像生成 Provider；仅靠文字描述难以稳定复现参考图的金属倒角、酒红珐琅和徽章层次。
- 用户与运营场景：PageBuilder 或其他已发布接口调用方按场景发起图像生成时，可以在媒体契约中附带一个参考图值；运行时仍由场景配置决定模型、Provider 和账号。
- 业务逻辑：
  1. `ScenarioImageGenerationGateway::generate()` 从 `$mediaContract` 仅保留显式 allowlist 字段。
  2. `image` 是 provider-neutral 媒体字段，必须原样进入 `AiService::generateImage()` 的 `$params`。
  3. `model`、`model_code`、`provider`、`account`、`endpoint`、`api_key` 等路由或敏感字段继续在任意嵌套层级 fail-closed；新增 `image` 不得绕过该校验。
  4. 无 `image` 的既有文生图调用保持原行为。
  5. 参考图选择、背景透明化、Logo 文字策略、OCR/Vision 验收和精确品牌字合成属于调用模块；`Weline_Ai` 不引入 PageBuilder 业务依赖。
- 范围：通用 `image` 媒体参数透传、聚焦 PHPUnit 回归测试、公开契约文档。
- 非目标：不在核心模块实现 Logo 设计、去背、OCR、Vision、PHP 品牌字排版、模型切换、Provider 切换或账号修复；不把 `GuoLaiRen/PageBuilder` 代码合入框架仓库。
- 数据/权限/安全：不新增持久化字段、权限或凭据；调用方与下游 Provider 继续负责参考图内容、URL/字节格式及大小的既有校验。路由字段禁入规则保持不变。
- 兼容/迁移：纯向后兼容的可选媒体字段；无数据库、Model Schema 或路由迁移。`etc/module.php` 本次保持 `1.1.2`，目标版本仅作开发追踪，待正式发布流程决定版本文件。
- 验收标准：聚焦测试证明 exact `image` 值到达 `AiService::generateImage()`；错误删除 allowlist 项时测试失败；目标源码与测试通过 PHP lint；两仓会话候选文件普通磁盘 diff 对齐。
- WebUI/E2E：整体 PageBuilder 能力须在真实 WLS 的工作台点击 Logo 重生成，看到透明高质徽章、无重复模型烤字、资产 URL 更新，并保留截图；该产品门禁不能由核心单测替代。
- 运营与支持影响：无新增后台配置；若参考图未生效，先检查调用模块是否在 `$mediaContract['image']` 提交有效值，再检查场景 Provider 对参考图的支持与日志。
- 依赖与风险：Provider 对图生图参数的实际支持、PageBuilder 参考图摄入完整性、真实 WLS/WebUI 可用性。核心只保证媒体边界不再静默过滤该字段。

### `REQ-AI-0002` 统一项目知识库与强制 MCP 准备协议

- 来源与确认：用户于 `2026-08-23` 明确要求完整实施《Weline_Ai 统一知识库与 MCP 迁移计划》，包括独立 MCP 双端封版、旧 AI 规则清理、模块文档自动索引、Codex/Cursor 强制入口、Deploy 结构化桥接与旧集中式 AI 目录历史清理。
- 目标版本：`1.2.0`。
- 背景/问题：框架规范曾分散在旧集中式 AI 目录、静态 Skills、客户端镜像和模块派生索引中，AI 每次需要重复加载大段上下文；独立 `Weline-Codex-Mcp` 与重复知识模块又形成了多个维护源。
- 用户与运营场景：支持本地 STDIO MCP 的 AI 客户端在开始框架开发前自动启动内置 MCP，完成项目身份、模块清单、三文档契约与索引新鲜度检查；仅在返回有效 readiness 后按当前任务取得最小必要规范和源码上下文。
- 业务逻辑：
  1. `Weline_Ai/Mcp` 是 MCP 唯一维护源，保持 `LearningMcp` 命名空间、Apache-2.0 子目录许可、PHP 8.2 兼容和对 Weline/WLS/业务数据库零运行时依赖。
  2. `prepare_project` 返回 `project-readiness.v1` 的 `ready`、`needs_repair` 或 `blocked`；readiness 与项目 revision、模块清单、文档 Hash 和客户端会话绑定。
  3. 除 health、安装和修复说明外，知识、编辑与发布计划工具必须校验 `readiness_id`；项目或文档变化会使旧 readiness 失效。
  4. `resolve_task_context` 返回有来源与 Hash 的 `guidance-bundle.v1`；`set_session_directives` 只保存在 MCP 进程会话内，不写仓库、SQLite 长期知识或凭据。
  5. 每个有效知识单元长期维护 `doc/README.md`、`doc/需求.md`、`doc/开发日志.md` 与必要专题文档；派生索引仅在项目隔离 SQLite 中，外部文档修改必须在下一次工具调用可见。
  6. 根 `AGENTS.md` 是唯一中立入口；Codex 与 Cursor 使用同一 STDIO MCP 和严格启动门禁，不再复制框架规范或生成静态开发 Skill。
  7. 现有 `Weline_Ai` Agent、Scenario、Provider、业务 Skill、Style、导入导出和后台功能保持兼容；重复知识模块退役，但不静默删除可能存在的 `ai_knowledge_call_history` 生产表。
  8. 部署能力只经 `Weline_Deploy` 公开 JSON CLI 获取只读预检和计划；未指定目标/ref 类型或未明确授权时不得真实发布。
- 范围：内置 MCP、readiness/guidance/session 协议、模块知识扫描与 SQLite 派生索引、统一客户端入口、旧知识系统退役、迁移/发布/历史清理工具与文档。
- 非目标：不新增知识管理后台 UI；不重排模块业务源码；不把临时会话决定自动晋升为长期规范；不在本需求中执行任何真实预发/生产部署。
- 数据/权限/安全：索引按规范化项目目录隔离；修复文档必须显式授权；会话指令和凭据不落盘；Deploy 默认只读；旧历史表只提供显式清理说明。
- 兼容/迁移：独立 MCP `v0.12.2` 先发布，迁入后导出最终 `v0.13.0` 并冻结独立仓；旧 `resolve_skill/get_skill` 暂作动态知识别名；业务 AI 契约保持兼容。
- 验收标准：当前 Git 树可证明的 92 个运行时模块与 1 个 Base Composer 聚合包（共 93 个有效知识单元）满足三文档契约；缺文档阻断且修复可控；readiness 失效/并发/回滚/外部编辑新鲜度测试通过；Codex/Cursor 全新克隆门禁通过；Weline 真实升级无业务回归；双远端版本和重写后 refs 一致。
- WebUI/E2E：MCP 本身以真实 STDIO 客户端和 CLI 全栈验收；Weline_Ai 既有后台能力在真实 WLS 做回归冒烟。不存在知识管理新 UI。
- 运营与支持影响：模块维护者只更新归属模块文档；客户端启动失败或 `needs_repair` 时按确定性 Bundle 修复；独立 MCP `v0.13.0` 后不再维护。
- 依赖与风险：客户端必须支持本地 STDIO MCP；历史重写会改变受影响分支后代 SHA；托管平台失联对象 GC 时间不可控。
