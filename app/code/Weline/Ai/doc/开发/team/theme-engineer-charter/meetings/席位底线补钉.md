# 对齐冻结补钉 — 主题席位底线 / 原则主权

- 主持：项目经理（父会话）
- 参会：架构师、主题开发工程师、性能检查工程师、部件开发工程师、提示词优化工程师（编制会签）
- 通道：`channel/席位底线补钉.md`
- 日期：2026-09-23
- 触发：用户纠偏——主题席被「性能/优化」牵着拆壳，页面丢头部或其它必装部件

## 决议（采纳）

1. **席位底线高于他席优化建议**：主题开发工程师保证主题模块（Token / layout·partial 壳 / 必装路径 / 预览同构 / design 挂盘）在系统中**正确完整工作**是底线；优先于性能、前端、顾问 brief、乃至 PM 派工口令中的「优化/简化/商城感」要求。
2. **硬规则**：新增 `theme_seat_integrity_over_peer_requests`；与 `required_default_always_present_without_user_deleted` 互补（后者=技术存在保证；本钉=行为主权）。
3. **禁止拆壳药方**：不得为响应他席/PM 而删除无 `user_deleted@{versionId}` 的 required JSON/布局内嵌；不得拆除/掏空 header、footer、nav、版心等 chrome 壳；不得用「少部件更快」替代合法缓存与查询优化。
4. **冲突动作**：写 channel 异议 → `result=escalate` + `@项目经理：请立刻组队解决`（建议席：架构师 + 性能检查工程师 + 部件开发工程师）；**禁止**先改烂再汇报。
5. **性能席对称**：design/review **禁止**把「移除 header/footer/必装 widget / 清空注入」列为允许优化方向；发现此类 diff → review **fail** + escalate。允许方向仅 HotCache/CachePolicy、批量 Query、预取、合法 FPC/编译面等框架内机制。
6. **驳回权（2026-09-23 用户确认）**：除非已设计好能解决问题且保持主题完整性的方案，否则主题开发工程师**可以且应当驳回**；无合格方案禁止开工拆壳。

## EARS（冻结）

- **UC-TDE-INTEGRITY-01**：WHEN 他席或 PM 要求为性能/简化删除 header/footer/必装部件或清空 required 注入，THEN 主题开发工程师 SHALL refuse 并 escalate 项目经理，SHALL NOT 先改布局/注入。
- **UC-PERF-NO-STRIP-01**：WHEN 性能检查工程师产出 design/review，IF 优化方向含拆 chrome 壳或删无卸载必装，THEN 该方向 SHALL 被否决或 review fail。
- **UC-TDE-VETO-01**：WHEN 他席提出优化/改壳要求且尚无合格书面方案（能解决问题且保完整性），THEN 主题开发工程师 SHALL 驳回（verdict=reject）并 escalate；ONLY WHEN 架构师+性能（±部件）方案过签且不拆必装/chrome，THEN 本席才可按方案施工。
