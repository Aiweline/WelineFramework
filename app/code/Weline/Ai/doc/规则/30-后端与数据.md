## 1. Taglib 优先于手写控件（`taglib_before_hand_rolled_controls`）

| 允许 | 禁止 |
|------|------|
| 先查 [场景映射表.md](../../../Taglib/doc/场景映射表.md) + [标签全量索引.md](../../../Taglib/doc/标签全量索引.md) + [4-内置标签/README.md](../../../Framework/doc/4-内置标签/README.md) | **未先查标签库**就手写 `<select>` / ISO text / 自造 chips；能用 `<w:*>` / `<lang>` / `<w:hook>` 时用裸 HTML |

无现成标签 → 在**数据拥有模块**新增 Taglib；**禁止**业务页临时拼装。选择性控件（下拉/单选/多选/chips/枚举）架构上优先标签。

## 2. Taglib 实现三条禁令

1. **禁止**在 `w:*` / Taglib **标签属性**里写 `<?=`、`<?php`。
2. **禁止**在 Taglib `callback()` / `runtime_callback()` 返回的 HTML 里写裸 `@static(...)`（`taglib_no_literal_at_static_in_callback`）——`.phtml` 源 AST 才解析 `@static`，callback 字符串按原样烘焙，浏览器 404 `.../@static(Module::css/foo.css)`。改用 `Template::fetchTagSource(DataInterface::dir_type_STATICS, Module::path)`（参考 `I18n\Taglib\Local::resolveModuleStaticUrl`）或 callback 内 `echo`。
3. 动态文案用 `@lang` / Hook，或在 PHP 块赋值后写到 **HTML 元素属性**（须 `htmlspecialchars`）。

权威：[如何自定义Tag.md](../../../Taglib/doc/如何自定义Tag.md)、[static-resource-versioning.md](../../../Framework/doc/static-resource-versioning.md)、[09-static标签](../../../Framework/doc/4-内置标签/09-static-template-js-css标签使用指南.md)。验证：浏览器 Network 无 `.../@static(` 字面量。

## 3. 站内跳转必须走 URL 模块 / url 标签（`storefront_internal_url_via_url_helper`）

**禁止拼接。** 站内 href/action/data-*-url / 店面 JSON 链接只能由官方 Url 入口生成。

| 层 | 推荐 | 允许 | 禁止 |
|----|------|------|------|
| **前端模板** | `@url{'path'}` / `<url>` 等同族标签 | 数据准备块 `$this->getUrl` 族 | HTML 硬编码 `/path`；属性内 `<?= $this->getUrl() ?>`；`Url::getPrefix().$path`；`'/' . $route` |
| **后端 PHP** | `Url::getUrl` / `getFrontendUrl` / `getBackendUrl` | `$this->getUrl` 族；薄封装且内部必须调 Url API | `'/' . $route`；`getPrefix()`/mount 字符串拼接；手写 `/module/action` |

说明：`Url::getPrefix()` 只含语种/货币，**不含** website mount（如 `/daocharms`）；用它拼 href 会丢站点基本地址。外链 http(s) 可原样。权威：[06-url标签使用指南.md](../../../Framework/doc/4-内置标签/06-url标签使用指南.md)。

## 6.1 Runtime 编排层禁止硬编码业务数据（`runtime_orchestrator_no_business_hardcode`，严重）

> **严重错误**：Framework Runtime / WLS 控制面是**编排层**，不是业务目录所有者。在 `WlsRuntime`（及同构的 FPC deferred warmup、READY、keep-warm、bag-prime 调度）里粘贴站点分类/商品/博客 slug、演示 SKU、商户专用店面路径，或「fallback」业务路径数组——**一律禁止**，即使用于性能热修也不豁免。

| 允许（编排） | 禁止（业务硬编码） |
|------|------|
| 调度 / 预算 / cap / owner 选举 / Fiber yield | 在 Runtime 写死 `/category/women`、`/product/sku-xxx`、某站专用 locale×path 矩阵 |
| 消费 `FpcWarmupProviderInterface` / `ViewWarmupContributionProviderInterface` / env `wls.worker.fpc_warmup_paths` | 用「稳定 fallback」名义把 catalog slug 数组塞进 `WlsRuntime` |
| 仅按**已文档化的路由形态**筛选（如 path 以 `/category/` 开头——形态，不是具体 slug） | Runtime 发明或复制归属模块的实体列表 |

**正确归属**：业务路径由**拥有模块**发布——例如 Product 从 `StorefrontAllMenuCategoryTreeService::navTree`（或等价活索引）写入 `ViewWarmupContribution`；Theme `FpcWarmupProvider` 聚合 contribution；Framework 只密封 Provider 给出的路径。

权威：[architecture/04-performance-budget.md](../../../Framework/doc/architecture/04-performance-budget.md)（warmup 路径已从硬编码演示商品/分类收敛为 Provider/env）；MCP `runtime_orchestrator_no_business_hardcode`；协同 `framework_decoupled_only`。

## 6.2 网站 / 设计主题概念禁止侵入框架模块（`website_concept_seed_not_in_modules`，严重·上下文携带·抽象）

> **严重错误（抽象门禁，不是站点黑名单）**：`app/code` 下的模块是**领域内核**。凡归属「某一个网站 / 某一个设计主题 / 某一个品牌开场」的分类树、SKU 货架、开站种子脚本、站专属 `*CatalogSeeder` ITEMS、站导入/挂架/Sample 开场器，以及**站/主题/品牌专属用户可见文案**（模块 `i18n/*.csv` 默认串、默认部件/布局/模板文案、品牌身份种子回退、点名某一垂直/品牌的 SEO/FAQ 导语）——**一律不得**放进任何框架模块。本条约束**当前与未来一切**新站、新主题；禁止用「只是示范站」「先塞模块以后再搬」开先例。N 站 ⇒ N 份主题/站柜包，绝不能变成 N 份模块污染。

| 允许（模块·全局领域） | 禁止（站/主题概念侵入模块） |
|------|------|
| **与具体 website code / 设计主题无关**的领域默认：Tax/Shipping seed-defaults、Setup/Install schema、系统 EAV；**中性**电商/领域措辞 | 绑定某一站或某一主题的开站种子、货架矩阵、分类树、站专属 Seeder/ITEMS、站导入与挂架脚本、站 Sample 开场包 |
| 模块对外的**通用** Mutation / Repository / 读写 API（供设计主题脚本调用） | 在模块内硬编码某站 SKU/文案/图、拒 default 且只接受某一 website code 的开站脚本；把某一品牌/垂直政策写进模块 CSV 或默认模板当全站默认 |
| 主题编辑器对 layout/部件字段的 **Meta / MetaLocal** 译文（经 `ThemeScopedI18nProjector`） | 用模块 `i18n/*.csv` 冒充某一站的默认品牌文案 |

**正确落点**：版本化站/主题概念 → `app/design/{Vendor}/{theme}/`（`data|scripts/`、同路径模板/部件覆盖）；站专属翻译 → **设计主题布局/部件配置**上的 Meta i18n，或 design 覆盖模板内文案；生产运维事实柜 → 本机 `websites/<site>/`（gitignore）。设计主题脚本可调用模块通用 API，**不得**把站/主题 ITEMS 或品牌政策文案写回模块。

**例子（不是规则正文）**：跨境售后通用表述留在 `Weline_Shipping`；某一服饰垂直的形制/尺码专属段只放 `app/design/{Vendor}/{theme}/Weline_Shipping/.../returns.phtml`。

权威：MCP `website_concept_seed_not_in_modules`；协同 `runtime_orchestrator_no_business_hardcode`（编排层禁业务路径；模块层禁站/主题概念货架与站专属文案）。

## 6.3 框架/功能可视化演示统一落 `Weline_Demo`（`framework_demos_live_in_weline_demo`，硬·抽象）

> Agent/人肉眼验收用的**可视化演示页**（DEV 标记、机制演示、「打开一页给我看标记」）一律写在 **`Weline_Demo`**。这是**模块归属**门禁，不是某一页特例。

| 允许 | 禁止 |
|------|------|
| 在本机 `app/code/Weline/Demo` 新增 Frontend 演示路由/模板 | 再开零散 `*Demo` / `*DupDemo` 模块 |
| 正式 PHPUnit / Playwright 仍落**归属业务模块** `test/` / `Test/` | 把抛演示页塞进 Checkout/Theme/Cart 等业务模块 |
| 豁免：`Weline_WidgetDemo`（可入库的部件夹具）；站/主题种子（§6.2）；内容运营 | 用演示模块替代正式 e2e；**把 `Weline_Demo` 提交进 Git** |

`Weline_Demo` **本机专用**：仓库根 `.gitignore` 已忽略 `/app/code/Weline/Demo/`——禁止再入库。

**例子（不是规则正文）**：同槽重复 DEV 红框 → `/weline_demo/frontend/slot-dup`。

权威：MCP `framework_demos_live_in_weline_demo`；宿主常带 `~/.cursor/rules/framework-demos-live-in-weline-demo.mdc`（`global_rules_dual_write_mcp_and_host`）。

## 8. Query / REST / BinQuery（`api_rest_in_owning_module`）

| 允许 / 必须 | 禁止 |
|------|------|
| **一律 QueryProvider** | 壳内重写 Provider 业务；手写 query-bin |
| Attribute **默认拒绝**（`external/frontend=false`）；公开须显式 opt-in + `auth` | 靠 Attribute 默认暴露；缺 `auth` 当已鉴权 |
| 薄 REST = `#[Acl]` + `w_query`；每入口**独立权限矩阵** | REST 有 Acl 而 query-bin 无 `backend_acl`；缺 `@Document`/Acl |
| Rest **只落归属模块** | 跨模块代写 Rest；**在 I18n 写 Website API** |
| 站内业务走 BinQuery；对外走 REST | 站内业务手写 REST / native fetch |
| 写操作 external 须 Key；敏感读不进 CDN 公开 | 写操作 external 无 Key；CDN 公开敏感读 |
| 改 Rest/BinQuery 须上场 **API 席**（`Team:API:` 双轨）；文档同变更集 | 改 Rest/BinQuery 不上场 API 席；只改代码不更文档 |

验证：BinQuery 须 `compile` 且可 `query:help`。权威：[API接口开发规范.md](../../../Framework/doc/3-开发/API接口开发规范.md)、[BinQuery/Provider开发指南.md](../../../Framework/doc/BinQuery/Provider开发指南.md)、[api-seat-charter](../开发/team/api-seat-charter/meetings/align-freeze.md)。

## 9.1 界面页控制器 vs 异步 BinQuery 资料更新（`ui_page_controllers_mutations_via_async_binquery`，严重）

> **严重**：除**界面请求**（渲染 HTML / 页面壳：列表页、编辑页、详情页）外，一切资料增删改 / 管理信息 I/O **必须**走异步 BinQuery（`Weline.Api.* → worker/query-bin → 归属模块 QueryProvider`）。**禁止**再为管理信息开多个 Controller 做 CRUD。

| 允许 / 必须 | 禁止 |
|------|------|
| 页面 Controller 只负责开页（index / edit / view 等页面动作） | 把 save / delete / export / 批量改做成 Controller `post*`/`get*` 或表单直打 Controller |
| 资料更新走异步 BinQuery + QueryProvider；站内 UI 调 `Weline.Api` | 为同一信息域开 Index/Edit/Save/Delete 等多个 CRUD 控制器（原始多控制器做法） |
| 薄例外与 `api_rest_in_owning_module` 对齐：multipart/stream、OAuth/换票、webhook、Framework BinQuery 网关壳 | 以「后台管理方便」为由继续堆 Controller 动作当 API |

宿主常带：`~/.cursor/rules/ui-page-controllers-mutations-via-async-binquery.mdc`（与 MCP 双写，见 `global_rules_dual_write_mcp_and_host`）。协同：`weline_api_not_raw_fetch`（传输）、`api_rest_in_owning_module`（Query 核）、`controller_url_action_not_http_prefix`（页面 URL 动词）。权威：[BinQuery/Provider开发指南.md](../../../Framework/doc/BinQuery/Provider开发指南.md)、[Weline.Api使用指南.md](../../../Frontend/doc/Weline.Api使用指南.md)。

## 9.2 管理界面须人性化完整操作（`admin_manage_ui_requires_humanized_full_ops`，严重）

> **严重**：开发后台/管理界面时，必须交付**可长期管理**的人性化能力（增删改查 + 列表检索 + 批量等），**禁止**只做「新增/开页」就宣称完成、留下不能改不能删不能批处理的残缺管理面。

| 允许 / 必须（多行资源默认基线） | 禁止 |
|------|------|
| 列表：可用检索/筛选/分页（多行时） | 只有一张空表或只读列表却无改删入口 |
| 新增 / 查看或打开编辑 / 修改保存 | **只做 create 就报完成**；缺 edit/update |
| 删除或领域安全的禁用/归档，且有确认 | 有数据却无法删除/下线 |
| 多选列表须有领域合适的批量（至少批量删除和/或批量启停/状态） | 勾选列存在却无任何批量动作 |
| 写操作仍走异步 BinQuery（§9.1） | 为补齐 CRUD 又开一堆 Controller 动作 |

窄例外：用户明示收窄范围；只读审计/日志/看板；单例 SystemConfig 式编辑页（批量 N/A）；不可变 append-only 流水。协同：`backend_admin_ui_requires_frontend_theme_skills`（外观壳）、`ui_page_controllers_mutations_via_async_binquery`（传输）、§9.3 简单新增/编辑弹层。宿主常带：`~/.cursor/rules/admin-manage-ui-requires-humanized-full-ops.mdc`。

## 9.3 简单管理新增/编辑须弹层 + 异步 BinQuery（`admin_simple_create_edit_via_modal_binquery`，严重）

> **严重**：管理列表页上，**不复杂**的新增/编辑默认走 **Weline.UI 弹层** + **异步 BinQuery** 完成；**禁止**把表单常驻展开在列表页里占满竖向空间。

| 允许 / 必须 | 禁止 |
|------|------|
| 列表 + 工具栏「新增」/ 行内「编辑」→ `data-w-component=dialog` / `Weline.UI.dialog.open` | 简单字段集却在列表上方/中间**常驻展开**整块表单卡 |
| 保存/删除等资料变更走异步 BinQuery（§9.1） | 弹层里仍用 Controller `save`/`delete` 当主路径（与 §9.1 冲突） |
| 复杂例外可用独立编辑页/Tab：多步向导、大地址/区域画布、富文本/媒体编排，或用户明示要整页 | 以「后台方便」为由把简单 CRUD 永久摊在页内 |

协同：`admin_manage_ui_requires_humanized_full_ops`（能力完整度）、`ui_page_controllers_mutations_via_async_binquery`（传输）、`weline_ui_floating_primitives`（弹层原语）。宿主双写：`~/.cursor/rules/admin-simple-create-edit-via-modal-binquery.mdc`。

**例子（仅举例，不是规则正文）**：企业邮箱「收件域导流」规则——列表页工具栏新增 / 行内编辑 → 弹层填收件域与中继，经 `saveOutboundRouteRule` BinQuery 保存。

## 11. 后台对话框（`no_native_js_dialogs`）

| 允许 | 禁止 |
|------|------|
| `Weline.UI.toast` / `Weline.UI.dialog.confirm` / `Theme.Notice` | JS `window.alert(` / `window.confirm(` / `window.prompt(` |

契约断言模板/脚本无原生对话框调用。注意：这是**独立高压线**，勿埋进 `no_generated_no_routes_xml`。权威：[开发标准与验收.md](../../../Framework/doc/3-开发/开发标准与验收.md)。

## 12. 缓存与性能（`performance_engineer_for_design_and_review`）

| 允许 / 必须 | 禁止 |
|------|------|
| 可缓存事实走 Framework **缓存类**：进程内存储 → 驱动存储；**同 key** 读写与清理同步；单次读命中进程内则不再打驱动 | **业务类再自做一层进程内缓存**（绕开 CachePool/Adapter）；读写/清理 **key 不一致**；清理只清驱动不清进程内（或反之） |
| 复杂 team 热路径须 `Team:性能检查工程师:` 设计检查 + 开发后复审 | 可变 Model / 个性化 HTML / 草稿 / 未提交事务读进共享缓存；**热路径设计不上场性能检查工程师** |
| 查出问题/缺口须立刻 escalate `@项目经理：请立刻组队解决` | **查出问题不立刻 escalate**；跨样本伪加速比 |
| 优化方向落在 HotCache / 框架约束内 | **把拆 header/footer/必装 widget 当优化药方**（主题席有驳回权） |
| 乱切语种/货币/页面找慢 → `get_skill(performance-cold-chaos-dig)` + [性能冷切扫描.md](../../../../../../dev/ai-command/ai/性能冷切扫描.md)（`w_fpc_pierce`+`_wb_nc`、慢阈值停下；**修后主表=修前冷 hit1 vs 修后冷 hit1**，暖命中仅附录） | 无穿章/无 `_wb_nc`/无冷前后对比、只用暖 hit2/hit3 命中表空谈「已粘 / 变快」 |

`cache_lookup_tier_process_shared_db` **已取消**——勿再当 MCP 硬规则要求业务类自做三层。权威：[统一缓存范围与性能优化.md](../../../Framework/doc/统一缓存范围与性能优化.md)、[性能检查.md](../../../../../../dev/ai-command/ai/性能检查.md)、[性能冷切扫描.md](../../../../../../dev/ai-command/ai/性能冷切扫描.md)。

## 13. ORM / 版本升级（`module_version_bump`）

改 Model / Controller 字段或路由必须 bump `etc/module.php` version：

```bash
php bin/w setup:upgrade -m Weline_Module          # 字段/Schema
php bin/w setup:upgrade --route                   # 仅路由图
```

**禁止**不 bump version 就改字段；**禁止**手改 `generated/`；**禁止**在 `Setup/Upgrade.php` 做字段 CRUD。权威：[模块版本与升级门禁.md](../../../Framework/doc/3-开发/模块版本与升级门禁.md)、[模块开发完整指南.md](../../../Framework/doc/3-开发/模块开发完整指南.md)。

## 13.1 业务层禁止 SQL 方言（`business_forbids_sql_dialect`，严重）

> **严重错误**：可移植性边界在 **ORM 数据库底层**。业务代码（Service / Model / Repository / QueryProvider / Controller / 模块 Setup·Migration / Observer / Plugin，以及非 Adapter 的 Framework 业务服务）**禁止**手写或拼接 MySQL / MariaDB / PostgreSQL / SQLite 方言 SQL；也禁止 `match`/`switch`/`if` 按 driver 拼出方言片段。

| 允许（ORM 底层） | 禁止（业务层） |
|------|------|
| `Weline/Framework/Database/Connection/Adapter/**` Connector（及同层 Adapter Query） | 业务模块里写 `ON CONFLICT` / `ON DUPLICATE KEY` / `INSERT IGNORE` / `REPLACE INTO` |
| Framework `Database/Compiler/**`、`Dialect/**`、`Schema/**` 编译器把可移植意图落到引擎 SQL | 业务里写 `JSON_EXTRACT` / `DATE_FORMAT` / `strftime` / `UNIX_TIMESTAMP` / `GROUP_CONCAT` / `FORCE INDEX` / `ENGINE=InnoDB` / `AUTO_INCREMENT` / MySQL `LIMIT offset,count` |
| 可移植 ORM Query：`where` / `insert` / `update` / Framework upsert·conflict 助手 / `fetch`·`fetchArray`；声明式 Model schema；Framework 暴露的 `DialectInterface` 助手 | 在业务里按 `mysql`/`pgsql`/`sqlite` 分支拼 SQL 字符串 |

**灰区（不是业务开绿灯）**：专用 Database / DbManager **管理台** introspection 可能需要 catalog SQL；**禁止**把该模式复制进电商/领域模块。

宿主常带：`~/.cursor/rules/business-forbids-sql-dialect.mdc`（与 MCP 双写，见 `global_rules_dual_write_mcp_and_host`）。权威：MCP `business_forbids_sql_dialect`；协同 `no_generated_no_routes_xml`（ORM 链以 `fetch`/`fetchArray` 收尾）。

## 14. Controller / 路由 / generated（`no_generated_no_routes_xml` / `controller_url_action_not_http_prefix` / `ui_page_controllers_mutations_via_async_binquery`）

- **禁止 AI/Agent 手改** `generated/**`（routers / hooks / plugins / events / commands / classmap / query_providers / taglibs / widgets / framework 快照等）与编译产物 `view/tpl/`：禁止 Write / StrReplace / 手写 return-array「修一下」。
- **只许系统写入**：`setup:upgrade`（字段/Schema）、`setup:upgrade --route`（仅路由图）、event/hook/taglib/widget/command 等正式收集·编译命令，或 Framework Publisher/Writer → `CompiledPhpRegistry::put`；下文**从 runtime 袋读**，禁止当第二真相源再 `include`。
- **禁止** `routes.xml`；路由由控制器发现（`setup:upgrade` 同步，仅路由图变更时 `--route`）。
- ORM 链以 **`fetch()` / `fetchArray()`** 收尾。
- **页面** Controller 的 URL 动作是 **`edit` / `add` / `view`** 等开页动词，**禁止**写 `getEdit` / `getAdd` / `postSave`——`get*`/`post*` 前缀只约束**请求方法**，不拼进 URL。
- **资料 save/delete/mutate 禁止再开 Controller 动作**——走异步 BinQuery（见 §9.1 `ui_page_controllers_mutations_via_async_binquery`）。

宿主常带：`~/.cursor/rules/no-generated-no-routes-xml.mdc`、`~/.cursor/rules/ui-page-controllers-mutations-via-async-binquery.mdc`（与 MCP 双写，见 `global_rules_dual_write_mcp_and_host`）。

对照 [03-自定义控制器.md §HTTP方法](../../../Framework/doc/2-快速开始/03-自定义控制器.md)、[开发标准与验收.md](../../../Framework/doc/3-开发/开发标准与验收.md)。
