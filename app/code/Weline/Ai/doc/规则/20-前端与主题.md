## 1. 自研主题 UI 优先（`weline_ui_theme_first`）

所有前台/后台可视化界面**必须**使用 Weline 自研主题体系（**Weline UI 2.0**）：组件类名（`w-field` / `w-input` / `w-button` / `w-select` 等）+ 主题 CSS 变量 Token（`--color-*` / `--weline-theme-*` / spacing·radius·shadow）。

**禁止**：Bootstrap / Element / Ant Design 等第三方 UI；硬编码 `#hex` / `rgb()` / 随意 `px` 间距；地址/地区级联手写国家/省/市 input（**必须** `<w:theme:address>`）。

权威：[Theme开发总指南.md](../../../Theme/doc/开发/Theme开发总指南.md)、[theme-css-variables-only.md](../../../Theme/doc/theme-css-variables-only.md)、[场景映射表.md](../../../Taglib/doc/场景映射表.md)。

## 2. 基础组件只用主题规范变量（`theme_base_components_token_only`）

基础/基础库组件（`w-button` / `w-input` / `w-select` / `w-textarea` / `w-field` / `w-badge` / `w-alert` / `w-text` / `w-menu` / `w-dialog` / `w-toast` / `w-table` 及 `foundation.css` 同级）**必须**只消费 `--weline-theme-*` / `--color-*` / `--backend-color-*`（及 spacing·radius·shadow）。

**禁止**为基础组件私写 hex/rgb 或平行色变量。品牌主题只改 `colors/_*.css` 色盘叶子；默认语义合同继承自 `variables/_colors.css` + `colors/_default.css`。权威：[theme-semantic-color-matrix.md](../../../Theme/doc/theme-semantic-color-matrix.md)。

**互补例外（不得用本条覆盖）**：见 §2b `theme_inverse_raised_paper_ink_pin`——inverse 下浅色 raised 面板的 foundation 纸面钉**不是**「禁止硬编码」的扫除对象。

## 2b. inverse 下 raised 纸面墨钉字面（`theme_inverse_raised_paper_ink_pin`，硬）

**抽象机制（WO-UI-CONTRAST-INVERSE）**：暗色 / inverse chrome（`[data-surface=inverse]` / `.w-surface-inverse`）会把 `--color-text*` / body-text 重绑成 on-dark 浅色。嵌在其下的**浅色 raised 面板**（下拉、抽屉、搜索纸面、地址弹层、语言/范围菜单等）若不本地恢复纸面墨，会白底浅字不可读。

| 必须 | 禁止 |
|------|------|
| 在 raised 根上**先钉** foundation 纸面字面（规范对 `#0f1111` / `#565959`，次级可 `#666666`）到 `--weline-chrome-body-text*`（或等价纸面局部），再绑 `--amz-drawer-text` / `--_paper-text` / `--color-text*` | 用已被 inverse 重绑的 `--color-text-primary` / `--color-text` / `--color-text-light` 等当纸面种子（会奶油叠奶油） |
| Token 化 /「去硬编码」扫除时**保留**上述钉字面；它们是对比度架构例外（同类：`@media` 断点字面量） | 把 `#0f1111` 改写成 `var(--color-text-primary)` 并宣称 Token 化成功 |
| 部件 CSS 特异度高于 Theme raised 重绑时，部件侧须自带同款钉，否则会盖掉 Theme 恢复 | 只改源文件不 bake/`theme:upgrade` 却宣称店面已修 |

**例子（仅举例，不是规则正文）**：迷你车抽屉、顶栏搜索纸面、配送地址弹层、账户下拉。权威：[theme-css-variables-only.md](../../../Theme/doc/theme-css-variables-only.md)「WO-UI-CONTRAST-INVERSE 纸面钉」；契约样板 `MiniCartShopifyDrawerContractTest` / `CheckoutDeliveryPanelPaperInkContractTest`。宿主双写：`~/.cursor/rules/theme-inverse-raised-paper-ink.mdc`。

## 2c. 前端必须守「变量 + 表面角色」双层（`theme_frontend_must_obey_tokens_and_surface_roles`，硬）

**抽象要求**：AI 前端 / CSS / Token 化合规 = **两层同时成立**，缺一层即违规。

| 层 | 含义 | 权威 |
|----|------|------|
| ① Token / CSS 变量 | 普通视觉消费已登记 `--color-*` / `--weline-*` 等；叶子落盘 `variables/` / `colors/` | `theme_base_components_token_only`、`theme-css-variables-only.md` |
| ② 表面角色例外 | inverse 下纸面钉、`@media` 断点字面等**故意保留的 foundation 字面**不得被 Token 化剥掉 | `theme_inverse_raised_paper_ink_pin`、同文档例外节 |

**Token 化 / 去硬编码动手前清单（硬）**：

1. `get_skill(weline-theme-development)` + Read `theme-css-variables-only.md` 例外；
2. 逐条字面量分类：普通色/间距 → 映射语义 Token；对比度/断点架构钉 → **保留**；
3. **禁止**「凡 `#hex` 一律改成最近的 `--color-text-primary`」无表面上下文启发式；
4. 改后契约锁负向模式 + inverse 下 Browser 对比度；部件 `layout_source` 须 bake / `theme:upgrade`——只改源不算店面 PASS。

复杂 Token/壳施工须派 **主题开发工程师**。宿主双写：`~/.cursor/rules/theme-frontend-obey-tokens-and-surfaces.mdc`。

## 3. 技能齐读（`css_or_theme_requires_ui_prototype_theme_skills` / `ui_skill_requires_theme_skill`）

凡任务/需求提到 **CSS** / **主题/theme** / **Token 化** / **去硬编码** / auto-literals，写样式或改主题前**必须**先加载并服从三件套，再执行 §2c 双层清单：

1. UI 技能 `frontend-design`
2. 原型技能 `prototype`
3. 主题技能 `weline-theme-development`（MCP `get_skill`）或 surface `frontend_development`

主题 Token 与 Weline UI 2.0 **优先于**通用 UI 技能的自造色板。UI 技能仅可指导**构图、层次、文案**；**禁止**按 UI 技能另发明 hex/rgb、px 间距阶梯、圆角阴影套件或平行 design token。宿主 `SKILL.md` 仅为可选薄壳。

后者覆盖**后台**：凡本仓前台**或后台/admin**界面工作，即使未提 CSS，也必须挂主题技能并与 Marketing/Smtp 既有页对齐（`backend_admin_ui_requires_frontend_theme_skills`）；**禁止**交裸 h1+form/table，搜索条全宽竖叠。

## 4. Theme 机制边界（`theme_mechanism_not_foreign_content`）

**抽象通则**：各自功能各自模块自管布局与模板；`Weline_Theme` **只**提供主题机制（含 `app/design` 继承/重写）；**禁止** Theme 兜底、代持、空挂其它业务模块的功能布局与主内容模板。登录/商品/结账等只是举例。

权威：[theme-mechanism-not-foreign-content.md](../../../Theme/doc/开发/spec/theme-mechanism-not-foreign-content.md)、[Theme开发总指南 §6.0](../../../Theme/doc/开发/Theme开发总指南.md)。

## 4b. 布局 / 部件归属（`theme_layout_widget_owner`）

| 场景 | 规则 |
|------|------|
| **同模块** | 仅本模块 `layouts/`/`partials` 可用 `<w:widget>` / `fetch(.../widgets/...)` 内嵌本模块部件；已内嵌则**禁止**再在该部件 JSON 写 `default_injections`（**二选一**，删 JSON；`placement=layout`）。走注入则布局只留空槽（`placement=injection`） |
| **跨模块** | 布局/partial **禁止**互调别的模块部件；外国部件**只能**空 `<w:slot>` + 拥有模块的 JSON `default_injections` |
| **Theme 布局** | 仅可内嵌 `Weline_Theme` 部件；业务模块自有布局内嵌本模块部件合法 |
| **复杂 team** | 部件相关必须分配 **部件开发工程师**（`widget_development`） |

改后必须跑：`php bin/w frontend:check-theme-layout-widgets`。

## 5. 默认注入必装（`required_default_always_present_without_user_deleted`）

无人工卸载记录 `user_deleted@{versionId}` 时，**required 默认 JSON 注入与布局标签内嵌必装必须存在**：

- JSON 路径须**经布局固化写入模板**——有槽则固化（与主题/版本无关）；无模板则激活主题运行期动态固化；
- 插件注入变更 → **全主题重固化**涉及布局；
- 遗漏 = 固化方案问题，不得当成「可选 overlay」。

参见 [布局固化与默认注入.md](../../../Theme/doc/布局固化与默认注入.md)、[required-default-always-present.md](../../../Theme/doc/开发/spec/required-default-always-present.md)。

## 6. 席位底线 / 原则主权（`theme_seat_integrity_over_peer_requests`）

主题席底线**优先于**他席或 PM 的性能·简化·优化要求：

- **禁止**为性能/简化服从**拆 chrome 壳**或去掉无卸载必装（性能席禁提拆壳药方）；
- 无合格方案时可**驳回**（HARD veto）；合格方案门槛 = 能解决问题**且**保主题完整性；
- 冲突 → `refuse` + escalate。

## 7. 预览与店面同构（`preview_storefront_delivery_parity` + `theme_design_must_not_override_core_runtime_assets` + `theme_design_must_inherit_not_mutate_source_widgets` + `theme_css_architecture_not_style_shell`）

- **禁止**仅为 `preview` / `editor_mode` / `visual_editor` 提前 return / 跳过 / 抽空真实店面逻辑；预览与发布**必须同一套业务逻辑**。
- **三态身份权威**：可视化 = **参数**；版本真实预览 = **Token 反解析**；正式 = **RequestContext**。禁止用 path 猜画布主题、用 URL 覆盖 Token、正式态读 draft/s*。
- `design` **禁止**同 key 覆盖 `theme.css` / `theme.js`。
- **`theme.css` 只写架构、不写风格（`theme_css_architecture_not_style_shell`）**：可写布局/表面机制（如 `[data-surface=inverse]`）/全局组件 Token 侧效应；**禁止** `.amazon-*` / `.w-amz-*`、单页英雄/chrome/toast 等风格壳——落独立风格 CSS 或布局 `<style>`。权威：[theme-css-architecture-vs-style.md](../../../Theme/doc/theme-css-architecture-vs-style.md)。
- **`design_theme` 改部件外观必须继承**：只落 `app/design/{Vendor}/{theme}/`（widgets/layouts/partials 同 key + 品牌 CSS）；**禁止**改 `app/code/**/view/theme/**/widgets` 与 `view/statics/{css,js}/widgets` 源头（否则所有使用该部件的主题一起被污染）。平台级部件修须显式 Mode A / 部件席。
- 改 Theme/`app/design` 前必须先声明 `work_mode`；派 **主题开发工程师**（`theme_engineer_for_theme_work`）。

参见 [preview-and-runtime-modes.md](../../../Theme/doc/preview-and-runtime-modes.md)、[theme-inheritance-and-file-conventions.md](../../../Theme/doc/theme-inheritance-and-file-conventions.md)、[主题开发.md Mode A/B](../../../../../dev/ai-command/ai/主题开发.md)。

## 8. 前端 JS 加载（`theme_js_module_declare_only` / `widget_static_assets_bake_to_head` / `weline_js_loader_framework_only`）

| 允许 | 禁止 |
|------|------|
| 业务模块 JS：`Weline.declare` + `data-weline-load`（+ `data-*` / `data-js-ns` / `data-uid` 于部件根节点） | 部件/布局手搓 `<script src="@static(...js)">`；裸 `<js>` 直拉**业务模块**；不注册 modules 就加载 |
| 静态文件：`layout-source` / `source` → **bake** → 指定位置去重 | 任何部件内联 CSS/可执行 JS（含 `style=` 与 `on*=`）或模板裸资源标签；跳过 bake 闭包 |
| 改登记后 `php bin/w resource:compile welineModules` | **改登记不 compile** |
| 核心 i18n 归 `Weline_Framework::js/i18n.js`；Theme declare 加载；`Weline_I18n` 仅增强 | **在 `weline.js` 写死 cart/account/compare 等业务名**、业务代理或兑券/加购/维护 UI；把核心 i18n.js 放进外置 `Weline_I18n`；把 Phrase 改名为 I18n（与小写 `i18n/` CSV 冲突） |
| 含 `<style>`/`<script>` 必须留在布局/partial 时标 `data-no-extract="true"` | 注入 `data-wslot` 槽的部件模板里写含 `<?=` 的内联 `<script>`（脚本放 `view/statics/js/widgets/{code}.js`，模板用 `@static(...)` + `defer` + `data-no-extract="true"`） |

权威：[前端JS模块加载规范.md](../../../Theme/doc/前端JS模块加载规范.md)、[部件静态资源固化规范.md](../../../Theme/doc/部件静态资源固化规范.md)、[Theme.js使用指南.md](../../../Theme/doc/Theme.js使用指南.md)。

## 9. 内容区宽度 / 版心（`frontend_unified_content_container`）

**禁止自写一套页面/模块容器**。

| 场景 | 做法 |
|------|------|
| 已包 `.w-container` 的页面 | 只能 `width:100%` + `padding-inline:0` |
| 未包容器的独立壳（checkout/cart 等） | 用 `--weline-layout-content-max-width` 与 `--weline-layout-content-padding-inline`（或 `.w-theme-content-width`） |

**禁止**：`1440px` / `1200px` / `1180px` / `90rem` 私有壳与 fallback；双重 gutter（`.w-container` 内再写 `max-width`+`padding-inline`）；`var(--weline-layout-content-max-width, 1440px)`。特质 Hero/CTA 色可在局部 scope 自定义，**宽度无例外**。

验证：ThemeFrontendLayoutsContentWidthContractTest / ThemeStorefrontModuleContentWidthContractTest；对照顶栏左右沿。权威：[theme-layout-content-width.md](../../../Theme/doc/theme-layout-content-width.md)。

## 10. 浮层与通用原语（`weline_ui_floating_primitives`）

| 允许 | 禁止 |
|------|------|
| menu / popover / tooltip / combobox / dialog / anchored-float；`UI.floating.attach` / `Weline.UI.dialog` | **手写 `left/top`**；自研 flip/边界检测；私有 portal/modal 栈；产品/媒体选择器内嵌窄侧栏自造浮层；地址多选菜单绕开 `UI.floating.attach` |

对照 `data-w-component=dialog\|menu\|…` / `UI.dialog.open` / `UI.floating.attach`；Browser 验底部展开上翻。权威：[anchored-float.md](../../../Theme/doc/widgets/anchored-float.md)、[Theme开发总指南.md §通用浮层](../../../Theme/doc/开发/Theme开发总指南.md)。

## 11. section 身份（`section_weline_code`）

必须为前台字面 `<section>` 与 `w:slot wrapper="section"` 配置非空语义 section 身份（属性名 `weline-code`；部件根节点用 `WidgetUiScope`）。

**禁止**：缺失/空 `weline-code`；无语义名如 `section1`；同文件重复 code。验证：`php bin/w frontend:check-section-code`。权威：[frontend-section-weline-code.md](../../../Theme/doc/frontend-section-weline-code.md)。

## 12. 地址 / 地区选择（`theme_address_for_region_pickers`）

- 地址/地区级联**必须**用 `<w:theme:address>`；**禁止**手写国家/省/市 input 或 ISO 国家码 text input。
- 列表/表单筛选用 `selection=single|multi`；仅选国可用 `levels=country`；chips/菜单走标签与浮层内核。

权威：[场景映射表.md](../../../Taglib/doc/场景映射表.md)。

## 13. 审图与附图（`user_image_attachment_triggers_shentu` / `ui_skill_surface_signal_gate`）

**任意附图即审**（含后台/CMS/错误页，不必再说「审图」）。

| 情形 | 处置 |
|------|------|
| 非报错 `ui_shot` | **默认 = 改 UI**（禁止只点评） |
| `error_shot` | 优先修异常；错误页可读性同时达标 |
| `web_ui` 附图 | 强制 `participate` + **原型上场**（复杂 team 席位：原型 + UI + 前端 + 主题） |
| 同回合联合 | 线稿抽取 → `prototype` 调整 → `frontend-design` → `weline-theme-development` CSS/Token |
| 缺 UI/原型技能 | 须提示并自行装入 Agent Store |
| 结果 | fail 必须改到 pass |

权威：[审图.md](../../../../../../dev/ai-command/theme/审图.md)。

设计阶段纳入平板（≈768）与 PC（≥1024），兼顾 375；验收收集**多断点证据**。

## 15. 前端 i18n（开发语言默认中文 + 中英 CSV）

| 规则 id | 要求 |
|---------|------|
| `module_i18n_chinese_source_default` | 模板 / 菜单 / ACL / `__()` / `@lang` / `<lang>` 用户可见源串必须写**简体中文**；**禁止英文当默认源串** |
| `frontend_ui_requires_zh_en_csv` | 多语言靠模块 `i18n/zh_Hans_CN.csv` + `en_US.csv`（**不是 CSS**）；zh 第二列中文身份、en 第二列真实英文；改文案同回合写齐并 `php bin/w i18n:collect` |
| `template_lang_not_php_i18n` | 前台 `.phtml` HTML 内**禁止** `<?= __() ?>`；用 `<lang>` / `@lang()` |
| `at_lang_no_unquoted_comma` | `@lang()`/`@lang{}` 源文含逗号**必须**加引号或改用 `<lang>`（未加引号逗号会被当参数分隔，编译成 `<?=__('a', .b)?>` 触发 ParseError） |

未完成双语不得宣称 UI 交付。工程团队前端席必须挂 `template_i18n` + `module_i18n_csv`。权威：[Theme开发总指南.md §4.1](../../../Theme/doc/开发/Theme开发总指南.md)、[01-lang标签使用指南.md](../../../Framework/doc/4-内置标签/01-lang标签使用指南.md)、[模块翻译CSV规范.md](../../../I18n/doc/模块翻译CSV规范.md)。

## 16. 前端开发规范强制要点（编号版）

0. **开发语言默认中文 + 中英 CSV（高压线）**：见 §15。
0b. **自研主题 UI 优先（高压线）**：见 §1–§3。
1. 先判定改动层：layout / partial / component / widget；**禁止**直接改 `generated/`、`view/tpl`。
2. **禁止**在 `w:*` / Taglib **标签属性**里写 `<?=`、`<?php`；动态文案用 `@lang`、Hook，或在 PHP 块赋值后再写到 **HTML 元素**属性（须 `htmlspecialchars`）。
3. **禁止**在会经 `data-wslot` 注入的**部件模板**里写含 `<?=` 的内联 `<script>`。
4. **禁止**在 Taglib `callback()` / `runtime_callback()` 返回的 HTML 里写裸 `@static(...)`（不会二次编译，浏览器会 404）；须用 `Template::fetchTagSource(DataInterface::dir_type_STATICS, ...)`，见 [如何自定义Tag.md](../../../Taglib/doc/如何自定义Tag.md) §静态资源。
5. **禁止**在布局 slot 的 `<else/>` 写业务/demo 占位 UI；空 slot + 部件 `default_injections` 负责开箱内容。
6. **部件放置**：见 §4。
7. **section 身份**：见 §11。
8. 视觉值优先主题 CSS 变量；浏览器业务请求走 `Weline.Api.*`。
9. **内容区宽度**：见 §9。
10. **响应式**：见 §14。
11. **Taglib / i18n**：见 §15 与 [规则/30](./30-后端与数据.md) §2。
12. 专项细则按任务再读：`部件开发指南.md`、`frontend-section-weline-code.md`、`theme-css-variables-only.md`、`theme-layout-content-width.md`。
