## 1. 自研主题 UI 优先（`weline_ui_theme_first`）

所有前台/后台可视化界面**必须**使用 Weline 自研主题体系（**Weline UI 2.0**）：组件类名（`w-field` / `w-input` / `w-button` / `w-select` 等）+ 主题 CSS 变量 Token（`--color-*` / `--weline-theme-*` / spacing·radius·shadow）。

**禁止**：Bootstrap / Element / Ant Design 等第三方 UI；硬编码 `#hex` / `rgb()` / 随意 `px` 间距；地址/地区级联手写国家/省/市 input（**必须** `<w:theme:address>`）。

权威：[Theme开发总指南.md](../../../Theme/doc/开发/Theme开发总指南.md)、[theme-css-variables-only.md](../../../Theme/doc/theme-css-variables-only.md)、[场景映射表.md](../../../Taglib/doc/场景映射表.md)。

## 2. 基础组件只用主题规范变量（`theme_base_components_token_only`）

基础/基础库组件（`w-button` / `w-input` / `w-select` / `w-textarea` / `w-field` / `w-badge` / `w-alert` / `w-text` / `w-menu` / `w-dialog` / `w-toast` / `w-table` 及 `foundation.css` 同级）**必须**只消费 `--weline-theme-*` / `--color-*` / `--backend-color-*`（及 spacing·radius·shadow）。

**禁止**为基础组件私写 hex/rgb 或平行色变量。品牌主题只改 `colors/_*.css` 色盘叶子；默认语义合同继承自 `variables/_colors.css` + `colors/_default.css`。权威：[theme-semantic-color-matrix.md](../../../Theme/doc/theme-semantic-color-matrix.md)。

**互补例外（不得用本条覆盖）**：见 §2c `theme_inverse_raised_paper_ink_pin`——inverse 下浅色 raised 面板的 foundation 纸面钉**不是**「禁止硬编码」的扫除对象。

**三层非矛盾（盯死）**：

1. **禁组件私造色**（本条）——组件不得自写 `#hex` / 平行 `--my-btn-*`。  
2. **主题盘必须补齐叶子**（§2a）——组件写了 `var(--…)` / `data-tone`，主题 `variables`/`colors`（含暗色）必须可解析。  
3. **严重度要绑 tone**（§2b）——不是「全默认 chrome」；tone 仍依赖 §2a 叶子上色。

## 2a. 引用 Token 必须有主题盘叶子（`theme_referenced_tokens_must_resolve`，硬）

组件 / foundation **只能**消费主题语义变量；**配色、字重、描边粗细、圆角、控件高度等**若被组件引用，**必须**统一落在主题全局盘并在亮/暗（及后台对应盘）可解析。

| 必须 | 禁止 |
|------|------|
| 引用 → `variables/_*.css` + `colors/_default`（+ `_light`/`_dark` 差异）+ Foundation `--weline-theme-*` 桥接同批齐 | 组件写了 `var(--token)` / 标了 `data-tone`，主题叶子缺失、空、暗色未配 → 属性有了颜色不生效 |
| 审图/验收发现按钮色/粗细未按主题生效 → **补主题全局叶子**（声明 `work_mode`）再 bake/`theme:upgrade` | 在组件 CSS 私造色或「空壳 var」当完成；只改属性不补盘 |

权威：[theme-css-variables-only.md](../../../Theme/doc/theme-css-variables-only.md)「提取必落盘 / 禁止空壳」。宿主双写：`~/.cursor/rules/theme-referenced-tokens-must-resolve.mdc`。

## 2b. 严重等级须语义 `data-tone`（`theme_semantic_severity_tone_required`，硬）

店面/后台凡表达**严重度、风险、结果或操作等级**的控件（删除/破坏、失败/阻断、风险确认、成功/通过、说明提示、主 CTA vs 次操作/取消），**必须**在 `w-button` / `w-badge` / `w-alert` / `w-text` 等上按矩阵绑定 `data-tone`：

| 场景 | tone |
|------|------|
| 主保存 / 发布 | `primary` |
| 次操作 | `secondary` |
| 取消 / 返回 / 纯 chrome | `neutral` 或 `quiet` |
| 删除 / 破坏 | `danger` |
| 风险确认 | `warning` |
| 成功结果 | `success` |
| 说明提示 | `info` |

| 必须 | 禁止 |
|------|------|
| 按上表（及矩阵全文）绑 `data-tone`，经 Foundation `--weline-theme-*` 上色 | 严重度不同却全部落组件默认 / `quiet` / `neutral` / 一律 `primary` |
| 色只走语义矩阵 Token；status 叶子须按 §2a 亮/暗可解析 | 另造 `#hex`/`rgb()`；**只标 `data-tone`、暗色叶子缺失却宣称已上色** |

`quiet`/`neutral` **仅**用于 chrome 级（取消、关抽屉、muted 辅助字）。权威：[theme-semantic-color-matrix.md](../../../Theme/doc/theme-semantic-color-matrix.md)。宿主双写：`~/.cursor/rules/theme-semantic-severity-tone.mdc`。

## 2c. inverse 下 raised 纸面墨钉字面（`theme_inverse_raised_paper_ink_pin`，硬）

**抽象机制（WO-UI-CONTRAST-INVERSE）**：暗色 / inverse chrome（`[data-surface=inverse]` / `.w-surface-inverse`）会把 `--color-text*` / body-text 重绑成 on-dark 浅色。嵌在其下的**浅色 raised 面板**（下拉、抽屉、搜索纸面、地址弹层、语言/范围菜单等）若不本地恢复纸面墨，会白底浅字不可读。

| 必须 | 禁止 |
|------|------|
| 在 raised 根上**先钉** foundation 纸面字面（规范对 `#0f1111` / `#565959`，次级可 `#666666`）到 `--weline-chrome-body-text*`（或等价纸面局部），再绑 `--amz-drawer-text` / `--_paper-text` / `--color-text*` | 用已被 inverse 重绑的 `--color-text-primary` / `--color-text` / `--color-text-light` 等当纸面种子（会奶油叠奶油） |
| Token 化 /「去硬编码」扫除时**保留**上述钉字面；它们是对比度架构例外（同类：`@media` 断点字面量） | 把 `#0f1111` 改写成 `var(--color-text-primary)` 并宣称 Token 化成功 |
| 部件 CSS 特异度高于 Theme raised 重绑时，部件侧须自带同款钉，否则会盖掉 Theme 恢复 | 只改源文件不 bake/`theme:upgrade` 却宣称店面已修 |

**例子（仅举例，不是规则正文）**：迷你车抽屉、顶栏搜索纸面、配送地址弹层、账户下拉。权威：[theme-css-variables-only.md](../../../Theme/doc/theme-css-variables-only.md)「WO-UI-CONTRAST-INVERSE 纸面钉」；契约样板 `MiniCartShopifyDrawerContractTest` / `CheckoutDeliveryPanelPaperInkContractTest`。宿主双写：`~/.cursor/rules/theme-inverse-raised-paper-ink.mdc`。

## 2d. 前端必须守「变量 + 表面角色」双层（`theme_frontend_must_obey_tokens_and_surface_roles`，硬）

**抽象要求**：AI 前端 / CSS / Token 化合规 = **两层同时成立**，缺一层即违规。

| 层 | 含义 | 权威 |
|----|------|------|
| ① Token / CSS 变量 | 普通视觉消费已登记 `--color-*` / `--weline-*` 等；叶子落盘 `variables/` / `colors/`（§2a 禁空壳） | `theme_base_components_token_only`、`theme_referenced_tokens_must_resolve`、`theme-css-variables-only.md` |
| ② 表面角色例外 | inverse 下纸面钉、`@media` 断点字面等**故意保留的 foundation 字面**不得被 Token 化剥掉 | `theme_inverse_raised_paper_ink_pin`、同文档例外节 |

**Token 化 / 去硬编码动手前清单（硬）**：

1. `get_skill(weline-theme-development)` + Read `theme-css-variables-only.md` 例外；
2. 逐条字面量分类：普通色/间距 → 映射语义 Token；对比度/断点架构钉 → **保留**；
3. **禁止**「凡 `#hex` 一律改成最近的 `--color-text-primary`」无表面上下文启发式；
4. 改后契约锁负向模式 + inverse 下 Browser 对比度；部件 `layout_source` 须 bake / `theme:upgrade`——只改源不算店面 PASS。

复杂 Token/壳施工须派 **主题开发工程师**。宿主双写：`~/.cursor/rules/theme-frontend-obey-tokens-and-surfaces.mdc`。

## 2e. 高对比度是硬原则（`theme_high_contrast_mandatory`，硬 · 主题开发 + 审图同守）

**主题 / 前端 / CSS / 组件 / 模板开发**与**审图**（`dev/ai-command/theme/审图.md`，含用户附图、验收截图、WB-OP 复审）**一律**按实测比值判定对比度，不看「看着能读」。

| 对象 | 门槛 | 目标 |
|------|------|------|
| 正文 / 副标题 / 标签 / 链接 / 按钮文字 | ≥ **4.5:1** | 7:1 |
| 大字号（≥24px，或 ≥18.66px 粗体）标题 | ≥ **3:1** | 4.5:1 |
| 非文本信息（placeholder、图标、控件边界 / 焦点环） | ≥ **3:1** | — |

**禁止**：同色相糊底（暖底暖字、深底深字、奶油底奶油字）；文字色跨表面继承（换表面不换墨）；inverse / 深色 header·footer·抽屉·浮层只绑背景不绑前景，导致子元素继承外层字色（白底白字 / 黑底黑字）。**inverse 表面必须前后景成对绑定**。

**验收（硬）**：

1. 用真机浏览器 `getComputedStyle` 逐可见文本节点取**实际文字色**与**实际不透明背景**（含祖先合成）算比值；
2. **审图结论逐节点列实测比值**；只写「可读 / 没问题」不算 pass，任一实测低于门槛 = **FAIL** → 同回合改表面/墨色对并重测；
3. 只改 Token 不等于全站对比度通过；未实测的页面在汇报中标注「未验证」。

权威：本节 + [审图.md](../../../../../../dev/ai-command/theme/审图.md) 检查清单 B；宿主双写：`~/.dsh/AGENTS.md`「主题/前端对比度」。

## 3. 技能齐读（`css_or_theme_requires_ui_prototype_theme_skills` / `ui_skill_requires_theme_skill`）

凡任务/需求提到 **CSS** / **主题/theme** / **Token 化** / **去硬编码** / auto-literals，写样式或改主题前**必须**先加载并服从三件套，再执行 §2d 双层清单：

1. UI 技能 `frontend-design`
2. 原型技能 `prototype`
3. 主题技能 `weline-theme-development`（MCP `get_skill`）或 surface `frontend_development`

主题 Token 与 Weline UI 2.0 **优先于**通用 UI 技能的自造色板。UI 技能仅可指导**构图、层次、文案**；**禁止**按 UI 技能另发明 hex/rgb、px 间距阶梯、圆角阴影套件或平行 design token。宿主 `SKILL.md` 仅为可选薄壳。

后者覆盖**后台**：凡本仓前台**或后台/admin**界面工作，即使未提 CSS，也必须挂主题技能并与 Marketing/Smtp 既有页对齐（`backend_admin_ui_requires_frontend_theme_skills`）；**禁止**交裸 h1+form/table，搜索条全宽竖叠。

## 4. Theme 机制边界（`theme_mechanism_not_foreign_content`）

**抽象通则**：各自功能各自模块自管布局与模板；`Weline_Theme` **只**提供主题机制（含 `app/design` 继承/重写）；**禁止** Theme 兜底、代持、空挂其它业务模块的功能布局与主内容模板。登录/商品/结账等只是举例。

权威：[theme-mechanism-not-foreign-content.md](../../../Theme/doc/开发/spec/theme-mechanism-not-foreign-content.md)、[Theme开发总指南 §6.0](../../../Theme/doc/开发/Theme开发总指南.md)。

## 4b. 布局 / 部件归属（`theme_layout_widget_owner`）

| 场景 | 规则 |
|------|------|
| **同模块** | 仅本模块 `layouts/`/`partials` 可用 `<w:widget>` / `fetch(.../widgets/...)` 内嵌本模块部件；已内嵌则**禁止**再在该部件 JSON 写 `default_injections`（**二选一**，删 JSON；`placement=layout`）。走注入则布局只留空槽（`placement=injection`） |
| **跨模块** | 布局/partial **禁止**互调别的模块部件；外国部件**只能**空 `<w:slot>` + 拥有模块的 JSON `default_injections` |
| **Theme 布局** | 仅可内嵌 `Weline_Theme` 部件；业务模块自有布局内嵌本模块部件合法 |
| **复杂 team** | 部件相关必须分配 **部件开发工程师**（`widget_development`） |

改后必须跑：`php bin/w frontend:check-theme-layout-widgets`。

## 5. 默认注入必装（`required_default_always_present_without_user_deleted`）

无人工卸载记录 `user_deleted@{versionId}` 时，**required 默认 JSON 注入与布局标签内嵌必装必须存在**：

- JSON 路径须**经布局固化写入模板**——有槽则固化（与主题/版本无关）；无模板则激活主题运行期动态固化；
- 插件注入变更 → **全主题重固化**涉及布局；
- 遗漏 = 固化方案问题，不得当成「可选 overlay」。

参见 [布局固化与默认注入.md](../../../Theme/doc/布局固化与默认注入.md)、[required-default-always-present.md](../../../Theme/doc/开发/spec/required-default-always-present.md)。

## 6. 席位底线 / 原则主权（`theme_seat_integrity_over_peer_requests`）

主题席底线**优先于**他席或 PM 的性能·简化·优化要求：

- **禁止**为性能/简化服从**拆 chrome 壳**或去掉无卸载必装（性能席禁提拆壳药方）；
- 无合格方案时可**驳回**（HARD veto）；合格方案门槛 = 能解决问题**且**保主题完整性；
- 冲突 → `refuse` + escalate。

## 7. 预览与店面同构（`preview_storefront_delivery_parity` + `theme_design_must_not_override_core_runtime_assets` + `theme_design_must_inherit_not_mutate_source_widgets` + `theme_css_architecture_not_style_shell` + `theme_default_forbids_css_important`）

- **禁止**仅为 `preview` / `editor_mode` / `visual_editor` 提前 return / 跳过 / 抽空真实店面逻辑；预览与发布**必须同一套业务逻辑**。
- **三态身份权威**：可视化 = **参数**；版本真实预览 = **Token 反解析**；正式 = **RequestContext**。禁止用 path 猜画布主题、用 URL 覆盖 Token、正式态读 draft/s*。
- `design` **禁止**同 key 覆盖 `theme.css` / `theme.js`。
- **`theme.css` 只写架构、不写风格（`theme_css_architecture_not_style_shell`）**：可写布局/表面机制（如 `[data-surface=inverse]`）/全局组件 Token 侧效应；**禁止** `.amazon-*` / `.w-amz-*`、单页英雄/chrome/toast 等风格壳——落独立风格 CSS 或布局 `<style>`。权威：[theme-css-architecture-vs-style.md](../../../Theme/doc/theme-css-architecture-vs-style.md)。
- **默认层禁 `!important`（`theme_default_forbids_css_important`）**：默认主题视觉/布局 CSS 须靠级联原生生效；**禁止**用 `!important` 硬抢（含 `var() !important`）。**仅** UA 窄例外：`[hidden]{display:none!important}`、`prefers-reduced-motion` 缩短动画。宿主双写：`~/.cursor/rules/theme-default-forbids-css-important.mdc`。
- **`design_theme` 改外观必须继承**：只落 `app/design/{Vendor}/{theme}/`（widgets/layouts/partials 同 key + 品牌 CSS）；**禁止**直接改上游 `app/code` 主题源。若仅靠 design 继承做不到 → **停手询问用户**（框架/默认层缺口），禁止静默改上游解围。平台级修须用户批准后显式 Mode A / 部件席。宿主双写：`~/.cursor/rules/theme-design-inherit-not-mutate-upstream.mdc`。
- **`theme_design_multi_path_is_inheritance_normal`（硬）**：同一设计主题根下，同一逻辑资源可同时出现在 modern `{area}/…`、兼容 `theme/{area}/…` / `view/theme/{area}/…`，以及 `theme:upgrade` 双写到该设计树内 `Weline/Theme/view/theme` URL 命名空间——这是**继承 + 发布正常态**，**禁止**当成「多份拷贝/漂移缺陷」去删一侧。权威编辑落设计主题 area 源，再 `theme:upgrade`。特例（如皮肤误放在无 `register` 的 `app/code` 模块 `templates/` 树）不是本条豁免对象。
- 改 Theme/`app/design` 前必须先声明 `work_mode`；派 **主题开发工程师**（`theme_engineer_for_theme_work`）。

参见 [preview-and-runtime-modes.md](../../../Theme/doc/preview-and-runtime-modes.md)、[theme-inheritance-and-file-conventions.md](../../../Theme/doc/theme-inheritance-and-file-conventions.md)、[主题开发.md「默认层级联与 design 继承改法」+ Mode A/B](../../../../../dev/ai-command/ai/主题开发.md)。

## 8. 前端 JS 加载（`theme_js_module_declare_only` / `widget_static_assets_bake_to_head` / `weline_js_loader_framework_only`）

| 允许 | 禁止 |
|------|------|
| 业务模块 JS：`Weline.declare` + `data-weline-load`（+ `data-*` / `data-js-ns` / `data-uid` 于部件根节点） | 部件/布局手搓 `<script src="@static(...js)">`；裸 `<js>` 直拉**业务模块**；不注册 modules 就加载 |

## 18. 响应式单一权威（硬）

- 同一页面/组件的响应式行为只允许一个权威文件：`默认主题` **或** `design 覆盖`；命中覆盖后默认层 CSS/JS 不再参与该页面行为，覆盖文件整体接管。
- 发布面的 `{area}/assets/...` 与 `Weline/Theme/view/theme/...` 双写是 `theme:upgrade` 构建产物，不属于本条「三套」；本条只约束运行时会同时参与层叠的 CSS/JS 规则层。
- 一个断点只声明一次；禁止 layout 内联 CSS、主题 CSS、部件 CSS、JS 重复声明/推导同一断点。
- `JS 禁止自行适配断点`：不得用 `matchMedia`、`window.innerWidth`、`outerWidth` 判断布局模式；只能读取 CSS 已表达状态（示例：`getComputedStyle(toggle).display`）。
- 覆盖需要不同断点时，覆盖文件内保留唯一 `@media`；禁止「默认 992 抽屉 + 主题 901 桌面栏 + JS 992 inert」三套并存。
- 反例：2026-10-25 汉服 PLP，三套规则导致 `901–992` 侧栏被隐藏、按钮不可见、JS 设 `inert`。
- 验收：断点两侧浏览器各测一次；`rg` 确认同一页面断点只出现在一个权威文件；JS 中无 `matchMedia`/`innerWidth` 布局判断。
- [theme-inheritance-and-file-conventions.md](../../../Theme/doc/theme-inheritance-and-file-conventions.md) «响应式单一权威»

## 19. 自定义主题验收：新开本地站点，禁止动既有站主题（硬 · `custom_theme_acceptance_new_local_website`）

**口径**：任何自定义（design）主题的测试 / 验收 / 演示 —— 尤其是网站柜子相关的新站主题 —— 一律**新开一个本地网站并让该站选这个主题**；**禁止**在默认站或任何既有站点上临时切换店面主题来验收（会污染既有站的店面身份与发布面，且验收结论无法独立复现）。
**冲突**：与「在既有站切主题更快」的旧习惯冲突时，以本条为准（用户 2026-10-28 指定，按当回合实际执行固化）。

### 步骤（本机）

1. **子域用站点语义 code（HARD `local_site_domain_semantic_code`，2026-10-29 用户指定）**：优先 `{site_code}.test.weline.com`（`site_code` 取 `php bin/w website:listing`；例 `amayum` → `amayum.test.weline.com`）；能免 hosts 就先试 `{site_code}.test.weline.localhost`。**禁止**把随机/哈希域（`local-demo-*`、`ai-test-*`、池子随机域）当该站主验收面。仅当语义域与既有冲突/不可用时才 `php bin/w website:domain-pool` 选 `ready=1 created=0` 的记录并记下 `pool_id`，同时在站点柜写明原因。绑定/解析后**必须回写站点柜**（`websites/README.md` 全集表 + `websites/<site>/server.md`「本地演示站」行）；下次读柜子直接复用，禁止再申请新域。
2. **建站**：`php bin/w website:create --name="<站点名>" --pool-id=<id> --code=<code> --json`
   - 落 `w_weline_websites_website`（`website_id` / `code` / `url`）+ **默认店铺** `w_weline_websites_store`（`is_default=1`）+ `w_weline_websites_website_domain`（`website_id` + `pool_id` + `domain`，`is_primary=1`），并消费域名池条目。
3. **绑域名（校验/补录）**：建站会自动写 domain 行；换域/加域时补 `root_domain`、`sub_path`、`is_primary`、`status=active`、`https_enabled=1`，并按 §「地址规则」选对 Host 形态。
4. **绑主题**（网站级，不写默认站）：
   - CLI：`WebsiteThemeBindingService::bindThemeForWebsite($websiteId, '<code>', $themeId, 0)`
   - 后台等价入口：网站信息 → 店面主题
   - 落表：`w_websites_theme_application`，`scope_key = website|<id>|<code>||||v1`，`area=frontend`。
5. **刷新站点识别缓存**：`php bin/w cache:clear --no-warm`；Worker 仍返回旧站时 `php bin/w server:reload`（`DetectWebsite` 有 `websites.detect.*` 进程级缓存）。
6. **验收并交付**：`https://<池子域>/~site/<code>/`（带 `w_fpc_pierce`，改过静态再叠 `_wb_nc`）。
   - 原因：项目 Host 的裸域按设计归默认站（`ProjectHostSiteMount` 的 `/~site/{code}` 挂载是项目 Host 上多站的正规入口），裸域不能用来验新站。

### 地址规则：裸域能否直达看 Host 形态（硬）

| Host 形态 | `LocalDomainPolicy::isStandardProjectHost` | 裸域 `/` 归属 | 自建站地址 |
|---|---|---|---|
| `{8位十六进制}.test.weline.com` | 1（标准项目主机） | **固定默认站**（`findDefaultSiteForProjectHost`） | 只能 `/~site/<code>/`（实测：加 `sub_path=/manufacture` 绑定后该路径仍 404，sub_path 只改站点归属不改路由） |
| `xxx.test.weline.com`（单标签非 8 位 hex） | 0 | 由 `WebsiteDomain` 行匹配该站 | `https://<domain>/` 直达 |

- **误判警报**：裸域看到别的站 ≠ 没建站；先看 `data-website-id` 命中的站，再用「website + 默认 store + domain 行 + 主题绑定」四元组核对。
- **要裸域直达**：域名必须非项目主机，且先完成本机域名准备（写 `/etc/hosts` + 通配证书需 macOS 管理员授权：`AiSiteLocalDomainReadinessService::prepare($domain, true)`；未授权返回 `TEST_DOMAIN_HOSTS_AUTHORIZATION_PENDING`）。授权后再补 domain 行并刷缓存。
- 未进 hosts 的池域名（curl 000/404）不得作为可交付地址。

### 已误切既有站时的还原（硬）

按**原引用逐字段还原**：`theme_id` / `theme_version_id` / `content_revision` / `version_owner_scope` / `version_owner_store_mode`
走 `Weline\Websites\Api\Theme\ThemeApplicationInterface::save($scopeKey, $storeMode, 'frontend', $reference, $expectedRevision)` 的 CAS 保存；
**禁止**手写 SQL 改 `w_websites_theme_application`；**禁止**用 `bindThemeForWebsite()` 带旧 versionId 去「还原」（它会按当前 storage scope 校验版本归属而抛 `所选主题版本不属于当前范围`）。
还原后在汇报里贴出还原后的 `reference_json` 作为证据。

### 站点生命周期

新站保留为该主题的**演示 / 回归站**（后续主题回归、交付截图、演示链接都指向它）；归档或删除须用户明确同意，禁止验收完就删。

## 20. 主题静态出版前缀按文件核盘（硬 · `theme_static_prefix_disk_verified`）

主题自算静态 URL（`AmayumView` 这类 `asset()/themeFile()` 帮助器）必须**逐文件**确认 `pub/static` 下真实存在再拼前缀。

| 发布树 | 前缀形态 | 由谁铺 |
|---|---|---|
| 代次树（theme 发布） | `/static/theme/v1/<build>/<ns>/frontend/`、`/static/<pair>/v1/<build>/<ns>/frontend/` | `theme:update` 生产模式 |
| 扁平树（部署发布） | `/static/<ns>/frontend/` | `deploy:upgrade` |
| 部署构建段 | `/static/<12hex>/<ns>/frontend/` | `deploy:upgrade` 的构建段（只含部分子树） |

- URL 的 `/static/` 段对应磁盘 `pub/static/`：拼盘路径时**去掉一次** `static` 段，别拼成 `pub/static/static/...`。
- **禁止**把「本次命中的前缀」记成请求级全局基址再给其它资源复用：不同资源可能只存在于不同树（实测主题 head 包在构建段、皮肤 CSS/图标只在扁平树），复用会把本来 200 的 CSS 换成 404 的图标。
- **禁止**只凭代次指针/`StaticBuildId` 拼 URL 不核盘；磁盘缺失即回退下一候选，全部缺失才用 `themeBase()` 兜底。
- 验收：页面里每个 `<link>` / `<script>` 静态 URL 逐条 `fetch` 全 200（含 SVG/favicon 的 Content-Type）；`rg` 页面 HTML 不出现未发布前缀。

## 20b. dev 模式换主题静态要 `deploy:upgrade`（硬 · `theme_static_refresh_requires_deploy_upgrade`）

`system.env=local`（dev）站点的 `theme:update` 是**空操作**（打印「dev 模式已就地固化/编译：changed=0」）：模板即时生效，但 `/static` 仍是旧构建代。

| 必须 | 禁止 |
|---|---|
| 让新 CSS/JS/图标上线：`deploy:upgrade`（生成新 `build_id` + 搬主题资产 + bump `global/storefront/deploy`） | 跑完 `theme:update`（或 `static:compile`，只预热缓存）就宣称静态已更新 |
| 再 `theme:publish-not-found-static` 发 404 快照；改了模板/组件缓存池（如 `var/cache/weline_theme_storefront_chrome`）后重取页面 | 只清浏览器/CDN 缓存就断言线上没生效 |
| 验收：`pub/static/.build.json` 的 `build_id` 变了 + 页面 HTML 构建段变了 + 新选择器能在对外 CSS 包里 `grep` 到 | 用「页面能 200」当静态更新的证据 |

## 20c. 站点图标是主题品牌资产（硬 · `site_icon_brand_assets_in_theme`）

| 必须 | 禁止 |
|---|---|
| 图标随主题自包含：`frontend/assets/icons/` 放 `favicon.svg` + 16/32/96 PNG + 192/512 + `apple-touch-icon-180`（iOS 用不透明底），在 head partial 声明并走主题资源 URL（带内容哈希 `?v=`） | 依赖框架默认 `Weline/Theme/view/theme/frontend/assets/images/theme/icon.png`（非品牌；站点上常 404，等于没有图标） |
| 图标发布到**所有**已存在的树（扁平 + 各构建段 + 各代次），否则按前缀命中就会 404 | 只往扁平树拷一份就以为全栈可用 |
| 验收：浏览器内对每个 `link[rel=icon]` / `apple-touch-icon` 实测 200 + 正确 `Content-Type`，覆盖首页 + 内容页 + 404 页 | 只看文件存在 / 只看 `<link>` 有输出 |

图标配色/字形复用站点既有品牌源（如主题 header 的品牌 mark 与颜色令牌），不得另起一套视觉。
