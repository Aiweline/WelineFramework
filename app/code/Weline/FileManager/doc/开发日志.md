## `1.1.2` — 嵌入式文件选择器底部可达

- 当前状态：`implemented_pending_runtime`
- 需求 ID：`REQ-FILEMANAGER-0003`
- 根因：外层弹窗的 iframe 同时受 flex 布局与脚本像素高度约束；弹窗头部、视口或浏览器可用高度变化后，旧的 `height/min-height/max-height` 会把 iframe 撑出 body，并被外层 `overflow: hidden` 裁掉。
- 实现：弹窗使用 `90dvh` 上限和 `flex: 1 1 0` 高度链；body/iframe 允许收缩，iframe 不再写入测量像素高度；通过正式 `theme:compile welineUi` 更新主题派生资源。
- 验证：JS/PHP 语法通过；嵌入式滚动定向契约 `1 test / 11 assertions`、完整 MediaManager 视图契约 `17 tests / 289 assertions` 通过；真实登录态浏览器 375/768/1024/1440 因浏览器控制连接中断而待执行。

## 2026-09-04 — 资产级来源元数据更新边界（1.1.6）

- `FileAssetLibraryInterface` 新增 `saveAssetMetadata()` 数据边界，使 Blog 等跨模块调用方可以在保留对象身份与语言行的前提下补齐来源、许可、用途、关系及复核记录。
- 更新受显式 `FileAccessContext`、对象身份、预期修订号、写意图事务与行锁保护；私有资产的既有 `access_policy` 不允许借此接口修改或删除。
- `describe()` 仅返回资产元数据 SHA-256 供写后读回，不暴露可能包含访问策略的原始 JSON。
- `referenceCount()` 在管理权限和非删除态边界内公开派生引用数量；实际 Hanfu R3 清理先对四个冻结对象全部计数归零，再进入删除循环，删除服务仍会在行锁内二次核对引用。
- 已执行 `setup:upgrade -m Weline_FileManager --skip-classmap`，数据库版本从 1.1.5 升至 1.1.6；160 个 Blog 资产的来源元数据与 320 行双语 locale 数据均已通过哈希及完整字段读回。
