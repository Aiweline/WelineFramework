# DataTable Taglib 场景映射表

| 场景 | 规范组合 | 数据/权限边界 | 禁止做法 |
|---|---|---|---|
| 标准后台列表 | `w:d-table` + `w:t-header` + `w:t-filter` + `w:t-footer` | 业务 QueryProvider + 具体 ACL | 手写第二套 GET 筛选条或把 Model 类名当授权 |
| 单表 CRUD | `w:d-table` 内生成或嵌套 `w:d-form` | backend capability 决定新增/编辑/删除 | 公开前台渲染写按钮 |
| 多模型读 | alias model + `join` + `alias.field` | Provider 校验 alias 和字段 | 无 alias 的跨表排序/筛选 |
| 多模型写 | `dependencies` + 默认事务 + `composite-write` | preview → 单次 token → execute | 跳过计划直接 saveData |
| 派生/分片只读列表 | `mode=local` + `local-data-el` + `filter-mode=client` | 浏览器 JSON；无 CRUD/导出/远程偏好 | 为让 local 可写而调用默认 Provider |
| 服务端页面筛选 | `w:t-filter filter-mode=page` | 原生 GET；JS 不拦截 | 同时再写一套业务 filter bar |
| 语言/模块/站点筛选 | `w:field type=language-select|module-select|website-select` 包裹官方 Taglib | DataTable 只提供字段容器，选项由官方 Taglib 生成 | 裸 `<select>` 循环拼领域选项 |
| 自定义行操作 | `row-actions` 的 `link` 或 `event` | event 交给业务 JS，再调用业务 Provider | JSON 中放函数、脚本或 adapter 类 |

## 领域筛选示意

```phtml
<w:t-filter advanced="true" collapsible="true" filter-mode="ajax">
    <w:field belong="t-filter" name="language" type="language-select">
        <!-- 放项目中对应的官方语言选择 Taglib；DataTable 保留其原始控件与提交值 -->
    </w:field>
</w:t-filter>
```

复杂类型没有领域数据时不会自己拼裸 select。运行时从字段容器内第一个 input/select/textarea 读取值，并把容器 `data-field` 作为过滤键。

## 属性继承

`d-table` 把 model、scope、provider、resource、dependencies、transaction、write-order、composite-write、confirm-write、filter-mode、filter-advanced 和 filter-collapsible 放入请求隔离的 TableContext。嵌套 `d-form`、`t-filter`、`t-footer` 继承相应属性；每次渲染结束必须 pop，WLS request reset 会清理残留状态。
