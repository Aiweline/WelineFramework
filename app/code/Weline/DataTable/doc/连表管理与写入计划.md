# DataTable 连表管理与写入计划

## 目的与边界

DataTable 的连表写入由声明、策略和执行三层组成：Taglib 声明模型 alias、依赖和 UI；QueryProvider 注册稳定资源、能力与 ACL；服务层生成并执行写入计划。浏览器提交的 PHP 类名只用于与已注册资源交叉校验，不能授予权限。

默认 `api-provider="datatable"` 仅注册 `demo.users`、`demo.products`、`demo.orders`、`demo.user_profiles`、`demo.user_addresses`。业务模块应提供自己的 QueryProvider，不要修改默认 Demo 注册表，也不要增加可由浏览器指定的 adapter 类属性。

## 声明示例

```phtml
<w:d-table
    model="Weline\Sales\Model\Customer as c, Weline\Sales\Model\Order as o"
    api-provider="sales-admin"
    resource="customer-orders"
    scope="sales-order-admin"
    join="left o on c.id = o.customer_id"
    dependencies="c.id->o.customer_id"
    write-order="c,o"
    transaction="true"
    composite-write="true"
    confirm-write="true">
    <w:d-form form-mode="modal" auto_fields="false">
        <w:field belong="d-form" name="c.name" required="true"></w:field>
        <w:field belong="d-form" name="o.order_no" required="true"></w:field>
    </w:d-form>
</w:d-table>
```

多模型未显式设置 `transaction` 时默认 `true`。`write-order` 必须恰好包含所有 alias 一次，并满足每条 `dependencies` 的父项在子项之前；省略时使用稳定拓扑排序。循环、未知 alias、未知字段或把值注入只读字段都会在预览前拒绝。

## 元数据协议

`metadata` 返回 `datatable.model-metadata.v1`。每个模型包含表名、主键、字段及空的 relations 扩展位。字段来自 ORM `columns()`；表尚未创建时回退到 `#[Col]` 声明，因此 setup 前仍可生成确定性计划。字段包含 required、nullable、readonly、writable、editable_inline、searchable、sortable、visible_default、filter_default 和 source。

密码、secret、token、API/private key 等敏感命名字段不会进入列表、筛选或写入计划，也不能写入。主键和未知字段由统一元数据层过滤。

## 两阶段协议

1. 表单将 dotted 名称（如 `c.name`）收集成按 alias 嵌套的数据。
2. `previewWrite` 规范化模型、字段、依赖、顺序和事务，返回 `datatable.write-plan.v1`。
3. 计划展示每一步的资源、操作、全部非敏感字段、必填、当前值、是否变更和依赖映射。
4. 缺必填时 `can_proceed=false`，不签发 token；用户返回修改。
5. 可执行时签发 5 分钟、64 位十六进制、单次使用 token，并绑定规范化载荷摘要与当前 session。
6. `executeWrite` 先删除 token，再校验过期与摘要；成功后按计划顺序执行。任何一步抛错由 `TransactionManager` 委托框架 `WriteIntentTransactionCoordinatorInterface` 回滚同一 `TransactionContext`。

token 的先删除再验证语义是有意设计：即使攻击者发送篡改载荷，该 token 也立即失效，不能再用原载荷重试。用户需要重新预览。

## Provider 策略要求

- 读操作可以按产品需求设为 `auth=any`，写入、记录加载和远程偏好必须 `auth=backend` 并绑定具体 ACL source。
- operation 必须 `external=false`；`frontend=true` 表示 worker 可调用，不表示匿名授权。
- Provider 内用稳定 resource 映射实际 Service/Model。不要接受浏览器传入的任意 Model、Service、adapter 或回调类。
- 业务校验放业务 Service；DataTable 只负责元数据、能力、确认协议、通用字段边界和事务编排。
- 多数据库连接不能宣称原子。当前计划的 `atomic_scope=single_connection`，若业务跨连接，应在业务 Provider 拒绝或明确降级并返回 warning。

## 失败与恢复

| 失败 | 行为 |
|---|---|
| 缺必填 | 返回计划，`can_proceed=false`，无 token |
| alias/字段/依赖无效 | 预览失败，不写数据 |
| 循环依赖 | 预览失败，不写数据 |
| token 过期、复用或格式错误 | 执行失败，不写数据 |
| 载荷摘要不同 | token 立即失效，不写数据 |
| 任一步保存失败 | 事务 rollback，错误返回调用方 |
