# WelineFramework 能力全景（Capability Atlas）

> **一句话 banner**
> 一个能把「域名 → HTTPS → 多站点 → 主题/商城 → CDN + FPC → 邮件/客服/消息 → SEO/GEO → AI 运营 → 自动部署」装进同一套模块化工程模型的 PHP 框架。
>
> **这份文档解决什么**
> 能力分散在 130+ 个模块里，代码和模块文档各自为政，人和 AI 都容易「只看到当前目录，看不到整张地图」。本文把能力按业务场景重新编排，并为每条能力标出**归属模块、权威入口、可继续阅读的文档**。
>
> **证据规则**
> 本文只写当前工作树可复查的能力：模块目录、公开契约、控制器/命令、模块 `doc/`。
> 「文件存在」不等于「已在你的环境验收」。涉及线上状态、跨平台门禁、外部服务的条目，以对应模块的「当前能力与验收状态」为准；没有证据的产品口径统一放进文末「边界与待确认」。

## 6. 边界与待确认（不要把产品口径写成既成事实）

| 说法 | 当前证据 | 结论 |
|---|---|---|
| “兼容 WPA” | 代码里是 **PWA**（manifest / service worker / 图标）；未发现名为 WPA 的协议或模块 | 按 PWA 理解；若 WPA 指别的协议，需要补充定义 |
| “VIP 积分体系” | `Weline_Points` 已实现成长值/VIP 等级/积分倍率/退款扣回；可花余额在 `CustomerAsset` 的 `points` 账户；默认开关为 0；后台等级 CRUD、结算/账户展示、免运费接入尚未覆盖 | 可以说“有 VIP 积分内核”，不能说“开箱全链路完成” |
| “GEO 模块” | `Weline_Geo` 有后台菜单与协议渲染；`Weline_GenerativeEngineOptimization` 菜单已禁用（legacy fork） | 说 GEO 找 `Weline_Geo` |
| “网站监控 / 售后 / 宠物” | `WebsiteMonitoring` README 标注未开发完整；`Rma` 只有文档占位；`StorePet` 没有 `etc/module.php` | 不要当已交付能力宣传 |
| “免费 token” / “免费模型” | `Weline_AiAcquisition` 的浏览器桥只负责在用户浏览器执行搜索与抽页；模型调用仍回后端，密钥不下发浏览器 | “免费 token”是运营口径，代码不承诺额度 |
| “超多支付方式” | `Weline_Payment` 是 Provider 壳；能接多少种取决于安装/实现的 Provider | 说“可扩展任意支付方式”，不要说固定数量 |
| “三平台生产就绪” | WLS 文档标注 `LOCAL_RUNTIME_VERIFIED / GA_BLOCKED_EXTERNAL` | 对外必须带外部门禁说明 |
| “OPS 自动部署” | 部署由 `Weline_Deploy` 负责；`Weline_Ops` 是 AI 运营台（画像/日更/派工/审批），不是部署器 | 说部署找 Deploy，说 AI 运营找 Ops |
| “闲时自动预热” | 有 CDN 定时预热、发布后逐 URL 重暖、WLS idle 阶段关键路径预热 | 可以说“定时 + 空闲时预热”，不要说“所有页面都保证已预热” |
