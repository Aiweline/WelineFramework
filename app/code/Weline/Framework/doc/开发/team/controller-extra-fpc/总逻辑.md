# 总逻辑一页纸 · controller-extra-fpc

## 口述主链

1. **读**：控制器 `@Extra type=fpc …` → 升级收集 → 侧车 → Coordinator 读策略（不发 changed）。
2. **写**：业务 Service 写成功、同事务 `w_changed(事实信封)` → ChangedType 校验 → Enricher 补 urls/namespaces → Recipe → Effects → Fpc/Cdn Capability。
3. **仍事件**：Seo / I18n / 配置类等继续听 `resource_changed`；`w_changed` 在 Capability 管线后仍 dispatch。
4. **硬切**：只删缓存向 Observer（Namespace/Impact-FPC/Cdn changed/Theme FPC 旁路）；无兼容双跑。

## 冻结接口名（施工对齐）

| 符号 | 用途 |
|------|------|
| `ChangedCapabilityInterface` | 执行 Effect（code/描述/支持的 effect、phase） |
| `ChangedTypeInterface` | 资源类型合同 + Enricher |
| `InvalidationEffect` | `bump_namespaces` / `purge_fpc_urls` / `purge_fpc_all` / `cdn_purge`；`phase=sync\|after_commit` |
| Extra type `fpc` | WLS/Server 注册；字段 enabled/ttl/namespaces |

## MVP Enricher

`product_search_projection`、`theme`、`theme_layout`、`cms_page`（+ 可选 `url_rewrite`）。

## 否决

Response/控制器加载代发 changed；业务清 FPC；HTTP 上下文代替业务时机。

## 架构师

每波对照本页：是否做成管子、是否业务清 FPC、是否误删 Seo。
