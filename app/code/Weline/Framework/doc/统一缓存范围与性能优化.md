## 范围声明

业务缓存继续使用 Framework 的 CacheManager、StorefrontScopeHotCache 和 namespace generation，不自行维护 Worker 静态数组、缓存键拼接或刷新锁。每项资源声明 CachePolicy，统一入口解释范围、变体、依赖和有效期。

| scope | 可共享边界 | 缓存键中的身份 |
|---|---|---|
| global | 所有网站、店铺、渠道 | 不含租户身份；按声明的语言等变体区分 |
| website | 同一网站的所有店铺、渠道 | website_code |
| store | 同一网站、店铺 | website_code、store_code、store_mode |
| channel | 指定网站、店铺、渠道 | website_code、store_code、store_mode、channel_code |

默认网站 `default` 和 website_id=0 仍属于网站范围，不是 global。非 global 资源在请求范围未冻结时保留 request fence，不能以缺省身份跨请求共享。原有 `website=true` 维度接口保持兼容，其含义仍是完整店面上下文；新增业务使用显式 scope。

`vary` 支持 lang（locale 别名）、currency、area；数据确实依赖这些维度才声明。公共 UI 翻译按 locale、模块和字典版本全局共享，不能把所有翻译按渠道复制。店铺或页面提供的覆盖译文按请求 EventDictionary 解析，不能写入公共 Worker 词条缓存。

## 统一入口

```php
$policy = new CachePolicy(
    resource: 'product.category_tree',
    pool: 'weline_product_storefront_category_tree',
    scope: 'website',
    dependencies: ['catalog'],
    freshTtlSeconds: 3600,
    staleTtlSeconds: 86400,
);
$value = $hotCache->rememberPolicy($policy, $logicalKey, $builder);
$hotCache->forgetPolicy($policy, $logicalKey);
```

传入策略时自动在 CacheManager 登记，之后可按 resource 名使用同一入口。`registerPolicy()`、`getPolicy()`、`getPolicies()` 提供统一注册和查询；业务资源的声明放在所属模块协调器中。Product 的声明统一位于 StorefrontCatalogCacheCoordinator。

策略签名、scope 投影、vary 和声明依赖的代次均参与键生成。fresh TTL 表示新鲜窗口，stale TTL 表示其后允许返回旧值的额外时间。仅通过显式策略的 getCustom/setCustom 路径访问底层池，避免池的 environment_scoped 再次扩大已声明的范围。

## 依赖与失效

`dependencies` 使用 catalog、config、price 等领域路径。沿用 NamespacePath 和 NamespaceGenerationRepository：网站依赖包括 global/storefront 下的对应领域和 website/{code} 下的领域；店铺、渠道在网站领域路径下细分。祖先代次自然影响后代，无需遍历删除。

分类原始索引与分类商品关系只依赖 catalog，不随无关价格、主题变更失效。含 URL 的菜单按渠道并保留语言、货币、区域变体，依赖 catalog/config；商品报价投影按渠道及语言货币，依赖 catalog/price/config。

`forgetPolicy` 删除当前策略和逻辑键的当前变体；影响全范围或多语言时由领域协调器 bump namespace，不能枚举少数语言代替范围失效。Product 写后继续通过 StorefrontCatalogCacheCoordinator 通知和失效。

## 热缓存行为

namespace 补齐可能在数据库读取时让出 Fiber。返回后必须核对最新进程代次：已被提交事件推进的快照不能由旧请求降级；同代次只能合并到最新成员集合，不能覆盖其他 Fiber 已补齐的 namespace。请求持有自己的快照，公共 L1 不按请求 ID 拆分。

URL 和范围解析完成后，`State::getLang/getCurrency` 直接复用已冻结的 `StorefrontCacheKeyContext`。解析前继续使用原有路径、查询参数及网站默认值回退；显式语言覆盖仍通过 `setRequestLanguageOverride` 管理，保留本地化结果重置。

进程 L1 统一限制条目数量，默认 1024 项，命中更新淘汰顺序。冷构建和 stale 刷新复用现有 SingleFlight；获取构建机会后再次读取共享池，复用其他 Worker 刚生成的数据。后台刷新保留入队时的缓存键，不能把旧代次构建写进新代次。

CacheManager 全部清理同时重置本 Worker 热缓存。完整 WLS 清理仍走现有 cache:clear 的 Worker 广播流程；单池底层 clear 与领域失效语义不可混淆。

## 2026-09-06 — Worker socket 等待边界计时

`SchedulerSystem::awaitSocket` 在已有 RequestLifecycleTrace 类已加载且启用时，用同一 `runtime.io.await_socket` span 记录至少10ms的等待或异常。类别为 `runtime`，不再次累加 DB/WLS，不新增 phase 汇总项；未加载或关闭 Trace 直接走原等待逻辑，不为 socket 等待自动加载 Trace。

该 span 的 prepare、dispatch、suspend、select 字段包含各自耗时和单调开始/结束坐标，未走到的阶段为 null。prepare 包含原输出缓冲 flush；dispatch 包含原 dispatcher/事件调用；suspend 表示调用 Fiber suspend 至恢复返回的墙钟区间，含等待与调度恢复，不能称为纯网络时间；select 只用于原同步/prepare 未获准时的回退。记录在原调用返回或抛出后执行，保留 bool、原异常对象和既有 Fiber 关闭行为，不修改 timeout、输出 flush、等待注册或协议。

通过同一请求中的客户端 RPC/read 单调区间定位嵌套等待；坐标仅在同主机同次启动内比较，父子 span 不可重复相加。只记录方向、路径、超时、结果、异常类与固定阶段坐标，不记录 socket、载荷或异常消息。明细仍受 Trace 的原有容量与慢样本保留规则约束，缺少 top 样本不能证明该等待未发生。正式收益与归因以实际 Worker reload 后的同请求日志为准，临时 Fiber/socket pair 用例不替代真实请求验收。

模板插槽同时记录 `theme.slots.cooperative_yield` 与 `theme.slots.boundary_scan` 的统一 measurePhase，分别只包围原有 SchedulerSystem::yield 与每轮 enumerateRegions；不通过会另行 yield 的 traceCall 添加观测，也不改变原调用次数。前者反映主动让出至恢复的累计墙钟时间，后者反映实际边界扫描次数与累计耗时，均已包含于其父阶段；二者仍受统一 phase 数量上限管理。

## 2026-09-06 — Session 预热使用业务连接预算
