## `2.4.0` — 首页 READY 预热默认 fail-open

- 当前状态：`implemented`
- 需求 ID：`REQ-FRAMEWORK-0006`
- 范围：`WlsRuntime::runRequiredHomepageProcessFpcReadyGate` / `isHomepageReadyGateFailOpen`；与 Server Orchestrator / Worker 启动门禁对齐。
- 事实：模板 `declare(strict_types=1)` 与编译器 hash 头冲突时产生不可捕获 `E_COMPILE_ERROR`，READY 前 in-process 渲染会杀死 Worker。
- 实现：默认 `ready_gate_homepage_fail_open=1`，READY 前跳过 in-process 首页证明并返回 `deferred-after-ready` proof；严格模式才走旧路径。
- 验收：与 `REQ-SERVER-0012` 同批；需 `server:reload` 后确认启动不再因首页未 hot 而 `WLS_STARTUP_FAIL_FAST`。

## `2.4.0` — 请求 authority 与 Session Cookie 身份

- 当前状态：`implemented_validated`
- 需求 ID：`REQ-FRAMEWORK-0003`
- 范围：`WlsRequest` 在 Host 省略端口时规范直连 `WLS_PORT`，在可信 Dispatcher 转发时恢复公共 Host/scheme/port，并由 `GlobalsEmulator` 原样保留 authority 快照；`SessionCookieNameResolver` 信任有效 `SERVER_PORT`。设备校验失败保留脱敏日志。无 schema 变更。
- 事实/发现：2026-08-18 直连 `https://host:9555` 曾因 HTTP/2 authority 省略端口造成 Cookie 名漂移；2026-08-26 生产公网 443 经负载均衡到 Worker 23922/23923/23924 时，先观察到内部端口污染 Session Cookie，随后又确认 `GlobalsEmulator` 从 raw Host 二次覆盖已规范化快照，导致页面 `<base>`、菜单和重定向仍含内部端口。
- 实现：非受信直连且 Host 无端口时，由 `WlsRequest` 用 `WLS_PORT` 写入规范化 `HTTP_HOST`/`SERVER_PORT`；仅当传输层已确认可信 Dispatcher 时，从其保存的 `Weline-Original-Host` 与 original scheme/port 恢复公共 authority。`GlobalsEmulator` 对 HTTP_HOST、SERVER_NAME、SERVER_PORT、HTTPS、REQUEST_SCHEME 和 WELINE_FULL_REQUEST_URI 优先使用不可变快照，仅在缺失时回退 Request API。
- 验收门禁：`WlsRequestForwardedOriginTest` 覆盖直连非标准端口、可信 Dispatcher wire Host=`app.example.com:23922` 以及 `GlobalsEmulator` 前后公共 HTTPS 443 不变；`SessionCookieNameResolverTest` 覆盖 `SERVER_PORT=443`、`WLS_PORT=23922` 仍为无后缀 `WELINE_SESSID`。生产需同时验证跨 Worker 登录态与页面所有绝对 URL/Location 均不含 23922/23923/23924。

## `2.4.0` — 网站有效货币解析契约

- 当前状态：`implemented_validated`
- 需求 ID：`REQ-FRAMEWORK-0002`
- 范围：`State::getCurrency()`、网站默认货币回退及聚焦回归；无 schema 变更。
- 事实/发现：网站默认及允许币种均为 USD 时，遗留 `user.currency=CNY` 仍被无条件采纳，导致默认商品与搜索路由显示 CNY 0.00；显式 `/USD` 路由正常。

- 验收：先以失败用例复现 `expected USD / actual CNY` 及大写默认值返回 `null`；实现后 21 个聚焦测试 / 94 个断言通过，9514 的默认商品、搜索、详情、购物车、结账前置页及四种本地化路径均使用 USD，控制台 0 error / 0 warning。
