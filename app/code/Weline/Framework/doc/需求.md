## 当前有效需求

### `REQ-FRAMEWORK-0001` 可选的认证设备生命周期契约

- 来源与确认：用户于 2026-08-11 确认多端登录与设备管理实施计划。
- 目标版本：`2.4.0`。
- 背景/问题：当前认证 Session 可并存，但核心没有中立的设备登记、验证和撤销扩展点。
- 业务逻辑：`AuthenticatedSession` 在登录、已登录判断和登出生命周期解析中立设备 Provider；密码登录登记设备，记住登录可通过显式上下文恢复既有设备，认证请求验证设备状态，登出撤销当前设备。
- 范围：中立 Interface/DTO、`AuthenticatedSessionInterface::login()` 向后兼容的可选上下文参数、`SessionFactory` Provider 注入、请求级验证缓存。
- 非目标：在 Framework 中保存设备、识别 Customer/Admin、定义页面、ACL、Cookie 名或业务保留策略。
- 数据/权限/安全：Provider 未声明时保持旧行为；Provider 已声明但不可构造、调用异常或拒绝验证时失败关闭；不得记录 Session ID、Token 或摘要。
- 兼容/迁移：旧调用方不传上下文仍可登录；部署前有效 Session 可由 Provider 惰性登记。
- 验收标准：未配置 Provider 时原有登录不变；配置 Provider 后登记、验证、撤销调用正确；被撤销 Session 下一次认证检查失败；frontend/backend/Fiber 状态不串扰。
- WebUI/E2E：由 `Weline_SessionManager` 前后台真实设备管理路径覆盖。
- 运营与支持影响：Provider 配置存在但不可用会阻止认证，应以脱敏日志定位，不得回退旧路径。
- 依赖与风险：认证热路径增加 Provider 调用，必须请求级缓存并避免进程级可变身份状态。
