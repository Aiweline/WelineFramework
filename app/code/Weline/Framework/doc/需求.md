## 当前有效需求

### `REQ-FRAMEWORK-0001` 可选的认证设备生命周期契约

- 来源与确认：用户于 2026-08-11 确认多端登录与设备管理实施计划。
- 目标版本：`2.4.0`。
- 背景/问题：当前认证 Session 可并存，但核心没有中立的设备登记、验证和撤销扩展点。
- 业务逻辑：`AuthenticatedSession` 在登录、已登录判断和登出生命周期解析中立设备 Provider；密码登录登记设备，记住登录可通过显式上下文恢复既有设备，认证请求验证设备状态，登出撤销当前设备。
- 范围：中立 Interface/DTO、`AuthenticatedSessionInterface::login()` 向后兼容的可选上下文参数、`SessionFactory` Provider 注入、请求级验证缓存。
- 非目标：在 Framework 中保存设备、识别 Customer/Admin、定义页面、ACL、Cookie 名或业务保留策略。
- 数据/权限/安全：Provider 未声明时保持旧行为；Provider 已声明但不可构造、调用异常或拒绝验证时失败关闭；不得记录 Session ID、Token 或摘要。
- 兼容/迁移：旧调用方不传上下文仍可登录；部署前有效 Session 可由 Provider 惰性登记。
- 验收标准：未配置 Provider 时原有登录不变；配置 Provider 后登记、验证、撤销调用正确；被撤销 Session 下一次认证检查失败；frontend/backend/Fiber 状态不串扰。
- WebUI/E2E：由 `Weline_SessionManager` 前后台真实设备管理路径覆盖。
- 运营与支持影响：Provider 配置存在但不可用会阻止认证，应以脱敏日志定位，不得回退旧路径。
- 依赖与风险：认证热路径增加 Provider 调用，必须请求级缓存并避免进程级可变身份状态。

### `REQ-FRAMEWORK-0002` 网站有效货币解析契约

- 来源与确认：商城真实路径验收发现旧 CNY 请求状态覆盖当前网站 USD 配置，用户于 2026-08-17 同意修复并同步核心。
- 目标版本：`2.4.0`。
- 背景/问题：无币种前缀路由直接信任 `user.currency` 或 Cookie，会使已从网站允许集合移除的旧币种继续进入商品、搜索和结账上下文。
- 业务逻辑：显式 URL 币种保持最高优先级；用户环境和 Cookie 偏好仅在当前网站允许货币集合内生效；无有效偏好时依次解析网站环境、请求网站变量、`WebsiteData` 默认值与应用环境，并最终回退站点允许列表首项。
- 范围：`State` 请求币种解析、请求级允许集合复用、`App::applyParsedUrl()` 请求上下文归一化，以及 `Env::system/router/dev()` 分组读取器对大写默认值的正确处理。
- 非目标：不改汇率、价格换算、网站 schema、报价或支付结算规则。
- 验收标准：默认商城路由使用网站有效默认币种；旧的已禁用偏好不会产生零价/不可购买状态；显式币种与既有本地化路径顺序保持兼容；`Env::system('currency', 'CNY')` 等大写默认值不得被 `Env::get()` 的模块名兼容分支误判。

### `REQ-FRAMEWORK-0003` 请求 authority 与 Session Cookie 身份

- 来源与确认：用户于 2026-08-18 报告直连非标准端口后台刚登录会间歇回到 `no_access_reason=not_logged_in`；2026-08-26 生产可信代理 443 又发现 Cookie 与绝对 URL 被内部 Worker 端口污染。
- 目标版本：`2.4.0`。
- 背景/问题：HTTPS 直连 `host:9555` 时，HTTP/2 `:authority` 可能省略端口；公网 443 经 Dispatcher 转发时，Worker wire Host 又可能是 `host:23922`。两种路径若混用监听端口与公网 authority，Session Cookie 会漂移，页面 `<base>`、菜单和重定向也会泄露不可达的内部端口。
- 业务逻辑：`WlsRequest` 是公网 origin 规范化唯一所有者；非受信直连且 Host 省略端口时由它把 `WLS_PORT` 规范进 `HTTP_HOST`/`SERVER_PORT`；仅在传输层已确认可信 Dispatcher 时，从 `Weline-Original-Host`/scheme/port 恢复公共 authority。`SessionCookieNameResolver` 只消费有效的规范化 `SERVER_PORT`，仅在其缺失或非法时回退监听端口。
- 范围：`WlsRequest` 直连端口回退、可信 Dispatcher 公共 authority 恢复、Session Cookie authority 解析；不改 Cookie Path、设备 fail-closed 语义。
- 非目标：不信任公网客户端自报的 Dispatcher/forwarded 元数据；不把内部 Worker 端口写入公网 URL 或 Cookie 名。
- 验收标准：Host 省略 `:9555` 的直连请求仍发出 `WELINE_SESSID_9555`；受信 Dispatcher 的 wire Host 即使为 `app.example.com:23922`，公共 HTTPS 443 仍生成 `https://app.example.com`、无后缀 `WELINE_SESSID`，跨 Worker 连续请求保持同一登录态。

### `REQ-FRAMEWORK-0004` QueryBin 不得把 runtime_task 拒绝伪装成 500

- 来源与确认：用户于 2026-08-18 在媒体管理页看到 `Internal server error.`；同意修复。
- 目标版本：`2.4.0`。
- 背景/问题：`QueryBin` 把未映射的 `ResumableTaskAccessDeniedException` 走通用 `Throwable` 分支，前端只看到 500 `business_error` / `Internal server error.`。
- 业务逻辑：该异常表示 backend 证明或 owner 不再匹配 Session，属于鉴权失败。QueryBin 映射为 401 `backend_attestation_invalid`，提示刷新页面；不得泄漏内部异常原文，也不得记为 Unexpected request failure。
- 范围：`QueryBin` 异常映射。
- 非目标：不改 runtime_task 的 404 伪装语义；不改 BinQuery 站外协议。
- 验收标准：该异常不再产生 500 `Internal server error.`；媒体管理等 backend Query 失败时前端可见鉴权类错误或成功加载。

### `REQ-FRAMEWORK-0005` HTTP 状态回执页可定制

- 来源与确认：用户于 2026-08-21 要求增强各 HTTP 回执状态错误码自定义页面。
- 目标版本：`2.4.0`。
- 背景/问题：`pub/errors/404.php` 等仅 `echo 404`；WLS 捕获 `NoRouterException` 时重新 include 且不注入消息变量，生产可见纯文本状态码。
- 业务逻辑：`ErrorPageRenderer` 统一渲染；优先事件覆盖 → `pub/errors/{code}.php` → `default.php` → 内置 HTML；JSON Accept 返回结构化 JSON；FPM/WLS/异常生产页同源。
- 范围：`ErrorPageRenderer`、`NoRouterException`、`Response::noRouter`、`WlsRuntime`、`HtmlRenderer` 生产态、`pub/errors/*`、事件 `error_page_render`。
- 非目标：改写维护页 `pub/errors/maintenance`；不在 Framework 内绑定站点品牌业务语义。
- 验收标准：404/403/429/500/503 HTML 含标题与引导，非纯数字；JSON 优先时返回 `ok/status/error/message`；单测覆盖渲染与 `NoRouterException` 正文。

### `REQ-FRAMEWORK-0006` 常驻运行的可关闭请求资源契约

- 来源与确认：用户于 2026-08-22 批准统一文件存储、CMS Store/Locale 与 WLS 常驻运行方案。
- 目标版本：`2.5.0`。
- 业务逻辑：Framework 只发布中立的可关闭请求资源契约；Storage 在 Fiber/Request 生命周期内登记句柄、流、临时文件和 Client lease，并复用现有 cleanup、模块 resetter、异常聚合和 Worker drain 链路。
- 范围：不可变资源描述、幂等 `close()`/`isClosed()` 语义以及常驻运行边界文档。
- 非目标：Framework 不认识磁盘、OSS、FileAsset、CMS 或厂商 SDK，也不持有业务请求状态。
- 安全与兼容：关闭失败继续执行后续清理并汇总；不得在进程级对象中保留用户、Scope、签名 URL、凭据或流。
- 验收标准：两个 Fiber 的资源注册与清理零串扰；请求结束资源回到基线；清理失败进入既有 drain 语义且不阻断后续清理。
