# 模块版本与升级门禁

> **硬规则**：改了会驱动框架「注册表 / Schema / 路由 / 模块 Setup」的代码，却**不**提升 `etc/module.php` 的 `version`，是 AI 与人工开发中最常见的报错来源之一。

## 权威文件

```php
// app/code/Weline/{Module}/etc/module.php
return [
    'name' => 'Weline_YourModule',
    'version' => '1.0.0',  // ← 每次可升级变更至少 patch +1
    'requires' => [ /* ... */ ],
];
```

- 版本权威来源：`etc/module.php`（见 [模块契约](../architecture/03-module-contract.md)）
- **禁止**只改 Model/`register.php` 却不改 `version` 就期望 Schema 生效

## 何时必须 bump 版本

| 变更类型 | 必须 bump | 升级命令 |
|----------|-----------|----------|
| Model 新增/删除 `#[Col]`、`#[Index]`、`#[Table]` | **是**（至少 patch） | `php bin/w setup:upgrade -m Weline_Module` 或全量 |
| **新建** Model 类（新表） | **是** | 同上 |
| Model `upgrade()` / `install()` 需执行的数据迁移 | **是** | 同上 |
| 新建/变更 **Controller** 公开方法（新路由） | **是** | `php bin/w setup:upgrade --route`（或全量 upgrade） |
| 新增 `Observer` + `etc/event.xml` | **是** | `php bin/w setup:upgrade` |
| 新增/变更 `hook.php` Hook 规约 | **是** | `php bin/w setup:upgrade --route` |
| 新增 Taglib 类 | 建议 bump | `php bin/w setup:upgrade`（含 taglib 收集） |
| 新增 Console 命令类 | 建议 bump | `php bin/w setup:upgrade --route` 或全量 |
| 仅改 Service/模板/i18n、**无** Schema/路由/注册变更 | 否 | 按任务验证即可 |

**semver 约定（开发期）**：

- 修 bug / 小改 Schema 或注册：`1.0.0` → `1.0.1`（patch）
- 向后兼容功能：`1.0.1` → `1.1.0`（minor）
- 破坏性变更：`1.1.0` → `2.0.0`（major）

## 标准流程（写代码后）

```text
1. 完成代码变更（Model / Controller / event.xml / hook.php …）
2. 打开 app/code/Weline/{Module}/etc/module.php → version patch+1
3. 执行升级：
   - Schema / Model：php bin/w setup:upgrade -m Weline_{Module}
   - 仅路由：php bin/w setup:upgrade --route --module=Weline_{Module}
   - 不确定：php bin/w setup:upgrade（全量）
4. 确认无致命错误；开发日志记录版本与命令
```

## 不 bump 版本的典型报错

| 现象 | 原因 |
|------|------|
| 数据库缺列 / Unknown column | SchemaDiff 未跑；`version` 未升 |
| `Schema checkpoint` / 请提升 version | 代码与 checkpoint 漂移 |
| 新控制器 404 | 路由图未刷新；常需 `--route` + 版本升级 |
| Model `upgrade()` 不执行 | `setup_version` 已等于 `version`，升级跳过 |
| Hook 规约/路由升级中断 | 缺 doc 或需 `--route` |

诊断只读：

```bash
php bin/w setup:schema:check
php bin/w setup:schema:check --module=Weline_YourModule
```

## 禁止

- 在 `Setup/Upgrade.php` 里手改字段代替 `#[Col]` + version bump
- 手改 `generated/` 修补 Schema 或路由
- 改 Model 字段后只跑单测、不跑 `setup:upgrade`
- 新建 Controller 后不跑 `--route` 就交付可访问 URL

## 与 AI 任务的关系

TaskContract / 开发日志中**必须写明**：

- 归属模块 `Weline_*`
- bump 后版本号（如 `1.2.3` → `1.2.4`）
- 实际执行的 upgrade 命令

## MCP 密封编辑强制门禁

`LearningMcp\ModuleVersionBumpGate` 在 `EditService::prepare()` 中于写盘前 fail-closed：

| 触发路径（同模块 `app/code/{Vendor}/{Module}/`） | 同计划必须 |
|--------------------------------------------------|------------|
| `Model/**/*.php` | 含 `etc/module.php` 且 `version` **严格大于** preimage |
| `Controller/**/*.php` | 同上 |
| `etc/event.xml` | 同上 |
| `hook.php` / `register.php` | 同上 |

违反时抛出 `EDIT_MODULE_VERSION_REQUIRED`（含 `violations` / 建议 upgrade 命令）。仅改 Service、模板、i18n 等非注册面路径**不**触发。

契约测试：`php app/code/Weline/Ai/Mcp/tests/module-version-bump-gate.php`
