# 安全响应头策略（TASK-P1D-REV-001）

## 目标

CSP / CORS 只能相对 Env Global 基线（含 Extends CSP 应用默认）收紧；Scope 策略必须先登记同
Scope、同 schema、同摘要的 verified LKG，随后才能通过 SystemConfig
保存边界激活。LKG 缺失、不匹配或持久化不可用时一律先于配置写入拒绝。
HTTPS 下 Cookie 仍由 `HeaderCollector` 强制 `Secure`。
**CSP 标准统一由 Framework 提供**（Extends `Security/Csp` + `CspSourceContributionRegistry` + `SecurityHeaderPolicyService`）；
Defaults 只保留自有面基线，业务第三方 / CDN / 供应商 SDK 一律由模块 Extends（有壳则 Provider `cspDirectives()`）贡献为应用默认（不可覆盖）。

## 运行时链路

```text
Core::header_xss()
  → SecurityHeaderPolicyService::resolveCurrentResponseHeaders()
  → SecurityHeaderPolicyOverrideProviderInterface
  → SystemConfigSecurityHeaderPolicyOverrideProvider
  → (Env|Defaults ∪ Extends CSP 应用默认) ∩ Scope，再强制 ∪ 应用默认
  → HeaderCollector

FullPageCacheCoordinator::applyCachedHeaders()
  → SecurityHeaderPolicyService::resolveCurrentResponseHeaders()
  → 当前请求 Origin + 当前 Scope 策略
  → detached Response
```

Framework 不依赖 SystemConfig 具体类。未安装配置 Provider 的
Framework-only/bootstrap 场景使用不可变 Env 基线（可含模块 CSP Contribution）；正式模块注册后，接口唯一映射到
SystemConfig Provider。

## FPC 命中

安全策略响应头不是共享页面正文的缓存事实。FPC 发布时会剔除
`X-Frame-Options`、`X-Content-Type-Options`、`X-XSS-Protection`、
CSP、CSP Report-Only 和 `Access-Control-Allow-Origin`；fresh、stale、
process 与 receipt 命中均在返回前重新解析当前 Scope 策略。

gzip/keep-alive 的预格式化响应键还包含当前有效安全头（含允许的请求
Origin）摘要。策略或 Origin 变化会自然切换到新格式化变体，旧响应不能
绕过更严格策略，也不能把某个 Origin 的 CORS 放行重放给另一个 Origin。
`Vary: Origin` 通过合并写入，必须保留既有 `Cookie` 与
`Accept-Encoding` 维度。

## Env Global 基线

```php
'security' => [
    'headers' => [
        // 与 SecurityHeaderDefaults 对齐；空串运行时回退到同类常量
        // 默认放行社媒/支付/主流 CDN 等大厂域名；img/font/media 允许 https:
        'csp' => SecurityHeaderDefaults::CSP,
        // Report-Only 默认空：与强制 CSP 相同时再输出会把响应头翻倍
        'csp_report_only' => '',
        // meta=写入 HTML（默认，响应头不再带大 CSP）；header=传统响应头
        'csp_delivery' => 'meta',
        'cors_origins' => '', // 空=禁止跨域回显；子 Scope 只能缩小白名单
    ],
],
```

常量源：`Weline\Framework\Http\Security\SecurityHeaderDefaults`。
`SecurityHeaderPolicyService::baselineFromEnv()` 对空串回退到该常量，再与 Extends
CSP 应用默认 **union**，避免误留空导致不输出 CSP。

### CSP 交付与响应头体积

浏览器 **不支持** 从 URL 自动拉取并应用 CSP（早期 `policy-uri` 已废止）。本框架用：

1. **`csp_delivery=meta`（默认）**：完整策略写入 HTML `<meta http-equiv="Content-Security-Policy" data-weline-csp="1">`，HTTP 响应头只保留短安全头（`X-Frame-Options` 等）。文档加载一次即可，不再每个响应携带 ~3KB+ CSP。
2. **`csp_delivery=header`**：传统响应头；若 `csp_report_only` 与强制 CSP 规范化后相同则 **省略** Report-Only。
3. **`compactForWire`**：`img-src`/`font-src` 等已含 `https:` 时剔除被覆盖的 `https://…` 主机。
4. **策略文档端点**：`GET /api/framework/csp-policy`（ETag / `Cache-Control: max-age=300`），供运维与 CDN 读取当前有效策略。

FPC：meta 交付时 formatted 缓存键仍含 CSP digest（`securityVariantMaterial`），策略变更会失效预压缩变体；发布前与明文重建路径会 `ensureDocumentCspMeta`。

### 开发态 CSP 工具链片段（仅响应时）

键：`security.headers.csp_developer_tooling`（Env / `app/etc/env.php`）。

MCP 硬约束：`cursor_debug_csp_developer_tooling`（见 `AI硬规则索引.md`）。Agent 使用 Cursor debug ingest（`#region agent log` → `127.0.0.1:7277`）前必须保证本键已配置，否则浏览器 CSP 会拦 `connect-src`，Cursor 记不到调试。

- 默认空；本机调试源（如 Cursor ingest `http://127.0.0.1:7277`）写在项目 `env.php`，**不要**写进 Framework 常量或 Extends
- 仅在 `DEV` 或 `DEBUG` 且该键非空时，由 `SecurityHeaderPolicyService::resolveCurrentResponseHeaders()` **union** 进当次响应的 `csp` / `csp_report_only`
- **不**写入 `baselineFromEnv`、`appDefaultCsp`、或 Extends `Security/Csp` 应用默认地板
- 生产（非 DEV 且非 DEBUG）即使 env 残留该键也不并入响应头

### 模块 CSP Extends（应用默认，不可覆盖）

业务模块通过 **Extends** 声明自有/专属第三方 SDK 域名，框架收集后作为**应用默认**：

- 并入 Global 基线（union）
- Scope 配置保存不得删除这些 source（`security_policy_app_defaults_immutable`）
- 运行时 `resolveEffective` 在 intersect 后强制 union 回应用默认
- 配置中心「安全响应头」展示 warning 提示当前应用默认列表

```text
app/code/{Vendor}/{Module}/extends/module/Weline_Framework/Security/Csp/{Name}.php
```

```php
namespace Vendor\Module\Extends\Module\Weline_Framework\Security\Csp;

use Weline\Framework\Http\Security\CspSourceContribution;
use Weline\Framework\Http\Security\CspSourceContributionProviderInterface;

final class SdkCsp implements CspSourceContributionProviderInterface
{
    public function contribution(): CspSourceContribution
    {
        return new CspSourceContribution([
            'script-src' => ['https://sdk.example.com'],
            'connect-src' => ['https://sdk.example.com'],
            'frame-src' => ['https://sdk.example.com'],
        ]);
    }
}
```

约束：

- **唯一注册方式**：Extends 路径 `extends/module/Weline_Framework/Security/Csp/`（规约见 `Framework/extends.php` → `Security/Csp`）
- **禁止** `etc/module.php` `provides` / `csp_source_contribution.*`
- 零参构造；只返回 directive=>sources；禁止 Closure / ORM / 请求期扫描
- 聚合：`CspSourceContributionRegistry`（读 `ExtendsData`）；编排：`SecurityHeaderPolicyService`（union 进基线 + 应用默认地板不可删）
- **标准统一由 Framework 提供**：接口 `CspSourceContributionProviderInterface`、DTO `CspSourceContribution`、注册表与策略服务；业务模块 / Provider **只贡献域名**，不自建 CSP 管道
- Framework Defaults **仅**保留自有面（`'self'` / `unsafe-inline` / `blob` / `https:` 资源面等）；业务第三方 / CDN（含 Stripe）**禁止**堆回 Defaults，须由模块 Extends / Provider `cspDirectives()` 贡献
- 有供应商壳的域：Provider 实现 `cspDirectives()`，模块 Extends 聚合类再 `contribution()`
- 无人壳的固定面（如商品视频嵌入、DataTable 公共 CDN）：模块 Extends 直接 `contribution()`
- 人机验证 → `CaptchaVendorsCsp`；万能支付 → `PaymentVendorsCsp`；社媒登录 → `SocialLoginVendorsCsp`；融媒体 → `SocialPlatformsCsp`；像素分析 → `PixelEventVendorsCsp`；Cloudflare Web Analytics → `CloudflareWebAnalyticsCsp`；商品视频 → `ProductMediaEmbedCsp`；公共 CDN → `DataTablePublicCdnCsp`
- 新增 Extends 后执行 `php bin/w setup:upgrade` 重建 Extends 注册表

`ContentSecurityPolicyNormalizer`：`union` / `intersect` / `assertNotWeaker` /
`assertContainsAppDefaults`。弱于基线 → `security_policy_weaker_than_baseline`；
删应用默认 → `security_policy_app_defaults_immutable`。

## Durable LKG

- Framework 契约：
  `SecurityPolicyLkgRepositoryInterface`。
- SystemConfig 实现：
  `OrmSecurityPolicyLkgRepository`。
- ORM 表：
  `system_config_security_policy_lkg`，唯一键
  `(schema_version, scope_key)`。
- 持久化字段：
  schema version、规范 Scope、SHA-256 摘要、UTC verified time。
- `InMemorySecurityPolicyLkgRepository` 仅是显式测试替身，禁止生产注册。

登记和激活必须是相同的完整候选。SystemConfig QueryProvider 操作
`registerSecurityPolicyLkg` 先执行对象 Scope 的 `UPDATE` 授权与
`expected_grant_version` 校验，再登记候选；后续
`SystemConfig::saveScopeConfig()` 会重新组装完整策略并核对摘要。

固定拒绝码：

- `security_policy_lkg_missing`
- `security_policy_lkg_mismatch`
- `security_policy_lkg_unavailable`
- `security_policy_weaker_than_baseline`

## 配置入口

配置模板：

`Framework/Extends/module/Weline_SystemConfig/Config/backend/security-headers.phtml`

字段：

- `security.headers.csp`
- `security.headers.csp_report_only`（默认空）
- `security.headers.csp_delivery`（`meta`|`header`，默认 `meta`）
- `security.headers.cors_origins`
- `security.headers.csp_developer_tooling`（仅 Env；DEV/DEBUG 响应时临时 union，非 Scope 配置项）

工作流：

1. 选择显式 TargetScope 和 locale，预览完整候选。
2. 使用同一 TargetScope、候选、inherit keys 和当前授权版本调用
   `registerSecurityPolicyLkg`。
3. 保存完全相同的候选；任何并发变化都会造成摘要不匹配并零写入拒绝。

## Cookie

`HeaderCollector::setCookie()`：当 `server.https=on`、`HTTPS` 或
`X-Forwarded-Proto=https` 时强制 `secure=true`。

## 验证

- 单元：
  `SecurityHeaderPolicyServiceTest`、
  `SecurityPolicyConfigGuardTest`、
  `CoreSecurityHeadersTest`、
  `FullPageCacheCoordinatorTest`。
- 集成：
  在隔离数据库运行 `setup:upgrade --model`，用两个独立 PHP 进程完成
  register/read，再验证 exact candidate 可保存、未登记摘要
  `security_policy_lkg_mismatch` 且原值不变。
- 运行时：
  对同一匿名 HTML URL 验证首次渲染、普通 FPC 命中和 gzip formatted
  命中都带当前安全头；带弱旧头的缓存载荷不得覆盖当前基线。
