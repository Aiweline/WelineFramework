# WelineFramework 开发标准与验收

本文保存跨模块稳定的工程约束。模块特定业务规则仍写入归属模块文档，由 Weline MCP 按任务检索。

## 源码和升级

- 不直接修改 `generated/`、`view/tpl/`、收集后的注册表或其他生成物；修改源或生成器并执行对应刷新命令。
- 不新增 `routes.xml`；Controller 路由通过 `php bin/w setup:upgrade --route` 同步。
- 表字段和索引由 Model 的 `#[Table]`、`#[Col]`、`#[Index]` 等声明；`Setup/Upgrade.php` 只做必要数据迁移，不成为第二套 Schema。
- 任何会驱动 Schema 同步的 Model 声明变更，必须至少 patch 提升归属模块 `etc/module.php` 版本，并执行或明确交接 `php bin/w setup:upgrade -m Vendor_Module`。
- 自动重构必须是结构感知、任务有界、可审查的，并逐文件验证 Diff；禁止盲目跨仓文本替换。

## 模块和数据边界

- `website_id=0`、`code=default` 是有效默认站点，不能用 truthy/`empty()` 当作缺失。
- PostgreSQL 是生产语义数据库；SQLite 只用于隔离可移植性检查，不能替代事务、锁、JSON、迁移和持久化的 PostgreSQL 证据。
- Framework 只承载平台抽象、运行时和中立契约，不能写入 Website、Product、PageBuilder 等具体业务语义。
- 跨模块禁止依赖对方具体 Service/Model/Helper/Controller。通知和副作用优先 Event/Observer；读取使用公开 Interface、QueryProvider/`w_query()`；写入使用归属 Interface、Hook、Queue 或其他公开命令边界。
- 新的 QueryProvider 应可通过 `php bin/w query:help <provider> [operation]` 发现并描述输入输出。

## HTTP、模板与前端

- 业务代码不得直接读写 `$_GET`、`$_POST`、`$_REQUEST`、`$_COOKIE`、`$_FILES`、`$_SERVER`；使用 Request 或 `WelineEnv`。例外只限运行时装配层、测试夹具和 CLI argv。
- 浏览器业务请求只使用 `Weline.Api.resource()`、`graph()`、`stream()` 经 Worker/QueryProvider 链路；禁止直接 fetch、XHR、axios 或手写业务 URL。
- 用户可见文字必须可翻译，插值使用 `%{name}` / `%{1}`；禁止原生 `alert`、`confirm`、`prompt`。
- `.phtml` 会被编译：HTML 标签和 Taglib 属性内不得出现 PHP；复杂分支、转义值和子模板应在顶部 PHP 或 Controller 预计算。不得在 partial 内调用 `$this->fetch()`，不得编辑 `view/tpl`。
- 语言、币种、Website/Store、文件、图标、DataTable、ACL、表单、SEO/Pixel 等领域控件必须使用归属模块 Taglib 或 Hook，不手写等价选择器。
- 模板变更后至少执行 `php bin/w theme:compile` 并检查目标页面无 500；整体 UI 仍须真实 Browser 验收。

## WLS 长驻运行时

- 不引入跨请求的进程全局可变状态；使用 Request/Context/Session/Fiber 作用域。
- WLS 敏感路径不得使用 `sleep`/`usleep`、`die`/`exit`、无限循环或无界同步 I/O。
- 验收前确认 Worker 和静态资源已加载本次改动；旧 Worker/cache 命中不是有效证据。

## 验收层级

| 变更表面 | 最低证据 |
|---|---|
| 纯函数、Service/Model 局部逻辑 | 聚焦单测或同级可重复测试 |
| 命令、API、路由、持久化、运行时 | 最近的真实命令/API/数据结果，加必要聚焦测试 |
| 页面、交互、后台操作、SSE、发布工作台 | 真实 WLS + 内置 Browser 的操作员等价路径及可见结果；必要时截图与 Console |
| 文档、规则、元数据 | Diff、格式、链接/路径与渲染检查 |
| 发布/部署 | 本地门禁加已授权目标的真实状态和可达入口 |

新增功能测试失败并修改代码后，必须重新执行代码复审再重测。没有匹配层级证据时不得报告完成。
