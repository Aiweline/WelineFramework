# 事件命名与注册规范

> 写 Observer 或 `dispatch` **前**必读。配合 [扩展点选型](./扩展点选型.md) 与 [event/README.md](../event/README.md)。

## 何时用 Event

| 意图 | 用 Event | 不用 Event |
|------|----------|------------|
| 通知、日志、清缓存、旁路扩展 | 是 | — |
| 跨模块读列表/详情 | 否 | QueryProvider / `w_query()` |
| 跨模块写业务状态 | 否 | 归属 Interface / Hook / Queue |
| UI 控件 | 否 | Taglib / Hook |

## 命名规则

- 格式：`{Module}::{domain}` 或 `{Module}_{Sub}::{action}`，**以已有文档为准**。
- 新建前在 [event/README.md](../event/README.md) 与 `Framework/doc/event/{域}/` 检索，避免重名或冲突。
- **禁止**静默发明未文档化的事件名。

示例（已文档化）：

- `Weline_Admin::msg` → [系统消息通知.md](../event/framework/系统消息通知.md)
- `Weline_Framework_Model::save_after` → 见 `event/model/` 域文档

## 新建 Event 四件套

| # | 产物 | 路径 |
|---|------|------|
| 1 | Observer | `app/code/Weline/{Module}/Observer/{Name}.php` |
| 2 | 注册 | `app/code/Weline/{Module}/etc/event.xml` |
| 3 | 事件文档 | `app/code/Weline/{Module}/doc/event/{topic}.md` |
| 4 | 触发方说明 | dispatch 处注释或归属模块 `doc/开发日志.md` 引用事件名与 payload |

### event.xml 示例

```xml
<event name="Weline_YourModule::your_event">
    <observer name="Weline_YourModule::your_observer"
              instance="Weline\YourModule\Observer\YourObserver"/>
</event>
```

### dispatch 示例

```php
$eventsManager->dispatch('Weline_YourModule::your_event', ['data' => $payload]);
```

payload 形状必须在 `doc/event/*.md` 写清。

## 检查清单（写代码前）

- [ ] 已在 event 索引检索，无现成事件可复用
- [ ] TaskContract 声明「新建扩展点」及事件名
- [ ] 已建 `doc/event/*.md`（含事件名、时机、数据格式、示例）
- [ ] `etc/event.xml` 与 Observer 类名一致
- [ ] 未跨模块 `new` 对方 Service 代替 Event
