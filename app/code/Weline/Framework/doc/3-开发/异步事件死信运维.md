# 异步事件死信运维

## 安全边界

Delivery 是异步 Observer 投递的只读权威记录。进入 `dead` 后不能把原行改回 `pending`；重放必须创建新 event ID、新 Outbox 和仅包含原 Observer 的新 target，并保留从新 Delivery 到原 dead Delivery 的审计链。

后台运维需要三个独立 ACL：

| ACL | 能力 |
|---|---|
| `Weline_Framework::event_delivery_view` | 查看当前站点的 Delivery 列表与脱敏详情 |
| `Weline_Framework::event_delivery_replay` | 为允许的 dead Delivery 创建新重放 |
| `Weline_Framework::event_delivery_all_websites` | 查看或操作非当前后台站点/全站范围 |

站点 0 是合法默认站，必须保留。`website_id` 缺失或为 null/空字符串时，只能继承非 null 的 `w_env_website_id()`；当前上下文也无站点时必须拒绝，不默认到全站。显式站点与当前站点不同，或 `scope=all`，均需 all-websites ACL。

## 后台入口

菜单 action 是：

```text
weline_framework/backend/event-delivery
```

实际 URL 必须通过当前动态 backend key 解析，不要把裸 `/admin` 写入书签或自动化。Controller 只渲染 shell，浏览器数据请求只能使用 `Weline.Api`，不使用 fetch/XHR/axios。`Weline.Api.resource()` 是异步工厂；页面应缓存其 Promise，list/detail/replay 三条路径都必须先等待实例解析，不能在 Promise 上直接调用 operation。工厂拒绝时要清除缓存，使用户点击刷新可以重建；详情和重放请求都绑定递增序号及启动时的 Delivery 标量，关闭弹窗或打开新记录后忽略迟到旧响应；重放成功仍可刷新全局列表，但不得覆盖新弹窗的目标、提示或按钮状态。

QueryProvider 名为 `async_event_delivery`，操作契约：

### `asyncEventDeliveryList`

```text
page=1
page_size=20       # 1..100
status=dead        # pending|provisioning|queued|running|retry_wait|succeeded|dead|superseded|skipped
website_id?        # >=0，0 合法
scope=current|all  # all 需 all-websites ACL
```

列表只返回身份、Observer、站点、资源、状态、attempt、Transport/Queue、终态原因和 replay 审计等白名单字段。

### `asyncEventDeliveryDetail`

```text
delivery_id        # 正整数
website_id?        # >=0，默认继承当前后台站点
```

详情会再从 payload 核对站点，不只依赖列表 SQL 过滤。原 payload/context 不直接输出；只展示 `schema/event/resource/website/impact/changed_fields/before/after` 和经白名单的 origin。

### `asyncEventDeliveryReplay`

```text
delivery_id
website_id?
reason             # trim 后 1..500 bytes
```

该 operation 是 backend-auth 写操作，仍需经过现有 bin-query/CSRF 验证和 replay ACL。

## 脱敏

`DeliveryAccessPolicy::redactedPayload()` 只返回白名单顶层字段，并递归处理：

- 最大展示深度 8，每个 object 最多 100 项，单字符串最多 2048 bytes。
- password、secret、token、cookie、session、CSRF、authorization、credential、private/API/access key、signature 等键值替换为 `[redacted]`。
- URL 去掉 query 和 fragment，不输出其中的密钥或签名。
- `last_error` 在输出边界再次复用 `AsyncErrorRedactor` 清除凭据片段：`Authorization` / `Proxy-Authorization` 不区分 Basic、Bearer、Digest 或其他 scheme，从分隔符后整行连同折叠续行置为 `[redacted]`，但不吞掉无缩进的下一条诊断，且重复处理保持幂等。结果最多 8 KiB，再执行 HTML escape；旧行、导入行或绕过状态机的脏数据也不能直接回显 secret/token/cookie。
- 不恢复或输出原 Session、cookie、CSRF 或管理员授权上下文。

日志也不记 payload/context/secret。重放成功只记 `event_async_replay_requested` 以及 `event_id/outbox_id/delivery_id/observer_key` 白名单字段。

## 重放流程

1. 要求 view + replay ACL，解析站点范围。
2. 重读 Delivery，要求仍是 `dead`；原行不加锁改状态。
3. 校验 payload SHA-256、JSON/context 和原 Outbox 的 event 审计链。
4. 在当前注册表重新解析原 `observer_key`；要求模块/Observer 存在、仍为 async、实现 `AsyncObserverInterface` 且支持原 schema。
5. 新建 event ID，用当前 Mapper 验证新 payload；`origin.replay` 保存原 delivery ID、`admin:{user_id}`、UTC 微秒时间和 reason。
6. 在主库事务中新建 Outbox，target 只有原 Observer，并记录 `replay_of_delivery_id/requested_by/at`。
7. 物理 commit 后触发 relay；原 dead Delivery 始终保持不变。

重放不恢复原管理员的权限主体；当前管理员只写入审计信息。

## retention 与 GC

| 记录 | 保留期 |
|---|---:|
| `succeeded/superseded/skipped` Delivery | 30 天 |
| 孤立且已 `expanded` 的 Outbox | 30 天 |
| `dead` Delivery | 180 天 |
| 含 `replay_of_delivery_id` 的终态 Delivery | 180 天 |

GC 每批 `1..500`，总 limit 由 Outbox + Delivery 共享。它只删终态 Delivery，不删被其他 replay 引用的原 Delivery；只有没有任何 Delivery 引用的 expanded Outbox 才可删。不得手工删未终态行或为清理队列把 dead 改 pending。

## 运维顺序

1. 确认 `event.async.producer_enabled` / `relay_enabled` 的当前发布阶段；两者默认都是 false。
2. 核对 `Weline_Queue` Transport provider、事件注册表和 Queue type。
3. 使用 current website 查看 dead 列表，先读脱敏详情，确认 Observer/schema 仍有效。
4. 输入可审计的 reason 执行一次重放，记录新 event/outbox ID。
5. 观察新 Delivery 进入终态，不改写原 dead。
6. 最后执行有界 GC，并核对删除数量和 replay 引用仍在。

## 命令与注册核对

命令类位于 canonical 扫描目录 `Framework/Event/Console/Event/Async/`，可用命令为：

```bash
php bin/w event:async:relay --limit=50
php bin/w event:async:gc --limit=500
```

不要使用旧的 `event:async-relay` / `event:async-gc` 名称。发布前仍需重建事件与容器，并核对 QueryProvider：

```bash
php bin/w event:rebuild
php bin/w framework:compile
php bin/w queue:collect
php bin/w query:help async_event_delivery
```

命令可解析不等于端到端已经验收；仍需在专用 WLS 上用动态 backend key 完成 Browser 验收：列表站点 0、脱敏详情、拒绝越站、允许的重放、原 dead 不变、新 Delivery 终态、无未处理 Console error。

## 回滚

1. 先关闭 async producer，防止新 Outbox。
2. 关闭 relay 新 claim，等待 running Delivery 终态；无法确认时冻结，不强改终态。
3. 回滚 UI/consumer/provider 时保留 Outbox、Delivery、revision 表和 replay 审计链。
4. 恢复 provider 后重建 registry/compiled provider，再先验证 current website 和 pending Queue，最后重开 relay/producer。
