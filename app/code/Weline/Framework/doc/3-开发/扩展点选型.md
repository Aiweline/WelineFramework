# 扩展点选型

> 跨模块扩展、读写的**机制选择**入口。写代码前必须先完成本页选型，再查具体契约文档。

## 选型表（硬规则）

来源：[开发标准与验收](./开发标准与验收.md) 模块边界条款。

| 你要做的事 | 优先用 | 禁止 |
|------------|--------|------|
| 通知、日志、清缓存、旁路扩展 | **Event** + `Observer` + `etc/event.xml` | 跨模块 new 对方 Service |
| 读列表/详情/聚合数据 | **Interface** / **QueryProvider** / `w_query()` | 跨模块依赖对方 Model |
| 写业务状态 / 执行命令 | 归属模块 **Interface** / **Hook** / **Queue** | 跨模块直调 Controller |
| 模板里的语言/币种/文件/图标等控件 | **Taglib** / **Hook** | 手写等价 select/input |
| 视图插槽（页头/页脚等） | **Hook** / 视图事件 | 改 core 模板 |

## 决策顺序

```text
1. 归类意图（通知 / 读 / 写 / UI）
2. 查索引（见下）是否有现成扩展点
3. 有 → 引用文档路径 + 事件名/Provider 名 + 数据契约
4. 无 → TaskContract 声明「新建扩展点」并补模块 doc；禁止发明未文档化的事件名
5. 源码核对：dispatch / event.xml / QueryProvider 注册与文档一致
```

## Event 示例

**系统通知**（跨模块发后台消息）：

- 事件名：`Weline_Admin::msg`
- 文档：`Framework/doc/event/framework/系统消息通知.md`
- 触发：`EventsManager::dispatch('Weline_Admin::msg', ['data' => [...]])`

**模型保存后**（旁路逻辑）：

- 文档目录：`Framework/doc/event/model/`
- 典型名：`Weline_Framework_Model::save_after`（以具体文档为准）

## MCP 使用提示

调用 `resolve_task_context` 时，在 `task` 中写明意图，例如：

- 「跨模块发送系统通知，应使用哪个 Event」
- 「读取异步 Delivery 列表，应使用哪个 QueryProvider」

并设置 `kinds: ["doc","rule"]` 或 `module: "Weline_Framework"` 以缩小检索范围。
