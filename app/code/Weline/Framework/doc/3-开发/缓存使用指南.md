# 缓存使用指南

## 基础维度契约

`w_cache($identity)` 返回具备 `NamespaceScopedCachePoolInterface` 能力的缓存池，未显式选择 namespace 时保持旧键兼容。

为保持第三方 `CacheManager` 子类和轻量 fake 的 LSP 兼容，`CacheManagerInterface::pool()` 的公开返回类型仍是旧 `CachePoolInterface`；Framework 自带 Manager 实际返回 scoped 实现，`w_cache()` 会校验该 opt-in 能力。需要 namespace 的业务应使用 `w_cache()` 或显式检查 `NamespaceScopedCachePoolInterface`，不能要求所有第三方 Manager 立即收窄返回类型。

1. 普通 `get/set/remember/delete/has` 自动注入当前 frozen `website + store + channel + store_mode + context_version + namespace fingerprint + lang + currency + area`。
2. `getCustom/setCustom/rememberCustom/deleteCustom/hasCustom` 的维度开关默认都是 false，表示逃逸该维度；传 true 才注入。

```php
$cache = w_cache('product');

// 普通业务值：自动使用站点/语言/货币/区域维度。
$cache->set('price:' . $id, $payload, 1800);
$price = $cache->remember('price:' . $id, 1800, $builder);

// 全局词典：Custom 全逃逸。
$phrase = w_cache('phrase');
$phrase->setCustom('phrase_locale_words_' . $lang, $words);
$words = $phrase->getCustom('phrase_locale_words_' . $lang);

// 只需语言维度。
$cache->getCustom('menu:header', lang: true);
```

不要用 `getCustom(..., website:true, lang:true, currency:true)` 代替普通 API。`website` 维度使用规范 `website_code`；零号站是 `default`，不把 `website_id` 直接写入普通缓存键。

`storefront-cache-v2` 的身份只来自请求内已经冻结的 `ScopeIdentity(kind=channel)`，不再分别从 `$_SERVER`、Website、Store 或 Channel 猜测。`App` 在商城 Scope 安装完成后创建一份不可变 `StorefrontCacheKeyContext`，普通缓存、environment key、router key 与 FPC 只读这份上下文。它固定读取同一个版本向量：

```text
global/storefront/config
global/storefront/price
global/storefront/theme
website/{website_code}
website/{website_code}/config
website/{website_code}/catalog
website/{website_code}/price
website/{website_code}/theme
```

同一请求内 generation 后续变化不会改写已冻结键；下一请求读取新向量并自然 miss。Scope 或版本向量不可得时，普通 website-scoped key 使用完整 request fence，禁止回退到 `default` 短键；FPC 则停止读取、构建和发布。WLS 缺失 `Context` 时 fence 每次随机且永不跨任务复用；CLI/FPM 缺失 `Context` 时使用 PID、请求启动时间和入口脚本组成的非静态 bootstrap fence，使同一次调用内 set/get 保持同键，但跨请求或进程隔离。Custom 全逃逸仍逐字保留逻辑键，不读取 Storefront 上下文；只启用语言或货币而未启用 website 时也不会附加 namespace fingerprint。

## SystemConfig 继承 version vector（TASK-P1C-003）

`system_config` 池的 single/rows/map/request 键额外嵌入祖先 scope generation（`KeyBuilder::systemConfigVersionVectorToken`）。父层写入时 `ScopeConfigCacheInvalidator` bump 该 scope generation，并精确删除真实继承后代键；有显式覆盖的后代可跳过。宁可扩大失效，不可脏读。详见 `Weline_SystemConfig/doc/README.md`。

## namespace scoped cache

公共用法：

```php
$cache = w_cache('product')
    ->withNamespace('website/default/catalog/product/123');

$cache->set('view', $payload, 600);
$payload = $cache->get('view');
```

`withNamespace()` / `withNamespaces()` 返回新的不可变 facade。重复调用会合并、去重并排序 namespace，不修改底层共享 CachePool/CacheManager 的“current namespace”。

```php
$base = w_cache('product');
$one = $base->withNamespace('website/default/catalog');
$two = $one->withNamespace('website/default/catalog/product/123');

// $base 仍是未 scoped 池；$one/$two 互不篡改。
```

facade 覆盖：

- 单值 `get/set/has/delete`；
- `getMultiple/setMultiple/deleteMultiple`；
- `remember/rememberCustom` 与 single-flight lock；
- 普通与 Custom 路径；
- 底层池实现 `TaggableInterface` 时的 tag 值、tag 失效和 tag 查询。

值键、lock 和 tag 必须使用同一个 namespace fingerprint，防止新 generation 等待旧 generation 的构建锁。

scoped facade 的 `clear()` 不执行底层全池清理；它对 facade 的 namespace 执行 `bumpMany()` 并返回 true。这是节点及后代的逻辑失效。

## NamespacePath

公开路径只有两种根：

```text
website/{code}/...
global/{scope}/...
```

规则：

- UTF-8 NFC，大小写保留；最多 16 段、512 bytes。
- 不允许首尾/重复斜杠、反斜杠、空段、`.`、`..` 或控制字符。
- 规范路径只接受已 raw-url-encode 的 segment；`%` 后必须是两位大写十六进制。
- 业务动态值应使用 `NamespacePath::website()` / `global()` typed builder，不要手工拼接未编码标识。
- `@clock` 是 DB 内部保留行，业务不能构造该路径。

`website/default/catalog/product/123` 的向量是：

```text
website/default
website/default/catalog
website/default/catalog/product
website/default/catalog/product/123
```

不包含单独的 `website`。缺失行按 generation 0 处理。失效某节点即 bump 该节点；因为读取总是展开全部祖先，它自然使节点及所有后代失效，v1 不再提供第二个 Prefix API。

## generation 与 fingerprint

`weline_cache_namespace_version` 保存：

```text
namespace_hash (SHA-256 PK)
namespace      (完整规范路径)
generation     (单调 bigint)
updated_at
```

命中 hash 后必须再比对完整 namespace；理论碰撞直接失败。`bumpMany()` 排序去重，对每个 namespace CAS +1，最后在同一事务推进 `@clock`，冲突最多重试 8 次。CAS 成败必须读取 `QueryInterface::update()->fetch()` 的 affected rows；Model 链式 `update()->fetch()` 返回的是 Model，不能把该对象当成“更新了 1 行”，否则并发 stale predicate 会被误报成功并丢失 `@clock` 增量。

fingerprint 材料为每个祖先的：

```text
sha256(namespace)=generation
```

对 pair 去重并字典序排序后：

```text
fingerprint = sha256("ns-v1|" + join(";", pairs))
```

`NamespaceKeyDecorator` 只负责纯键装饰，不查 DB；`KeyBuilder::build()` 仍为纯函数。装饰后的值键前缀为 `@ns/{fingerprint}/`，tag 前缀为 `@ns-tag/{fingerprint}/`。

## 请求/Fiber 快照

1. 每个请求/Fiber 首次 scoped 访问固定 DB `@clock`。
2. clock 与进程快照一致，且进程已知向量包含全部祖先时，复用完整不可变进程值。
3. 否则用一次批量 SQL 读取当前需要的祖先向量，整体替换进程快照。
4. 同一请求后续仅补读未冻结祖先，已冻结值不变。
5. 事务 afterCommit 推进当前进程快照；WlsRuntime 在请求初始化后 begin，在 `finally` 中 end/clear。
6. repository 在没有 RequestContext 时仍会复查 DB clock，但这不能代替商城 Scope 身份；raw Worker pre-router FPC 在没有完整 frozen Scope 时必须暂停。FPM/CLI/Queue Worker 无 IPC 时仍依赖同一 repository 正确收敛。

进程层只保存一个整体替换的 clock/vector 值，请求/Fiber 只读副本；不要新建 static、`$GLOBALS` 或跨请求 current namespace。

## FPC 一致性

`App` 在请求/Fiber 内完成 Store/Channel 解析后冻结 `StorefrontCacheKeyContext`。`FullPageCacheCoordinator` 不再维护第二套 Website/版本事实；它复用该上下文的完整 Scope、locale、currency 和上述八路径 fingerprint。以下所有键面使用同一身份：

- fresh、stale、schema-neutral stale；
- formatted/gzip；
- process payload、process formatted；
- warmup/published receipt；
- build lock 与 release lock。

新 generation 通过新键自然 miss，不读旧 stale，也不等旧 build lock。schema-neutral stale 只忽略 payload schema，不忽略 namespace generation。release lock 必须使用 acquire 时保存的完整键。

阶段一的登录态策略是整页硬旁路：当前 authority 对应的 `WELINE_SESSID` 或 `WELINE_SESSID_{port}` 一旦确认登录，serve/build/publish 全部为 false；非法 Session ID 或 Session 存储异常也按可能已登录处理。只允许短暂缓存“已登录=true”，不得缓存匿名 false，避免同一 Session 在登录转换后继续命中公开页面。Authorization 请求同样绕过 FPC，private full-page cache 固定关闭。

非标准端口请求必须通过 `SessionCookieNameResolver` 使用当前 authority 的精确 Cookie 名（例如 `WELINE_SESSID_19626`）；认证读取和 FPC 登录旁路使用同一解析规则，不能一边识别端口 Cookie、一边回退字面量 `WELINE_SESSID`。

公开 FPC 只接受 200、非空 HTML。响应含 `private`、`no-store`、`no-cache`、零 max-age、`Pragma: no-cache`、原始或 Framework 管理的 `Set-Cookie`，以及 Cookie/Accept-Encoding 以外的 `Vary` 时都不得发布。Cookie、Token、用户身份和一次性 bootstrap 只能在缓存命中后的请求边缘装饰。

安全响应头同样不作为共享载荷重放：FPC 存储时剔除框架基线安全头、
CSP 和 CORS Origin，命中时按当前 Scope 与请求 Origin 重新生成。
formatted/gzip 键包含当前安全头摘要，`Vary: Origin` 必须与 Cookie、
Accept-Encoding 合并，不能覆盖已有维度。

精准资源变更不得调用 `FullPageCacheCoordinator::clearProcessCache()` 做跨站全清。该入口只保留给旧 `cache_clear` 兼容和明确的运行时生命周期清理。

公开 pre-router fast path 在 Websites Scope provider 存在时不会根据 URI、语言或币种猜测 Store/Channel；只有请求内已经解析并冻结的完整 Scope 才能发布 FPC。WLS 首页内部 prime 的 v1 receipt 会携带该次发布实际使用的 16 位十六进制 `cache_key`，且 `identity_digest = SHA-256(cache_key)`。接收 Worker 还会校验 GET、规范 URI、匿名会话和摘要，再只从这个精确 fresh shared key 回填 L1；最终 READY 证明也只读对应 process L1，不回退 stale、渲染或公开 pre-router Scope 猜测。旧 v1 receipt 没有 `cache_key` 时仅保留混合版本兼容路径；无法获取 namespace fingerprint 的 fallback receipt 不得成为 READY 证明。

## 发布、兼容与回滚

| 配置 | 默认 |
|---|---:|
| `cache.namespace.publisher_enabled` | false |
| `cache.namespace.legacy_full_clear_fallback` | true |
| `wls.cache_namespace.require_capability` | false |

模块 `etc/env.php` 只提供默认值；运行环境可在 `app/etc/env.php` 用同名路径覆盖。Website afterCommit 与 WLS publisher 都通过环境有效值读取 `publisher_enabled`，Website 旧全清分支同样通过环境有效值读取 `legacy_full_clear_fallback`，因此无需修改模块源码即可执行 Release B 或回滚切换。

DB generation 是权威，WLS publisher 只是 afterCommit 加速。`publish()` 只做有界 Master 接纳，不等 Worker ACK；publisher 失败时新请求仍通过 DB clock 收敛。

- Release A 保持 publisher/required capability 关闭、legacy fallback 开启。
- 所有 routing-eligible Worker 已替换且上报 capability + clock 后，才可进入 Release B；精准 IPC/FPC 验收后才关 legacy fallback。
- 回滚先关 publisher，重开 legacy fallback，等待 namespace operation 终态，再对目标实例执行并等待旧 `cache_clear` ACK。共享开发环境不得用无实例限定的全局 `cache:clear` 触碰其他任务实例；`server:cache:clear` 只清 Dispatcher 路由缓存，不能替代 Worker 全缓存协议。不删 namespace 表或降低 generation。

配置切换后需重建 registry/provider 并重启 WLS Master，仅 reload Worker 不足够。本文不表示三数据库、新旧 Worker 混合版本或 Release B 已验收通过。

## 迁移检查

- 旧裸键会自然冷 miss，无需物理删除。
- 依赖全局共享的写入必须改为 `*Custom` 全逃逸，否则会被默认维度分片。
- 只在需要精准资源失效的代码上显式加 `withNamespace()`；不得让普通未 scoped 键悄然改变。
- generation 表属于 Schema upgrade：使用正式 `php bin/w setup:upgrade` 创建/升级，并在目标 DB 验证 CAS 与请求快照。只需重建路由时使用 `RouteUpdateService::updateRoutes()`；`setup:upgrade --route` 不能替代 Schema 门禁，当前编排仍会进入 SchemaDiff。
