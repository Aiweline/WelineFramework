# 最终 HTTP 响应就绪

事件名：`Weline_Framework_Http::response_ready`

FPM 请求在最终 `Response` 发出前触发。观察者从 `response` 读取响应，并可通过同名字段回填装饰后的 `Weline\Framework\Http\Response`；替换后类型仍必须是 `Response`。

响应面矩阵：

- WLS 正常响应：`Weline_Framework::App::run_after`。
- FPM 正常响应：`Weline_Framework_Http::response_ready`。
- FPC 早期命中：`Weline_Framework_Fpc::cache_hit_response`。

同一观察者可以注册多个响应面，但必须请求级幂等。运行时只应命中对应的一条装饰路径，不得重复签发 bootstrap 或重复写 Cookie。

约束：

- 只处理当前请求，不得把 Response、Cookie 或请求身份保存到静态状态。
- 装饰 gzip 响应必须先严格解码、完成结构校验和装饰、再重新编码；解码或编码失败时 fail-closed。
- 装饰响应体后必须同步清理或重算 `Content-Length`、ETag、Digest 等实体校验头，并维护正确的 `Content-Encoding` 与 `Vary`。
- 敏感页面若注入一次性凭证，必须设置 `private, no-store`，且凭证不得进入日志。
- rollout `off` / `shadow` 不得注入 bootstrap、写 Cookie 或改变缓存头；只有权威绑定模式才允许做一次性装饰。
- FPC 中只能保存共享 HTML。Token、Cookie、用户身份与 bootstrap 必须在命中后按当前请求生成。
