# FPC 命中响应就绪

事件名：`Weline_Framework_Fpc::cache_hit_response`

Full Page Cache 在早期命中并构造最终 `Response` 后、返回客户端前触发。事件字段 `response` 可被观察者替换。

该事件用于请求级、不可缓存的最终装饰，例如依据当前 Scope 签发一次性 Worker bootstrap。缓存中只能保留共享 HTML；Cookie、Token、用户身份和一次性 ID 必须在命中后生成，且装饰后的响应必须标记为不可缓存。回填后的 `response` 仍必须是 `Weline\Framework\Http\Response`。

共享页面在发布前已经通过 `FullPageCacheCoordinator` 的硬门禁：只允许匿名、无 Authorization、完整 frozen channel Scope 和完整 storefront generation 向量；带 `Set-Cookie`、private/no-store/no-cache、零 max-age 或不安全 `Vary` 的响应不会进入公开 FPC。当前 authority 的端口限定 Session Cookie 也参与登录判定，Session 状态不可读时按可能已登录处理。

本事件只装饰本次命中产生的响应，观察者不得把装饰后的正文或 Headers 回写 fresh、stale、formatted、receipt 或 process FPC。需要新的缓存变体时必须先扩展统一 Scope/版本 key contract，不能在观察者中另造用户键。

安全响应头属于命中时的当前策略，不属于共享 FPC 载荷。
`FullPageCacheCoordinator` 在构造 fresh/stale/process 响应时统一调用
`SecurityHeaderPolicyService::resolveCurrentResponseHeaders()`；缓存发布会
剔除基线安全头、CSP 与 `Access-Control-Allow-Origin`，formatted/gzip
键则绑定当前策略与请求 Origin 摘要。禁止观察者把旧策略头重新写回缓存，
也禁止跨 Origin 重放 CORS 结果。

观察者修改压缩响应时必须严格解码、验证完整 HTML 结构、装饰并重新编码，同时维护 `Content-Encoding`、`Vary`，清理或重算 `Content-Length`、ETag、Digest 等实体头；任何步骤失败均应 fail-closed。

响应面关系：WLS 正常响应使用 `Weline_Framework::App::run_after`，FPM 正常响应使用 `Weline_Framework_Http::response_ready`，本事件只覆盖 FPC 早期命中。观察者必须请求级幂等，避免重复签发。rollout `off` / `shadow` 不注入、不写 Cookie、不改变缓存头；只有权威绑定模式才做一次性请求装饰。
