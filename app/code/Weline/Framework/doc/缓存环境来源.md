# 缓存环境来源

## 当前请求与固定范围

网站、店铺、渠道的固定身份和元信息继续使用统一冻结范围上下文及范围缓存，不因请求端口、路径或请求 ID 拆分。包含绝对链接的 HTML 使用 `KeyBuilder::environmentContext()` / `environmentHash()`，额外携带当前请求的 `website_url`、`host` 和 `base_url`。

`KeyBuilder::requestScopeValue()` 优先读取已有 `w_env()` / `WelineEnv` 门面提供的有效上下文值，再保留原有空值和 CLI 无上下文时的 `$_SERVER` / `WelineEnv::server()` 回退。网站 URL 使用门面已有的 `website_url` 别名，不能使用未映射的 `website.url`。显式 `base_url` 原样保留（包括挂载路径）；缺失时协议与 Host 也通过同一读取流程组合。此处不查询网站模型、不改写数据库 canonical URL，也不改变 WLS 的 URL 路由语义。

## 2026-09-13：修复环境键与链接读取来源不一致

真实跨实例验收出现正常端口 9555 的页面复用含 19655 链接的 HTML。只读真实类微复现确认：当前上下文与全局变量不同步时，WLS 链接使用上下文，原缓存键优先使用全局变量，可能按另一个 origin 保存 HTML；此外 `website.url` 未映射至 `route.website_url`。

定向用例位于 `Framework/Test/Unit/Cache/KeyBuilderStorefrontTest.php`：当前上下文覆盖旧全局值并与真实 `WlsRequest::getBaseHost()` 一致；相同固定范围的 HTML 环境键随 transport 变化而公共范围键不变；CLI 无上下文继续回退，显式 `base_url` 挂载路径不丢失。修改前新增 3 个用例、7 次断言中 2 个按预期失败。验证命令：

```bash
vendor/bin/phpunit --bootstrap app/bootstrap_phpunit.php app/code/Weline/Framework/Test/Unit/Cache/KeyBuilderStorefrontTest.php
```

此记录是开发证据；实际默认/隔离实例交错访问、既有范围 namespace 失效和浏览器验收由主任务统一执行，不能用单测替代。

## 实际验收结果（2026-09-13）

源码经正常 framework:compile 和两个实例 managed reload 加载；旧输出仅沿现有 theme 精确叶子 81→82 失效，父代次未变。同一 H2/同 worker 的 19655→9555→19655 每页 186 个同站链接全部正确，默认另一 worker 也为 0/0/0 错误；HTML/footer 完整。浏览器禁缓存的首页、英文筛选、第二页及详情页实际通过来源与页脚检查，既有 category-menu 重复 ID 警告仍保留。本批定向 PHPUnit 合计 22 tests/182 assertions 通过。英文 MISS 2.296s/HIT 58–51ms，不能视为冷启动达到 70ms。
