# 外部活动折扣集成（ExternalDealDiscountProvider）

面向其他业务模块（促销活动、限时抢购、会员日等）对接万能折扣的正式扩展说明。

## 目标

- **一活动一规则**：业务侧保存活动时 upsert 一条 Marketing `automatic` 规则，并把 `rule_id` 回写到活动实体。
- **改活动联动改规则**：再次保存时带上已有 `rule_id`（`existingRuleId`），由 Marketing 更新同一条规则，而不是新建。
- **禁用走业务侧**：在业务模块停用活动即可；Marketing 后台不可删除外部托管规则。

## 唯一写入入口

`Weline\Marketing\Api\Deal\ExternalDealDiscountProviderInterface`

- 注册：`Weline_Marketing/etc/module.php` → `provides`
- 实现：`Weline\Marketing\Service\ExternalDealDiscountProvider`
- 解析：`RuntimeProviderResolver::resolve(ExternalDealDiscountProviderInterface::class)`

**禁止**跨模块直接写 `Weline\Marketing\Model\Rule\Rule` 或调用 `RuleEngine` 落库。

## 对接步骤（推荐）

1. 业务模块在活动/主题保存成功后，解析 SKU（或商品 ID→SKU）。
2. 通过 `RuntimeProviderResolver` 取得 `ExternalDealDiscountProviderInterface`。
3. 构造 `ExternalDealDiscountRequest` 并调用 `upsert()`。
4. 将返回的 `ExternalDealDiscountResult::ruleId` 持久化到活动实体（如 `marketing_rule_id`）。
5. 前台陈列可用业务侧折扣配置算展示价；加购/结账必须走 `DiscountQuoteServiceInterface`，与规则同源。

## Request 字段契约

| 字段 | 含义 |
|------|------|
| `sourceModule` | 来源模块代码，如 `Weline_Promotion` |
| `sourceType` | 来源类型，如 `promotion_activity_theme` |
| `sourceId` | 业务主键字符串（主题 ID） |
| `sourceKey` | 业务可读键（如 `deals`） |
| `displayName` | 规则名称 |
| `discountType` | `none` / `percentage` / `fixed_amount` |
| `discountValue` | 折扣值 |
| `skus` | 命中 SKU 列表 |
| `active` | 是否启用（活动启用且折扣有效时为 true） |
| `existingRuleId` | 已绑定规则 ID；0 表示新建 |
| `priority` | 优先级，默认 80 |
| `metadata` | 附加信息（theme_id、page_slug 等） |

## Upsert 行为

- 规则类型：`automatic`
- 条件：`product_sku in` + SKU 列表
- 动作：`matched_products` + `sku_list` + `external_managed=1` + source_*
- 描述标记：`[weline:external_managed=1;source=…;module=…;id=…;key=…]`
- `active=false` 或折扣无效时：规则置为 `inactive`，清空条件/动作（保留绑定，便于再次启用）

## 参考实现

`Weline_Promotion\Service\PromotionThemeDealDiscountSyncService`

- 主题保存时调用提供者
- `SOURCE_MODULE=Weline_Promotion`，`SOURCE_TYPE=promotion_activity_theme`
- 主题字段 `marketing_rule_id` 与规则 1:1

## 护栏

- Marketing 列表对托管规则展示「系统同步」徽章
- `Rule::delete` / `postDelete` / 托管规则 `postSave` 均拒绝，并提示到源模块管理活动

## 验收清单

1. 保存活动后，万能优惠规则列表可见对应 automatic 规则，且带「系统同步」。
2. 再次改折扣/选品并保存，仍是同一 `rule_id`，报价生效。
3. 在 Marketing 删除该规则被拒绝；在业务侧停用活动后规则变为 inactive。
4. `php bin/w framework:compile`（新增 provides 后）后 `RuntimeProviderResolver` 可解析提供者。
