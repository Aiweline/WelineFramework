# Weline_Geo 需求

## 2026-09-09 — 定时推送失败须可处理（1.0.19）

推送管理页须将定时（含历史 auto）推送失败优先列出，展示失败原因，并提供查看错误与重试；不得只淹没在空的全部历史空态中。运营页不得把统一配置技术 key 作为主文案展示。

## 2026-09-09 — 定时推送统一配置（1.0.18）

定时推送启停须走 `Weline_SystemConfig` 统一配置（`geo/push/scheduled_enabled`），并用 `<w:config:embed>` 嵌在「推送管理」页；禁止业务页手写开关存库。开启后每天执行一次；人工一键推送不受该开关限制。

## 2026-09-09 — 推送失败须可读明细（1.0.17）

后台一键推送失败时，对话框不得只显示「请重试」；须带上业务摘要与各平台失败原因（如无账户密钥、HTTP 状态与响应摘要）。

## 2026-09-09 — 推送历史与手动推送（1.0.16）

推送管理展示推送历史。空态须说明「先配置平台账户与启用内容源，再一键推送」。后台手动一键推送须同步执行并写入 PushLog（成功/失败均可见），不得只入队却让历史长期空白。

## 2026-09-09 — 内容源只读元数据（1.0.15）

内容源（Feed）由系统自动种子维护；后台「内容源管理」仅允许开关是否启用，禁止新建与修改名称/类型/URL/频率/配置等元数据。种子 `ensure` 不得覆盖操作员已设置的启用状态。

## 2026-09-09 — 平台编辑选择标签与完整目录（1.0.10）

平台/内容源格式须用官方 `<w:theme:search-select>`，禁止原生 `<select>`。添加页须展示完整内置目录（含已配置的 Google 等），已配置项可标注「已配置」；再次保存仍按 `platform_code` upsert。

## 2026-09-09 — 后台 JSON 保存契约（1.0.8–1.0.9）

平台/Feed/推送后台 AJAX 保存必须返回 `{success,message,data}` JSON；失败须把可诊断信息带回对话框。同一 `platform_code` 新建应更新已有记录，不得因唯一索引报原始 SQL 错误。

## 2026-09-09 — 内置平台预设与账户密钥（1.0.6–1.0.7）

添加平台时，内置适配器须提供默认推送地址与内容源格式并自动填入；密钥/凭证配置在平台账户。当前不要求各平台 OAuth 一键授权（后续可按平台扩展）。

## 当前有效需求

### `REQ-GEO-0004` GEO Feed 每 10 分钟检查有变更才生成

- 来源与确认：用户于 2026-09-09 要求源定时产生，禁止触发式更新以免阻塞；每十分钟检查有新才生成。
- 目标版本：`1.0.3`。
- 业务逻辑：关闭保存路径上的生成/推送入队；Cron `*/10` 同步源并仅在 FeedItem 新于 `last_generated_at` 时写 `pub/geo-feeds`；协议读预生成 site 文件。
- 验收标准：契约单测断言 cron 表达式与 item-add 不再入队；手动 tick 后 site 文件存在且无变更时 skipped。

## 当前有效需求

### `REQ-GEO-0003` 默认启用 GEO Feed 并由业务变更写入 FeedItem

- 来源与确认：用户于 2026-09-09 要求网站默认启用；产品/博客等订阅变更写入对应类型；完成后触发灌数。
- 目标版本：`1.0.2`。
- 背景/问题：协议 `feed_enabled` 开着但 `geo_feed`/`geo_feed_item` 为空，AI RSS 空壳。
- 业务逻辑：安装/升级种子 content/product/article 默认 Feed；SEO url_changed 与 Product projection / Blog 保存写入 FeedItem；CLI 存量回填；协议端合并启用 Feed 条目输出。
- 验收标准：`/geo-feed.xml` 与 `/geo-feed.json` 含非空 items；后续产品/博客保存可继续写入。

## 当前有效需求

### `REQ-GEO-0002` Feed 生成/推送队列按 feed 合并入队

- 来源与确认：用户于 2026-09-07 要求与 Search 同类风暴一并修复 Geo / GenerativeEngineOptimization。
- 目标版本：`1.0.1`。
- 背景/问题：Realtime FeedItem 保存对同一 feed 反复 `queue create`，形成 N 条 pending 与 CLI 冷启动风暴。
- 业务逻辑：同一 `feed_id` + generate/push slot（含 format / platform 指纹）只保留一条幂等队列；pending 刷新 content；running 使用 followup；终态安全重开。
- 验收标准：契约单测断言 `createIfAbsent` 与稳定 slot key；同 feed 突发写入不再线性放大 Queue 行数。
