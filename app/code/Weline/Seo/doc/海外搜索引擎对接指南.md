# 海外搜索引擎对接指南

> 面向运营 / Agent：在 **Google Search Console 已对接** 的前提下，按推荐顺序接好海外三条通道。  
> 国内百度另文处理；本指南不覆盖 360 / 搜狗等「仅生成 Sitemap、无官方自动提交 API」的目录型平台。

**后台入口：** SEO 管理 → SEO 账户（与 Google 同构，**不单开** Bing / IndexNow / Yandex 专用面板）。  
选中平台后，表单上方会展开与 Google 同级的「支持的功能 / 配置提示 / 出网依赖 / 分步配置指南」；各字段旁 hint 与分区说明也由 Adapter `config_fields` 提供。  
**相关文档：** [账户与定时任务简要说明](账户与定时任务简要说明.md) · [平台绑定功能说明](平台绑定功能说明.md) · [SEO-CDN上线配置与验收](SEO-CDN上线配置与验收.md)

---

## 1. 海外值得做的三条（Google 之外）

| 优先级 | 平台码 | 账户名称建议 | 主要能力 | 凭证 |
|--------|--------|--------------|----------|------|
| 1 | `bing` | `Bing-weline:{域名}` | URL 推送（建议开 IndexNow）；Sitemap `SubmitFeed`（需 API Key） | 站点 URL +（可选）Webmaster API Key + IndexNow Key |
| 2 | `indexnow` | `IndexNow-weline:{域名}` | 中枢 URL 通知（Bing / Yandex / Naver / Seznam / Yep / Internet Archive / Amazonbot 等参与方） | IndexNow Key + 公网 Key 文件 URL |
| 3 | `yandex` | `Yandex-weline:{域名}` | 直连 `https://yandex.com/indexnow` 的 URL 通知 | 与上共用同一 Key / Key 文件；Endpoint 指向 Yandex |

**Google（已对接时保持不动）：**

- 平台码 canonical：`google`（`SeoPlatformCode`）。
- 普通商品页 **不**走 Indexing API；Google 账户的「URL 定时推送」强制关闭，靠 Sitemap + Search Analytics。
- 同站同平台只保留一个绑定（`enforceSinglePlatformBinding`）。

**推荐组合（海外店）：** Google（Sitemap/统计）+ Bing（IndexNow 推送，有 Key 再开 Sitemap 提交）+ IndexNow 中枢 + Yandex 端点。

## 2. 总流程（每个新站都走一遍）

```
① 确认公开 HTTPS 主机（生产 www / apex，禁止用 localhost 当 Key 主机）
② 生成 IndexNow Key → 部署公网 UTF-8 .txt → 用爬虫 UA 从源站验 200
③ 后台建 Bing / IndexNow / Yandex 三账户 → 填同一 Key →「验证连接」
④ 绑定目标 Website（常为 website_id=0）→ 打开 URL 推送；Bing 无 API Key 时先关 Sitemap 定时提交
⑤ 手工 POST 一条首页 URL 到三个 Endpoint，期望 HTTP 202
⑥ 改一个商品/文章触发业务 URL 推送，或等 Cron `seo_url_pusher`（约 5 分钟）
⑦ 写验收记录（见 §8）
```

开关语义（账户级 / 绑定级）：

| 开关 | 含义 |
|------|------|
| `SeoAccount.enable_cron_push_urls` | 账户级 URL 推送总开关 |
| `SeoWebsiteAccount.enable_url_push` | 该站绑定是否参与 URL Push |
| `SeoAccount.enable_cron_sitemap` | 账户级 Sitemap 定时提交总开关 |
| `SeoWebsiteAccount.is_auto_submit` | 该站绑定是否自动提交 Sitemap |

IndexNow / Yandex：**不支持** Sitemap 文件自动提交 → `enable_cron_sitemap` 必须为 0。  
Bing：仅有 IndexNow、尚无 Webmaster API Key 时 → `enable_cron_sitemap=0`；补上 API Key 并验证通过后再开。

## 3. IndexNow Key 文件（三条海外通道的共用前提）

### 3.1 规则（硬）

1. Key：`8–128` 位字母、数字或连字符（建议 `openssl rand -hex 16` → 32 位十六进制）。
2. 公网文件：站点 **Web root（`pub/`）** 下 `{key}.txt`，内容与 Key **完全一致**（UTF-8、无 BOM、无换行更稳妥）。
3. `key_location` 必须与要推送的 URL **同主机**（例如 URL 是 `https://www.example.com/...`，则 Key 也必须是 `https://www.example.com/{key}.txt`，不要混用 apex / www，也不要用测试域）。
4. IndexNow **不会**提高排名；只加快「变更被发现」。HTTP **202** = 已接受、Key 校验可能仍在进行中 → **不是**「已收录」，模块也不会因此死循环重推。

官方：<https://www.indexnow.org/documentation> · 参与方列表：<https://www.indexnow.org/searchengines.json>

### 3.2 部署示例（生产）

```bash
KEY=$(openssl rand -hex 16)
# 例：应用根 /www/wwwroot/example.com ，Web root = {应用根}/pub
printf '%s' "$KEY" > "/www/wwwroot/example.com/pub/${KEY}.txt"
# 备份到 var/backup/seo-indexnow-{时间戳}/（禁止覆盖已有备份目录）
```

### 3.3 验证

**不要用裸 curl 从办公网 / Agent IP 判断成败。** 部分站开启 WLS `attack_guard` 会对异常 UA/IP 返回 403，而 `robots.txt` 可能仍因缓存显示 200。

在源站本机用爬虫 UA 探活（示例）：

```bash
curl -sS -D- -o /tmp/indexnow-key.txt -w "%{http_code}\n" \
  -H "Host: www.example.com" \
  -H "X-Forwarded-Proto: https" \
  -H "X-Forwarded-For: 1.1.1.1" \
  -H "User-Agent: Mozilla/5.0 (compatible; bingbot/2.0; +http://www.bing.com/bingbot.htm)" \
  "http://127.0.0.1:9510/${KEY}.txt"
# 期望：HTTP 200，body 与 KEY 完全一致
```

后台「验证连接」会对 `key_location` 做可读性 + 内容匹配检查（通过后仍以引擎提交响应为准）。

### 3.4 手工试推（三条 Endpoint）

```bash
KEY=…          # 与文件内容一致
KEY_URL=https://www.example.com/${KEY}.txt
HOST=www.example.com
URL=https://www.example.com/

payload=$(printf '{"host":"%s","key":"%s","keyLocation":"%s","urlList":["%s"]}' \
  "$HOST" "$KEY" "$KEY_URL" "$URL")

curl -sS -o /tmp/in-hub.json -w "hub=%{http_code}\n" -X POST \
  "https://api.indexnow.org/indexnow" \
  -H "Content-Type: application/json; charset=utf-8" -d "$payload"

curl -sS -o /tmp/in-bing.json -w "bing=%{http_code}\n" -X POST \
  "https://www.bing.com/indexnow" \
  -H "Content-Type: application/json; charset=utf-8" -d "$payload"

curl -sS -o /tmp/in-ya.json -w "yandex=%{http_code}\n" -X POST \
  "https://yandex.com/indexnow" \
  -H "Content-Type: application/json; charset=utf-8" -d "$payload"
```

期望：多为 **202**（空 body 或 JSON `success`）；4xx/非 2xx 先查 Key 主机、Key 内容、URL 是否同 host。

## 4. 后台建账户（字段对照）

入口：**SEO 管理 → SEO 账户 → 新增**。平台选择器分组见 `SeoPlatformGroupCatalog`：「推荐接入」含 Google / Bing / 百度 / IndexNow；Yandex 在「IndexNow 生态」。

### 4.1 Bing（`platform=bing`）

| 字段 | 必填 | 说明 |
|------|------|------|
| 已验证站点 URL `site_url` | 是 | 与 Bing Webmaster 已验证站点一致，如 `https://www.example.com` |
| 使用 IndexNow 推送 `use_indexnow` | 建议开 | 打开后 URL 推送走 `https://www.bing.com/indexnow`，**可不填** API Key |
| IndexNow Key / Key 文件地址 | 开 IndexNow 时要 | 与 §3 同一套 |
| Bing Webmaster API Key `api_key` | Sitemap 自动提交时要 | [Webmaster → Settings → API Access](https://www.bing.com/webmasters) |

**开关建议：**

- 仅 IndexNow：`enable_cron_push_urls=1`，`enable_cron_sitemap=0`
- 已填 API Key 且「验证连接」通过：可再开 `enable_cron_sitemap=1`（`SubmitFeed`）

适配器：`Service/Adapter/BingSearchEngineAdapter.php` · Sitemap：`Adapter/BingSitemapAdapter.php`

### 4.2 IndexNow 中枢（`platform=indexnow`）

| 字段 | 必填 | 说明 |
|------|------|------|
| IndexNow Key | 是 | 同 §3 |
| Key 文件公开地址 | 是 | 同主机公网 `.txt` |
| IndexNow Endpoint | 否 | 默认 `https://api.indexnow.org/indexnow` |

- `enable_cron_push_urls=1`
- `enable_cron_sitemap=0`（协议不提交 Sitemap 文件；Sitemap 仍靠 robots / 各站长平台）

适配器：`Service/Adapter/IndexNowSearchEngineAdapter.php`

### 4.3 Yandex（`platform=yandex`）

与 IndexNow 相同字段，但：

- Endpoint 填 **`https://yandex.com/indexnow`**（或留空由 `YandexSitemapAdapter` 默认端点处理——账户侧建议显式填写，避免歧义）
- 开关同 IndexNow：只开 URL 推送

适配器复用 IndexNow 推送实现；Sitemap 平台码 `yandex`。

### 4.4 绑定站点

1. 账户表单内用 Website 多选绑定目标站（常含 **默认站 website_id=0**）。
2. 绑定行打开 `enable_url_push`；需要自动交 Sitemap 的平台再开 `is_auto_submit`。
3. 保存后核对：同站同平台仅一条绑定；未绑定平台 **不会** 生成该平台目录下的 sitemap 文件。

## 5. 运行时怎么推

1. 业务变更 → `UrlSubmitService::requestSubmit()` / 事件 `Weline_Seo::integration::url_submit_request` → 只入队，不在请求内打外网。
2. `Cron\UrlRewriteSubmitSync`（约 5 分钟）补漏 rewrite diff。
3. `Cron\UrlPusher`（约 5 分钟）消费 `push_urls`，按绑定账户的 Adapter 出站。
4. Sitemap：`Cron\SitemapSubmit` 先同步 Provider → 生成文件 → 仅对「支持且开启」的账户 `submitSitemap`。

详见 [账户与定时任务简要说明](账户与定时任务简要说明.md)、[url-rewrite-cron-submit](url-rewrite-cron-submit.md)。

## 6. 本机库 vs 生产库（防踩坑）

| 项 | 说明 |
|----|------|
| 账户表 | 本机 `mig_clone_*` 与生产库 **不自动同步**；两边都要建账户或按站柜流程导入 |
| Key 文件 | 必须在 **生产 Web root** 可被引擎抓取；只写本机 `pub/` 对公网无效 |
| `site_url` / Key 主机 | 必须是生产公网主机（如 `www.changanhanfu.com`），不要填 `*.test.weline.com` |
| 探活 403 | 先排除 `attack_guard`；用源站 + 爬虫 UA；必要时按站柜执行 `server:security:unblock`（慎用 `--clear-all`） |
| 改生产前 | 先备份将改动的表/文件到带时间戳目录，禁止覆盖已有备份 |

站点级已落盘事实（账户 ID、Key 路径、备份路径）写在各站 **`websites/<site>/`** 柜内文档（不进 Git 的站点事实），不要把密钥抄进模块通用指南正文以外的「假通用」段落。

## 7. 验收清单

- [ ] Key 文件源站爬虫 UA → HTTP 200，body = Key  
- [ ] 后台三账户「验证连接」通过（IndexNow / Yandex / Bing+IndexNow）  
- [ ] 目标 Website 已绑定三账户，URL 推送开；Bing 无 API Key 时 Sitemap 提交关  
- [ ] 手工 POST 三 Endpoint → 多为 202  
- [ ] 触发一笔真实 URL 变更后，任务表出现 `push_urls` 且终态非反复失败  
- [ ] `robots.txt` 仍声明规范 `Sitemap:`；公开 `/sitemap.xml` 可访问  
- [ ] 验收记录写入 [SEO-CDN上线配置与验收](SEO-CDN上线配置与验收.md)「当前验收记录」或站柜 SEO 文档

## 8. 故障速查

| 现象 | 排查 |
|------|------|
| 验证失败：Key 不可读 | 文件是否在 `pub/`；主机是否与 `key_location` 一致；是否被 attack_guard 拦（换爬虫 UA / 源站探） |
| 验证失败：内容不匹配 | 文件是否多了换行/空格/BOM；是否部署了旧 Key |
| 推送 422 / 拒绝 | URL 与 Key 不同 host；keyLocation 路径不在允许前缀；混批多 host |
| Bing Sitemap 提交失败 | 未填 `api_key` 却开了 `enable_cron_sitemap` → 先关开关或补 Key |
| 任务成功但「没收录」 | 正常：IndexNow 只通知发现；收录看站长平台与质量，不是 202 的承诺 |
| 本机有账户生产没有 | 见 §6，生产库需单独写入 |

## 10. 明确不做 / 后置

- **百度**：国内通道，需资源平台 Token；模型已就绪，另开作业。  
- **Google Indexing API**：仅 JobPosting / BroadcastEvent 等类型；电商商品页不要当通用秒收录。  
- **Naver Crawl Request API**：需官方合作开通，与 IndexNow 参与方通知不是同一条产品路径。  
- **360 / 搜狗 / 神马 / Brave / Qwant 等**：无等价公开自动提交 API → 只生成 Sitemap + 站长后台手动/自然发现，不优先排期写「假自动提交」。
