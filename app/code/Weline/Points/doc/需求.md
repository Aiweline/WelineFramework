# Weline_Points 需求

## 1. 目标

给电商站点一套站内积分与会员 VIP 等级：

- 顾客现金实付后赚积分；赚分按**站点基准货币**计算，不直接用结账币数字。
- 结账时积分按兑换比例抵扣，购物车/迷你购物车/结账页可报价，默认单笔上限 30%。
- 退款时花掉的积分原路退回，本单赚到的积分按退款比例扣回。
- 按累计赚取积分（或成长值）自动升级 VIP 等级，等级提供折扣、积分倍率、包邮权益。
- 商品可配置独立积分获取比例或每件固定积分。

## 2. 两本账

| 账 | 内容 | 抵扣/退款 |
|---|---|---|
| 可花积分 | `CustomerAsset` 的 `points` 余额，单位是点 | 抵扣扣减；退款按比例退回 |
| 会员累计 | `CustomerState.growth_value` + `lifetime_points` | 只增不减，不参与抵扣 |

累计赚取积分是 VIP 等级默认依据；抵扣后不减少，所以不会掉级。

## 3. 赚分

- 触发：订单进入已支付投影（`Weline_Order::order_paid`）。
- 基数：订单总额减去资产抵扣额与积分抵扣额，即实付现金。
- 换算：结账币实付现金先换成站点基准货币；缺汇率则整单跳过，禁止 1:1 直算。
- 计算：基准币实付现金向下取整到主币单位 × 赚分比例 × VIP 倍率，全部向下取整。
- 商品行：有商品 EAV 属性时逐行计算；`points_earn_fixed` > 0 覆盖比例，否则用 `points_earn_ratio` 或后台默认倍率。
- 游客、缺失顾客、HelpPay 代付不赚。
- 同一订单同一支付只赚一次。
- 默认关闭。

## 4. 花分/抵扣

- 复用 `Weline_Payment` 的 `points` 资产策略：预占 → 提交 → 释放/退回。
- 结账报价按站点基准货币与汇率折算，单笔最多抵扣 `points/discount/max_ratio`（默认 0.3）。
- 同一应付只能选支付或折扣一种角色；本模块默认只开折扣角色。
- 兑换比例为 0 时即使 enabled 打开也不参与。
- 积分记点，不把 1 点写成 1 分钱。
- 单笔抵扣上限默认 30%，积分不会单独把应付降到 0；现金仍需走 PSP。

## 5. 退款

- 花掉的抵扣积分：按 `DiscountApplyRecord` 与退款金额比例退回。
- 赚到的积分：本模块按退款现金比例扣回，独立事件号。
- 扣到 0 为止，余额不为负；扣不回的差额记审计欠账。
- 不拦截现金退款。
- 成长值与累计赚取积分不因退款降低。

## 6. VIP 等级

| 默认等级 | 累计积分门槛 | 积分倍率 | 折扣率 | 包邮 |
|---|---:|---:|---:|---|
| 普通会员 | 0 | 1.00 | 0% | 否 |
| 白银会员 | 1,000 | 1.05 | 1% | 否 |
| 黄金会员 | 5,000 | 1.10 | 3% | 否 |
| 铂金会员 | 20,000 | 1.20 | 5% | 是 |
| 钻石会员 | 50,000 | 1.30 | 8% | 是 |

- 等级取已达到的最高启用门槛。
- `points/vip/basis` 可选 `lifetime_points`（默认）或 `growth`。
- 等级倍率只放大新赚积分，不改写已有积分。
- 折扣率、包邮是权益字段，由结算/运费模块读取；本模块只提供读取契约。
- 默认 `points/vip/enabled=0`：累计值照常记录，但全员按普通会员权益。

## 7. 商品积分属性

- 由模块自动向 Product EAV 声明：
  - `points_earn_ratio`（小数）：该商品行积分倍率。
  - `points_earn_fixed`（整数）：每件固定积分，大于 0 时覆盖比例。
- 后台默认：`points/product/default_ratio`、`points/product/default_fixed_points`。
- 属性挂在 `storefront` 属性集、`specs` 组，商品编辑页可配置。

## 8. 默认关闭

以下全部满足才可赚分/抵扣：

1. 客户资产 `customer_asset` mode 为 allowlist/on。
2. `points/earn/enabled=1`（赚分）。
3. `points/discount/enabled=1`（抵扣）。
4. `payment/asset/points/enabled=1`。
5. `payment/asset/points/exchange_ratio>0`。

## 9. 明确不做

- 积分过期、清零、有效期。
- 提现、转让、跨站共用、现金购买积分。
- 负余额。
- 代付使用积分。
- 按国家分叉规则。

- 订单 `b63f4fc5-287e-401b-a246-aea4c8cdf15d` paid，grand_total 317.73；支付 `PAY20261026160406941379` success 222.42。
- 积分 reserve → commit → earn 齐全；余额 101998 → 92467，预占 0；VIP lifetime 2283 → 2518（silver，未下降）。
- 退款按现金实付（`orderTotal − points apply`）比例退回；`returnCommitted` 幂等时不重复累加 `returned_points`。
- B2B 零现金 deposit 分支提交积分；commit/release 失败写 `w_log_error('points')`。

已知限制（未验收/未修复）：

- 订单 `money_snapshot` 与成功页总额未减积分（仍显示 317.73，实际扣 222.42）。
- commit/release 失败无自动重试/outbox，PSP 成功而 commit 失败时积分保持预占。
- 支付阶段不重复校验 30% 上限，依赖 apply 时服务端 clamp。
- VIP 折扣率、包邮未接入结账/运费链路；后台等级 CRUD 未做。
- `architecture:check` 对 Points 仍报 6 条 findings（2 条 internal_api + 4 条循环引用）。
