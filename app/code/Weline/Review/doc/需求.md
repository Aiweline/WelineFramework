## 当前有效需求

### `REQ-REVIEW-0001` 万能类型化评论与电商默认能力

- 来源与确认：用户在评论模块设计会话中确认，2026-08-22 再次确认将站点验收结果写回框架。
- 目标版本：`1.0.0`
- 背景/问题：评论能力必须属于全局基础设施，业务模块只声明自己的评论类型、扩展字段和展示覆盖，不得把通用能力放进 WeShop。
- 用户与运营场景：游客或登录用户可对某一已注册类型的实体提交评论；默认商品类型支持总体、质量、交付、服务四项五星评分，以及文字、图片、视频和匿名展示。
- 业务逻辑：每种评论类型拥有独立评论表；类型 Provider 解析实体并声明字段，字段定义同时驱动浏览器表单和服务端校验；新增字段后表单自动出现。新评论同步写入 `pending`，AI 审查由 Cron 扫描，结论不明确时转为 `ai_pending_blocked` 并通过 Msg 通知人工，不使用 Queue。
- 范围：类型注册、独立评论表、公共媒体票据、匿名/登录评论、图片 6 张、视频 2 个、主题/模块模板覆盖、BinQuery 表单/列表/上传/提交。
- 非目标：不由业务模块重复实现网站/店铺范围；不使用 raw fetch；不把评论提交放入 Queue。
- 数据/权限/安全：前后端使用同一字段约束；所有必填评分均在服务端校验为 1–5 整数，扩展评分写入 `extra_json` 并在公开列表回读；媒体校验 MIME、大小、数量和绑定实体；浏览器请求统一走 `Weline.Api.resource('review')`。
- 兼容/迁移：模板优先级为当前主题、父主题、类型拥有模块、Weline_Review 默认模板；模块只能重写自己声明的类型。
- 验收标准：四项商品评分以直接选星而非下拉框展示，并支持鼠标、触摸、键盘与原生必填校验；已通过评论列表的 `total` 必须来自 ORM 分页总数，缺失时回退当前映射条目数；总体及扩展评分、文字、图片和带控制器的视频同步展示。
- WebUI/E2E：在真实 WLS 的商品详情页选择四项评分并提交文字、图片、视频评论；后台审核后前台显示一条评论、四项评分且计数正确；前后台控制台无新增错误；主题覆盖与默认模块模板链路均可解析。
- 运营与支持影响：审核员通过 `REQ-REVIEW-0002` 的后台入口处理评论。
- 依赖与风险：商品、客户、Msg、Cron 均为可选依赖；未注册类型不能覆盖或提交评论。

### `REQ-REVIEW-0002` 后台统一评论审核管理

- 来源与确认：用户审阅双向差异与同步建议后，于 2026-08-22 明确要求“写回，写回框架后在框架测试一下”。
- 目标版本：`1.0.0`
- 背景/问题：通用评论需要由框架模块自动提供网站级后台审核入口，业务类型模块不应重复实现评论管理。
- 用户与运营场景：具备权限的后台人员查看全部或按状态筛选评论，检查文字、图片和视频，并执行通过或拒绝。
- 业务逻辑：后台列表聚合默认商品评论和媒体；支持 `pending`、`ai_pending_blocked`、`approved`、`rejected` 状态；仅允许把指定评论更新为 `approved` 或 `rejected`；操作后返回同一管理页并显示国际化消息。
- 范围：后台菜单、ACL 列表权限、ACL 审核权限、状态筛选、分页、文字/图片/视频预览、通过/拒绝操作及中英文提示。
- 非目标：本次不新增评论表字段、不改变 Cron/AI 审核策略、不实现批量审核或其他评论类型的专属后台模板。
- 数据/权限/安全：列表和审核 Controller 均声明 ACL；POST 审核表单使用框架 CSRF；评论 ID 和目标状态在服务端校验；输出统一转义；媒体视频只提供浏览器原生 controls。
- 兼容/迁移：无 Schema 变更，模块版本保持 `1.0.0`；未来类型可按框架扩展规则提供自己的字段与展示。
- 验收标准：后台菜单可见；列表可显示评论对象、状态、文字、图片和视频；筛选有效；通过/拒绝后状态正确；前台只显示已通过评论且总数正确。
- WebUI/E2E：真实 WLS 中完成“前台游客提交含图片和视频的评论 → 后台列表出现 pending → 点击通过 → 后台显示 approved → 前台显示 1 条评论、图片和可播放视频”；检查无权限分支或 ACL 声明契约。
- 运营与支持影响：新增评论审核工作台，操作说明见 `doc/运营/评论审核.md`。
- 依赖与风险：后台运行环境必须已执行路由升级；测试媒体和评论必须在验收后精确清理。
