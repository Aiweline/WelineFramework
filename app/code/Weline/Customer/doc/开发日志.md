# Weline_Customer 开发日志

## 2026-09-14 — 登录成功回跳以当前店面语种覆盖旧 redirect（1.0.113）

- 问题：阿语登录后进到印地语个人中心；`withCurrentLocalizationPrefix` 在目标已带 `/{locale}/` 时原样放行，session/`redirect_url` 里残留的 `/hi_IN/` 盖过当前 `/ar_SA/`。
- 修：有当前路径/Referer/`Url::getPrefix()` 时一律剥语种再贴当前前缀（与 OAuth `forceLocalizationPrefix` 同策略）；已登录短路改 `getUrl`/`redirect('customer/account')`。
- 契约：`CustomerAuthReturnUrlServiceTest`。

## 2026-09-14 — 退出登录重定向改用 Url::getUrl（1.0.112）

- 问题：Logout / Query logout 用硬编码 `/customer/account/login`，经 `redirect()` 再拼前缀时丢失店面语种，落到默认站首页。
- 修：GET 退出用 `redirect('customer/account/login', [w_auth=>0])`（内部一次 `getUrl`）；JSON/Query 直接 `Url::getUrl(..., [w_auth=>0])`。禁止把已带语种的 path 再丢给 `redirect('/')` 以免 `/ar_SA/ar_SA/...`。`withAuthRefreshSignal` 仍保留绝对 URL 源；无路径语种时回退 Referer / `Url::getPrefix()`。模板退出链继续用 `@url`。
- 附：本机 `app/etc/env.php` 的 `lang` 从误设 `ar_SA` 恢复为 `zh_Hans_CN`，否则 `@url` 对阿语也不拼 `/ar_SA/`。

## 2026-09-14 — Google 快捷登录 start 固定无语言前缀（1.0.111）

- 问题：Google OAuth 要求固定跳转/回调地址；给 start 拼 `/{locale}/` 易与 Cloud Console 登记不一致，并干扰 locale 还原。
- 修：`startUrl('google')` 用 `getOriginUrl` + `withoutStorefrontLocalizationPrefix`；JS `resolveProviderOauthStart` 对 Google 去前缀并只靠 `return_url` 携带店面语言。
- 契约：`SocialLoginOAuthIntentContractTest`、`SocialLoginQuickAuthContractTest`。

## 2026-09-14 — 快捷登录阿语回跳误到印地语（1.0.110）

- 问题：从 `/ar_SA` 快捷登录，OAuth 成功后落到 `/hi_IN`。
- 根因：`locale_prefix` 优先用 start 请求/Query `getPrefix()`，错误前缀盖住 `return_url`；callback `forceLocalizationPrefix` 又对已带 locale 的 return_url 原样放行。
- 修：start/bootstrap 优先 `return_url`→Referer→current；JS 以页面路径前缀为准并 strip 再贴；forced 前缀覆盖错误 locale。
- 契约：`SocialLoginStorefrontLocaleTest`、`CustomerAuthReturnUrlServiceTest`、`SocialLoginQuickAuthContractTest`。

## 2026-09-14 — 社媒代理改 7897 + 回跳错误按店面语言翻译（1.0.109）

- 报错图：印地语店面 toast 仍中文；出站代理配置 `127.0.0.1:7892` 已死，Clash 实际在 `7897`。
- 修：配置改为 `http://127.0.0.1:7897`；callback 先按 state 语言 `setRequestLanguageOverride` 再 `__()`；Provider 抛未译 msgid；补 `en_US`/`hi_IN` 译文。
- 验证：代理 resolve 含 7897；locale languageFromPrefix UT。

- 数据/配置/迁移：无 Customer Schema；旧 Token 经确认后惰性迁移。
- 兼容与回退：仅 Provider 未配置时继续旧流程。

## 2026-08-29 — 注册页 getAccountApi().then TypeError

- **现象**：`api`/`account` 预加载成功后，提交注册仍报 `getAccountApi(...).then is not a function`。
- **原因**：全量 `Weline.Api.resource()` 返回同步 Proxy；旧内联脚本未 `Promise.resolve`，且 Theme 部件 HTML 缓存仍吐旧版。
- **修复**：`register.phtml` 增加 `asPromise()`，所有路径保证返回 thenable；清理 Customer/Theme `view/tpl` 并重启 WLS。

## 2026-08-29 — 登录按钮多重 loading

- **现象**：提交时按钮上同时出现 3 个 spinner。
- **原因**：`data-w-login-spinner` + busy 文案内 `w-spinner` + `.w-button[aria-busy]::after` 三层叠加。
- **修复**：模板只保留 idle/busy 文案切换；busy 仅靠 foundation `aria-busy::after` 画一个 spinner；同步 `account-login.js`（Customer + Theme UI 页）。
