## 当前有效需求

### `REQ-CUSTOMER-0003` 顾客社媒登录（Google/FB/Ins）

- 来源与确认：用户 2026-09-04 要求创建社媒登录；登录布局设 slot + 应用部件默认注入；每项可独立开关；先对接 Google、Facebook、Instagram。2026-09-05 追加个人中心绑定管理与首次授权「绑定已有 / 新建」。同日确认：须配置凭据后才能激活，激活后才在前台展示。同日确认：提供商改为 `extends` Provider（对齐 Payment），其他模块实现 `SocialLoginProviderInterface` 接入；**禁止**用 Hook 注册 OAuth 提供商；内置三家迁入 Provider 类。
- 业务逻辑：登录表单社媒区释放 `account-login-social-providers`；部件 `account-social-login` 默认注入；`SocialLoginProviderCatalog` 经 extends 扫描 Provider；SystemConfig `customer/social_login/{code}/*` + `enabled`；`isActive` 门禁展示与 OAuth start；部件 `enable_*` 可再关；未绑定时进入选择页；个人中心 `#social-login` 绑定/解绑；Provider 须提供 Logo 与指南/政策元数据及 phtml，公开导航 `/guide/social-login`（指南正文走与支付指南同款 i18n/AI 翻译流水线）；Multipass 等非 OAuth widget 身份桥仍可用 login providers Hook；服务器无法直连提供商 API 时可配 `customer/social_login/http_proxy`（或 `HTTPS_PROXY`）；OAuth state/pending 经 `SocialLoginTransientStore` 落盘，回跳不依赖 Session Cookie；**`social-login/start|callback` 须忽略维护恢复探测（HEAD / `_maintenance_recovery_probe` / `X-Maintenance-Recovery-Check`），不得消费一次性 code/state**；登录页/全站可弹出 Google One Tap 或 Facebook FedCM 芯片（`quick_prompt`），**须用户点击确认，禁止 auto_select / getLoginStatus 静默自动登录**；已登录本站则抑制全部自动提示；**OAuth / 快捷登录成功必须 `formatAuthSuccessRedirect` 回到登录前业务页，不得硬跳个人中心**；**Instagram 须走 Instagram API with Instagram Login**（authorize `www.instagram.com/oauth/authorize`，scope `instagram_business_basic`，Instagram App ID/Secret），**禁止**再依赖已下线的 Basic Display；仅专业号（Business/Creator）可授权。
- 验收标准：仅「已配置且已激活」的提供方在登录页展示；未激活不渲染；个人中心可见已激活/已绑定状态；首次授权可选择绑定已有或新建并自动登录；第三方模块可通过 extends 目录接入且无需改 Customer 硬编码列表；指南总览与各提供方指南/政策页可打开。
- 范围：Customer 登录槽、部件、Provider 接口/扫描、OAuth 壳、指南政策页与侧栏导航、绑定表、配置模板、个人中心绑定分区、契约测试、extends 文档。
- 非目标：本轮不做 Apple/微信/X 业务实现（仅预留扩展点）；不混入 `Weline_Social` 发布侧平台 OAuth；不把 Multipass 迁到 SocialLoginProvider。

### `REQ-CUSTOMER-0001` 前台每设备记住登录接入

- 来源与确认：用户于 2026-08-11 确认多端登录与设备管理实施计划。
- 目标版本：`1.0.1`。
- 用户与运营场景：Customer 在多浏览器登录时，每个设备拥有独立的记住登录凭证；下线其中一个设备不影响其他设备。
- 业务逻辑：设备 Provider 可用时，密码登录沿用正常 Customer 登录并为当前设备签发 `w_frontend_ut`；自动登录先解析新凭证并恢复原设备，成功后轮换凭证；已登录用户可把经确认归属的旧 `w_ut` 惰性迁移。
- 范围：Customer 记住登录签发、自动恢复、退出清理和重复签发入口收口。
- 非目标：Customer 保存设备 ORM、直接渲染设备管理 UI、管理后台设备或查看其他客户设备。
- 数据/权限/安全：跨模块只依赖 Framework 发布的中立契约；原始 Token 仅进入 HttpOnly Cookie；Provider 声明故障时不得回退旧 Token。
- 兼容/迁移：Provider 未配置时保留现有 `CustomerToken`/`w_ut` 行为；Provider 可用后，仅在确认旧 Token 属于当前 Customer 时迁移并删除旧行。
- 验收标准：两台前台设备可独立记住登录；撤销 B 后 B 不能自动恢复，A 保持登录；frontend/backend Cookie 不串域。
- WebUI/E2E：两个隔离浏览器上下文完成登录、设备列表、远端下线和被下线后的登录跳转。
- 运营与支持影响：迁移后回滚旧代码可能要求用户重新输入密码，不恢复已删除旧凭证。
- 依赖与风险：现有多个记住登录签发入口必须统一使用同一服务，避免部分路径继续全用户覆盖 Token。
