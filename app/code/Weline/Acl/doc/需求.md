## 当前有效需求

### `REQ-ACL-0001` 角色授权勾选后必须持久保存

- 来源与确认：用户于 2026-08-18 在角色授权验收中发现：test 角色内容管理已满选 23/23，再勾仪表盘并保存后变成 8/23；明确要求「不能丢权限，勾选了就要」。
- 目标版本：`1.1.1`
- 状态：implemented
- 背景/问题：后台角色权限树保存时，jstree three_state 只把叶子标为选中、父节点不提交；服务端又把「父菜单未出现在 POST」当成整棵子树取消，把仍勾选的 CMS/媒体等叶子一并丢掉。
- 用户与运营场景：超管在「权限分配」页勾选若干菜单/接口后点保存；刷新后勾选必须还在；已归配该角色的后台用户必须能进入对应页面。
- 业务逻辑：提交集合是授权事实。已勾选的 source（含仅提交叶子、未提交父菜单）保存后必须仍在角色授权中；取消勾选只影响被取消的节点及其子孙。不得因搜索、筛选、折叠、three_state 半选或只提交叶子而删除仍勾选的权限。父菜单由已保存叶子向上补齐，供菜单可见。
- 范围：角色授权页提交脚本、`reconcileTagGrantsForSave` / `revokeUncheckedMenuSubtrees` / `expandMenusAncestors` 保存管道、刷新后树状态与被授权用户可见性。
- 非目标：不改对象 Scope ACL；不改超管 role_id=1 旁路；不在本次修询盘菜单 `weline_inquiry` 前缀 404。
- 数据/权限/安全：不得把未勾选的资源写成已授权；不得扩大到站级授权包之外；保存后仍走既有 `role_access_save_before`。
- 兼容/迁移：无 Model Schema 变更；不升 `etc/module.php` 的安装版本。既有「取消父菜单则子孙一并取消」仍成立，前提是这些子孙未再出现在提交集合中。
- 验收标准：内容管理满选后再勾仪表盘并保存，刷新后内容管理仍为满选、仪表盘为已选；test 角色用户侧栏可见对应菜单，并能打开询盘、CMS、媒体（若这些叶子仍在勾选中）；取消某一叶子后仅该叶子及子孙消失。
- WebUI/E2E：超管打开 test 角色授权 → 勾满内容管理 + 仪表盘 → 保存 → 刷新核对计数 → 用 test 账户登录打开对应后台页。
- 运营与支持影响：运营按现有「权限分配」操作即可，无需新配置；若历史角色已被错误保存丢权，需超管重新勾选一次。
- 依赖与风险：依赖 jstree 勾选事件把授予/撤销写入共享集合；依赖角色已归配到用户。
