顶栏「More」挤掉右侧导航 —— 单行宽度预算原型

原型（可丢弃）— 复刻 header-default.js 的 syncNavStackMode / clustersOnSeparateRows / measureCatAvailableWidth / measureNavAvailableWidth / computeHideFromRaw，数字取 daocharms 线上实测。

问题：宽屏本应「左分类 + 右导航在同一行内互让宽度」。现状代码有两个洞：
① sepRows 误判：判定"是否两行"只看 offsetTop 差 ≥ max(24, 左高×0.75)。两侧内容高度不同（如右簇 Cart 变两行、top 差≈30px）时，同一行也被当成两行 → 双方都按整行 1200 规划 → 实占 ≈1400 → nowrap 溢出被裁。
② CSS 兜底缺口：nowrap 下浏览器按 min-content(=max-content) 收缩 flex 项。左簇若没有 overflow:hidden（jsdom 复现证实），它拒绝收缩，把右簇直接压没——即使 JS 预算算对了也白搭。
验证：切到各场景点「按步骤推进」；对照页跑修复版（rect 佐证 sepRows + 单行总预算）。

基线 innerW=1200 一切正常 → 第 2 步只把右簇变高（什么都没变窄）→ 观察「误判两行?」与「右簇被裁?」。对照页同三步跑修复版：不再溢出。

等高压窄 1200→900→820：左簇先折叠进 More、右簇始终完整。修复不能弄坏这条路径。

≤768 合法栈模式：左右各一行，各自整行预算；右簇再变高也不应有异常。

三条判定：① nowrap flex 下左簇按 max-content 占满、右簇被压到 0 宽——flex-shrink:1 救不了（min-content≈max-content，nowrap 长文本），overflow:hidden 也不改变结果；所以「挤出去」是数学必然，唯一出路是 JS 折叠（More）。② 同一行时 Δtop 实测 −9px → 现状阈值 24 不误报，但更高差(≥24)会误判两行、令双方各按整行规划 → 溢出。③ 探针 C（同布局 + 真实 More 折叠算法）：折叠后 leftW=228 / rightW=289、右簇完整可见、overflow=−1 ⇒ 互让机制本身有效，坏在 sepRows 误判把它关掉。
