# 主题页头页尾强契约 —— 自定义主题必须全站生效

## 一句话

**页头/页脚是主题（theme）拥有的 chrome，不是布局（layout）的私有内容。** 任何页面，无论布局来自主题还是模块回退，都必须渲染当前活动主题的 header/footer partial。

## 1. 资源归属

- 主题的 chrome partial 只放在主题自己的目录：
  - `app/design/{Vendor}/{theme}/frontend/partials/header/default.phtml`
  - `app/design/{Vendor}/{theme}/frontend/partials/footer/default.phtml`
- 兼容结构 `view/theme/frontend/partials/...` 同样有效，但同一主题只保留一份实现。
- 主题可以继承父主题或默认 Theme 的 chrome；一旦自己提供了同名 partial，它必须是全站实际消费的那一份。

## 2. 布局只允许通过 Partials 挂载

所有店面布局必须使用：

```html
<w:block class="Weline\Theme\Block\Partials" area="frontend" type="header" default-option="default" .../>
<w:block class="Weline\Theme\Block\Partials" area="frontend" type="footer" default-option="default" .../>
```

禁止：

- 写死 `Weline_Theme::theme/frontend/partials/header/default.phtml` 或 `footer/default.phtml`；
- 写死 `Weline_Frontend::templates/public/header.phtml` / `footer.phtml`；
- 在布局里 `fetch` 其他主题的 header/footer；
- 用布局私有 CSS 去「修」一个不属于本主题的 header/footer。

例外：`blank`、`test`、明确无 chrome 的嵌入片段（如 `guide/size-guide.phtml`）可以不挂 header/footer，但必须由主题文档写明用途。

## 3. 解析优先级（强契约）

`Partials::getPartialsPath()` 对 `header` / `footer` 按以下顺序解析：

1. 活动主题链（当前主题 → 父主题）中的同名 partial；
2. 活动主题配置的 partials option（ThemeData / theme config）；
3. 默认 Theme 的同名 partial（仅当活动主题链完全没有该 chrome）；
4. 模块提供的 partial（仅作最后兜底）。

布局实体（layout entity）会固化 partial 源。若固化的 header/footer 来自默认 Theme 或别的模块，而活动主题已经有自己的 header/footer，运行时必须**改绑到活动主题**，不得继续输出旧主题的 chrome。实现见 `Partials::isForeignThemeChromeSource()` / `resolveLiveThemeChromePartial()`。

## 4. 未覆写布局的页面

页面类型没有主题布局时，框架回退到模块布局是允许的；但模块布局里的 `<w:block Partials type="header|footer">` 仍按第 3 条解析，所以：

- **页头页尾仍然来自自定义主题；**
- 页面正文是否套用主题视觉，取决于主题是否为该 page type 提供布局/样式，不影响 chrome 契约。

## 5. 新主题落地清单

1. 提供 `frontend/partials/header/default.phtml` 与 `frontend/partials/footer/default.phtml`，或明确声明继承父主题/默认 Theme。
2. 所有 `frontend/layouts/**/*.phtml` 用 Partials 挂 header/footer（blank/test 除外）。
3. 跑 `vendor/bin/phpunit -c tests/phpunit/config.xml --no-coverage app/code/Weline/Theme/test/Unit/ThemeChromeLayoutContractTest.php`。
4. 跑 `vendor/bin/phpunit -c tests/phpunit/config.xml --no-coverage app/code/Weline/Theme/test/Unit/LayoutEntity/PublishedChromeSourceSelectionTest.php`。
5. 逐路由实测：header/footer 根节点必须命中主题自己的 class/data-testid；出现默认 Theme 的 `weline-header` / `weline-footer` 即失败。
6. 主题静态资源更新后按项目既有流程刷新 `pub/static` 与布局实体；不得只改源码就宣称线上生效。

## 6. 验收证据

- 源码：本契约测试通过；
- 运行时：至少覆盖首页、列表页、详情页、FAQ、指南、购物车、结算、账户、政策页；桌面 1440 与手机 375；
- 任一页面出现非当前主题的 header/footer，视为未完成，不得用「该页没有覆写布局」解释。

## 7. 跨 Host 缓存与本地预览

主题 chrome 会被多层缓存复用，必须保证输出与 Host 解耦：

- 主题生成的**站内链接**一律根相对（保留 mount path/query/fragment）；禁止把 `http://` / `https://` 站点域名写进 header/footer/商品卡/分类导航/面包屑。
- **canonical / hreflang / og:url / JSON-LD / sitemap / 邮件外链**保持绝对 URL，且使用规范站点 URL，不跟随预览别名。
- 缓存层已有 origin 维度：chrome partial、product card、homepage/blog 整页 HTML 袋（v8+）、header nav fragment；新增整页/片段缓存必须带 origin（host + website_url + base_url + visitor host）。
- READY 预热默认只预热本实例 `public_origin` 对应的注册站点 Host；本机预览实例不得用生产站点 URL 预热，否则会把生产绝对链接写进本地 FPC。
- 发布/清缓存后必须同时清 FPC HTML 与 layout HTML bag；只清 CSS/模板缓存不够。
