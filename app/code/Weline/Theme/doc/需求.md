## 当前有效需求

### `REQ-THEME-0001` 全局亮暗色与 Bootstrap 组件适配

> 自 `2.0.0` 起由 `REQ-THEME-0003` 取代。历史三态主题语义保留，Bootstrap adapter、旧变量别名和旧 UI 兼容承诺全部终止。

- 来源与确认：用户在 2026-08-10 明确确认实施计划，并确认委派代码编辑固定使用 `gpt-5.6-terra`。
- 目标版本：`1.0.8`。
- 背景/问题：设计主题的同路径 CSS/JS 会整体覆盖默认 Theme 资产；部分 Head 使用白色硬编码，导致暗色下 Card 和其他 Bootstrap 组件不能全局继承正确颜色。
- 用户与运营场景：访客和后台管理员可选择跟随系统、亮色或暗色；所有普通 Bootstrap/Weline 通用组件在任意页面自动适配，模块作者无需增加页面级暗色补丁。
- 业务逻辑：`data-theme-preference` 保存 `system|light|dark` 偏好；`data-theme`、`data-theme`、后台 `data-theme-mode/data-layout-mode` 始终保存已解析的 `light|dark`；`color-scheme` 与解析结果一致。前台使用 `weline-theme`，缺失表示 system，不固化系统解析结果；仅 system 模式响应系统颜色变化。`Weline.Theme.switch()` 兼容旧调用并支持 system，事件同时提供解析主题和偏好。
- 范围：默认 Theme 语义 Token、Bootstrap 5.1.3 组件 adapter、Bootstrap 5.3 变量前向兼容、前后台预解析、Backend 持久化和 Admin/Theme 三态入口、Weline_Default token overlay、聚焦测试与 E2E 资产。
- 非目标：不升级 Bootstrap、不增加数据库 schema/迁移、不为业务页面写专用暗色选择器、不自动同步到站点仓库。
- 数据/权限/安全：前台仅写浏览器本地偏好；后台仍使用当前用户主题配置，不引入 fetch/Ajax。服务端只接受三态，非法新写入拒绝；历史非法值回退亮色。所有可见文案走 i18n。
- 兼容/迁移：兼容旧 `light|dark` 与旧布尔配置；`system` 在旧代码上安全表现为亮色。保留旧 `--theme-*` / `--admin-*` 别名，但其唯一来源是 `Weline_Theme` 的 canonical 语义层；设计主题只能覆盖 palette/品牌 Token。
- 验收标准：主题 CSS 前完成预解析；在前后台 system/light/dark、刷新和系统变化下，Card、Modal、Offcanvas、Dropdown、Accordion、Table、List Group、表单、Nav/Tab、Pagination、Alert/Badge、Toast/Popover 及交互状态均使用语义 Token；正文对比度至少 4.5:1，边界/焦点至少 3:1。`php bin/w e2e:run --module=Weline_Theme --project=chromium` 的全部用例必须通过；历史用例若绑定已移除的业务主题资产，应迁移为该模块的稳定公开契约，不得以伪造资产或弱化断言取绿。
- WebUI/E2E：真实 WLS + 内置 Browser 测前台、Dashboard、Theme 编辑器三态切换、重载、系统变化及组件可见结果；固定 Playwright 前后台 case-id 覆盖同一主路径。
- 运营与支持影响：无新增配置或迁移；支持人员可通过三态控件恢复 light，回滚时 system 按旧实现亮色回退。
- 依赖与风险：Bootstrap 5.1.3 不消费 5.3 CSS 变量，必须保留直接 adapter；资产加载顺序无法证明时不得删除设计主题覆盖。

### `REQ-THEME-0002` Head 币种上下文单一来源

- 来源与确认：2026-08-17 商城验收发现服务端网站币种与 Head 的 `user.currency` 硬编码回退可能分裂，用户同意按核心币种契约修复。
- 业务逻辑：前端 `WelineApiConfig`、`__WelineThemeConfig` 的当前币种必须直接使用 `State::getCurrency()`，不得在 Head 再实现一套用户币种或 CNY 回退规则。
- 范围：默认 Theme Head 与契约测试；设计主题覆盖必须遵循同一规则。
- 非目标：不改变默认币种配置、可用币种列表或支付方式。
- 验收标准：服务端页面、QueryBin API 上下文和浏览器 Theme 配置报告同一当前币种。

### `REQ-THEME-0003` Weline UI 2.0 自研主题与组件体系

- 来源与确认：用户于 2026-08-21 批准完整实施计划，并明确要求所有通用第三方 CSS/JS 转为自研、旧接口零兼容。
- 目标版本：`2.0.0`。
- 背景/问题：后台重复加载 Bootstrap，通用 CSS 约 `1.09 MB raw / 166 KB gzip`；通用 UI、图标和插件资源分散、重复且大部分页面未使用。
- 用户与运营场景：框架维护者使用一套小型、可组合、可审计的主题标准；后台获得完整组件集，前台只加载共享 token、布局原语和当前路由组件。
- 业务逻辑：公共 CSS 仅使用 `w-*` 与固定 `@layer`；主题根属性为 `data-w-area`、`data-theme-preference`、`data-theme`。交互只经 `Weline.UI` 和 `data-w-component/action/target`，组件按根节点幂等挂载并支持动态片段卸载。
- 范围：原生 CSS/ES Module、token、布局、批准的组件矩阵、焦点/浮层原语、显式资源清单、确定性编译、审计命令、本地 SVG 图标注册表与 `<w:icon>`、Theme 组件展示和真实路径验收。
- 非目标：复制第三方组件的完整 API；支持旧浏览器；引入 Node/Tailwind/Sass/CDN/外部字体；自动同步站点仓库或发版。
- 数据/权限/安全：消息默认 `textContent`；富内容只接受可信 `Node/Element`；不新增业务请求通道。旧图标类值只做一次性幂等迁移，不在运行时解析。
- 兼容/迁移：不提供 Bootstrap、jQuery、Vue、RequireJS、旧 UI class、旧全局对象、字体图标或旧变量别名兼容。迁移以路由为原子单位，同一路由不得同时加载新旧 UI，最终切版前必须达到零引用。
- 专用引擎边界：仅允许 TinyMCE、CKEditor、Editor.js、Swagger UI、Prism、Marked、ApexCharts、Chart.js、FullCalendar、pdfmake、JSZip、Dropzone；必须由所属模块路由级加载且不得依赖禁用基础库。
- 验收标准：审计零禁用引用；后台全局 CSS `≤55 KB gzip`、前台 foundation `≤25 KB gzip`、首屏 UI JS `≤35 KB gzip`、单懒加载组件 `≤8 KB gzip`、后台全局 CSS+JS `≤90 KB gzip`、每区域全局 UI 请求 `≤3`。
- WebUI/E2E：唯一 WLS 实例使用可用端口 `>=9502`；内置 Browser 覆盖登录、Dashboard、Theme 编辑器、用户、菜单、DataTable、FileManager、SystemConfig、前台首页和前台 DataTable，并检查三态、375/768/1024/1440、键盘、焦点、控制台和网络资源。
- 运营与支持影响：这是破坏性升级；模块模板必须改用新组件和 Taglib，出现旧资源即构建失败。回退使用任务级反向补丁和数据快照，不提供运行时开关。
- 依赖与风险：跨模块模板量大；专用引擎若无法脱离禁用基础库，其迁移批次必须在删除前停止并改用自研最小能力或允许的独立引擎。
