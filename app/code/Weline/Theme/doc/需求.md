## 当前有效需求

### `REQ-THEME-0012` 空 slot 不因刷新/渲染自动回填默认部件

- 来源与确认：2026-08-25 用户确认：主题编辑器删除部件后，哪怕 slot 为空，刷新也不得自动补回；`default_injections` 只用于主题初始化，或用户点击 slot 初始化 /「应用」tab 显式应用。插槽默认工具条需提供「初始化」入口。
- 业务逻辑：打开/刷新 Theme Editor、slot/预览布局渲染路径禁止调用 `applyMissingForLayout` / `applyMissingForAllPageTypes`。默认写入仅允许：主题初始化/种子、草稿重置恢复默认、部件首次入库、`Dashboard layout_identity_ready`、部件库「应用」tab / 显式 slot 初始化（`init-slot-defaults`）。删除后写 `user_deleted` 仍保留；空布局保持空，只渲染模板 slot。
- 范围：`ThemeEditor::index`、`SlotRendererService::getLayoutData`、相关契约测试与 Widget/Theme 文档。
- 验收标准：删除默认部件后刷新编辑器，该部件不会写回布局；空 slot 可保持为空；「应用」tab 仍可手动恢复。

### `REQ-THEME-0011` 激活前台主题后网站首页接到 layouts/homepage

- 来源与确认：2026-08-25 用户要求 Theme 模块一旦激活主题，就必须把网站首页接到 Theme 的首页布局上。
- 业务逻辑：激活 frontend（或全局）主题成功后，为该主题种子 `homepage` 默认布局（不覆盖已有 draft/published）；`FrontendLayoutProvider` 暴露 `homepage` → `layouts/homepage/default.phtml`。站点根路径由 `Weline_Index` 在检测到激活前台主题时设置 `layoutType=homepage`，经 `ControllerFetchFileBefore` 渲染 Theme 首页布局；无激活主题时回退官方 `Index.phtml`。不强制改写站点自定义 `start_page_path`。
- 范围：`ThemeContextService::activateThemeForArea`、`FrontendLayoutProvider`、`Weline_Index` Index 控制器与 shell。
- 验收标准：有激活前台主题时 `/`（映射到 `index/index`）HTML 含 `theme-layout-homepage` / `homepage-main`；无主题时仍为官方 Index 页。

### `REQ-THEME-0010` 店面商品无图统一 SVG 占位标准

- 来源与确认：2026-08-25 用户要求所有前端商品图位「没有图就用 SVG 占位」，并与主题统一标准。
- 业务逻辑：`Weline\Theme\Helper\StorefrontImagePlaceholder` 为唯一占位入口；空 URL / 任何 `data:image/*` / 已知失效远程图一律改为**一份**本地静态 SVG 的普通 `src`（`images/storefront-placeholder/default.svg`）。**禁止** `data:image/svg+xml;charset=…` 媒体直出。模板用 `data-storefront-img` + `data-fallback`；`storefront-image-fallback.js` 全局绑定破图切换。
- 范围：Theme Helper/JS/hook、Product 相关/推荐/分类/目录/详情图位、Theme 相关/最近浏览演示占位。
- 验收标准：无图或失效图不露出浏览器破图红字；各商品位视觉为统一渐变 SVG 占位。


### `REQ-THEME-0008` 商品详情主信息槽仅留占位由应用注入部件

- 来源与确认：2026-08-25 用户要求 Theme 详情页产品主要信息做成部件；布局只留 slot 与预览占位；Product 经 `default_injections` 注入。
- 业务逻辑：`product` 布局 `product-main` 仅保留预览占位（FCDC/标题/SKU 示意），禁止内嵌 `w:widget`，也不再用 `contentTemplate` 渲染产品主信息；主信息由 `Weline_Product` `product-info` 默认注入。
- 范围：`layouts/product/default.phtml`、DefaultLayoutSeeder、契约测试。
- 验收标准：布局含 `product-main` 预览占位；源码无 `contentTemplate` 与内嵌 `product-info` 部件标签。

### `REQ-THEME-0007` 主题 CSS/PHTML 禁止硬编码颜色与尺寸

- 来源与确认：用户于 2026-08-24 明确要求框架主题禁止在 `.phtml` / 业务 CSS 中直接写颜色、字号、间距等视觉字面量，必须使用主题变量色盘；并要求在 Theme 模块文档内固化，随后扫描默认主题列出待 Token 化文件。
- 业务逻辑：默认主题与设计主题的源 CSS、以及模板内嵌 `<style>` / 行内 `style`，颜色与尺寸等视觉值只能来自 `variables/**`、`colors/**` 及语义 Token（如 `var(--w-*)`）；禁止 `#hex`/`rgb()`/`px`/`rem` 等私写字面量，也禁止 `var(--token, 字面量)` fallback。**提取变量必须同次写入色盘/变量盘叶子默认值**（颜色进 `_colors.css` + 必要时 `_light`/`_dark`）；禁止只改引用、把颜色丢进 `_auto-literals.css` 导致 Editor/页面表现为未设置。
- 范围：Theme 模块强约束文档、需求登记；默认主题 `view/theme/{frontend,backend}` 业务 CSS/PHTML 硬编码改为 Token（叶子值仅保留在 `variables/**`、`colors/**`）。
- 非目标：不改 `generated/`；不把业务模块私有皮肤当作例外；不在本需求内强制升级 Rules/CLI 门禁。
- 验收标准：强约束与审计文档可检索；默认主题业务侧复扫 `hard_color`/`hard_size`/`var_fallback` 均为 0（排除 variables/colors、注释与 data-URL）；新增颜色 Token 在 `_colors.css`（或 `colors/**`）有非空叶子，且不在 `_auto-literals.css`。

### `REQ-THEME-0006` 模块业务路由归属与 product 内容回退

- 来源与确认：2026-08-22 规范仓评论验收发现 Theme fallback 提前消费 `/products`、`/product/{id}`，且 product 布局未渲染 Controller 提供的 `contentTemplate`；用户要求缺少即修复。
- 业务逻辑：已安装 Product 模块拥有商品目录和数值商品详情别名；Theme 只在模块路由未拥有路径时提供公共页面 fallback。商品详情主信息自 `REQ-THEME-0008` 起改由 Product `product-info` 经 `default_injections` 注入 `product-main`，不再依赖布局渲染 `contentTemplate`。
- 范围：Theme 前台 Router、product 默认布局及聚焦契约测试。
- 非目标：不改变 Product 查询、商品数据或 PageBuilder 路由。
- 验收标准：`/products` 与 `/product/{id}` 进入 Product Controller；商品详情保留完整 Theme 壳层并显示产品内容、Review BinQuery 与前端运行时。

### `REQ-THEME-0005` 前端 section 使用稳定语义 weline-code

- 来源与确认：2026-08-22 完整前端规范检查发现 loading 组件仍使用非语义 `section_1`；用户要求缺少即修复。
- 业务逻辑：所有前端字面 `<section>` 必须拥有非空、稳定、可定位的语义 `weline-code`；通用组件使用 `theme.component.{name}`，不得使用纯序号占位。
- 范围：loading 源模板的标识修复及全量 `frontend:check-section-code` 验证。
- 非目标：不改组件结构、样式或交互，不编辑编译产物。
- 验收标准：规范检查通过且 loading 组件使用 `theme.component.loading`。

### `REQ-THEME-0001` 全局亮暗色与 Bootstrap 组件适配

> 自 `2.0.0` 起由 `REQ-THEME-0003` 取代。历史三态主题语义保留，Bootstrap adapter、旧变量别名和旧 UI 兼容承诺全部终止。

- 来源与确认：用户在 2026-08-10 明确确认实施计划，并确认委派代码编辑固定使用 `gpt-5.6-terra`。
- 目标版本：`1.0.8`。
- 背景/问题：设计主题的同路径 CSS/JS 会整体覆盖默认 Theme 资产；部分 Head 使用白色硬编码，导致暗色下 Card 和其他 Bootstrap 组件不能全局继承正确颜色。
- 用户与运营场景：访客和后台管理员可选择跟随系统、亮色或暗色；所有普通 Bootstrap/Weline 通用组件在任意页面自动适配，模块作者无需增加页面级暗色补丁。
- 业务逻辑：`data-theme-preference` 保存 `system|light|dark` 偏好；`data-theme`、`data-theme`、后台 `data-theme-mode/data-layout-mode` 始终保存已解析的 `light|dark`；`color-scheme` 与解析结果一致。前台使用 `weline-theme`，缺失表示 system，不固化系统解析结果；仅 system 模式响应系统颜色变化。`Weline.Theme.switch()` 兼容旧调用并支持 system，事件同时提供解析主题和偏好。
- 范围：默认 Theme 语义 Token、Bootstrap 5.1.3 组件 adapter、Bootstrap 5.3 变量前向兼容、前后台预解析、Backend 持久化和 Admin/Theme 三态入口、Weline_Default token overlay、聚焦测试与 E2E 资产。
- 非目标：不升级 Bootstrap、不增加数据库 schema/迁移、不为业务页面写专用暗色选择器、不自动同步到站点仓库。
- 数据/权限/安全：前台仅写浏览器本地偏好；后台仍使用当前用户主题配置，不引入 fetch/Ajax。服务端只接受三态，非法新写入拒绝；历史非法值回退亮色。所有可见文案走 i18n。
- 兼容/迁移：兼容旧 `light|dark` 与旧布尔配置；`system` 在旧代码上安全表现为亮色。保留旧 `--theme-*` / `--admin-*` 别名，但其唯一来源是 `Weline_Theme` 的 canonical 语义层；设计主题只能覆盖 palette/品牌 Token。
- 验收标准：主题 CSS 前完成预解析；在前后台 system/light/dark、刷新和系统变化下，Card、Modal、Offcanvas、Dropdown、Accordion、Table、List Group、表单、Nav/Tab、Pagination、Alert/Badge、Toast/Popover 及交互状态均使用语义 Token；正文对比度至少 4.5:1，边界/焦点至少 3:1。`php bin/w e2e:run --module=Weline_Theme --project=chromium` 的全部用例必须通过；历史用例若绑定已移除的业务主题资产，应迁移为该模块的稳定公开契约，不得以伪造资产或弱化断言取绿。
- WebUI/E2E：真实 WLS + 内置 Browser 测前台、Dashboard、Theme 编辑器三态切换、重载、系统变化及组件可见结果；固定 Playwright 前后台 case-id 覆盖同一主路径。
- 运营与支持影响：无新增配置或迁移；支持人员可通过三态控件恢复 light，回滚时 system 按旧实现亮色回退。
- 依赖与风险：Bootstrap 5.1.3 不消费 5.3 CSS 变量，必须保留直接 adapter；资产加载顺序无法证明时不得删除设计主题覆盖。

### `REQ-THEME-0002` Head 币种上下文单一来源

- 来源与确认：2026-08-17 商城验收发现服务端网站币种与 Head 的 `user.currency` 硬编码回退可能分裂，用户同意按核心币种契约修复。
- 业务逻辑：前端 `WelineApiConfig`、`__WelineThemeConfig` 的当前币种必须直接使用 `State::getCurrency()`，不得在 Head 再实现一套用户币种或 CNY 回退规则。
- 范围：默认 Theme Head 与契约测试；设计主题覆盖必须遵循同一规则。
- 非目标：不改变默认币种配置、可用币种列表或支付方式。
- 验收标准：服务端页面、QueryBin API 上下文和浏览器 Theme 配置报告同一当前币种。

### `REQ-THEME-0003` Weline UI 2.0 自研主题与组件体系

- 来源与确认：用户于 2026-08-21 批准完整实施计划，并明确要求所有通用第三方 CSS/JS 转为自研、旧接口零兼容。
- 输入控件补充确认：用户于 2026-08-22 确认将自研主题输入控件的容器自适应规则补入本需求并实施。
- 输入控件宽度契约：原生 `input`、`select`、`textarea` 必须以包含块宽度为上限，并可在 flex/grid/modal 中收缩；`.w-input`、`.w-select`、`.w-textarea` 继续填满可用宽度。checkbox、radio、button、submit 等固有尺寸控件不得被公共规则拉伸。
- 输入控件验收：常规表单与 modal 中的长 placeholder/value 不得顶破容器；375px 视口不得因表单控件产生水平滚动；checkbox、radio、button 的尺寸与布局无回归。
- 目标版本：`2.0.0`。
- 背景/问题：后台重复加载 Bootstrap，通用 CSS 约 `1.09 MB raw / 166 KB gzip`；通用 UI、图标和插件资源分散、重复且大部分页面未使用。
- 用户与运营场景：框架维护者使用一套小型、可组合、可审计的主题标准；后台获得完整组件集，前台只加载共享 token、布局原语和当前路由组件。
- 业务逻辑：公共 CSS 仅使用 `w-*` 与固定 `@layer`；主题根属性为 `data-w-area`、`data-theme-preference`、`data-theme`。交互只经 `Weline.UI` 和 `data-w-component/action/target`，组件按根节点幂等挂载并支持动态片段卸载。浮层默认以触发元素为稳定锚点，只有明确的上下文菜单才可使用指针锚点；相同布局输入必须产生相同位置。共享内核负责 visual viewport、safe area、自动翻转/限界、可用尺寸、滚动/缩放/旋转重排、嵌套 portal 逻辑父子关系和顶层 Escape，调用方不得手算坐标或复制移动断点。`hidden` 是不可被组件 `display` 覆盖的状态契约，mount/unmount 不得重复绑定。
- 范围：原生 CSS/ES Module、token、布局、批准的组件矩阵、焦点/浮层原语、显式资源清单、确定性编译、审计命令、本地 SVG 图标注册表与 `<w:icon>`、Theme 组件展示和真实路径验收。对 Theme 可视化编辑器等已有产品面，迁移只替换通用 UI 依赖与呈现外壳，必须以迁移前完整能力清单逐项等价保留业务功能、数据契约、状态与用户路径；拖拽、富文本、图表、文档等重写成本接近独立项目的功能引擎不属于“自研 UI 组件”范围。
- 非目标：复制第三方组件的完整 API；精简、删除或降级现有业务功能；将完整主题编辑器替换为薄壳或演示页；支持旧浏览器；引入 Node/Tailwind/Sass/CDN/外部字体；自动同步站点仓库或发版。
- 数据/权限/安全：消息默认 `textContent`；富内容只接受可信 `Node/Element`；不新增业务请求通道。旧图标类值只做一次性幂等迁移，不在运行时解析。
- 兼容/迁移：不提供 Bootstrap、jQuery、Vue、RequireJS、旧 UI class、旧全局对象、字体图标或旧变量别名兼容。迁移以路由为原子单位，同一路由不得同时加载新旧 UI，最终切版前必须达到零引用。
- 专用引擎边界：TinyMCE、CKEditor、Editor.js、Swagger UI、Prism、Marked、ApexCharts、Chart.js、FullCalendar、pdfmake、JSZip、Dropzone，以及经能力成本评估确认应保留的拖拽/排序等功能引擎，均可作为无皮肤或弱 UI 的专用能力保留。每个引擎必须有模块 owner、适配器、路由级清单和能力回归；不得接管全局主题、不得全局暴露、不得携带通用 UI CSS，也不得依赖 Bootstrap/jQuery 等禁用基础库。
- 验收标准：审计零禁用引用；后台全局 CSS `≤55 KB gzip`、前台 foundation `≤25 KB gzip`、首屏 UI JS `≤35 KB gzip`、单懒加载组件 `≤8 KB gzip`、后台全局 CSS+JS `≤90 KB gzip`、每区域全局 UI 请求 `≤3`。所有 menu/popover/tooltip/combobox/`anchored-float` 等浮层在同一锚点连续开关时不得漂移，必须被 visual viewport、safe area 和设定 padding 完整包含；手机端不得横向溢出，关闭、Esc、外部点击与刷新初始态必须一致；嵌套子层点击不得误关父层，单次 Escape 只能关闭最上层，抽屉滚动不得因浮层而失效。Theme 可视化编辑器预览内部件操作条必须经 `anchored-float` 贴边展示，不得手写坐标；必须通过迁移前/迁移后能力矩阵和真实 WebUI 路径证明无功能损失；可视化拖拽必须稳定显示 inside/before/after，跨 iframe 原生 drop 缺失时仍按同一 session 的最新有效候选只插入一次，拖出、Escape、切换视图或刷新不得误插入，结构视图与可视化视图必须复用相同 slot 接纳和保存契约。
- WebUI/E2E：唯一 WLS 实例使用可用端口 `>=9502`；内置 Browser 覆盖登录、Dashboard、Theme 编辑器、用户、菜单、DataTable、FileManager、SystemConfig、前台首页和前台 DataTable，并检查三态、375/768/1024/1440、键盘、焦点、控制台和网络资源。
- 运营与支持影响：这是破坏性升级；模块模板必须改用新组件和 Taglib，出现旧资源即构建失败。回退使用任务级反向补丁和数据快照，不提供运行时开关。
- 依赖与风险：跨模块模板量大；专用引擎若无法脱离禁用基础库，其迁移批次必须在删除前停止并改用自研最小能力或允许的独立引擎。

### `REQ-THEME-0004` Theme Editor Scope 驱动的逐值继承与局部覆盖

- 来源与确认：用户于 2026-08-22 将原“网站/店铺 Scope 隔离保存”升级为已确认的框架级计划，并进一步确认 Channel 也可换 Theme/改配置：Scope 是编辑器最高级上下文，每层仅拥有实际修改路径。
- CMS/FileAsset 补充确认：同日用户确认 CMS 编辑上下文以 Website 下的 Store+Locale 为变体身份，`locale_code` 独立于三段 Scope；CMS bridge 升级为 `weline.cms-theme-editor.v2`，Theme 只经公共变体接口读写，并由 FileManager 内容验证器校验类型化 `file-image` 节点。
- 目标版本：`2.1.1`（`2.1.0` 数据模型之上补充布局 identity hash 的幂等迁移）。
- 用户与运营场景：管理员可在 Global、Website、Store 或 Channel 上修改 Theme 绑定、布局、部件、Meta、外观和语言资源；本级未修改值持续跟随直接父级，已修改值明确标记本级所有。
- 固定依赖：`Scope → 编辑区域 → Theme → 布局类型 → 布局选项 → Language`。切换 Scope 先完成待提交增量，失败则留在原上下文；成功后释放旧锁、清空版本/前端缓存并使用服务端规范 Scope 整体重载。
- 继承语义：当前层不存在 Patch 是继承的唯一含义，不复制父值、不存 `is_inherit`。空字符串、`0`、`false` 和显式 `null` 都是合法自有值；恢复继承通过 `inherit` 删除本级 Patch。
- 版本与合并：Theme 选择本身是可继承绑定，草稿不影响前台，发布后才产生不可变 Release。父级未覆盖路径自动流入子级；子级标量覆盖继续优先；父级删除被子级修改的节点/锚点产生结构冲突。任一父级发布不被后代冲突阻断，冲突 Store/Channel 继续服务上一个有效 Release。
- 数据与兼容：新 `theme_scope_workspace/revision/patch/release` 是 Scope 继承权威来源；现有 ThemeLayout/Version/VirtualLayout/Meta/I18n 继续由各模块拥有，仅通过 Adapter 作兼容投影。布局用稳定 `node_uid` 合并，原始模板源码不做逐行合并。
- 上下文与安全：Theme UI 开放 Global/Website/Store/Channel 四级。`target_type/target_id` 与这四级 Scope 正交，禁止混用。新写入只接受 typed `editor_context.scope`、`expected_revision`、`expected_parent_release_id` 和 `changes[]`；运行时禁止读取 Session、草稿或请求参数。
- 输入宽度契约：Theme 自研文本控件使用 `box-sizing:border-box; min-inline-size:0; max-inline-size:100%`，块级输入填满可用宽度；flex/grid 父项同步允许收缩，复合字段窄宽度换行。Modal/Drawer/Popover/工具栏溢出菜单同时受容器与视口限制，不得用隐藏横向溢出掩盖缺陷；checkbox/radio/color 保留固有尺寸。
- 迁移：先只读预检 Scope 冲突、重复身份和歧义节点，再双读、语义差异回填、切换 canonical writes。`website.default.__store__` 转为 `website.__store__.default`；歧义子树整体保留为本级覆盖并记录告警，不删除旧数据。
- 非目标：不把业务 target 写入 Scope，不清理旧表，不自动分发消费站点。
- 验收标准：聚焦测试覆盖 Scope 往返、显式空值、恢复继承、稳定 UID、乐观并发、父子合并/冲突、迁移幂等和缓存失效；真实 WLS + 内置 Browser 完成 Website/Store 继承、局部覆盖、父级再发布、结构冲突、恢复继承和草稿/发布隔离；在 320/375/768/1280px 及 200% 缩放下任一字段不超过最近容器。
