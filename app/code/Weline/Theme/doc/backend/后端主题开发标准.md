# 后端默认主题开发标准（Backend Theme Standard）

> 状态：**现行**（2026-10-21 起）
> 归属：`Weline_Theme` / `view/theme/backend` + `view/ui/css`（后端 area）
> 适用：后台默认主题（`Weline_Theme` 下的 `backend` area）、后台布局、片段、组件类、
> 以及**所有模块的后台页面模板**（`app/code/*/*/view/templates/backend/**`）。
>
> 本文是后端 UI 的唯一开发标准。与旧文档冲突时以本文为准；与全局硬规则冲突时以
> `app/code/Weline/Ai/doc/AI硬规则索引.md` 与 MCP `hard_constraints` 为准。

---

## 0. 一句话标准

后台页面只允许由 **一套壳层（layout）+ 一套语义类（`w-*`）+ 一套 Token** 组成；
禁止页面自带风格壳、内联视觉字面量、同步阻塞脚本和 `!important` 抢样式。

---

## 1. 分层与目录（只改默认主题）

| 层 | 位置 | 职责 | 禁止 |
|---|---|---|---|
| Layout | `view/theme/backend/layouts/<layoutType>/<option>.phtml` | 页面骨架、区域、hook/block/partial 挂载 | 业务查询、内联样式、跨模块 widget |
| Partial | `view/theme/backend/partials/<type>/<option>.phtml` | head/topbar/sidebar/content/breadcrumb 等 chrome | 完整业务流程、私有布局 |
| Component | `view/theme/backend/components/*.phtml` | 可视化编辑器的可拖拽原语 | 页面业务内容 |
| Token | `view/theme/backend/variables/_*.css`、`colors/_*.css` | 唯一视觉来源（叶子值） | 被页面/组件绕过 |
| Area CSS | `view/ui/css/foundation.css`、`view/ui/css/backend.css` | 全站原语与后端壳层机制 | 品牌皮肤、页面级特例 |
| Theme CSS | `view/theme/backend/assets/css/theme.css` | 后端主题桥接 + 旧类兼容层 | 第二套组件库、`!important` |
| Module page | `app/code/<Vendor>/<Module>/view/templates/backend/**` | 业务页面内容 | `<style>` 视觉壳、内联 `style`、同步脚本 |

**只修改默认主题**：后台只有 `Weline_Theme` 默认主题；不得新增/修改 `app/design` 下的后台皮肤，
不得改其它模块的 Theme 私有 CSS 来“补”默认主题。业务模块页面只消费默认主题的类与 Token。

### 1.1 构建关系（必须记住）

```
view/ui/css/foundation.css  ─┐
view/ui/css/backend.css     ─┼─ resource:compile welineUi ─→ view/statics/ui/weline-*.css
view/theme/backend/variables/*.css + colors/*.css + assets/css/theme.css
                              └─ ThemeHeadChromeCssPack PACK_BACKEND ─→ 单个 head <link>
```

- 源文件是 `view/ui/css/*.css`；`view/statics/ui/weline-*.css` 是**编译产物**。
  改源后必须执行 `php bin/w resource:compile welineUi`，否则页面仍读旧产物。
- 改布局/片段/Token 后执行 `php bin/w theme:upgrade`（或按 `-t/-l/-o` 局部升级），
  再刷新页面验证；禁止手改 `generated/`。

## 2. Token 与字体

### 2.1 唯一视觉来源

- 颜色：`--weline-theme-*`（语义）→ `--backend-theme-*`（后端桥接）→ `--backend-color-*`（兼容别名）。
- 间距：`--weline-space-1…12`（8pt 基线）；圆角：`--weline-radius-sm|md|lg|round`；
  控件高：`--weline-control-height-sm|--weline-control-height|lg`；
  字号：`--weline-font-size-xs|sm|md|lg|xl`。
- 新增叶子：颜色进 `variables/_colors.css` + `colors/_default.css`（含 `_light`/`_dark` 差异），
  间距/字号/边框/阴影进对应 `variables/_*.css`；不得只写 `var(--x)` 不落盘。

### 2.2 后端字体（硬）

后台是**工作界面**，正文与标题统一无衬线（sans）。衬线/楷体只允许出现在前台品牌主题。

```css
/* 允许：后端 area 作用域，不动前台 */
[data-w-area="backend"] {
  --weline-font-sans: "Noto Sans SC", -apple-system, BlinkMacSystemFont, "Segoe UI",
    "PingFang SC", "Microsoft YaHei", Arial, sans-serif;
  --weline-font-ui: var(--weline-font-sans);
  --weline-font-display: var(--weline-font-sans);
  font-family: var(--weline-font-sans);
}
```

禁止把 `--weline-font-sans` 的全局 `:root` 值改成宋体（会污染后台）；
`foundation.css` 的全局字体栈保持前台语义，后台差异只在 backend 作用域覆盖。

### 2.3 禁止（默认层）

- `#hex` / `rgb()` / `hsl()` / 命名色；裸 `px`/`rem` 用作字号、间距、圆角、阴影、控件高。
- `var(--x, #fff)` / `var(--x, 16px)` 这类字面量 fallback（收敛为纯 Token）。
- `!important`（唯一例外：`[hidden] { display: none !important }` 与
  `prefers-reduced-motion` 内动画缩短）。
- 页面模板里的 `<style>` 视觉块与 `style="..."`（布局百分比/`--w-*` 变量接线除外，
  且不得出现颜色、字号、间距字面量）。

## 3. 页面骨架（所有后台页面统一）

```html
<main class="w-backend-page" id="main-content" data-layout="main_content">
  <header class="w-backend-page__heading">
    <div class="w-backend-page__title">
      <h1>页面标题</h1>
      <p class="w-backend-page__subtitle">一句话说明</p>
    </div>
    <div class="w-backend-page__actions"><!-- 主操作 ≤1 --></div>
  </header>
  <nav aria-label="面包屑" class="w-backend-page__breadcrumb">…</nav>

  <section class="w-card">
    <header class="w-card__header">
      <h2 class="w-card__title">区块标题</h2>
      <div class="w-card__actions"><!-- 次操作 --></div>
    </header>
    <div class="w-card__body">
      <div class="w-toolbar"><!-- 搜索/筛选/批量 --></div>
      <div class="w-table-wrap"><table class="w-table">…</table></div>
      <nav class="w-pagination">…</nav>
    </div>
  </section>
</main>
```

规则：

1. **一屏一个第一视线**：页面标题或主数据区；主按钮每屏 ≤1 个 `data-tone="primary"`。
2. 页面标题由 `partials/layout/main-content.phtml` 统一输出；业务模板**不得再写第二个 h1**。
3. 工具栏、表格、空态、错误态、加载态必须齐全（见 §5）。
4. 页面内容宽度交给 `.w-backend-main`；业务模板禁止再写 `max-width`/`padding-inline` 私有容器。
5. 面包屑由页面头解析器统一输出；模板不重复渲染。
6. 响应式：375 / 768 / 1280 三档无横向滚动；表格可横滑或转卡片；触控目标 ≥44px。

## 4. 组件与语义类（消费清单）

| 场景 | 标准写法 | 关键约束 |
|---|---|---|
| 主/次/危险按钮 | `.w-button[data-tone="primary\|success\|warning\|danger\|neutral"][data-variant="solid\|outline\|quiet"]` | 主按钮 ≤1；只写图标时加 `aria-label` |
| 卡片 | `.w-card` + `.w-card__header/__title/__body/__footer` | 不嵌套卡片；用间距分组 |
| 表格 | `.w-table-wrap > table.w-table` | 行高一致；操作列右对齐；空态用 `.w-empty` |
| 表单 | `.w-field` + `.w-field__label/__control/__hint/__error`；控件 `.w-input/.w-select/.w-textarea/.w-check` | label 必须绑定；错误态必须可读 |
| 状态 | `.w-badge[data-w-background="success\|warning\|danger\|muted\|info"]` 或 `.w-alert[data-tone]` | 语义与颜色一致，禁止全靠灰色 |
| 标签页 | `.w-tabs` + `[data-w-component="tabs"]` | 不用 Bootstrap `nav-tabs` |
| 弹层 | `Weline.UI.dialog` / `.w-dialog__surface`；抽屉 `.w-drawer` | 禁止原生 alert/confirm/prompt |
| 浮层 | `data-w-component="menu\|dropdown"` + `UI.floating` | 禁止手写 `left/top` |
| 分页 | `.w-pagination`（空文件须补实现或删除） | 不用 Bootstrap pagination |
| 空态 | `.w-empty`（原因 + 下一步动作） | 禁止“暂无数据”孤零零一句 |
| 加载 | `.w-skeleton` / `.w-spinner` | 不用整屏 spinner 遮住布局 |
| 文本 | `.w-text[data-tone="muted\|danger"][data-size="sm"]` | 不写行内颜色 |
| 分栏（工具页） | `.w-split[data-split="start\|end"]` + `.w-split__aside/__main` | 仅工具页；≤64rem 自动单列 |
| 日志 / 审计视图 | `.w-log` > `.w-log__line`（`__time` / `__level[data-tone]` / `__message`） | 等宽、级别语义色、行 hover；不做整屏遮罩 |
| 终端容器 | `.w-terminal` + `.w-terminal__toolbar/__surface` | 只给尺寸/内边距/配色，内部由 xterm 等自绘 |
| 状态灯 | `.w-status-dot[data-tone="success\|warning\|danger\|info"][data-size]` | 只表达状态，不替代可读文字 |

> 旧类 `.btn / .card / .form-control / .page-title-box / .box / .table-responsive / .nav-tabs`
> 只在 `theme.css` 的**兼容层**里映射到上述 Token；新模板禁止再写旧类。

## 5. 状态完整性（比“好看”更影响信任）

每个交互面必须实现：默认 / hover / focus / active / disabled / loading / empty / error / success。

- 空态：说明为什么空 + 一个可执行动作。
- 错误态：原因 + 出口（重试 / 返回 / 联系）。
- 加载态：骨架或局部 busy，不遮整页。
- 禁用态：说明原因（tooltip 或辅助文字）。
- 所有可聚焦控件有可见 focus ring（`--weline-theme-focus` / `--backend-focus-ring`）。

## 6. 异步与资源加载（硬）

### 6.1 脚本

- 后台 head 只允许 **一个启动桩 + defer 核心脚本**（`Weline_Backend::view/blocks/header/base.phtml`）：
  启动桩把 `Weline.declare/load/mount/dom.observe` 排进 `Weline.__bootQueue`，
  核心脚本全部 `defer`，按声明顺序执行；body 内联脚本的早期调用由队列回放。
- 页面/模块脚本：在模块 `view/statics/backend/weline.modules.js` 登记，
  用 `Weline.declare(...)` / `data-weline-load` 按需加载；禁止 `<script src>` 直拉业务模块脚本。
- 页面模板禁止内联 `<script>` 业务逻辑；确需页面初始化时，写进模块 JS 并由
  `data-weline-load` 声明。编辑器/特殊页（Theme Editor）例外必须注释原因并走 module 加载。
- 禁止 `fetch` / `XHR` / `$.ajax` / `axios`；站内请求走 `Weline.Api.*`。
- 改登记后执行 `php bin/w resource:compile welineModules`。

### 6.2 样式

- 后台 CSS 由 `ThemeHeadChromeCssPack::PACK_BACKEND` 一次输出，**必须保持阻塞**（防 FOUC）；
  禁止 `media="print" onload` 之类延迟首屏样式。
- 页面模板不得引入第三方/临时 `<link rel="stylesheet">`。**唯一例外：模块页面私有布局 CSS**
  （`<link rel="stylesheet" href="@static(<Module>::css/backend/<page>.css)">`），且必须同时满足：

  1. 只承载**页面私有布局/尺寸/定位**（表格列宽、缩略图尺寸、分栏、编辑区高度），
     不得重新实现 `.w-button/.w-card/.w-table/.w-field/.w-badge` 等 §4 通用组件外观；
  2. 只消费主题 Token（禁止 `#hex` / `rgb()` / `hsl()` / 命名色 / 裸字号）；
  3. 禁止 `!important`；规则包在 `@layer page { … }` 内，避免压过 foundation components 层；
  4. 文件名与页面一一对应（如 `css/backend/order-admin.css`），新增/修改需在交付说明登记；
  5. 模块静态 CSS 改动后必须随 `php bin/w deploy:upgrade` 发布到 `pub/static`，否则页面读旧文件。

  通用模式（多个模块都要用）必须上升为默认主题原语（`view/ui/css/backend.css`），不得复制到各模块。
- **§12 已登记工具页**允许其内部配色字面量暂存于模块私有 backend CSS（如 WLS 控制台深色面板），
  但必须：① 在 [`工具页迁移清单.md`](./工具页迁移清单.md) 登记「待 token 化」；② 仍禁止 `!important`；
  ③ 后续批次必须把颜色收敛为模块私有 Token（`--wls-*`）。未登记的工具页按普通模块页处理（Token-only）。

## 7. 旧类 → 标准映射（迁移用）

| 旧写法 | 新写法 |
|---|---|
| `page-title-box` + `h4` | `.w-backend-page__heading` + `h1` |
| `card` / `card-body` / `card-header` | `.w-card` / `.w-card__body` / `.w-card__header` |
| `btn btn-primary` / `btn-outline-*` | `.w-button[data-tone="primary"]` / `[data-variant="outline"]` |
| `form-control` / `form-select` | `.w-input` / `.w-select` |
| `table table-hover` / `table-responsive` | `.w-table` / `.w-table-wrap` |
| `badge bg-success` | `.w-badge[data-w-background="success"]` |
| `alert alert-warning` | `.w-alert[data-tone="warning"]` |
| `nav nav-tabs` | `.w-tabs` + `data-w-component="tabs"` |
| `row` / `col-md-*` | `.w-grid` / `.w-stack` / `.w-cluster` |
| 行内 `style="color:#..."` | `.w-text[data-tone]` 或主题类 |
| 行内 `style="margin/padding:12px"` | `.w-stack` / `--w-*` 接线或主题工具类 |
| `!important` 抢样式 | 提高选择器特异性或补 Token 叶子 |

迁移顺序：先删页面 `<style>` 里的视觉字面量与 `!important` → 再替换旧类 → 最后删空壳类。

## 8. 验收与门禁

### 8.1 必跑

```bash
php bin/w resource:compile welineUi          # 改了 view/ui/css
php bin/w resource:compile welineModules     # 改了 JS 登记
php bin/w theme:upgrade                      # 改了布局/片段/Token
vendor/bin/phpunit app/code/Weline/Theme/test/Unit
vendor/bin/phpunit app/code/Weline/Backend/test/Unit/View/BackendViewContractsTest.php
php app/code/Weline/Theme/bin/backend-theme-audit.php   # 静态扫描（新增）
```

### 8.2 视觉与功能

- 用真实后台（默认 `admin/admin`，本机后台入口见 `php bin/w server:status`）截图：
  - 1440×1000：仪表板、用户列表、主题列表、主题编辑器、任一模块表单
  - 375×812：同一页面无横向滚动、侧栏可收
  - `data-theme=dark`：文字对比度可读、无白底白字/黑底黑字
- 交互：侧栏折叠、菜单搜索、语言切换、用户抽屉、主题列表 tab、主题编辑器保存；
  Console 无 error（BinQuery 401 环境问题除外）。
- 对照 `设计品味.md` 六问自检，结果写进交付说明。

### 8.3 门禁（新增页面/改页面必须满足）

1. 无 `<style>` 视觉块、无行内视觉字面量、无 `!important`。
2. 无旧 Bootstrap 类、无第二个 `h1`、无私有页面宽度。
3. 脚本走 module 声明或 `defer` 核心；无同步 `<script src>` 业务脚本。
4. 空/错/加载/禁用四态齐全；主按钮 ≤1；focus ring 可见。
5. 文案中文源串 + zh/en CSV；无原生 `alert/confirm/prompt`。

## 9. 旧代码清理规则

- 删除：0 字节组件、无引用的 legacy partial/layout、重复的 1280/1440 布局壳、
  已被 `w-*` 取代的旧组件 CSS、页面内一次性 `<style>` 皮肤。
- 保留：兼容层（旧类→Token）直到全仓后台模板迁移完成；兼容层不得再新增视觉规则。
- 删除前必须全仓检索引用（`grep -r`），并跑 Theme 单测；不允许“先注释掉”或留 TODO 壳。
- 不允许把旧模板复制成 `*_legacy.phtml` / `*_old.phtml` 继续留着。

## 10. 禁止清单（高压线）

- 改 `generated/`、`view/tpl/`、`view/statics/ui/weline-*.css` 编译产物。
- 在默认主题写品牌皮肤（`.amazon-*`、单页英雄皮肤、登录页专属插画风格）。
- 主题布局内嵌非 `Weline_Theme` 的 `<w:widget>`；跨模块内容只走拥有模块的 `default_injections`。
- 后台页面使用前台 `--weline-theme-*` 而不带 backend 桥接，导致暗色白底浅字。
- 用 UI 技能/前端设计技能发明私有 palette、spacing、radius、shadow。
- 为“好看”新增第三方 UI 库、图标库或 Web Font（字体必须走 `w:theme:font` 与 Token）。

## 12. 工具页例外（仅限专业工具界面）

> 状态：过渡机制（2026-10-21 起）。目标是**收敛**，不是长期保留。

### 12.1 什么算工具页

同时满足以下特征的后台页面才可申请例外：

1. 页面本身是一套**专业工具界面**（文件管理器、媒体库、邮件客户端、终端/日志流、主题编辑器画布等），
   而不是“列表 / 表单 / 详情 / 配置”这类标准页；
2. 页内布局体系与后台壳层正交（分栏、树、文件网格、拖拽区、编辑器），无法用 §4 的通用原语表达；
3. 迁移会破坏核心交互（拖拽、预览、实时编辑）且当前没有等价原语。

标准页（列表/表单/详情/配置）**一律不得**申请例外。

### 12.2 允许与禁止

- 允许：页面外壳（标题/面包屑/工具栏/主操作/提示）必须迁移到 §3 骨架与 §4 语义类；
  工具内部自有样式必须优先落盘为**模块私有 backend CSS**（`view/statics/css/backend/*.css`，
  遵守 §6.2 的 Token-only / `@layer page` / 禁止 `!important` / 文件与页面一一对应）。
  仅当落盘会破坏运行时（例如样式由 JS 动态注入、随画布尺寸实时改写）才允许暂时保留 `<style>`，
  且必须在 `<style>` 前写注释：
  `<!-- Weline backend theme: tool-internal styles, see 后端主题开发标准 §12 (pending migration) -->`。
- 禁止：以“工具页”为名保留整页旧皮肤（按钮/卡片/表单/表格样式必须换成 `w-*`）；
  以“工具页”为名新增内联样式；把例外当长期方案。
- 例外页面必须登记到 [`工具页迁移清单.md`](./工具页迁移清单.md)，逐页给出：模块/模板、
  保留原因、依赖的原语缺口、计划迁移批次。
- 例外页面不计入“标准页零违规”基线；`backend-theme-audit.php --files` 的对应条目应能在
  清单中找到，才算**已登记例外**，否则视为违规。

### 12.3 退出条件

当 §4 原语补齐（如文件网格、分栏、日志视图、树）后，例外页面按批次迁移；迁移完成的页面
从清单删除，审计基线同步下调。禁止在清单里长期挂账不迁移。
