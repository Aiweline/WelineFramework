# daocharms-3d 独立购物主题规格

状态：ready-for-plan，身份、业务契约和验收用例已确定；独立施工允许，视觉细节以UI/原型实际协商补齐。正式验收仍须成果审查。

## 背景

用户要求以daocharms为父主题创建daocharms-3d。顾客在古风三维镇中寻找、查看、选择规格并购买数据库商品；搜索、分类、购物车、结账、登录、个人中心及原网站其它功能完整保留。原独立模拟首页不作为正式商城交付。

## 用户故事与要求

作为顾客，我能在镇内搜索真实商品并到达展品，核对主图、名称、规格、价格后加购。作为会员，我能在镇内账户界面查看同一真实订单、维护地址并退出。作为搜索访客，我可通过商品和分类链接直接访问服务端内容，不依赖三维画布。

- EARS-1：当顾客选中镇内商品时，系统应使用当前作用域的真实商品与Offer身份打开既有购买面板，显示有效规格和售价。
- EARS-2：当顾客提交搜索词时，系统应调用现有搜索业务返回结果，允许打开同一商品及定位对应三维陈列。
- EARS-3：当顾客加购或修改数量时，系统应更新既有持久购物车，镇内背包和商城购物车显示同一结果。
- EARS-4：当顾客完成当前环境结账时，系统应生成真实业务订单，并在同一会员订单列表中可查。
- EARS-5：当浏览器未启用WebGL或JavaScript时，系统应继续提供现有可访问商城功能与服务端商品链接内容。
- EARS-6：当商品没有经核实的准确几何模型时，系统应保留原图并明确区分近似模型与图片陈列，不标称准确还原。

## 方案边界

work_mode=design_theme；area=frontend；独立app/design/Weline/daocharms-3d，parent=daocharms。保留父主题chrome、默认注入、43页继承和SEO hooks。仅追加独立资产、语义Token和三维增强；不得同key替换theme.css/theme.js。

业务复用公开Query：product.getPurchasePanel、现有购物按钮、cart持久会话、search.search、account与checkout既有组件。完整目录采用正式服务端批量查询，不拿前台禁止的searchPublishedOffers做浏览器请求。浏览器业务I/O仅Weline.Api。

当前环境启用fake_card沙盒，只能证明沙盒业务订单；本规格不增加真实扣款方式，不授权生产发布。

## 用例与验收映射

| 用例 | 预期结果 | 实际运行证据 |
|---|---|---|
| UC-1 搜索及目录定位 | 搜索DB商品并选中同ID三维展品；空结果可读 | 正式主题搜索操作/商品ID与截图 |
| UC-2 规格及加购 | 真实价格/规格，加购持久Cart；刷新仍存在 | Cart业务返回与刷新后页面 |
| UC-3 结账 | 地址/配送/总价可操作，沙盒生成订单 | order_uuid及服务端可回查订单 |
| UC-4 个人中心 | 登录、订单详情、地址及退出可用，查到UC-3订单 | 当前会员与同order_uuid |
| UC-5 SEO与降级 | canonical/hreflang/实体数据/SSR链接继承正确，无JS仍可购物 | HTML与真实商品、分类、账户路由 |
| UC-6 多端游逛 | 375/768/1440可交互，表单输入不移动，碰撞不挡商品 | 断点截图与实际操作 |
| UC-7 资产真实性 | 准确模型/近似展示区分，真实主图保留 | 有限资产清单与逐展品核对 |

测试落点与确切正式主题URL随契约冻结补齐。测试不能用模拟响应、内存订单或壳层冒烟代替上述业务通路。
