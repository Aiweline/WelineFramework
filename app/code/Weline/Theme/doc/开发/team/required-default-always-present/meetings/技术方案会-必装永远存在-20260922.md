---

## 1. Stance（一句话）

`+skip_fill_solidified` **可**跳过 entity fill / 重路径 splice，但 **不得**跳过 required overlay；`fillRequiredDefaultsOnShell` **不得**因 published +「壳完整」硬 early-return —— 无 `user_deleted@{versionId}` 则 required `default_injections` 与布局标签内嵌必装部件必须始终存在。

---

## 2. 用户冻结纠偏（不可改）

与发布态 / 固化壳无关。只要没有人工卸载记录 `user_deleted@{versionId}`：

1. required `default_injections` JSON 注入必须始终渲染进声明槽；
2. 布局标签内嵌的必装部件也必须始终存在；
3. 唯一省略：本版本 `user_deleted@{versionId}`（无后缀旧 `user_deleted` **不算**本版本卸载）。

---

## 3. 现状根因（只读确认）

wave8-8s5 把「固化壳 ≈ 零补槽」推到必装路径上，造成双断：

| 断点 | 行为 | 后果 |
|------|------|------|
| `LayoutSlotRenderer` | `!$needsSafetyNet` → `+skip_fill_solidified` → **直接** `strip` + return | 不跑 `fillRequiredDefaultsOnShell` / overlay |
| `ThemeLayoutEntitySlotFiller::fillRequiredDefaultsOnShell` | published 且 `!shellNeedsRuntimeSafetyNetFill` → **硬 return** | 即使有调用方，overlay 仍 no-op |

登录页空槽 `account-login-social-providers` 因此丢 `account-social-login`（部件走 `placement=injection`，依赖 overlay，不靠布局旁路 fetch）。

---

## 4. 批准修复语义

| 能力 | 批准 | 说明 |
|------|------|------|
| `+skip_fill_solidified` 跳过 **entity fill** | ✅ | 性能快路径可保留：不跑完整 `fill` / entity splice |
| `+skip_fill_solidified` 跳过 **required overlay** | ❌ | strip 前必须仍跑 required overlay（或等价：必调 `fillRequiredDefaultsOnShell` 且该方法本身不再 published no-op） |
| `fillRequiredDefaultsOnShell` published 完整壳 early-return | ❌ | 去掉该硬 return；published 也必须 `RequiredDefaultInjectionStorefrontOverlay::append` |
| Overlay plan 省略条件 | 仅 `user_deleted@{versionId}` | 不得因 published / 固化 / 「槽已有其它部件」省略本身份 required 项 |

可选实现形状（主题席自选，须满足上表）：

- **A（推荐）**：`skip_fill` 分支在 `strip` 前显式调用 `fillRequiredDefaultsOnShell`，再 strip；**并**删掉 `fillRequiredDefaultsOnShell` 的 published early-return。
- **B**：把 required overlay 抽到 LayoutSlot 公共尾段（零补槽与安全网共用），`skip_fill` 只跳过 heal/entity 段。

内嵌必装（layout 标签 / `<w:widget>` 路径）不在本波 PHP 主修点内；本波盯住 **injection overlay 被误跳过**。内嵌路径若另有 strip/omit，另开议题，不得用本修复去改 XOR。

## 6. 禁止事项

1. **禁止**用运行时 presence / 槽内 count / HTML tip 去重补丁当主修复（「页上已有就跳过补」≠ 用户纠偏）。
2. **禁止**改回 `login.phtml` 旁路 `fetch('…/account-social-login.phtml')` —— 保持 injection XOR（空槽 + JSON）。
3. **禁止**把「发布态 / 固化壳 / bake 完备」当作可省略 required 的条件。
4. **禁止**为修登录页而逐布局特判；修系统级 LayoutSlot / SlotFiller 一处。
5. **禁止**把旧无后缀 `user_deleted` 当成本版本卸载。

## 7. 与 XOR（同身份 layout vs injection）关系

沿用 `required-default-injection/meetings/技术方案会-同身份XOR-20260921.md`：

| 选择 | 布局/宿主 | widget.php |
|------|-----------|------------|
| **injection（登录社媒：现行）** | 只留空 `<w:slot id="account-login-social-providers">` | `placement=injection` + required `default_injections` |
| **layout** | 已 `fetch` / `<w:widget>` | `placement=layout` + **清空** `default_injections` |

本波关系钉死：

- **必装永远存在** 解决的是：选了 injection 之后，overlay **必须**在店面（含 `+skip_fill_solidified`）把部件写进空槽。
- **XOR** 解决的是：同源同码不得 layout+injection 双路径同时存在。
- 二者正交：修 overlay 漏跑 ≠ 允许双路径；保持 XOR ≠ 允许空槽永久空。
- `account-social-login` 继续走 injection；部件席验登录槽，**不**回滚 login 旁路 fetch。
