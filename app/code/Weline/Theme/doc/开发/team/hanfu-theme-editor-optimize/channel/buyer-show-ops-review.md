## 4. 对照汉服商城运营标准：该不该有、缺什么算「什么都没有」

| 触点 | 运营标准意图（既有 wave） | 现状 | 「什么都没有」是否成立 |
|------|--------------------------|------|------------------------|
| **首页买家秀** | 必须有 UGC 图墙；≤1 行 4–6 格；货架优先于内容 | 槽位有，**图全是占位** | **是（内容维度）** |
| **首页买家评价** | 与买家秀去重（星级证言 ≠ 图墙） | 另有 testimonials 槽（历史 wave 已过签结构） | 结构有；内容另债 |
| **PDP** | 详情须有可提交的图文评论信任位 | 评论壳在、**无已审内容** | 壳有；信任证据空 |
| **PDP 独立「买家秀」墙** | 非强制第二套模块；可用评论媒体区承担「晒图」 | 无 looks 墙；靠 Review 媒体 | 不强制再建模块 |
| **列表页买家秀墙** | 非 must；有评论后卡片可显示真实评分 | 无墙 | 不判「模块没做」 |

**顾问口径**：用户说的「这个模块」在现网对应首页 **买家秀图墙空壳**；技术上模块/部件「做过壳」，运营上 **等于没做实货**。

## 5. 对转化的影响

汉服为高决策、强「上身想象」品类：

1. **真实穿搭图**是降低退货焦虑与尺码恐惧的主信任证据之一；占位 SVG 直接破坏「可买商城」心智，且违反占位禁入交付。  
2. CTA「晒出你的汉服」无闭环 → 无法沉淀 UGC，获客素材与 PDP 信任双缺。  
3. PDP 评论空 → 星级/晒图证据链断裂，集合页也无法回填真实评分，连带列表信任变薄。  
4. 与竞品独立站常见「Customer Looks / 买家秀」对比，当前首页区块会显得 **半成品**，拖累 CVR 与品牌可信度。

## 6. escalate → PM：要开发 / 要运营落地什么（EARS + 验收）

> 顾问只定义「要什么」；施工归属席由 PM 派。优先 **内容填充（可最快止血）**，再排 **闭环产品化**。

### WO-BUYER-SHOW-01 · P0 首页真实买家秀资产（内容止血）

**EARS**  
When 访客打开汉服站首页买家秀区块，the system shall 展示 **≥4 且 ≤6** 张**真实汉服穿搭/试穿照片**（非 `default.svg`、非纯色块），并保持单行图墙密度（对齐 MALL-05）。

**验收点**  
1. 主题编辑器 / 发布配置中 `image-gallery` looks 的 `items` **非空**，每项含真实 `image` URL。  
2. 禁缓存打开首页：DOM 中 looks 图 `src` **不含** `storefront-placeholder/default.svg`。  
3. 气质：长安汉服水墨/古风可买；禁框中框、脏边、西式模板感棚拍堆砌。  
4. 规格建议（资产）：竖构图约 **3:4**，单边短边 ≥800px；WebP/PNG；可点进对应 PDP 或集合（`link` 可选但推荐）。  
5. `ops_acceptance`：顾问复审观感 pass。

`suggested_seats`: 主题开发工程师（配置/发布）, 出图或内容运营（6 张资产）, 测试（DOM 抽检）

### WO-BUYER-SHOW-02 · P0 CTA 不再空转（投稿入口）

**EARS**  
When 访客点击或看到买家秀 CTA「晒出你的汉服穿搭」，the system shall 提供 **可完成的下一步**（以下任一，PM 选一拍板）：  
A) 锚到当前 PDP 或固定活动商品的评论提交区（图文）；或  
B) 账户中心晒单/订单晒图页；或  
C) 运营活动落地页（征集规则 + 上传说明）。

**验收点**  
1. CTA 可点击且非死文案；点击后 2 步内可见上传/评论表单或明确活动说明。  
2. 未登录路径有登录回跳，不静默失败。  
3. 文案与中英 CSV 一致（改串则翻译工程师）。

`suggested_seats`: 部件/前端（入口接线）, 主题（文案与链接配置）, Customer/Review 归属视方案, 翻译工程师（若改串）

### WO-BUYER-SHOW-03 · P1 评论晒图 ↔ 买家秀（可选产品化，非新建平行模块）

**EARS**  
When 某商品存在 **已审核且含图片** 的商品评论，the system shall 允许运营将「评论媒体」用于首页/PDP 买家秀展示（聚合或精选），**禁止**再造一套平行晒单库（优先复用 `Weline_Review` 媒体）。

**验收点**  
1. 至少 1 条路径：后台精选评论图 → 首页 looks；或自动取已通过带图评论填充（需风控：仅 approved）。  
2. 无图评论不影响图墙。  
3. 文档写清：买家秀 = 展示面；评论 = 生产与审核源。

`suggested_seats`: 架构师（扩展点选型）, 部件开发工程师, Review 归属开发, 测试

**非目标（顾问纠偏）**：禁止立项「全新 BuyerShow 模块」除非架构证明 Review 无法承载；当前缺口是 **内容与接线**，不是缺模块名。

---

### WO-BUYER-SHOW-04 · P1 PDP 信任证据种子（运营+审核）

**EARS**  
When 核心上架 SKU（建议 Top 20 汉服）对访客展示详情，the system shall 使至少一批商品具备 **≥1 条已通过、含图** 的评论（种子内容或真实征集），使评论区非长期空态。

**验收点**  
1. 抽样 ≥3 个热销 PDP：评论列表非 empty 文案；可见图片缩略图。  
2. 后台「评论管理」可见对应 approved 记录。  
3. 卡片评分仅来自真实聚合（禁假星）。

`suggested_seats`: 运营内容（种子文案/图）, Review 审核路径, 测试

### WO-BUYER-SHOW-05 · P2 列表页（可选）

**EARS**  
If 商品已有真实评分聚合，then 集合/搜索卡片 shall 展示评分与条数；不要求列表页独立买家秀墙。

**验收点**：有评论商品卡片见星级；无评论不显示假数据。
