## 2. 根因假设与验证顺序（冻结）

### 2.1 根因假设（按概率，非互斥）

丢失 **不是**「随机丢注册表」。常见路径：

| # | 假设 | 可观察信号 |
|---|------|------------|
| H1 | 嵌套槽边界存在但槽内无节点（发布漏页 / 漏 `is_active_frontend` / structure 未含 nested） | 槽 marker 在，inner 空或仅模板占位 |
| H2 | Overlay 未把 required 注入写进 **容器部件内** 嵌套槽（只认布局根槽 / 缺 boundary 时尾挂） | HTML 尾部出现购买钮或根本无；`product-info` 内仍空 |
| H3 | 版本卸载误判 / 旧 `user_deleted`（无 `@versionId`）被当成卸载 | 本版本无 `user_deleted@{versionId}` 仍不注入 |
| H4 | 部件「空渲染」被当成「部件丢失」（`quote_only`、货币不可用、express 方法列表空） | wrapper/testid 缺或整块无痕；与业务关开关混淆 |
| H5 | FPC / 实体烘焙缓存仍是漏节点快照 | 清 FPC 或 bypass 后出现差异 |
| H6 | Express 无 failsafe，且空列表时壳消失 | `product-express-payment` 槽无根节点 |

### 2.2 验证顺序（施工前 / 复现必遵）

**硬顺序：先实机看 `/product/{id}` 店面 HTML，再判假设。**

1. **实机 HTML 槽探查（最先）**  
   - 打开可售零售 PDP（非 `quote_only`）。  
   - 在响应 HTML 中定位：  
     - `data-wslot="product-purchase-actions"` / 槽边界 `product-purchase-actions`  
     - `data-wslot="product-express-payment"` / 对应边界  
   - 判定：槽 **是否存在**、inner **是否空**、是否已有 `data-testid="product-add-to-cart"` / `product-buy-now"` / `product-express-payment"`。  
   - 若槽空 → 进入 H1/H2/H3/H5；若有 wrapper 但不可点 → 进入 H4（空渲染分轨），**不得**先改 Product 内嵌 CTA。

2. **卸载键**  
   - 查当前已发布 `ThemeLayoutVersion` 是否存在 `user_deleted@{versionId}`。  
   - 无版本后缀的旧 `user_deleted` **不算**本版本人为卸载（对齐 0036）。

3. **发布实体 / structure**  
   - 已发布页型是否含产品布局节点；nested slot 是否进 structure；主题切换后是否仍缺。

4. **Overlay 覆盖面**  
   - `ThemeLayoutEntitySlotFiller` → `RequiredDefaultInjectionStorefrontOverlay::append` 是否在嵌套边界内替换；缺 boundary 时是否错误尾挂。

5. **FPC**  
   - 仅在 1–4 仍矛盾时对比 bypass / 清缓存。

6. **空渲染分轨**  
   - 对 `quote_only` / 无 express method 对照页：期望「壳或占位在、业务钮可隐藏」，不是「槽整块无痕」。

> 验证未完成前，禁止以 failsafe / 布局硬嵌作为「已修好」结案。

## 3. 目标架构（冻结）

### 3.1 分层职责（不变）

| 层 | 模块 | 职责 |
|----|------|------|
| 契约与店面保证 | `Weline_Theme` | required overlay、版本卸载决策、嵌套槽填充、不写布局 |
| 槽声明 | `Weline_Product` | `product-info` 内嵌套空槽；**不**拥有跨模块 CTA 终态 |
| 加购 / Buy Now / Express | Cart / Checkout / Payment | `default_injections.required=true` + 部件实现 |

### 3.2 方案：在现有 0036 overlay 上补强嵌套槽

**采用（终态）**

1. 继续以 `RequiredDefaultInjectionContract::merge` 决定「本页须出现哪些 required 节点」。  
2. `RequiredDefaultInjectionStorefrontOverlay`（经 `ThemeLayoutEntitySlotFiller`）在 **店面已发布** 路径：  
   - 识别 `product-purchase-actions`、`product-express-payment` 等 **容器部件嵌套槽** 边界；  
   - 缺节点且未版本卸载时，把渲染结果注入 **该嵌套槽 inner**，而不是仅布局根或文档尾。  
3. 发布烘焙仍应尽量把 required 写入实体（降 FPC/首屏缺口概率）；**烘焙失败不得消灭店面保证**（0036）。  
4. 卸载仅 `user_deleted@{versionId}` 生效；升版本无新卸载则重新保证出现（丙）。

**明确拒绝（终态）**

- Product 布局 / `product-info` **硬嵌** Cart/Checkout/Payment 模板或长期 `data-purchase-failsafe`。  
- 编辑器打开/刷新静默 `applyMissing`（仍守 `REQ-THEME-0012`）。  
- 把 `required=false` 推荐件抬成必装。  
- 用「业务关了」解释非卸载下的槽空/无 testid。

### 3.3 与停工项对齐

| 原选项 | 本会态度 |
|--------|----------|
| 甲（仅发布烘焙、店面绝不补） | **否决为终态**；可作烘焙质量目标，但不能单独满足用户「未卸载则必现」。 |
| 乙（店面缺节点仍出现） | **采纳**；已由 `REQ-THEME-0036` 立法；本切片补嵌套槽落地缺口。 |
| 丙（卸载版本隔离） | **采纳**；契约已有 `user_deleted@{versionId}`；施工须保证决策路径一致。 |

**无重大矛盾 → 标可冻结。** 不重回立项停工。

## 4. 空渲染 vs 部件丢失（分轨，冻结）

| 轨 | 定义 | 店面要求 | 验收记法 |
|----|------|----------|----------|
| **A. 部件丢失** | 非人为卸载下，required 部件根未进入渲染树（无 wrapper / 无约定 testid） | Overlay 必须补出部件根 | UC5 缺陷 |
| **B. 空渲染** | 部件已挂载，但业务条件导致按钮/方法列表为空（如 `quote_only`、货币不可用、express 无可用 method） | **禁止整块无痕消失**：须保留可见壳、业务占位或明确降级文案；testid 根节点仍在（express 非卸载时） | UC7 / 业务预期，**不**记架构丢失 |

施工约束：

- Overlay 路径若 `renderNode` 得到空串 / 仅注释，**不得**静默 `continue` 导致「像没注入」；须落到可观测占位或健康信号（DEV 可 toast；店面至少壳在）。  
- Express：**非卸载时槽内节点必须存在**（即使 method 列表空）；历史上「无 failsafe」不得再导致壳消失。

## 5. 自愈策略（冻结）

| 面 | 行为 |
|----|------|
| **店面（已发布）** | 必补：缺 required 且无本版本卸载 → overlay 注入嵌套槽（不写布局文件）。 |
| **主题编辑器草稿** | 仍遵守「空槽不因打开/刷新自动回填」（`REQ-THEME-0012`）。 |
| **编辑器显式恢复** | 提供 **一键恢复 required**（应用 Tab / 插槽初始化 / 等价显式动作）：仅恢复 `required=true` 默认注入，不静默写推荐件；写入后可发布。 |

自愈边界：模块禁用、整站关闭购物、本版本认定卸载 → 不自愈。

## 6. UT / e2e 门禁（冻结）

### 6.1 Unit / 契约

- `RequiredDefaultInjectionContract`：三件套 `required:true` 声明仍锁定。  
- Overlay / filler：**嵌套槽**缺节点且无卸载 → 注入后 HTML 含目标槽 inner 内的部件根（禁止仅尾挂冒充 PASS）。  
- 版本卸载：有 `user_deleted@{versionId}` 则不出现；旧无后缀 `user_deleted` 不挡本版本。  
- 空渲染分轨：业务空输出不得被契约当成「未注入成功」而不加壳（按第 4 节）。

### 6.2 e2e / WB-OP（可售零售 PDP，非卸载）

| 断言 | 必须 |
|------|------|
| 加购 | 存在 `[data-testid="product-add-to-cart"]` |
| Buy Now | 存在 `[data-testid="product-buy-now"]` |
| Express | **非卸载时**存在 `[data-testid="product-express-payment"]` 节点（方法可空，节点不可无） |
| 人为卸载 | 对应 testid 可不存在；其余未卸载 required 仍在 |
| 切主题 / 编译后 | 未卸载前提下三件套门禁仍成立 |
| 非目标 | 仅 failsafe、无正式注入部件 → **不得** PASS |

e2e：正式 Playwright runner（`e2e:run` / `npx playwright test`），headless；章节 + plan-suite 按框架门禁。

## 7. 施工切片建议（非本波执行）

1. **后端**：嵌套槽 boundary 解析与 overlay 注入落点；空渲染占位；卸载键一致性；契约 UT。  
2. **前端 / 编辑器**：一键恢复 required UX；不破坏 0012。  
3. **Payment**：express 壳在无 method 时仍输出根节点 + testid。  
4. **测试**：PDP e2e 锁三 testid + 卸载负例 + 切主题。  
5. **收敛**：架构达标后排期移除/降级 Product `purchase-failsafe`（另任务，勿与本保证混验收）。

## 8. 风险与非目标

- FPC 与烘焙质量仍影响首包；overlay 是保证层，不替代发布质量。  
- 非目标：改加购/结账 API；强制询价商品显示加购；Theme 布局内嵌三模块模板终态。
