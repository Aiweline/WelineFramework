## 2. ArrayType × item 内 `product_picker`（缺口确认）

**确认缺口：是。**

- `Weline\Widget\Ui\ParamType\ArrayType::renderItemField` switch 仅：`select` / `image|image_picker|media_image|file_image` / `url` / `color` / `bool` / `textarea` / default→text。
- **无** `product_picker` 分支；项内声明该 type 会退化成普通文本框。
- 顶层可选类型已存在：`ParamTypeRenderer::OPTIONAL_TYPE_CLASSES['product_picker']` → `Weline\Product\Ui\ParamType\ProductPickerType`（部件级 `product_ids` 可用，如 `product-carousel` / `featured-products`）。
- 主题编辑器本地 fallback（`theme-editor.js` / `weline-theme-editor.js` 的 `renderFallbackArrayItemField`）同样未识别 `product_picker`，会落到 text input——即便 PHP ArrayType 修好，若仍走 fallback 路径也会丢选品 UI（与 media-item-fields 技术方案「数组唯一入口走 ArrayType」一致）。

**须扩展**：

1. `ArrayType::renderItemField` 委托 `ProductPickerType`（或等价 HTML），注意项内字段值形态（逗号 ID / JSON）与数组 hidden JSON 同步。
2. 前端 `Weline.Widget.Params` 克隆 template / 序列化项时兼容 picker DOM。
3. 主题编辑器数组路径优先消费 ArrayType HTML（已有 media-item-fields 决议），避免第二套 fallback 再退化。

**冲突风险**：中。嵌套 dialog（项内 picker 已用 `Weline.UI.dialog`）与编辑器侧栏 z-index 需回归；值协议须与顶层 `product_picker`（逗号分隔 ID）对齐。

## 3. ParamSchema `*_items` 模式

权威模式（Theme）：

- 声明文件：`app/code/Weline/Theme/Ui/ParamSchema/{name}_items.php`
- 返回：`base_type => array` + `item_schema` + 可选 `sortable` / `max_items` / `add_label`
- 扫描：`ParamSchemaScanner` → `generated/param_schemas.php`
- 展开：`ParamSchemaRegistry::expandParams`（`schema_type` 保留语义名；运行时 `base_type=array`）

样例：

| schema | 用途 | item 字段要点 |
| --- | --- | --- |
| `banner_items` | hero-slider 轮播图 | media_image + string/url/select |
| `testimonial_items` | testimonials | string/media_image/textarea/number |

**video-carousel 建议**：新增 `video_carousel_items.php`（或 `video_items`），item 含平台/URL/embed/作者文案 + `product_ids`（`type=product_picker`，待 ArrayType 扩展后生效）。部件 `@param` 或 `widget.php` 覆写 `type=video_carousel_items`，与 hero-slider 对 `banner_items` 的登记方式一致。

**冲突风险**：低。目录内已有 15 个 `*_items`，无命名撞车（需避开已有 `banner_items` 等）。

## 4. StorefrontProductWidgetCatalog 按 ID 取卡

类：`app/code/Weline/Product/Service/StorefrontProductWidgetCatalog.php`

| 公开方法 | 是否按 ID |
| --- | --- |
| `cards($limit)` | 否（推荐池 / Hanfu 优先） |
| `bestSellerCards` / `newArrivalCards` / `relatedCards` / `youMayLikeCards` / `bundleCards` | 否（或仅 seed/exclude） |

**底层已有按 ID 能力**：`StorefrontCatalogViewService::publishedOffersForProductIds(array $productIds, …)`；Catalog 内部（newArrival / companions / bundle seed）已调用，但**未**暴露 `cardsByIds(list<int>): list<card>` 一类公共 API，也未 `mapOffer` 公开。

旁证：`featured-products` / `product-carousel` 已声明 `product_ids=product_picker`，但 featured 实际仍 `->cards($limit)`，**忽略**已选 ID——说明「选品回填」与「前台按 ID 取卡」两条链都未完全闭环。

**须扩展（推荐）**：在 `StorefrontProductWidgetCatalog` 增加按 ID 列表取卡（内部 `publishedOffersForProductIds` + 现有 `mapOffer` / `withReviewAggregates`），供 video-carousel 与既有 product_ids 部件共用。

**冲突风险**：低（加方法，不改现有卡片形状）。注意 Hanfu SKU 过滤策略：按 ID 显式选品时应**尊重 ID 顺序、勿再强制 HF-* 过滤丢品**。
