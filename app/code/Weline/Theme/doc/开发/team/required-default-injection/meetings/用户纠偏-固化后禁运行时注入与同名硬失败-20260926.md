# 用户纠偏：固化后禁运行时注入 + 同名双路径硬失败

- 日期：2026-09-26
- 席位：用户口头纠偏（PDP `product-info` 双渲诊断后）
- 相对：`用户纠偏-同部件XOR非硬强制-20260921.md`（未填 soft-skip 仍保留；**同码叠渲 soft-skip 作废**）

## 正确语义

| 规则 | 含义 |
|------|------|
| **固化即固化** | 布局实体固化完备后，店面运行时**不得**再实时注入同名部件 HTML。 |
| **未固化只固化** | 运行时仅在尚未固化时触发 `dynamicSolidify` / rebake 写关系壳；禁止把每请求 Overlay 当主路径。 |
| **同名双路径硬失败** | 布局已内嵌（`placement=layout` / `<w:widget>`）↔ **绝对禁止** JSON `default_injections` / `DefaultLayoutSeeder` / 实体节点再嵌同名。命中必须直接报错（`required_default_injection_duplicate` / Seeder 门禁），禁止 soft-skip。 |

## 禁止误读

- ❌ 「槽内同码 count>1 只打日志继续出站」
- ❌ 「固化壳上再跑 Overlay 补一份 product-info」
- ✅ 「源侧二选一 + 门禁致命；店面同码双份硬失败」
- ✅ 「未填（声明但缺）仍可 soft-skip，不另增店面 500」

## 严格档落地（2026-09-26）

判据（请求内权威、无需查盘/查声明）：

```php
ThemeLayoutEntityPublishedSlotHost::publishedSolidifiedArtifactLoaded()
// = CTX_FRAGMENTS 为数组 且 page_html 非空
```

为真 ⇒ 运行时**禁止**注入 / 补槽 / 部件声明查询，直接以固化模板交付。
固化壳缺槽位 = **固化缺陷** → 记硬失败 `solidified_shell_missing_required_slot` + 重固化（rebake）；
**不得**每请求 Overlay 打补丁。为假（无固化产物）才允许回退注入，且优先 `dynamicSolidifyPublishedPage`。

运行时三个注入落点收口：

1. `Observer/LayoutSlotRenderer.php` → `fillRequiredDefaultsOnZeroFillPath()`（`+skip_fill_solidified` 快路径）
2. `Observer/LayoutSlotRenderer.php` → `+safety_net_fill` 分支（有固化 ⇒ 只记缺陷）
3. `Service/StorefrontSsrChromeHealer.php` → `fillRequiredPageDefaults()`（SSR-slim：cart/checkout）

另收口：`ThemeLayoutEntitySlotFiller::healNarrowFilterPlaceholders()` 的 Overlay 兜底。

**唯一显式例外（需用户确认）**：`fillBlankNestedChromeExtensions()` 的 `layout_type=mini-cart` 兜底保留。
理由：① 它是**嵌套 chrome 扩展**槽（迷你车抽屉 footer-extras 优惠券/留言），非布局槽 / 部件计划注入；
② 触发前提是该槽**为空**（部件不存在 —— 用户原文「除非部件不存在」）；
③ A/B 实测：一并禁注 ⇒ PDP/HOME `required-injection-presence` **6 → 0**、`footer-extras` 整块消失（真丢功能）。
durable 修法已加（`finalizePublishedChromeRenderedHtml` 固化时补 mini-cart 必装写进 chrome 快照），
待重固化生效后即可删除该兜底。

**不算注入**（允许的固化产物盘读）：`prefillPublishedChromeFromRenderedSnapshot` /
`splicePublishedChromeFromDisk` / `chromeSlotProjectionFromRenderedSnapshot`。
**允许的注入时机**：固化/bake（`finalizePublishedChromeRenderedHtml`）+ 编辑器/预览（draft）。

权威：`app/code/Weline/Theme/doc/布局固化与默认注入.md` §3.2.1 + §4。

## 关联：PDP look 段整块双渲（另一缺陷类）

用户报的「两个部件渲染」在 PDP 上另有一处**真因**：详情描述里 `look_title`/`look_body`
被生成器写两遍（`$feature` + `$pair` 追加的 `weline-detail-prose`），烘进 `description` EAV ⇒ 每请求双渲。
与固化/注入无关；已修生成器 + 双列存量数据。见 `Theme/doc/开发日志.md`（2026-09-26 条目）。
