# 立项会

参会: 项目经理、需求分析、领域探查

## 待决问题

required 的 default_injections 在店面消失，是不是架构问题。用户要求：这类部件必须出现，除非认为在这个版本卸载了部件。

## 选项

- 甲：不改店面渲染禁令。发布烘焙时，required 且无 user_deleted 的注入必须进入已发布实体。缺发布、漏页型、主题标志不对，算发布缺陷，不在打开页面时补。
- 乙：收窄 REQ-THEME-0012 / 0014。缺发布实体且本版本无卸载决策时，店面仍须出现该部件。这等于渲染路径允许补齐。
- 丙：卸载按版本隔离。现有 user_deleted 没有版本列。新版本是否重新注入，须单独确认。

## 表态

- 需求分析：同意乙。0012 原意是删除后刷新不回填，不是从未发布则永久占位。异议：版本键未记载，不能代定。
- 领域探查：同意甲，否决乙。店面 fill 缺实体不回退 required；现场注入违反 0012。异议：甲不覆盖「新版本重新出现」。
- 项目经理：无人能同时满足「不改硬规则」和「未卸载则店面必现，且按版本卸载」。

## 决议

~~停工。异议保留。~~

**2026-09-20 用户确认后解除停工（店面保证）：**

- 采纳 **乙**：缺节点且未卸载 → 店面仍须出现（渲染期补齐，不写布局）。
- 采纳 **丙** 语义：卸载按版本（`user_deleted@{versionId}`）。
- **甲不得作为唯一保证**。
- 口令：有 slot + required + 未人工卸载 → 必须注入；与实体/烘焙/缓存状态无关。

权威：`meetings/设计共识-有槽必注.md`；需求 `REQ-THEME-0036` / 收窄后的 `REQ-THEME-0012`。

## 证据

- REQ-THEME-0012：空 slot 保持空；渲染路径禁止 applyMissing。
- REQ-THEME-0014：user_deleted 后对账不回填；店面仍禁止静默 applyMissing。
- user_deleted 无版本维（ThemeWidgetDefaultInjection / LayoutIdentityHasher::injection）。
- 本次 /products 占位来自未发布实体与迁移漏 products、漏 is_active_frontend，不是编辑器删除。
