# 技术方案会：槽清单先读 → 再注入（架构级）

- 日期：2026-09-21
- 席位：项目经理 / 架构师（[方案正文](0644249e-81cd-4f76-8538-67675974e6d7)）
- 用户建议：先读布局、了解完用哪些 slot，再处理注入；架构级；性能要好
- 结论：`result=closed`（无停工级矛盾）

## 决议句（待用户确认）

店面 required 注入改为：**声明闭包建槽清单 → 拓扑序注入计划 → 单遍（或按 DAG 层）执行 → 末次断言**。  
热路径禁止「边渲边发现槽」的多轮全页试探作为默认。

## 流水线

| 阶段 | 做什么 | 热路径成本 |
|------|--------|------------|
| S0 | 指纹命中 inventory 缓存 | O(1) |
| S1 | 建 `SlotInventory`（壳槽 ∪ Catalog 容器 nested slots 闭包） | bake/缓存；miss 才算 |
| S2 | 建 `InjectionPlan`（required − 卸载 − 已存在；拓扑序） | O(声明数) |
| S3 | 按 Plan 注入（每槽一次；整槽 once） | O(\|plan\|×单槽定位) |
| S4 | 断言未填硬失败 | O(\|plan\|) |

## 槽清单权威（不是 HTML 试探）

1. **页壳模板** → 根槽  
2. **Catalog 容器 `slots` + 本页容器闭包** → 嵌套槽（如 product-info → purchase-actions）  
3. `structure.json` → 只证「已装什么」，**不**当落点全集  
4. 运行时 HTML 边界 → 只当注入坐标与校验，**不当发现器**

## 性能禁令

- 禁止默认 `while` 多轮全页 `enumerateRegions` + 整页重写当发现手段  
- inventory / plan 骨架可 bake + APCu；键含 theme/page/scope/release/Catalog/壳 hash  

## 与有部件必入

- 义务主语仍是部件；清单只回答「落点能不能谈」  
- 清单无目标 / 有槽未填 → 硬失败；卸载仍是唯一业务例外；整槽 once  

## 波次

- **P0**：InventoryBuilder + InjectionPlanner + Overlay 按 Plan 执行（砍默认多轮试探）  
- **P1**：inventory sidecar bake/缓存；结构消空嵌套卫生
