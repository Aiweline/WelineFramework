# 设计共识：required 默认注入 = 有部件必入声明槽

- 日期：2026-09-20（同日纠偏主语：部件，非插槽）
- 触发：用户明确「除非人工卸载应用，否则就无关任何」；再纠正「和插槽没有关系……是部件……有这个部件就必须插到声明槽」
- 席位：项目经理 / 需求分析 / 领域探查 / 架构师
- 旧口令「有槽必注 / 有槽才注」**弃用**（曾把槽当触发条件，属误读）

## 1. 一句话

**部件一旦声明了 `required=true` 的 `default_injections`（写明目标槽），只要这个部件还在（模块在场 + Catalog 有声明）且本主题布局版本未人工卸载（`user_deleted@{versionId}`），就必须出现在它声明的那个槽里。插槽只是落点，不是条件。**

「无关任何」包括但不限于：发布实体是否缺节点、page-config 是否 param-only、structure ghost、FPC 旧缓存语义上的「看起来像没装」、迁移漏页、烘焙 snapshot 是否列出该 code、Catalog 声明顺序导致嵌套落点稍后才出现。这些都**不能**当作不注入的理由。

落点约束（实现，非业务主语）：禁止在文末新建 ghost slot；某次渲染树里目标槽尚未出现时先多轮等待父容器注入；目标槽已在树中则缺部件必须硬失败。

## 2. 与旧停工选项的关系

立项波曾卡在甲（只靠发布烘焙）/ 乙（店面可补齐）/ 丙（版本卸载）。

| 选项 | 本共识 |
|------|--------|
| 甲 | **否决作为唯一保证**：只靠烘焙仍会因漏 bake / 旧实体失败；店面不得靠「实体没有」永久空白 |
| 乙 | **采纳（店面）**：缺节点且未卸载 → 店面必须把部件渲进声明槽（`RequiredDefaultInjectionStorefrontOverlay` / Contract）；**不写布局**仍成立 |
| 丙 | **已落地语义**：卸载按版本（`user_deleted@{versionId}`）；无后缀旧 `user_deleted` **不算**本版本卸载 |

## 3. REQ 边界（纠偏）

### 3.1 `REQ-THEME-0036`（主保证 · 店面）

- 作用面：**店面已发布渲染**。
- 条件：部件存在（required 声明在 Catalog）+ 本版本无 `user_deleted@{versionId}`。
- 动作：填槽路径必须把该部件渲进**其声明的** slot；**禁止**因实体缺节点而留下空占位。
- 槽：目标地址；模板里本来就摆着。无落点 ≠ 无义务（不得建成 ghost；多轮后落点仍无则属布局/声明不一致，落点已在则未填必抛）。
- 不写布局：overlay 不代替「应用」写入草稿/发布实体；实体完整是双保险，不是唯一保证。

### 3.2 `REQ-THEME-0012`（收窄误读）

- **原意（保留）**：用户在编辑器里**删掉/卸载**部件后，打开/刷新编辑器**不得**静默 `applyMissing*` 把删掉的东西写回。
- **误读（禁止再当权威）**：「实体里从来没有 / slot 空着」→ 店面也可以一直空。那与 0036 与本共识冲突。
- 编辑器草稿：仍禁止「删除后刷新回尸」；**未卸载的 required** 不靠打开编辑器静默写布局，店面靠 0036 保证可见。显式「应用 / 插槽初始化 / 恢复默认」仍可写草稿。

### 3.3 `REQ-THEME-0014`

- `required=true` = 默认安装；`required=false` = 推荐，不提升为必装。
- 人工卸载写版本化 `user_deleted@…`；对账不回填已卸载项。

## 4. 实现落点（团队须认路径）

| 保证层 | 路径 | 职责 |
|--------|------|------|
| 契约 | `RequiredDefaultInjectionContract` | merge / 版本卸载判定；主语=部件 |
| 店面 | `RequiredDefaultInjectionStorefrontOverlay` + `ThemeLayoutEntitySlotFiller` | published 多轮补注声明槽；落点在则未填硬抛 |
| 写入 | `WidgetDefaultInjectionService::saveInjection` | **不写 PUBLISHED**；published 空写不得假记 applied |
| 编辑器 | `ThemeEditor` | 仍禁删除后静默 applyMissing（0012） |

## 5. 验收口令（团队自检）

1. 部件 required 声明存在且未卸载 → 店面其**声明槽**内必有该部件 testid/根标记。  
2. 本版本人工卸载 → 店面与编辑器对账都不再出现。  
3. 推荐项（`required=false`）不因本共识自动出现。  
4. 不得用「snapshot 没列」「page-config 只有参数」「声明顺序靠后」对外宣称「没注入」。
