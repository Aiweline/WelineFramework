# 设计共识：required 默认注入 = 有槽必注

- 日期：2026-09-20
- 触发：用户明确「除非人工卸载应用，否则就无关任何，只要有 slot 就要注入」
- 席位：项目经理 / 需求分析 / 领域探查 / 架构师（本文件为共识正文，施工前全员对齐）

## 1. 一句话

**`required=true` 的 `default_injections`：模板/渲染里只要存在对应 `slot`，就必须出现该部件；唯一合法例外是本主题布局版本上的人工卸载（`user_deleted@{versionId}`）。**

「无关任何」包括但不限于：发布实体是否缺节点、page-config 是否 param-only、structure ghost、FPC 旧缓存语义上的「看起来像没装」、迁移漏页、烘焙 snapshot 是否列出该 code。这些都**不能**当作不注入的理由。

## 2. 与旧停工选项的关系

立项波曾卡在甲（只靠发布烘焙）/ 乙（店面可补齐）/ 丙（版本卸载）。

| 选项 | 本共识 |
|------|--------|
| 甲 | **否决作为唯一保证**：只靠烘焙仍会因漏 bake / 旧实体失败；店面不得靠「实体没有」永久空白 |
| 乙 | **采纳（店面）**：缺节点且未卸载 → 店面填槽必须出现（`RequiredDefaultInjectionStorefrontOverlay` / Contract::merge）；**不写布局**仍成立 |
| 丙 | **已落地语义**：卸载按版本（`user_deleted@{versionId}`）；无后缀旧 `user_deleted` **不算**本版本卸载 |

## 3. REQ 边界（纠偏）

### 3.1 `REQ-THEME-0036`（主保证 · 店面）

- 作用面：**店面已发布渲染**。
- 条件：`required=true` + 渲染 HTML 中存在该 slot 边界/包装 + 本版本无 `user_deleted@{versionId}`。
- 动作：填槽路径必须把部件渲进该 slot（overlay / merge），**禁止**因实体缺节点而留下空占位。
- 不写布局：overlay 不代替「应用」写入草稿/发布实体；实体完整是双保险，不是唯一保证。

### 3.2 `REQ-THEME-0012`（收窄误读）

- **原意（保留）**：用户在编辑器里**删掉/卸载**部件后，打开/刷新编辑器**不得**静默 `applyMissing*` 把删掉的东西写回。
- **误读（禁止再当权威）**：「实体里从来没有 / slot 空着」→ 店面也可以一直空。那与 0036 与本共识冲突。
- 编辑器草稿：仍禁止「删除后刷新回尸」；**未卸载的 required** 不靠打开编辑器静默写布局，店面靠 0036 保证可见。显式「应用 / 插槽初始化 / 恢复默认」仍可写草稿。

### 3.3 `REQ-THEME-0014`

- `required=true` = 默认安装；`required=false` = 推荐，不提升为必装。
- 人工卸载写版本化 `user_deleted@…`；对账不回填已卸载项。

## 4. 实现落点（团队须认路径）

| 保证层 | 路径 | 职责 |
|--------|------|------|
| 契约 | `RequiredDefaultInjectionContract` | merge / 版本卸载判定 |
| 店面 | `RequiredDefaultInjectionStorefrontOverlay` + `ThemeLayoutEntitySlotFiller` | published 填槽缺则渲；PDP 可二次壳层补扫 |
| 写入 | `WidgetDefaultInjectionService::saveInjection` | **不写 PUBLISHED**；published 空写不得假记 applied |
| 编辑器 | `ThemeEditor` | 仍禁删除后静默 applyMissing（0012） |

## 5. 验收口令（团队自检）

1. 有 slot、required、未卸载 → 店面 HTML 必有该部件 testid/根标记。  
2. 本版本人工卸载 → 店面与编辑器对账都不再出现。  
3. 推荐项（`required=false`）不因本共识自动出现。  
4. 不得用「snapshot 没列」「page-config 只有参数」对外宣称「没注入」。
