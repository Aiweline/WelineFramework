# 技术方案会：重复前端部件（有部件必入声明槽）

- 日期：2026-09-21
- 席位：项目经理 / 架构师 / 后端 / 测试
- 架构结论：result=closed（无停工）

## 问题

验收 PDP 时加购/立即买出现多份 `widget-wrapper`。用户此前记得的「重复前端部件」成立。

## 根因

契约误读成「每个同 id 区域各注一份」。  
真实 HTML 存在同 `product-purchase-actions` 多区域（嵌套空占位），Overlay 逐区补满 → 可见双份/三份。

正确语义：**声明槽内该部件至少出现一次（整槽 once）**，不是 per-region。

## 分层解法

| 层 | 动作 | 本轮 |
|----|------|------|
| **保证层** | `anyRegionHasWidget` / 页级 `data-slot-id` 绑定已有则跳过；缺则只注**一个**最深空区；二次扫「全无才缺」 | **必须落地**（2.2.498） |
| **结构层** | 中期消同 id 空嵌套（bake/健康） | 跟进卫生，不替代去重 |
| **failsafe / sticky** | 不算声明槽重复；failsafe 须 `hidden`；sticky 另面 | 验收排除 |

## 验收口径

主购买卡内可见加购/立即买各 **1**；排除 `[hidden]` failsafe；sticky 不计入 buybox 份数。

## 决议

固化保证层去重；结构消空嵌套不阻塞本轮交付。
