# 自定义（design）主题开发路线

> 适用范围：`app/design/{Vendor}/{theme}/` 下的自定义主题 —— 新开主题、给既有站做品牌皮肤、把落地页做成可复用主题。
> 抽象口径：本文不绑定任何具体站点/品牌/主题名，一律用 `{Vendor}/{theme}/{brand}` 占位。
> 权威关系：Token/版心/部件/固化的机制正文在 Theme 模块 doc；本文是**施工顺序 + 必查项 + 踩坑**的路线，冲突时以机制正文与 MCP `hard_constraints` 为准。

## 0. 开工前：三条硬前提

| 前提 | 做法 |
|---|---|
| `work_mode` | 首条回报写 `work_mode=design_theme`（默认层才是 `default_theme`；Theme PHP 才是 `theme_module_runtime`） |
| 落点边界 | 只新增/修改 `app/design/{Vendor}/{theme}/**`；`app/code/**` 上游主题源只读，做不到就停手问用户 |
| 验收站点 | **新开本地站点选该主题**验收（`custom_theme_acceptance_new_local_website`），禁止在默认站/既有站临时切主题 |

开工命令：

```bash
php bin/w theme:listing                      # 现有主题与 id
php bin/w website:domain-pool                # 申请本机子域（选 ready=1 created=0）
```

## 0.1 建站四步：申请本地域名 → 建站 → 绑域名 → 绑主题（硬，缺一步就不算「建好」）

**顺序固定**，每一步都要有可核验的落表/落盘证据；只做「建主题 + 绑主题」而没建站，等于没有可验收的店面。

| 步骤 | 动作 | 落点 / 证据 |
|---|---|---|
| ① 申请本地域名 | `php bin/w website:domain-pool` 选 `ready=1 created=0`，记 `pool_id`；域名形态见 §0.2 | 池行 `status/resolve_status=https_status=valid` |
| ② 建站 | `php bin/w website:create --name="<站点名>" --pool-id=<id> --code=<code> --json` | `w_weline_websites_website`（`website_id/code/url`）+ **默认店铺** `w_weline_websites_store`（`is_default=1`）+ `w_weline_websites_website_domain`（`website_id`+`pool_id`+`domain`+`is_primary=1`），并消费池条目 |
| ③ 绑域名（校验/补录） | 建站会自动写 domain 行；换域/加域时按同表补 `root_domain`、`sub_path`、`is_primary`、`status=active`、`https_enabled=1` | 目标 Host 首屏必须是**该站**：`data-website-id="<website_id>"`、`body` 带该主题类 |
| ④ 绑主题 | `WebsiteThemeBindingService::bindThemeForWebsite($websiteId,'<code>',$themeId,0)`（后台等价：网站信息 → 店面主题） | `w_websites_theme_application`：`scope_key=website\|<id>\|<code>\|\|\|\|v1`，`reference_json.theme_id=<themeId>` |

建站/换绑后必须刷站点识别缓存，否则门店仍按旧站渲染：

```bash
php bin/w cache:clear --no-warm     # DetectWebsite 有 websites.detect.* + 进程级缓存
php bin/w server:reload             # Worker 仍返回旧站时
```

验收三元组（缺一即未建好）：`data-website-id` = 目标站、`body` 含目标主题类、`w_websites_theme_application.reference_json.theme_id` = 目标主题。

## 0.2 地址规则：裸域能不能直达，取决于 Host 形态（实测）

| Host 形态 | 判定 | 裸域 `/` 归属 | 自建站可达地址 |
|---|---|---|---|
| `{8位十六进制}.test.weline.com`（如 `a1b2c3d4.test.weline.com`） | **标准项目主机**（`LocalDomainPolicy::isStandardProjectHost()=1`） | **固定归默认站**（`DetectWebsite::findDefaultSiteForProjectHost`），非默认站被跳过 | 只能 `https://<项目主机>/~site/<code>/`（实测：同主机加非空 `sub_path=/manufacture` 绑定后 `/manufacture/` 仍 404——sub_path 只改站点归属，不改路由） |
| `grocery.test.weline.com` 这类单标签名（非 8 位 hex） | 非项目主机（`isStandardProjectHost()=0`） | 由 `WebsiteDomain` 行直接匹配该站 | `https://<domain>/` 直达 |

- **误判警报**：「打开裸域看到的是别的站」≠ 没建站，通常是②③④已完成、只是把标准项目主机的裸根当成了自建站入口。先用 `data-website-id` 判定命中的是哪个站。
- **要裸域直达**（如 `{brand}.test.weline.com`）：该名字必须是**非项目主机**（单标签、非 8 位 hex）。完整三步：
  1. **补 `WebsiteDomain` 行**（`domain` / `root_domain=test.weline.com` / `sub_path=''` / `status=active` / `https_enabled=1`），刷 `cache:clear --no-warm`；
  2. **服务端先验**（DNS 未就绪也能验）：`curl -k --resolve <domain>:443:127.0.0.1 https://<domain>/`，必须看到 `data-website-id="<目标站>"` + 目标主题 body 类；
  3. **本机解析**：`/etc/hosts` 加 `127.0.0.1 <domain>`。本机可能已有 `*.test.weline.com` 的通配解析指向非回环地址（实测 `198.18.1.180`，不可达），此时 `AiSiteLocalDomainReadinessService::inspect($domain)` 报 `TEST_DOMAIN_RESOLUTION_CONFLICT`（提示已改为「证书已就绪，只差 hosts」）。写入路径：`HostsFileManager::addDomain()` 在 **macOS + CLI** 下会自动用 `osascript … with administrator privileges` 弹一次系统授权并回读校验（`WELINE_HOSTS_NO_ADMIN_PROMPT=1` 可关闭）；无 GUI/被拒绝时才回 `needs_admin` + 手动命令。
  4. **CA/HTTPS 不用单独准备**：本机 `*.test.weline.com` 由 Weline Local Development CA 的**通配证书**覆盖（`openssl`/`curl` 校验 `ssl_verify=0`）；域名为单标签即可直接享用，不必逐域签发。
  5. **别把别人的授权当成本条授权**：`198.18.0.0/16` 是本机代理（如 ClashX TUN fake-IP）的假地址段，`/Library/PrivilegedHelperTools` 里可能只有代理的 helper、没有 WLS hosts helper，因此「刚才弹窗已点允许」可能批的是代理，hosts 仍没写入——以 `grep <domain> /etc/hosts` 的结果为准。
  6. **浏览器 DNS 负缓存**：hosts 改好后 curl 已 200，但浏览器标签仍报 `ERR_CONNECTION_CLOSED` 时，换新标签/重开浏览器（或等 Chrome 负缓存过期）再验，别当成站点没建。
  7. **写不进 hosts 时的验收兜底**：从 `/etc/hosts` 里挑一个**已在解析、未被 `WebsiteDomain` 占用**的非项目域名（如 `local-demo-*.weline.test`），给该站补一条 domain 行即可立刻用浏览器验收；等目标域名解析就绪后再补正式行、必要时切 `is_primary`。
- 池里的 `local-demo-*.weline.test` 等未进 hosts 的域名：直接 curl 是 000 / 404，**不能当已可用域名**交付。

## 1. 主题骨架（先结构，后皮肤）

```
app/design/{Vendor}/{theme}/
├── register.php                     # Register::register(TypeInterface::type, '{Vendor}_{Theme}', ['name','parent','path'], 版本, 描述)
└── frontend/                        # 只做前台也必须有 frontend/（themeSupportsArea 依赖）
    ├── colors/_*.css                # 色盘层
    ├── variables/_*.css             # 刻度层（展示级字号/节奏/媒体比例）
    ├── assets/css/{brand}-*.css     # 品牌皮肤（可多层：chrome / landing / commerce）
    ├── assets/js/{brand}-*.js       # 仅在需要时
    ├── assets/images/**             # 走 ns 静态路径（见 §6）
    ├── partials/head/theme-head-css-overlay.php   # PACK_OVERLAY 清单（关键！§3）
    └── layouts/{layoutType}/{option}.phtml        # 同 key 覆盖布局（整份替换，不合并）
```

- 继承：不覆盖的 layout/partial/widget 自动继承默认层；**同 key 覆盖 = 整份替换**。
- 模块模板覆盖走 `{Module_Code}/templates/{frontend|backend}/...`；**禁止** `frontend/templates/`。
- `layoutType` 用斜杠嵌套（`account/login`），禁 `account.login`。

## 2. 变量与色盘（Token 实名制）

| 类别 | 只许用 | 说明 |
|---|---|---|
| 间距 | `--weline-space-1…15` | 禁裸 `12px`/`0.55rem` |
| 圆角 | `--weline-theme-radius-{sm,md,lg,xl,full}` | 叶子定义在 `theme.css`；控件 md、卡片 lg、大面 xl、胶囊 full |
| 字号 | `--weline-font-size-{xs…4xl}` | 展示级大标题在主题 `variables/_*.css` 定义 `--{brand}-fs-*`（clamp） |
| 阴影 | `--weline-shadow-{sm,md,lg}` / `--weline-theme-shadow-*` / `--focus-ring` | 禁自造 |
| 颜色 | `--color-primary*` / `--color-text*` / `--color-bg-*` / `--color-border-*` / `--color-surface*` / `--color-on-primary` | 叶子写在 `colors/_*.css` |
| 版心 | `--weline-layout-content-max-width` + `--weline-container-gutter` | 唯一两个；容器实现 `.w-container` / `.w-theme-content-width` |
| 画布 | `--weline-page-canvas-{color,image,size,repeat,position}` | 页面底色/纸纹只走这五个；禁 `body{background-image}` |
| chrome | `--weline-chrome-*` | 共享 header/footer 壳消费；改壳观感优先改这族 |

**层级顺序**：`_light` → `_default` → 品牌 `_*.css` → `_dark`。品牌盘**禁删** secondary/status 全家，只覆盖叶子。
**禁虚构变量名**：写规则前先 `rg` 该名字是否真有叶子；`var(--x, fallback)` 的 fallback 也必须是真实叶子。

**踩坑（实测）**：深色带里放浅色卡片时，**不要**在深色带上重绑 `--color-text` 家族——卡片会被洗成浅字压白底。正确做法：浅卡显式用固定墨阶 token（如 `--{brand}-text-ink`），深带标题显式写 `color: var(--color-text-on-dark)`（全局 `h1..h6{color:var(--weline-theme-text)}` 会盖掉继承色）。

## 3. CSS 加载与合并（最容易「改了没生效」）

前台 head 顺序（`ThemeHeadChromeCssPack`）：

```
layout-critical（内联，FOUC 守卫）
→ PACK_TOKENS      : 默认层 variables/_spacing|_auto-literals|_typography + colors/_default|_ink|_light|_dark
→ PACK_STOREFRONT  : foundation + weline-frontend + theme.css + disk override
→ disk override link
→ PACK_OVERLAY     : 主题私有叶（common + 当前 layout_type）
```

- **PACK_TOKENS 只认默认层文件名**：品牌色盘 `colors/_{brand}.css` 与自定义 `variables/_{brand}.css` **不会**自动进包，必须写进 overlay 清单。
- 主题私有叶清单：`{area}/partials/head/theme-head-css-overlay.php`，返回
  `['common' => ['theme/frontend/colors/_{brand}.css', …], 'layouts' => ['homepage' => ['theme/frontend/assets/css/{brand}-landing.css']]]`。
  `common` 每页加载；`layouts[{layout_type}]` 只在该布局加载。
- `theme_css_merge` 在本框架版本恒为 on（auto/on 都为真），所以 overlay 会合包；保留 skin partial 兜底时用 `themeOverlayAbsorbed(PACK_OVERLAY)` 判断，避免双 link。
- **design 禁同 key 覆盖** `assets/css/theme.css` / `assets/js/theme.js`（那是全局运行时入口）。
- `theme.css` 属默认层架构 CSS：只写布局骨架/表面机制/Token 侧效应，禁品牌风格壳。

**踩坑（实测）**：改完主题 CSS 用浏览器验收，URL 必须带 `_wb_nc=<时间戳>`；只带 `w_fpc_pierce` 时店面会继续返回钉着旧 pack 哈希的 layout-projection HTML，看到的是旧样式（很容易误判「选择器无效」）。

## 4. 布局 CSS：骨架先行（硬顺序）

1. **骨架**：`.{brand}-shell`（版心）、band 竖排节奏（`--{brand}-space-section`）、栅格列数、容器 `min-width:0`。
   - 版心只消费 `width: min(100%, var(--weline-layout-content-max-width)); margin-inline:auto; padding-inline: var(--weline-layout-content-padding-inline)`。
   - **禁** `calc(100% - Npx)`、禁按断点各写一套 gutter（header/正文/footer 会不同构）。
2. **关键 CSS 上折**：首屏可见部分放内联或 `layout-critical`；长尾放 overlay 叶。
3. **皮肤**：色/字重/描边/阴影/悬浮态；再上动效。
4. **反色带**：背景与前景成对（见 §2 踩坑），并给 `data-surface="inverse"` 场景补前景变量。
5. **长页背景**：不用整页大渐变（8bit 量化成色带），要纹理走 canvas token 或 ≤240px 无缝小图。

## 5. 响应式：单一权威

- 同一组件的断点只在一个文件声明一次；命中 design 覆盖后默认层不再参与该页面行为。
- `@media` 条件里**不能写 `var()`**（整条静默失效）；断点写真值。
- **JS 禁自行适配断点**：不得 `matchMedia`/`innerWidth` 判布局；只能读 CSS 已表达状态（`getComputedStyle(toggle).display`）。
- 中文大标题别用 `text-wrap: balance`（会把「变成」断成「变/成」）；靠字号 clamp 与列宽控制换行。

## 6. 图片与媒体

**格式与预算（权威：规则/40 §4 + `web_images_webp_compressed`）**

| 用途 | 长边 | 体积预算 | 备注 |
|---|---|---|---|
| 内容图 / 商品图 | ≤1600px | ≤200KB | 视网膜 ≤2×，禁放大 |
| 缩略图 / 卡片图 | 按展示尺寸 | ≤80KB | 同一张图按比例派生 |
| Hero / Banner | ≤2560px | ≤350KB（**主题 banner 实践目标 70–120KB**） | 保证清晰度前提下取小 |
| 图标 / logo | — | ≤30KB | 优先 SVG；位图才 WebP |

- 终态一律 `.webp`（PNG 仅在真 alpha 且消费端不支持 WebP、favicon/.ico、用户明确要求时保留）。
- 原始大图只作源文件：不进 `pub/media`、不直上页面。
- `<img>` 必须带 `width`/`height` 或容器 `aspect-ratio`（防 CLS）；非首屏 `loading="lazy" decoding="async"`。
- 商品/媒体图缺失 → `StorefrontImagePlaceholder::resolve()` 的**静态 SVG**；**禁止** `data:image/*` 直出。

**主题自有静态**

- URL：`/static/{Vendor}/{theme}/{area}/assets/images/...`（ns 路径，不带 build 前缀）；CSS 里图片 `url()` 由打包重写回该路径。
- 需要缓存破坏时用 `?v=<内容指纹>`（mtime+size 短码），禁手写 `@static?v=`。
- 图片资产**不随 CSS 合包发布**；新增图片要在发布后 `curl` 验 200，未验证前优先用纯 CSS 纹理/占位，避免 404。

## 7. JS 开发

- `weline.js` 只是**加载引擎**：`Weline.declare/load`、`data-weline-load|declare`、`data-weline-mount`、`Weline.dom.observe`；禁在 `weline.js` 里写业务或业务名单。
- 业务模块 JS 由所属模块 `weline.modules.js` 注册；模板里**禁**裸 `<script src>` / `@static(...js)` 拉模块脚本。
- 主题自己的 JS 用 `<theme:js>Weline_Theme::theme/{area}/assets/js/{brand}-*.js</theme:js>` 挂盘；主题 JS 只做本主题呈现（导航态、轮播、粘性），不做业务取数。
- 浏览器业务 I/O 只走 `Weline.Api.*`（BinQuery）；禁 `fetch`/`XHR`/`axios`/`$.ajax`。
- 观察 `document/documentElement/body` 的 DOM 变更走 `Weline.dom.observe`（共享总线），禁裸 `new MutationObserver`。
- 动效：只做 transform/opacity；`@media (prefers-reduced-motion: reduce)` 里关过渡。
- 模板内 PHP 闭包**禁止** `static fn` 捕获 `$this`（WLS worker 静默空响应），用普通匿名函数。

## 8. 部件（widget）与组件（component）

| 层 | 职责 | 落点 |
|---|---|---|
| layout | 页面骨架 + slot/hook | `layouts/{layoutType}/{option}.phtml` |
| partial | header/footer/head 等可切换壳 | `partials/{type}/{option}.phtml` |
| component | 无业务 UI 原语 | `components/*.phtml`（+ Weline UI `w-*`） |
| widget | 可视化可拖拽运营块 | `widgets/{type}/{code}/default.phtml` + `@widget.*` |

- 部件参数：`@param 参数名 {default=,type=,label=,description=}`（**空格分隔**；`@param.` 点号格式只对主题 partial 生效，部件配置不解析）。
- 布局内嵌只允许 `Weline_Theme` 自己的部件；跨模块一律「空槽 + 拥有模块 JSON `default_injections`」，同身份 XOR，禁双路径。
- **默认注入经布局固化**：无 `user_deleted@{versionId}` 且槽存在时，required JSON 注入必须固化进布局模板；省略即漏装（省略理由只有本版本人工卸载）。
- 部件静态资源（`layout-source` / `source`）由布局 bake 到 head 统一去重；禁部件内联 `<style>`/可执行业务 JS。
- 新主题首页建议保留默认布局全部 slot id/accept 与 hook：兜底内容换成自己的 section，widget 仍可覆盖（功能对等）。

## 9. phtml 的 meta 与参数

```php
/**
 * Layout: {layoutType} {option}
 *
 * @meta.name {default="…",name="…",description="…"}
 * @meta.cache.mode {default="chrome",name="缓存模式"}
 * @meta.cache.auth {default="guest",name="鉴权维度"}
 * @meta.cache.ttl {default="300",name="新鲜期秒"}
 * @param.title {default="",name="页面标题",description="留空取站点名"}
 * @param.meta_title {default="",name="SEO标题",description="有实体 SEO 时不覆盖实体"}
 * @param.{media_key} {default="",name="图片",description="留空走主题内 CSS 占位"}
 */
```

- 取参：`$meta = $this->getData('meta') ?? []`，随后 `$meta['x'] ?? $this->getData('x')`；改完 `$this->assign('meta', $meta)` 再渲染。
- 必须保留的开关：`showHeader` / `showFooter`（缺省会掉 chrome）。
- section 身份：`<section … weline-code="{vendor}.{page}.{block}">`；`w:slot wrapper="section"` 也必须带非空 `weline-code`；改后跑 `frontend:check-section-code`。
- slot：`id` / `name` / `accept` / `multiple` / `exclusive` / `reject` / `wrapper` / `class` / `position` / `append`；兜底内容放在 `<w:hook>…<else/>…</w:hook>`。
- 文案：源串写中文，双语走模块 i18n CSV 或主题内 `['zh'=>…,'en'=>…]` 成对；`WidgetI18n::label()` 解析词典，非中文 locale 无词条时回落英文。店面语言切换以 **URL path** 为准（`/de_DE/…`），只读 `getLangLocal()` 会回落站点默认语言。
- 品牌/站名取 `SiteBrand`，不要硬编码站名。

## 10. 验收（可机器判定）

```bash
php bin/w theme:install -t {theme}        # 或 setup:upgrade
php bin/w theme:listing                  # 出现 id/name/parent
php -l <每个改动的 php/phtml>             # 模板 PHP 段落也要过
php bin/w frontend:check-section-code
php bin/w frontend:check-theme-layout-widgets
```

浏览器（ego / 无缓存）：

| 判定 | 阈值 |
|---|---|
| 页面 200 + `body` 主题类 | 必须 |
| `documentElement.scrollWidth == innerWidth` | 无横向溢出（1440/1024/390 三档） |
| 文本对比度（computed color + 祖先合成背景） | 正文/标签 ≥4.5:1；≥24px 大标题 ≥3:1 |
| `img.naturalWidth === 0` 数量 | 0 |
| 英文站 mf/section 内 CJK | 0（zh 页为中文属应然） |
| PHP 警告 | `Warning/Deprecated/Fatal` 计数 0 |

交付 URL 必须带 `w_fpc_pierce`；改过静态再叠 `_wb_nc=<时间戳>`。新站验收地址：`https://<池子域>/~site/<code>/`（裸域回落默认站）。

## 11. 常见失败模式（全部实测过）

| 现象 | 根因 | 正解 |
|---|---|---|
| 改了 CSS 页面没变 | 取到旧 layout-projection（旧 pack 哈希） | URL 加 `_wb_nc`；必要时 `cache:clear --no-warm` |
| 品牌色盘写了不生效 | 文件名不在 PACK_TOKENS 白名单 | 写进 `theme-head-css-overlay.php` 的 `common` |
| 深色带标题看不见 | 全局 `h1..h6` 的 color 覆盖继承 | 反色带标题显式 `color: var(--color-text-on-dark)` |
| 浅卡片文字发白 | 深色带重绑了 `--color-text` 族 | 浅卡用固定墨阶 token |
| 首屏标题断在词中 | `text-wrap: balance` + 中文字号过大 | 去 balance，调字号 clamp/列宽 |
| 主题图片 404 | 设计主题资产未发布 | 发布后 curl 验 200；上线前用 CSS 纹理 |
| 新站裸域显示别的站 | 项目 Host（8 位 hex）裸域按设计归默认站 | 用 `/~site/{code}/` 或非空 `sub_path`；要裸域直达换非项目主机并完成 hosts+证书授权（§0.2） |
| 「没有建站」但表里有 website/store/domain | 把裸项目主机当成自建站入口 | 先看 `data-website-id` 命中哪个站，再按 §0.1 三元组核对 |
| 还原站点主题报「版本不属于当前范围」 | `bindThemeForWebsite` 按当前 storage scope 校验 | 走 `ThemeApplicationInterface::save()` 按原引用五字段 CAS |
| 自包含模块页（如 `/app/download`）在所有站都长成某一个设计主题的皮 | 页面不挂主题 Token，CSS 里写死品牌色兜底（纸色/朱红/serif），Token 永远取不到 | 模块页也挂 `PACK_TOKENS` + `PACK_OVERLAY`（不挂 storefront 皮肤），CSS 只消费 `--color-*`（`--weline-theme-*` 的映射在 `theme.css`，不挂 storefront 时不存在），字体用 `--weline-font-display`；设计主题靠 overlay 自动继承，模块里不写品牌色 |
| 某个设计主题想改自包含页观感 | —— | 在 `app/design/{Vendor}/{theme}/{Module_Code}/templates/{area}/…` 同 key 覆盖模块模板；能靠色盘继承就不要复制整页 |
| 原生部件（如 `newsletter-popup`）在所有站都长成某个设计主题的皮 | 默认部件模板里把"品牌资产"当默认兜底（如古风宣纸 webp），等于把品牌皮写进模块；部件契约测试还把它钉成断言 | 默认部件的 `@param` 图默认留空、模板用 `hasXxx` 条件渲染（无图走 Token 卡片降级）；品牌皮由设计主题的**覆盖 CSS 叶**自绘并登记进 `theme-head-css-overlay.php` + skin 兜底；同时把契约测试里"默认必须含品牌资产"的断言改成"默认不得内置品牌资产" |
| 设计主题里已写好品牌覆盖叶但没生效 | 叶文件存在、却漏登记 overlay/skin 清单 | 登记到 `theme-head-css-overlay.php` 的 `common`（或对应 layout 桶）+ merge=off 兜底的 skin partial；用 `curl` 取站点 CSS 包 `grep` 规则确认已进包 |
