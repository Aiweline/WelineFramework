# 部件静态资源固化规范（硬）

> 权威：店面部件 CSS/JS 静态文件须经 `w:widget` 属性（或等价 `@widget.*` 元数据）声明，在**布局固化（bake）**时汇入资源闭包，按声明位置统一去重排放。  
> MCP：`widget_static_assets_bake_to_head`；配套 [部件开发指南.md](./部件开发指南.md)、[前端JS模块加载规范.md](./前端JS模块加载规范.md)。

## 1. 属性契约

标签：`<w:widget>`（Taglib `widget`）。

```html
<w:widget type="demo" name="demo"
  layout-source="Weline_Demo:widget/demo.css,Weline_Demo:widget/demo.js"
  source="Weline_Demo:widget/demo-normal.css,Weline_Demo:widget/demo-normal.js"
  source-postion="footer"
  />
```

| 属性 | 含义 | Bake 后 |
|------|------|---------|
| `layout-source` | 布局/壳关键（LCP、防塌缩、chrome 几何） | 早挂 head（layout 桶，优先于常用） |
| `source` | 常用部件静态资源 | 按资源位置正常加载（常用桶；同 URL 与 layout 去重） |

- 值：逗号分隔的 `Vendor_Module::相对路径`（与 `@static` 模块路径同形）。
- **禁止**在 path 上自带 `?v=` / `#fragment` 当缓存戳；版本由 `Template::fetchTagSource` 统一追加。收集器会剥掉 query/hash，但声明侧应写干净路径，避免误以为戳生效。
- 按扩展名分流：`.css` → `<link rel="stylesheet">`；`.js` → 指定位置的外部 `<script src>`（**仅**本 bake 清单通道）。
- 模板注释等价元数据（注册表 / 注入规划可读）：`@widget.layout_source {...}`、`@widget.source {...}`（语法同属性值）。布局标签未写属性时，bake 回落注册表默认。

### 资源位置与优先级

`source-postion` 为公共属性，`source-position` 为兼容别名；两者同时出现时 `source-postion` 优先。节点、注册元数据与资源闭包内部统一字段为 `source_position`；模板元数据使用 `@widget.source_position {footer}`。未声明时默认 `head`。

| 位置值 | 输出位置 |
|------|------|
| `head` | head 内普通资源区 |
| `body` / `end-body` | 同义，结束 body 标签前 |
| `footer` | 结束 footer 标签前；页面无 footer 时落到 body 末尾 |

`layout-source` 固定提前在 head 输出，不受普通资源的位置选择影响。同一 URL 只发射一次，layout 声明优先于 source；同一普通 source 多位置声明按 head → footer → body 的优先级保留一份；不得因普通资源先被发现就丢失布局优先级。前台正式页、版本预览和编辑器动态部件须使用相同语义。

所有部件 CSS 与可执行 JS 必须外置；禁止 `<style>`、内联可执行 `<script>`、`style=` 和 `on*=`，不按大小、是否含 PHP 或主辅路径放行。实例配置通过 `data-*` 等纯数据通道传递，由外部脚本读取，不拼接执行代码。纯 JSON 数据不是可执行 JS，但优先使用数据属性。

## 2. 主路径：PHTML 声明与正常资源发射

按照[纯 PHTML 固化合同](./布局固化与默认注入.md)，固化目录不再生成 page-assets.json / chrome-assets.json。部件调用在 PHTML 中保留显式资源声明或现有注册表声明的引用；正常模板执行使用现有统一资源发射器，按 head/footer/body 位置输出并去重，layout-source 优先级不变。

固化时需要解析的节点资源属性随显式参数写入对应调用，不另外保存资源清单文件。动态业务产生的正常资源声明继续走同一发射器，不借资源处理重新播种布局、查询注入计划或调整部件顺序。

| 允许 | 禁止 |
|------|------|
| 复用正常部件/模板资源声明及指定位置输出 | 新增 assets sidecar 或为资源重新解释整棵布局树 |
| 同 URL 规范化去重，保留执行/级联顺序 | 模板裸资源标签，以及任何内联 CSS/可执行 JS（含 style= 与 on*=） |
| 参数或声明变化时重生成相关 PHTML | 删除公共资源或 required 部件以简化热路径 |

## 3. 与 `data-weline-load` 边界

| 通道 | 用途 |
|------|------|
| `layout-source` / `source` | 部件**静态文件**（Module::path），bake → 指定位置 |
| `data-weline-load` / `weline.modules.js` | **业务模块名**编排（Cart/Account/…），ModuleLoader |

禁止用模板手搓 `<script src="@static(...js)">` 拉业务模块。  
**书面例外**：经 `layout-source`/`source` 声明且 bake 进闭包的 `.js` 静态文件，允许由统一资源发射器输出一次 `<script src>`（见 `theme_js_module_declare_only` 例外说明）。禁止借例外在模板内任意插 script。

## 4. layout-source 滥用门禁

默认仅 **chrome / header / footer / navigation（及主题白名单 code）** 可标 `layout-source`。  
content / product 货架等乱标 → 契约 FAIL。防首屏 link 膨胀与 head 袋污染。

## 5. 失效矩阵

| 变更 | 动作 |
|------|------|
| publish / 结构或参数写 / 注入收集 | BakeCoordinator 重生成受影响 PHTML 并失效相关资源缓存 |
| 改资源/位置属性或等价 `@widget` 元数据 | `widget:refresh` + 相关闭包失效 |
| 静态文件路径 / 编译产物 URL | `resource:compile` 后 stamp/fp 变 → 重 bake 或 bust |
| `user_deleted@{versionId}` | 从闭包剔除对应 deps |
| design 品牌 CSS | 外挂 disk override；**禁**进 layout 闭包覆盖 `theme.css` |

## 6. 预览与 FPC

- 编辑器 sanitize 可能剥 body `link`/`script` → 预览须消费 bake/位置分发同构通道或 Editor 补种，禁止只靠 body 内嵌 link。
- FPC：闭包进最终 HTML；缺 marker / 有部件无关键 CSS 的毒页拒发布或作废 HIT。

## 7. 迁移义务

新部件与存量部件**一律**改本方式：静态 CSS/JS 进文件 + 属性/元数据声明；删除模板内所有 CSS/可执行 JS（包括 `<style>`、可执行 `<script>`、`style=`、`on*=`）及裸 `@static` link；`emitStylesheetLinkOnce` 等 once 抄写收敛到统一发射器。


## 8. 资源文件配置与压缩合并

主题编辑器「基础信息」抽屉顶部使用「基础配置」「资源文件配置」双页签，默认显示基础配置。资源设置统一归属 SystemConfig 分组 `theme_resource_files`，按当前 global/website/store/channel 作用范围保存并继承。

点击「资源文件配置」或该分组配置保存成功时，编辑器先完成待处理的编辑保存，再通过现有布局编译入口固化当前选中的布局实体及公共壳资源绑定，成功后刷新预览 iframe。固化沿用当前范围、区域、布局和版本的人工卸载规则，不创建发布版本；iframe 保留原路径、语言和预览状态。固化失败应提示错误，不刷新为旧模板。只有实际保存成功才触发配置更新事件，不能用控件值改变代替保存结果。

| 配置键 | 值与默认 |
|------|------|
| `resource_files/css_minify`、`resource_files/js_minify` | `auto` / `on` / `off`；默认 `auto`（`auto`→开发关/生产开；部件与主题碎片共用） |
| `resource_files/css_merge`、`resource_files/js_merge` | `auto` / `on` / `off`；默认 **`on`**（**部件**：layout 单包 + late source → `/widget-assets/`） |
| `resource_files/css_merge_start`、`resource_files/js_merge_start` | 正整数；默认 **`6`**；编辑器文案为「前段合包部件数」——仅 source：前 N 阻塞合包 / 其后延迟合包；layout 单包忽略 |
| `resource_files/theme_css_merge`、`resource_files/theme_js_merge` | `auto` / `on` / `off`；默认 **`on`**（**主题 head** → `/theme-head/`） |

**合并键**的 `auto` 与 `on` 均**始终开启**（开发/生产）；仅 `off` 关闭。压缩键 `auto` 仍跟环境。压缩与合并独立。部件合包与主题碎片合包开关**相互独立**。

起始序号按页面实际渲染的部件前序计数；默认 **N=6**：**前 N 个** source 合成 **一个阻塞合包**，**第 N+1 个起**合成 **一个延迟合包**（CSS 常带 `media=print` onload）。`kind=layout` 的 CSS 在 `css_merge` 开启时整页合成**一个**阻塞包（忽略起始序号），紧随 theme-head 单包。普通 source 按 CSS/JS 类型及输出位置分别合并，不跨位置；不可合叶子仍保留文件边界。

JS 压缩遇到反引号时保守保留原文。完整无内联与位置契约仍按前文执行。

## 8.1 Head Chrome Pack（主题碎片 CSS / JS）

店面/后台 head 在 **`resource_files/theme_css_merge`** / **`theme_js_merge`** 开启（`auto`/`on`）时：

- CSS：[`ThemeHeadChromeCssPack`](../Service/ThemeHeadChromeCssPack.php) → `pub/static/.../Weline/Theme/theme-head/{sha256}.css`
- JS：[`ThemeHeadChromeJsPack`](../Service/ThemeHeadChromeJsPack.php) → 同目录 `{sha256}.js`（经典槽：`early`=prepaint，`after-css`=css-ready）
- Formal `compileAfterPromote` 落盘 `com_*` 后调用 `warmAreaPacks` 预热产物（热路径只消费已烘焙 link）

| 包 | 内容（顺序固定） | 说明 |
|----|------------------|------|
| **`tokens`** | variables + light/default/ink 色板 | 前台**第一枪**阻塞（变量壳）；不含 foundation/theme.css |
| **`storefront`** | foundation/frontend → **theme.css** → `_dark` | 前台**第二枪**全局基础；产物在**当前主题**静态命名空间 |
| **`overlay`** | design `theme-head-css-overlay.php`：`common` + `layouts[layout_type]` | 前台**第三枪**主题私有叶（按布局）；flat 清单兼容为全站 common |
| **`backend`** | tokens（light/default/dark）→ foundation/backend → theme.css | 后台仍单包阻塞 |
| `tokens-*` / `ui` | 遗留碎片包常量 | 仅作合包组成/回落参考；模板默认走 storefront/backend |
| `early` / `after-css` | prepaint / css-ready | 经典 JS；**永不**合并 `type=module` 的 `weline-ui.js` |

**主题 overlay（设计主题私有叶）**：各 design 主题自维护 `theme/{area}/partials/head/theme-head-css-overlay.php`。推荐结构：`['common'=>[...], 'layouts'=>['1col'=>[...], ...]]`；flat 清单视为全站 `common`。运行时并入**本主题** `PACK_OVERLAY`（第三枪），按当前 `layout_type` 过滤；基座无清单则不出第三枪。`themeOverlayAbsorbed(..., PACK_OVERLAY)` **仅当本请求已 `tryLinkHtml(PACK_OVERLAY)` 产出 `<link>` 且清单非空**时为真（fail-closed：thin design prefix 有清单却未 emit 第三枪时，skin 仍走 `theme:css` 回落，禁止静默丢皮肤/响应式）。产物 hash 含清单路径 + layout 过滤指纹；`buildHeadChromeArtifact` 必须传入采源主题，禁止写入基座命名空间或跨范围复用。

**源叶子不删**：外观盘 / design 覆盖仍编辑源 CSS；运行时单包可含其字节，**禁止写回**源 `theme.css`。主题碎片开关关闭时 head 回落逐条 `<theme:css>` / `@static`。

## 8.2 Chrome 宿主嵌套 slot 的关键 CSS（升格 layout）

嵌套 slot（如迷你车 `footer-extras` 内的 `storefront-money-summary`）在部件 PHTML 上通常只声明 `@widget.source`。在 `css_merge` 默认开启且宿主出现在第 N+1 个部件之后时，这些 CSS 会进入 **late source 合包**（常带 `media=print` onload），首屏打开抽屉时易出现金额行 flex / 对比度 / compact 金额未绘制的回归。

**机制（归属 `Weline_Theme`）**：

- [`SharedChromeService::CHROME_HOST_NESTED_LAYOUT_CSS_PEERS`](../Service/SharedChromeService.php) — 声明 chrome **宿主** widget_code → 必须阻塞加载的 peer CSS 路径。
- [`ThemeLayoutEntityAssetCollector::promoteChromeHostNestedLayoutCss`](../Service/LayoutEntity/ThemeLayoutEntityAssetCollector.php) — bake 收集节点后，若页面含对应宿主，将 peer 并入 **layout_css**（与宿主 `layout-source` 去重）。

宿主 PHTML 仍可在 `@widget.layout_source` 显式列出 peer CSS（双保险）；**禁止**在 Cart/B2B 主题再复制一份 flex/对比度当主路径。新增同类宿主时扩展 `CHROME_HOST_NESTED_LAYOUT_CSS_PEERS` + 契约测，而非仅改单站 CSS。

**Partials / design 店面壳（硬）**：页头未走 `header-container` 部件时，壳模板须调用 `SharedChromeService::emitPartialsHeaderShellLayoutCssHtml()`（常量 `PARTIALS_HEADER_SHELL_LAYOUT_CSS`）。发出的每条 `<link>` **必须**同时带 `data-weline-widget-asset="layout"` **与** `data-weline-module-source`（与部件 bake `emitHtml` 同契约），`WidgetAssetArtifactPublisher::canMerge` 才能把叶并进整页 layout 包。**禁止**壳上手写裸 stylesheet `<link>`（缺 module-source 时只剩独立请求，绕过 `css_merge`、与部件 layout_source 重复）。

## 8.3 迷你车 chrome 嵌套三轴统一（归属 `Weline_Theme`）

| 轴 | 单一真相 | 改动入口 |
|----|----------|----------|
| 资源 | PEERS → bake 升格 **layout 阻塞包** | `CHROME_HOST_NESTED_LAYOUT_CSS_PEERS` + Collector |
| 壳/护嵌 | `footer-extras` ∈ `MINI_CART_NESTED_CHROME_SLOTS`；solidify **始终** `persistChromePayload`；**建袋**填实进 `storefront_chrome`（schema v25+，含 v24 嵌套填实）；出站 `fillEmptyNestedChromeSlots` **仅安全网** | SharedChrome + Partials + BakeCoordinator + SlotRenderer |
| 生命周期 | 调用方默认 `WelineMiniCartExtras.boot()`；孤儿候选才 `rebuild`（须保留 `preferredIdentity`/`data-active-tab`，禁止无脑 rebuild 打回首签） | `mini-cart-extras-tabs.js` + 调用方（如 B2B selling-mode） |

契约聚合：`MiniCartChromeNestingUnityContractTest`。Checkout/Marketing/B2B 只提供叶子；禁止 design 主题私有复制金额 flex 当主路径。

## 8.4 主题命名空间产物与 hash 跳过

| 对象 | 落点 | 说明 |
|------|------|------|
| 模块叶子 CSS/JS | `pub/static/Weline/{Module}/...` | **共享只读输入**；不按 design 各拷一份 |
| widget-assets / theme-head 合包 | `pub/static/{themeNs}/Weline/Theme/widget-assets\|theme-head/{sha256}.*` | **当前主题**命名空间；`buildWidgetAssetArtifact` / `buildHeadChromeArtifact` 须传显式主题 |
| 布局固化物 | `generated/theme-layout-entities/{themeId}/` | 按主题 id 隔离 |

- **禁止**因部件来自模块/默认主题，就把合包写到 Default 或无主题前缀路径。
- **禁止**「默认只 bake/合包一次、全站自定义主题共用」——会互相踩踏。
- **同内容 hash、目标文件已存在 → 跳过写入**（快路径）；跨主题允许磁盘重复同名 hash，换隔离正确性。多主题升级必须 `ThemeData::setCurrentTheme` 钉住当前主题再发合包。
