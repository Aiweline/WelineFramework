# 部件静态资源固化规范（硬）

> 权威：店面部件 CSS/JS 静态文件须经 `w:widget` 属性（或等价 `@widget.*` 元数据）声明，在**布局固化（bake）**时汇入资源闭包，按声明位置统一去重排放。  
> MCP：`widget_static_assets_bake_to_head`；配套 [部件开发指南.md](./部件开发指南.md)、[前端JS模块加载规范.md](./前端JS模块加载规范.md)。

## 1. 属性契约

标签：`<w:widget>`（Taglib `widget`）。

```html
<w:widget type="demo" name="demo"
  layout-source="Weline_Demo:widget/demo.css,Weline_Demo:widget/demo.js"
  source="Weline_Demo:widget/demo-normal.css,Weline_Demo:widget/demo-normal.js"
  source-postion="footer"
  />
```

| 属性 | 含义 | Bake 后 |
|------|------|---------|
| `layout-source` | 布局/壳关键（LCP、防塌缩、chrome 几何） | 早挂 head（layout 桶，优先于常用） |
| `source` | 常用部件静态资源 | 按资源位置正常加载（常用桶；同 URL 与 layout 去重） |

- 值：逗号分隔的 `Vendor_Module::相对路径`（与 `@static` 模块路径同形）。
- 按扩展名分流：`.css` → `<link rel="stylesheet">`；`.js` → 指定位置的外部 `<script src>`（**仅**本 bake 清单通道）。
- 模板注释等价元数据（注册表 / 注入规划可读）：`@widget.layout_source {...}`、`@widget.source {...}`（语法同属性值）。布局标签未写属性时，bake 回落注册表默认。

### 资源位置与优先级

`source-postion` 为公共属性，`source-position` 为兼容别名；两者同时出现时 `source-postion` 优先。节点、注册元数据与资源闭包内部统一字段为 `source_position`；模板元数据使用 `@widget.source_position {footer}`。未声明时默认 `head`。

| 位置值 | 输出位置 |
|------|------|
| `head` | head 内普通资源区 |
| `body` / `end-body` | 同义，结束 body 标签前 |
| `footer` | 结束 footer 标签前；页面无 footer 时落到 body 末尾 |

`layout-source` 固定提前在 head 输出，不受普通资源的位置选择影响。同一 URL 只发射一次，layout 声明优先于 source；同一普通 source 多位置声明按 head → footer → body 的优先级保留一份；不得因普通资源先被发现就丢失布局优先级。前台正式页、版本预览和编辑器动态部件须使用相同语义。

所有部件 CSS 与可执行 JS 必须外置；禁止 `<style>`、内联可执行 `<script>`、`style=` 和 `on*=`，不按大小、是否含 PHP 或主辅路径放行。实例配置通过 `data-*` 等纯数据通道传递，由外部脚本读取，不拼接执行代码。纯 JSON 数据不是可执行 JS，但优先使用数据属性。

## 2. 主路径：Bake 主 + 请求 Δ 辅

```
节点图 ∪ 计划内 required（减 user_deleted）
  → 解析 layout-source / source / source_position（节点字段或注册表）
  → page-assets.json / chrome-assets.json（sidecar）
  → 店面 head / footer / body 末尾消费（去重；layout 优先）
```

| 允许 | 禁止 |
|------|------|
| 固化算静态闭包，读路径直读 | 每请求重扫全部部件 deps 做主 |
| 请求期仅合并动态 Δ（overlay / 预览 / 个性化 / draft） | 声称「固化后绝对零解析」而丢掉 required Δ |
| sidecar / 指定位置资源片段 | 把唯一真相焊进 `shell.phtml` 或 `chrome.rendered` |
| 同 URL 规范化去重 | 模板裸资源标签，以及任何内联 CSS/可执行 JS（含 style= 与 on*=），不分大小或主辅路径 |

与 `ThemeLayoutEntityBakeCoordinator` / `rebakeAfterInjectionCollect` **同闸**重算闭包。

## 3. 与 `data-weline-load` 边界

| 通道 | 用途 |
|------|------|
| `layout-source` / `source` | 部件**静态文件**（Module::path），bake → 指定位置 |
| `data-weline-load` / `weline.modules.js` | **业务模块名**编排（Cart/Account/…），ModuleLoader |

禁止用模板手搓 `<script src="@static(...js)">` 拉业务模块。  
**书面例外**：经 `layout-source`/`source` 声明且 bake 进闭包的 `.js` 静态文件，允许由统一资源发射器输出一次 `<script src>`（见 `theme_js_module_declare_only` 例外说明）。禁止借例外在模板内任意插 script。

## 4. layout-source 滥用门禁

默认仅 **chrome / header / footer / navigation（及主题白名单 code）** 可标 `layout-source`。  
content / product 货架等乱标 → 契约 FAIL。防首屏 link 膨胀与 head 袋污染。

## 5. 失效矩阵

| 变更 | 动作 |
|------|------|
| publish / 结构写 / 注入收集 | BakeCoordinator 同闸重写 assets sidecar |
| 改资源/位置属性或等价 `@widget` 元数据 | `widget:refresh` + 相关闭包失效 |
| 静态文件路径 / 编译产物 URL | `resource:compile` 后 stamp/fp 变 → 重 bake 或 bust |
| `user_deleted@{versionId}` | 从闭包剔除对应 deps |
| design 品牌 CSS | 外挂 disk override；**禁**进 layout 闭包覆盖 `theme.css` |

## 6. 预览与 FPC

- 编辑器 sanitize 可能剥 body `link`/`script` → 预览须消费 bake/位置分发同构通道或 Editor 补种，禁止只靠 body 内嵌 link。
- FPC：闭包进最终 HTML；缺 marker / 有部件无关键 CSS 的毒页拒发布或作废 HIT。

## 7. 迁移义务

新部件与存量部件**一律**改本方式：静态 CSS/JS 进文件 + 属性/元数据声明；删除模板内所有 CSS/可执行 JS（包括 `<style>`、可执行 `<script>`、`style=`、`on*=`）及裸 `@static` link；`emitStylesheetLinkOnce` 等 once 抄写收敛到统一发射器。


## 8. 资源文件配置与压缩合并

主题编辑器「基础信息」抽屉顶部使用「基础配置」「资源文件配置」双页签，默认显示基础配置。资源设置统一归属 SystemConfig 分组 `theme_resource_files`，按当前 global/website/store/channel 作用范围保存并继承。

点击「资源文件配置」或该分组配置保存成功时，编辑器先完成待处理的编辑保存，再通过现有布局编译入口固化当前选中的布局实体及公共壳资源绑定，成功后刷新预览 iframe。固化沿用当前范围、区域、布局和版本的人工卸载规则，不创建发布版本；iframe 保留原路径、语言和预览状态。固化失败应提示错误，不刷新为旧模板。只有实际保存成功才触发配置更新事件，不能用控件值改变代替保存结果。

| 配置键 | 值与默认 |
|------|------|
| `resource_files/css_minify`、`resource_files/js_minify` | `auto` / `on` / `off`；默认 `auto` |
| `resource_files/css_merge`、`resource_files/js_merge` | `auto` / `on` / `off`；默认 `auto` |
| `resource_files/css_merge_start`、`resource_files/js_merge_start` | 正整数；默认 `6` |

自动模式在开发环境关闭、生产环境开启；显式开启或关闭覆盖环境默认。压缩与合并独立：开启压缩不要求合并，开启合并不要求压缩。这里不引入懒加载。

起始序号按页面实际渲染的部件前序计数，包含嵌套部件、没有资源的部件和声明 layout-source 的部件；默认第 6 个起合并，前 5 个保持独立。layout-source 资源始终独立并提前输出，不因计数或合并阈值进入普通资源包。普通 source 从其对应类型的阈值开始，按 CSS/JS 类型及实际输出位置分别合并，保留原有执行与级联顺序，不跨位置合并。

JS 压缩遇到反引号时保守保留原文，避免改变模板字符串及其插值语义；禁止以破坏行为为代价追求压缩体积。完整无内联与位置契约仍按前文执行。
