## 0. 产品需求冻结（2026-09-28 · 审查修订版）

本节落实产品方最新确认，替代此前的“纯配置写 sidecar”“直接 include”“scope 字符统一替换下划线”等约定。

### 0.1 固化合同

| 项目 | 约定 |
|---|---|
| 输入 | 原布局模板、第三方默认注入声明、指定版本的数据库编辑意图 |
| 产物 | 一份普通派生 PHTML，直接表达调用顺序、嵌套、显式参数及语言差异 |
| 编辑触发 | 新增、移动、卸载、普通参数修改、语言配置修改均同步重固化受影响模板 |
| 模板选择 | 有对应派生 PHTML 就选择它；没有就选择原布局；随后统一走正常 Template/Taglib/语言 com_* |
| 身份 | theme、area、规范 scope、storeMode、版本 V、模式、修订 R、layoutType、layoutOption、target 全程传递 |
| 模式投影 | 版本 owner 的规范 scope 与 storeMode 分开存储；运行时布局解析转入旧范围接口前，必须按显式 store_mode 编码范围，不能丢弃 test/dev 并按 normal 校验 |
| 预览身份 | Token 的规范 scope、store_mode 与已校验的 editor_context 一致；该编辑身份对应的规范范围和旧编码范围都可作为同一范围的投影，其他范围仍拒绝 |
| 数据 | 数据库保留编辑意图和版本历史；正常命中固化模板不查库重新播种部件位置 |
| 文件 | 根为 generated/theme-layout-entities；仅 PHTML，无结构/配置/绑定/资源 JSON 或结构 JS |
| 无需固化 | 没有编辑意图、配置覆盖和有效注入时使用原模板；用户明确卸载全部部件仍属于有效编辑意图 |
| 更新 | 系统/主题更新：每个范围只重建**当前生效**版本。无独立主题应用、也无编辑意图的 store/channel **沿用上级网站产物**，不预固。网站级改动只固网站级。注入变更可另含该范围当前草稿。 |

### 0.2 可读模板目录

```text
generated/theme-layout-entities/
  {theme_id}/{area}/scope/{scope分段编码}/mode/{storeMode编码}/
    draft/ 或 v{N}/
      pages/layouts/{layoutType}/{option}.phtml
      pages/layouts/{layoutType}/{option}/sources/{Module}/{原正文路径}.phtml
      pages/targets/t-{targetType编码}/i-{targetId}/layouts/{layoutType}/{option}.phtml
      theme/partials/{type}/{option}.phtml
```

scope 按规范段分别编码，保留连字符、下划线、大小写与段边界；长段按可逆分块规则落盘，避免文件系统单段长度限制。不得把 shop-a 和 shop_a 变成相同目录。layoutType 与 option 分别保留，如 homepage/default.phtml、checkout/default.phtml。V/R 是选择与缓存身份，不额外创建永久 R 目录或 JSON 清单。

### 0.3 生成与执行分工

生成阶段解析默认值、主题参数、实例参数和各语言差异，固定部件关系。PHTML 的语句顺序就是执行顺序，PHP 数组仅存部件参数，不存整棵布局树交给运行期解释。

运行阶段使用现有组件注册表和渲染分派，保留文件模板、虚拟模板内容及 Block。已解析参数不再被当前 ThemeData 默认值覆盖；媒体类型还原、商品查询和业务逻辑照常执行。默认语言参数与编辑器的语言专属图片等差异同存 PHTML，缺少语言覆盖时继承基础参数。com_* 继续负责正常模板语言编译。

原 PHP、Hook、条件、Partial、属性和资源机制保持正常。关系转换同时支持 w:slot 与 data-wslot，只修改对应关系片段，不清空整槽以重建页面。嵌套槽使用组件实例局部回调，并隔离请求/Fiber；不通过输出 HTML 扫描重新安放部件。

源码内嵌的原生 `w:widget` 也是组件槽的拥有实例，即使本版本没有保存其布局节点，也必须承接声明的 required 子注入。生成阶段先识别这些源码实例，再走指定版本的主题参数、语言差异和默认值冻结；子调用显式写入该实例的 `renderResolved` 回调。重复原生实例按原调用位置和 ref 独立绑定，已保存实例不重复生成。原参数中的 PHP/模板表达式在原作用域求值后合入冻结参数，运行期不借原生分派重新合并当前主题默认值。

布局中的字面模块 `fetch` / `fetchHtml` 依赖也在生成阶段独立编译为普通 PHTML；有 target 的依赖沿用同页 target 路径。控制器只进行一次正常布局 `fetch`，在正文执行前选择并捕获依赖源，随后包一层布局；已有 `meta.content` 时不执行正文 fallback。公共 Partial 的字面依赖保持共享，缓存使用已捕获字节与版本身份。依赖更换或页面删除时，旧依赖在同一个可补偿发布批次中移除；仍被其他公共 Partial 引用的依赖保留。历史候选仅在内存中使用，普通请求不生成、补播种或通过 HTML 补位。

### 0.4 正式发布与语言 com_* 门禁

Theme 固化物（`generated/theme-layout-entities/`）**不是常驻源**，随正式版本发布才存在。正式（formal）发布合同：

1. 落盘本批派生 PHTML（实体字节）；  
2. 调用 Framework `TemplateCompileService`，按默认站已启用语种（含 zh_Hans_CN + en_US）与默认币种，对本批 page / public partial / 布局字面 `<w:widget>` 模板编译语言 `com_*.phtml`；  
3. **两步都成功**才算发布成功；编译失败则回滚已 promote 的实体字节，不得对外密封半吊子版本。  

草稿（draft）只写实体、不挡编辑保存。`com_*` 仍是 Template 编译缓存，不是永久权威、不是语种 HTML 快照。CLI/`s:up`/`theme:upgrade` 须用 `Printing` 分别输出「主题布局预固化」与「主题布局语言编译」进度。店面：有密封实体则选中并 include 对应 `com_*`；无实体则回落人工布局模板（§0.1）。

## 1. 一句话

**适用边界（2026-09-25 收口）**：本文“无卸载必装”针对 `required=true` 的默认安装项；`required=false` 或未标 required 的推荐项仍按 `REQ-THEME-0014` 由用户显式安装。推荐项一旦成为用户配置，固化和版本继承须保留；不能因为存在 JSON 声明便自动强装所有推荐项。现有 `RequiredDefaultInjectionContract::requiredForPage` 与 `WidgetDefaultInjectionService` 已按 required 区分，本文不再作相反承诺。

JSON `default_injections`（应用部件默认注入）在**固化布局模板**时写入对应布局的固化产物；**只要声明槽存在且没有人工卸载**，就必须被固化进去——与主题版本号、是否「当前激活」无条件关系。店面遗漏默认部件，优先判定为**固化方案/触发时机出问题**，而不是「可选的运行时补丁忘了跑」。

**固化写的是关系模板，不是渲染快照（硬）**：编译/固化把 slot 与部件对准坑位、对接身份与显式参数，形成派生 PHTML，再由正常模板系统产生 `com_*.phtml`；**禁止**把某次请求的部件 HTML 烘焙进模板。部件 HTML 在请求期经现有组件渲染器产生，固化调用使用显式参数的 `renderResolved`。原生 Widget 标签保留其原有能力。

## 2. 应用部件默认注入（JSON）

### 2.1 谁走这条路

- 跨模块外国部件进入店面的**唯一合法路径**：拥有模块在 `widget.php` / `@widget.default_injections` 声明注入；宿主布局只留空 `<w:slot>`。
- 同模块 XOR：布局已 `<w:widget>` 内嵌 ↔ **禁止**再写同部件 `default_injections`（见部件开发指南）。
- **Theme 边界（严重 · 2026-10-07）**：Theme 提供槽 / 固化 / 注入**机制**，不提供外模块页面主内容。禁止 Theme 用 required `default_injections` 把 Customer 登录等业务 path 页「空挂」到 Theme（反例：`form/account-login` → `foreign-theme-account-login` 独占主区）。外模块主内容由拥有模块布局 content/`fetch` 承载；Theme 可选装饰部件不得 required。权威：[theme-mechanism-not-foreign-content.md](./开发/spec/theme-mechanism-not-foreign-content.md)。

### 2.2 固化时是否注入（硬）

| 条件 | 固化时是否写入布局固化模板 |
|------|---------------------------|
| `required=true` 且**没有**本版本人工卸载 `user_deleted@{versionId}` | **必须注入**（主题重写布局、删改继承、槽被裁掉都不豁免；Theme 须保证/合成声明槽宿主，如 `storefront-float-*`） |
| 存在 `user_deleted@{versionId}`（人工卸载） | **不得**再注入 |
| 主题是否激活、主题版本号、发布壳是否「看起来完整」、design 是否改写 Footer/首页 | **无关** — 不得据此省略 |

口令：

1. **唯一省略条件** = 人工卸载记录 `user_deleted@{versionId}`。  
2. **与主题 / 版本 / 布局改写无关**：JSON 默认应用部件必须出现；声明槽被 design 裁掉时 Theme 须合成宿主（如 float 层）并仍注入。  
3. **required 与否**：`required=true` 为开箱默认安装；未标 required 或 `false` 为推荐项，只有显式安装后才成为用户意图参与固化。不能把推荐状态误当成必装状态。

### 2.3 计划账本与入库 / 读库（硬）

三层模型：

| 层 | 载体 | 职责 |
|----|------|------|
| 代码声明 | 模块 `widget.php` / `@widget.default_injections` | 采集源（仅入库冷路径扫描） |
| **计划账本** | `widget_registry_entry.default_injections_json`（`has_default_injections=1`） | **固化时读计划的唯一真相** |
| 决策表 | 目标为版本修订的 `theme_scope_version_widget_decision`（旧表只作迁移输入） | 人工卸载等运营决策 |
| 磁盘固化 | 主题+版本身份下的页面及公共 Partial **模板**（§0） | 店面按控制器模板加载 |

**入库触发**（均走 `WidgetRegistryRefreshService::refresh` → 扫码写账本；有变更则 `widget_install_after` → `rebakeAfterInjectionCollect`）：

| 触发 | 入口 | `collection_source` |
|------|------|---------------------|
| 系统 Setup 升级后 | `Weline_Widget` `SetupUpgradeAfter` | `setup_upgrade_after` |
| 模块 install / upgrade | `ModuleInstallAfter` / `ModuleUpgradeAfter` | `widget_registry_refresh` |
| 定时 | Cron `widget_registry_refresh`（`20 * * * *`） | `cron_widget_registry_refresh` |
| CLI | `php bin/w widget:refresh` | `widget_refresh_command` |

**读计划**：

- **允许**：bake / rematerialize / rebake → `DefaultInjectionPlanRepository::listDeclarations`（读库，请求级 memo）。
- **禁止**：完整已固化店面请求每请求查计划 / 扫 Catalog / 跑 `WidgetScanner`。
- `ThemeComponentCatalog` / `generated/widgets.php` 仍服务编辑器可放置清单；**必装计划不再经 Catalog**。

### 2.4 遗漏时怎么归因

若店面应有的默认应用部件未出现：

1. **先查固化**：该主题（及应有的其它主题）下，对应 `layout_type` 的固化模板是否缺失、过期、或固化时未纳入 `default_injections`。  
2. **再查账本**：`widget_registry_entry` 是否已入库计划（升级 / cron / `widget:refresh` 是否跑过）。  
3. **不要**把「发布壳完整 / `+skip_fill_solidified` / 编辑器不回填」当成可以丢必装的合法理由。  
4. 普通请求缺少对应派生文件时使用原模板；编辑保存、升级或注入收集负责重建。禁止通过运行时改写 HTML 补洞，授权历史预览只能用其精确 V/R 输入在内存中重编（见 §3）。

## 3. 模板生成、保存与读取

### 3.0 普通派生模板

Materializer 从当前源模板生成 PHTML，仅变更编辑和注入涉及的部件关系片段。未编辑默认节点保留源顺序；编辑节点使用保存后的明确顺序。同一实例只有一个位置，同名槽在不同组件实例中互不干扰。Hook 及其默认分支保持原语法层级。

固化调用显式携带模块、类型、代码、node_uid、已解析配置、语言差异和子槽回调。保留现有组件注册表、类型值还原、模板/虚拟内容/Block 派发。原生 Widget 的公开语法不承担所有主题组件类型。

解析器只选择源模板。禁止跳过普通 Template 流程直接 include 固化文件。页面、Partial 和组件内容统一经过普通 Taglib 和对应语言 com_*，保留原路径上下文，确保 $this、相对引用、资源与翻译正确。

### 3.1 缺少派生模板

没有对应派生模板时选择原布局。编辑保存、升级及注入收集负责生成需要固化的模板；有合法持久输入的缺失产物可由生成入口恢复。恢复仍生成 PHTML，不在输出 HTML 上 Overlay/heal 补洞。

### 3.2 保存与并发

- 结构、配置及语言配置保存都重新生成候选；相同输入产生相同字节，未变时不重复写文件。
- 同 owner 的写入口共享互斥范围，基于真实数据库 R 检查冲突；锁不能按 R 分裂，也不能只凭 PID 把并发 Fiber 视为重入。
- 页面及受影响公共 Partial 先全部生成，再在临界区完整替换；普通写入失败恢复已替换文件。若数据库已保存，返回实际修订及固化失败，禁止报成功或谎称回滚。
- 参数保存接口同样返回 `saved_revision`：已提交的固化失败包含 `database_saved`、`artifacts_saved`、`actual_revision`、`actual_content_revision`、`theme_version_id` 和 `revision_id`；提交前失败不报告已保存修订。客户端须根据真实回执重新读取当前状态。
- 请求在同 owner 的短读锁内固定页面和已有公共 Partial 的源字节；释放后再执行业务。编译摘要来自同一次读取，com_* 原子替换且正确隔离语言和必要版本上下文。
- V/R 通过已有资源快照明确指向资源修订/发布引用；首次草稿同样留下可重放基线。旧 Token 不读取最新草稿；缺失历史依据时如实报告。

### 3.2.1 稳态读取

命中固化 PHTML 后，运行期不再查布局配置/结构侧车、不查默认注入计划补洞、不重新排序。允许正常身份解析、组件注册信息、媒体还原和业务数据查询。公共 Partial 不得从当前 ThemeData 重新覆盖历史参数。

编辑器打开、读取工作区、刷新与切换语言同样不自动写入默认节点，也不推进内容/资源修订。旧 `reconcile-required-defaults` 接口只返回当前工作区，保留给缓存中的旧客户端；显式「应用」和插槽「初始化」仍可安装默认部件。required 的存在性由生成阶段按该修订的卸载意图合并保证，不能通过读取后的逐节点保存来补齐。

### 3.3 注入变化与删除

插件声明新增、修改或删除时，取变更前后受影响布局的并集，对相关主题、版本和草稿重固化。无人工卸载的 required 默认必须入槽；推荐项只有被显式安装后参与固化。

布局已无任何持久编辑意图、配置覆盖或有效注入时，删除对应派生模板并失效缓存，使原模板重新成为来源。明确卸载默认部件或卸载全部部件仍是有效意图，不能按节点数量为零判定为“没有编辑”。

### 3.4 部署生命周期 → 自动固化全部主题布局模板（硬）

> **2026-09-28 产品冻结**：废止「升级只 purge、靠首访惰性、非激活可不固化」作为目标。系统更新须**主动固化所有主题**的布局模板。

下列命令在**成功收尾**后须完成布局模板固化（同进程去重，避免 setup 内嵌 deploy 双跑）：

| 命令 | 要求 |
|------|------|
| `php bin/w setup:upgrade` | 自动固化**全部主题**布局模板 |
| `php bin/w deploy:upgrade` | 同上（与 setup 去重） |
| `php bin/w core:update` | 同上（与上列去重） |
| `php bin/w theme:upgrade`（或等价） | **`-t` 指定主题**或**省略则全部**更新布局固化模板（可与静态资源升级同入口） |

物化输入（每次固化）：

1. **当前**布局源文件信息（§0）  
2. 指定 V/R 的主题编辑信息 / 版本用户意图（含目标 V/R 卸载决策）  
3. **当前**计划账本必装 JSON（无卸载则写入）  

口令：

1. 固化的是**模板**（主题+版本身份），不是语种 HTML 快照（§0）。  
2. **不**删除数据库布局/草稿/版本/决策；写出位置必须是 **`generated/theme-layout-entities/`**（§0），不是 `var/`。  
3. 顺带清理主题相关 FPC/HotCache，避免吐旧 HTML。  
4. 普通请求缺少派生文件时按 §3.1 使用原模板。**例外（2026-10-07）**：店面非 editor/preview 路径由 `ThemeLayoutEntityRequestSolidifyGate` 比对注入指纹 / 关键槽（含迷你车 `footer-extras`）/ 派生产物；过期、缺失或同 serial_key **pending** 时：**幂等入队异步重固**（`ThemeLayoutEntitySolidifyQueue` + `PostResponseTaskQueue`），**本响应回落原模板**，禁止读旧派生与半成品。同 `theme|area|scope|storeMode|layoutType|layoutOption|V|R` **串行**；不同 layout 允许 Fiber 并发。授权历史预览可按精确 V/R 的既有引用生成内存候选，仍不替代系统更新预固化。  
   **补（2026-10-08）**：无布局实体意图时 bake 可对页面候选写 `path=>null`（故意不生成派生、继续源模板）。stamp 与注入指纹一致后，**不得**再仅因缺派生 PHTML 反复入队；关键槽空（footer-extras）或缺 stamp/指纹过期仍入队。  
   **排水（2026-10-08）**：闸门任务落盘 `generated/theme-layout-entities/{theme}/.solidify-jobs/`；权威排水为 Cron `theme_layout_solidify_drain`（每分钟）。WLS 可另用 `PostResponseTaskQueue` 加速同一落盘任务；**FPM 不得依赖**进程内队列。  
   **回落禁缓存（2026-10-08）**：`use_original_template=true` 时只调 `SharedResponseCachePolicy::forbid('theme_layout_solidify_fallback_original')`（浏览器/`Cache-Control: no-store`）。**禁止** Theme 直写 `CDN-Cache-Control` / `Cloudflare-*` / WLS FPC 头。Framework 发 `Weline_Framework::response::shared_cache_forbidden`：`Weline_Cdn`（CF）写边缘 `no-store`；`Weline_Server` 标 `X-Wls-Fpc-Status: BYPASS`；`FullPageCacheCoordinator::canPublishResponse` 见 forbid / 共享 HeaderCollector `no-store` 时**禁止**写入 WLS process/shared FPC。主路径仍靠发布/升级预固；请求门禁只作保险。  


**实现锚点**：

- `ThemeLayoutEntityPaths::root()` → `generated/theme-layout-entities/`
- `ThemeLayoutEntityUpgradeSolidifyService`（setup/deploy/core after + `theme:upgrade`）
- `SolidifiedControllerTemplateResolver` + 模板事件选择源文件，再走正常 Template 编译
- 公共 Partial 与页面同一修订，走正常模板流程；不交付按语言烘焙的公开 HTML 快照

## 4. 边界与迁移

- 输入 JSON 声明和数据库历史继续存在；移除的是固化目录中的侧车文件与依赖它们的读取链。
- 纯参数修改也更新 PHTML。不同语言图片/链接属于参数，不能以 com_* 的正常文本翻译替代。
- 完整布局表单在清空后重新加入部件时，保留既有清空标记、人工卸载记录和未修改的公共部分；只渲染明确重新加入的部件。旧格式表单没有携带这些记录，不表示用户要求恢复模板默认部件。
- 历史冻结编辑意图和显式参数；源模板及组件实现随代码升级，不保证旧 HTML 或 PHP 源码逐字节回放。
- 当前文件内容须完整读入后计算摘要；不得先读旧内容、再从已更换文件计算新摘要。
- 同一请求中的版本快照 head／资源引用使用 Framework 请求缓存复用，键包含完整 owner、V、mode、R。写入快照时失效；事务内直接读库并清除已有复用结果，未提交数据不得进入缓存。不同请求不共享草稿快照。
- 字面 `fetch`／`fetchHtml` 引用的语法解析可按源字节摘要在同一请求内复用；主题、区域和相对路径解析仍使用当前源上下文。该优化不复用已渲染 HTML，不增加固化侧车文件，也不改变候选 PHTML 内容。
- 从现有编辑/历史数据重新生成 PHTML 并验证后，移除旧侧车和缓存引用。不得删除源模板、数据库编辑内容或用户卸载决定。
- 当前选定草稿存在旧缺失引用时，升级入口可在同 owner 锁内验证实际 workspace、修订和命令归属，将可证明的当前输入捕获为新 R；有效旧引用保持，零命令资源保持无编辑意图。新基线不得反向关联旧缺证修订，旧 Token 仍须明确报告缺失历史依据。普通读取不执行此迁移。
- 不新增发布状态机、永久 compiled 存储或跨数据库/多文件的分布式事务。
