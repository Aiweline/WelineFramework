## 1. 一句话

**适用边界（2026-09-25 收口）**：本文“无卸载必装”针对 `required=true` 的默认安装项；`required=false` 或未标 required 的推荐项仍按 `REQ-THEME-0014` 由用户显式安装。推荐项一旦成为用户配置，固化和版本继承须保留；不能因为存在 JSON 声明便自动强装所有推荐项。现有 `RequiredDefaultInjectionContract::requiredForPage` 与 `WidgetDefaultInjectionService` 已按 required 区分，本文不再作相反承诺。

JSON `default_injections`（应用部件默认注入）在**固化布局模板**时写入对应布局的固化产物；**只要声明槽存在且没有人工卸载**，就必须被固化进去——与主题版本号、是否「当前激活」无条件关系。店面遗漏默认部件，优先判定为**固化方案/触发时机出问题**，而不是「可选的运行时补丁忘了跑」。

**固化写的是关系模板，不是渲染快照（硬）**：编译/固化把 slot 与部件对准坑位、对接身份与显式参数，形成可执行的 `layout.phtml` / `com_*.phtml`；**禁止**把某次请求的部件 HTML 烘焙进模板。部件 HTML 一律在店面执行该模板时由 `Widget::renderRuntimeInline` hydrate。

## 2. 应用部件默认注入（JSON）

### 2.1 谁走这条路

- 跨模块外国部件进入店面的**唯一合法路径**：拥有模块在 `widget.php` / `@widget.default_injections` 声明注入；宿主布局只留空 `<w:slot>`。
- 同模块 XOR：布局已 `<w:widget>` 内嵌 ↔ **禁止**再写同部件 `default_injections`（见部件开发指南）。

### 2.2 固化时是否注入（硬）

| 条件 | 固化时是否写入布局固化模板 |
|------|---------------------------|
| `required=true` 且目标布局存在对应 `<w:slot>`（或等价可注入槽），且**没有**本版本人工卸载 `user_deleted@{versionId}` | **必须注入** |
| 存在 `user_deleted@{versionId}`（人工卸载） | **不得**再注入 |
| 主题是否激活、主题版本号、发布壳是否「看起来完整」 | **无关** — 不得据此省略 |

口令：

1. **唯一省略条件** = 人工卸载记录 `user_deleted@{versionId}`。  
2. **与主题 / 版本无关**：只要槽在，JSON 默认应用部件就应固化进该布局对应模板。  
3. **required 与否**：`required=true` 为开箱默认安装；未标 required 或 `false` 为推荐项，只有显式安装后才成为用户意图参与固化。不能把推荐状态误当成必装状态。

### 2.3 计划账本与入库 / 读库（硬）

三层模型：

| 层 | 载体 | 职责 |
|----|------|------|
| 代码声明 | 模块 `widget.php` / `@widget.default_injections` | 采集源（仅入库冷路径扫描） |
| **计划账本** | `widget_registry_entry.default_injections_json`（`has_default_injections=1`） | **固化时读计划的唯一真相** |
| 决策表 | 现为 `theme_widget_default_injection`；目标改为版本修订的 `theme_scope_version_widget_decision` | 人工卸载等运营决策；旧字符串只作一次性转换输入 |
| 磁盘固化 | 主题实体 `layout.phtml` / `chrome.rendered` / `shell.phtml` | 店面热路径直读 |

**入库触发**（均走 `WidgetRegistryRefreshService::refresh` → 扫码写账本；有变更则 `widget_install_after` → `rebakeAfterInjectionCollect`）：

| 触发 | 入口 | `collection_source` |
|------|------|---------------------|
| 系统 Setup 升级后 | `Weline_Widget` `SetupUpgradeAfter` | `setup_upgrade_after` |
| 模块 install / upgrade | `ModuleInstallAfter` / `ModuleUpgradeAfter` | `widget_registry_refresh` |
| 定时 | Cron `widget_registry_refresh`（`20 * * * *`） | `cron_widget_registry_refresh` |
| CLI | `php bin/w widget:refresh` | `widget_refresh_command` |

**读计划**：

- **允许**：bake / rematerialize / rebake / 不完整壳安全网 → `DefaultInjectionPlanRepository::listDeclarations`（读库，请求级 memo）。
- **禁止**：完整已固化店面请求每请求查计划 / 扫 Catalog / 跑 `WidgetScanner`。
- `ThemeComponentCatalog` / `generated/widgets.php` 仍服务编辑器可放置清单；**必装计划不再经 Catalog**。

### 2.4 遗漏时怎么归因

若店面应有的默认应用部件未出现：

1. **先查固化**：该主题（及应有的其它主题）下，对应 `layout_type` 的固化模板是否缺失、过期、或固化时未纳入 `default_injections`。  
2. **再查账本**：`widget_registry_entry` 是否已入库计划（升级 / cron / `widget:refresh` 是否跑过）。  
3. **不要**把「发布壳完整 / `+skip_fill_solidified` / 编辑器不回填」当成可以丢必装的合法理由。  
4. 运行时动态补洞只是**无固化模板时的自愈**（见 §3），不是长期替代固化的主路径。

## 3. 主题内布局对应固化模板

固化产物（实体布局 `layout.phtml` / 整壳 `shell.phtml` / chrome 等）由 BakeCoordinator / Materializer 写入主题实体目录；店面优先**直读固化模板**。

### 3.0 固化产物 = 关系模板（硬 · 非渲染快照）

| 写入固化/编译模板的 | **不得**写入固化/编译模板的 |
|---------------------|---------------------------|
| slot 坑位、部件 type/name/code/module、显式 params、template_ref、资源声明 sidecar | 某次请求渲染出的部件 HTML（含商品身份、locale 文案、form_key、登录态） |
| `<w:widget>` → `<?= Widget::renderRuntimeInline([...关系规格...]) ?>` | 按部件 code / placement / page_layouts 维护「是否延期」白名单 |

口令：

1. **对准坑位**：固化/Taglib 编译只完成 slot↔widget 对接，产出可执行 phtml **模板**。  
2. **模板 ≠ 渲染结果**：`com_*.phtml` / 实体 `layout.phtml` 不是某次 PDP/请求的 HTML 快照。  
3. **统一运行时壳**：所有合法 `<w:widget>` 编译期唯一产物是 `renderRuntimeInline`；禁止特判 `product-info` 等名单。  
4. **hydrate 时序**：店面直读已发布模板 → PHP 执行关系壳 → 运行时读注册表、合并默认参数、渲染模板/Block → 每请求得到当前身份 HTML；结构未变则**不**重固化。

边界（分层 · 勿混改）：

| 层 | 形态 | 本契约 |
|----|------|--------|
| Taglib → `view/tpl` `com_*.phtml` | 必须 `renderRuntimeInline([...关系规格...])` | **在范围内**（曾误烘焙 HTML，已统一关系壳） |
| Materializer → 实体 `layout.phtml` / `chrome.phtml` | 已是 `ThemeLayoutEntityWidgetRenderer::renderBound(uid, …)` 关系壳 + sidecar | **已对齐，勿当 HTML 快照改** |
| `PublishedSlotHost` | 请求期 `include` 关系模板后得到 HTML 再塞槽 | **排除**（消费模板，不是固化定义） |
| `chrome.rendered.{locale}.html` | 语种级 **性能** HTML 快照（整壳直读） | **排除**；≠「布局固化模板 = 关系壳」语义；见下方整壳硬规则 |

静态 CSS/JS sidecar 仍按 [部件静态资源固化规范.md](./部件静态资源固化规范.md) 与结构同闸收集，不等于把部件 HTML 快照进模板。

**旧产物迁移（硬）**：升级前若 `com_*.phtml` / 实体布局模板里已烘焙过部件 HTML（无 `renderRuntimeInline` / 旧名单 `renderDeferredInline` 壳），**不会**因代码兼容自动变关系壳——须删对应 `view/tpl` 编译产物（或触发布局重编译/重固化）后再访问店面，使 Taglib 按新契约写出关系壳。抽检：编译产物不得再含 `data-product-id=` / `product-native-detail` 等请求态 HTML 标记。

**整壳 `shell.phtml`（硬）**：正式 chrome 段必须读取已 finalize 的公开 HTML 快照（嵌套 `footer-*-links` 已 promote）。现入口为 `ThemeLayoutEntityChrome::renderCurrent`；目标改为请求固定的同 V/R chrome binding，快照以 binding 与公开变化键定位，禁止裸调用后重新选“当前版本”；**禁止**把 raw `chrome.phtml` 注入器拼进 shell（否则 container 先渲染时嵌套扩展槽变空，语言/货币 hook 仍在——半套页脚）。

**注入收集重固顺序（硬）**：先物化关系模板，再 finalize 新 chrome rendered，最后发布固定该 chrome 的 page bundle/shell。目标实现写新不可变文件后原子替换 binding，不原位覆写或先删除在途请求引用的旧文件。

### 3.1 无固化 → 运行期动态固化（当前激活主题）

- 请求命中时若**尚无**可用的布局固化模板：对**当前激活主题**在运行期执行一次动态固化（物化该布局对应模板），再交付。  
- 目的：冷启动 / 新主题 / 首次访问不因缺模板交白卷。  
- 动态固化同样必须遵守 §2.2：无 `user_deleted` 则把 JSON 默认注入写进模板。

### 3.2 已有固化 → 仅结构变更再固化

一旦该布局的固化模板已存在，**不要**每个请求重固化。再次固化的触发仅限：

| 触发 | 范围 |
|------|------|
| 主题侧**新增**部件（结构写入 / 拖入 / 布局结构变更） | 重固化受影响布局（及必要的 chrome/整壳） |
| 主题侧**移除**部件（含人工卸载写入 `user_deleted`） | 重固化受影响布局，且卸载的默认注入不再写入 |
| 纯配置改（config-only sidecar） | **不**重写结构 `*.phtml`（既有 BakeCoordinator 闸） |

### 3.3 插件安装 JSON 默认注入 → 全主题重固化涉及布局

模块/插件安装或收集到新的（或变更的）JSON `default_injections` 时：

1. 解析注入声明涉及的全部 `layout_type`（及槽）。  
2. **对所有主题、版本及草稿**中这些布局的已有固化槽重固化（不仅当前激活主题）。没有产物的槽按新声明标记输入指纹，明确访问时定点生成，不为此次变更扫描全站 URL。
3. 实现锚点：`ThemeLayoutEntityBakeCoordinator::rebakeAfterInjectionCollect`（注入收集后同闸刷新固化产物）。  
4. 重固化时仍只跳过带 `user_deleted@{versionId}` 的项；其余有槽则写入。

口令：插件带来的默认应用部件，靠**全主题对应布局重固化**进入模板，而不是指望某一主题「下次碰巧跑 overlay」。

### 3.4 部署生命周期 → 删除全部布局固化磁盘产物（硬）

下列命令在**成功收尾**后均须清布局固化物（同语义、同进程 `runOnce` 去重）：

| 命令 | 事件 | 失效 reason |
|------|------|-------------|
| `php bin/w setup:upgrade` | `Weline_Framework_Setup::upgrade_after` | `setup_upgrade_layout_entities_invalidated` |
| `php bin/w deploy:upgrade` | `Weline_Framework_Deploy::upgrade_after` | `deploy_upgrade_layout_entities_invalidated` |
| `php bin/w core:update` | `Weline_Deploy::core_update_after` | `core_update_layout_entities_invalidated` |

目标部署须先停写、停止接收新请求并排空旧 Worker，避免 purge 删除在途请求持有的文件；purge 后加载新代码再恢复服务：

1. **删除** `var/runtime/theme-layout-entities/` 下全部布局固化磁盘产物（`layout.phtml` / `shell.phtml` / `structure.json` / chrome 快照与 sidecar）。  
2. 删除的是**派生磁盘产物**，**不**删除数据库布局/草稿/版本/`user_deleted` 决策。  
3. **禁止**把升级恢复做成「按 DB 旧 structure 全量 `rebakeAfterInjectionCollect` / rematerialize」——源主题/design 模板可能已改，DB 快照可能仍陈旧（例如 product-main 仍绑预览占位）。  
4. 清理后顺带 `ThemeRuntimeCacheCleaner::clearAllThemeRelatedCaches(…, <上表 reason>)`，避免 FPC 继续吐旧 HTML。  
5. **当前激活主题**：首访走 §3.1 **运行期动态固化**（`dynamicSolidifyPublishedPage`），从**当前源模板 + 当前注入账本 + 该版本持久用户意图**重建；不得重放陈旧自动结构。历史预览也遵守同一规则，不承诺当年 HTML 字节不变。
6. **非激活主题**：可保持无磁盘固化，直到激活/访问或其它明确固化触发（插件注入变更仍走 §3.3）。
7. `setup:upgrade` 内嵌 `deploy:upgrade` 时，共享服务只 purge **一次**（`ThemeLayoutEntityUpgradePurgeService::runOnce`）。

实现：`ThemeLayoutEntityPaths::purgeAllEntities` · `ThemeLayoutEntityUpgradePurgeService` · `Observer/SetupUpgradeAfterPurgeLayoutEntities`（三事件 sort=300）。

## 4. 与旧表述的纠偏

| 旧误解 | 正确做法 |
|--------|----------|
| 「必装与固化无关，靠请求期 overlay 永远补」 | 必装**通过固化写入模板**保证；无卸载则固化不得省略 |
| 「缺默认部件 → 再加一层运行时 fill」 | 缺默认部件 → **查/修固化方案与触发**；仅无模板时允许运行期动态固化 |
| 「只固化当前激活主题即可」 | 日常无模板时动态固化激活主题；**插件默认注入变更**必须**所有主题**对应布局重固化 |
| 「换主题版本就可以丢掉 JSON 默认注入」 | 与主题版本无关；唯一省略 = 人工卸载 |
| 「固化时扫 Catalog / widgets.php 拿计划」 | 固化只读 `widget_registry_entry` 计划账本；Catalog 留给编辑器清单 |
| 「店面每请求查计划」 | 完整壳直读磁盘；计划查询仅限固化冷路径 / 不完整壳安全网 |
| 「固化进模板 = 把部件 HTML 烘焙进 com_/layout.phtml」 | 固化进模板 = **slot↔widget 关系壳**；HTML 在请求执行模板时 hydrate |
| 「只有 product-info 等动态部件才延期渲染」 | **所有** `<w:widget>` Taglib 编译统一 `renderRuntimeInline`；禁止部件名单特判 |

布局标签内嵌必装（`placement=layout`）仍由源布局标签承载；JSON 路径与标签路径 XOR，二者在无卸载时都必须在店面可见——JSON 路径的载体就是**固化进布局模板**（写入的是放置关系，不是渲染快照）。

## 5. 相关实现与门禁（指针）

- `Service/LayoutEntity/RequiredDefaultInjectionBakeMerger.php` — bake 前 merge required JSON（减 `user_deleted`）；计划来自 `DefaultInjectionPlanRepository`

- `Service/LayoutEntity/ThemeLayoutEntityPaths.php` — `purgeAllEntities`（部署生命周期清盘）  
- `Service/LayoutEntity/ThemeLayoutEntityUpgradePurgeService.php` — `runOnce`（setup / deploy:upgrade / core:update 去重）  
- `Observer/SetupUpgradeAfterPurgeLayoutEntities.php` — 三事件 sort=300  
- `Service/LayoutEntity/ThemeLayoutEntityMaterializer.php` — 物化 layout/chrome；`structure.json` 含 `page_type`  
- `Service/LayoutEntity/ThemeLayoutEntitySlotFiller.php` — 缺模板动态固化；Overlay 仅安全网  
- 门禁：`php bin/w frontend:check-theme-layout-widgets` · `frontend:check-required-injection-sibling-fetch`  
- 部件放置 XOR：[部件开发指南.md](./部件开发指南.md)
