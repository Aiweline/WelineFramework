# Weline_Theme 开发日志

## 2026-08-25 — SlotRenderer 跨 header/content narrow 丢主内容

- 当前状态：`implemented`
- 现象：分类页（如 `/category/books/av/albums`）Slot 处理前有 `#category-layout-main`（~870KB），处理后主区消失（~407KB）；仅剩 Header/Footer。
- 根因：已发布布局同时有 header 槽（`delivery`）与 content 槽（`category-recommendations`）。`narrowHtmlToSlotFragment` 裁出跨 `</header>` 的片段；`LIBXML_HTML_NOIMPLIED` 把 `weline-main-content` 提升为 slot-root 的 document 兄弟，序列化只输出 slot-root 子节点，主内容被丢。
- 实现：1) 边界跨越 `</header>` 时跳过 narrow，改走整 body DOM；2) `reparentPromotedSlotRootSiblings` 把被提升的兄弟挂回 slot-root。
- 验收：`SlotRendererHeaderNarrowFragmentTest`（cross-header skip + reparent）；分类页 HTML 含 `#category-layout-main` / `.weline-main-content`。

## 2026-08-25 — theme:address 补 runtimeCallback，修复分类页被 PHP 泄漏吞掉

- 当前状态：`implemented`
- 现象：前台分类页（如 `/category/books/av/albums`）主内容空白/布局乱；HTML 中泄漏 `Weline_Taglib_resolve`/`$Taglib__*`，且 `=>`/`?>` 被转成 `&gt;`。
- 根因：`Shipping` quick-add 里 `<w:theme:address country="<?= ... ?>">` 因动态属性走 `renderRuntimeTag`；`Address` 只有编译期 `callback`（返回 `<?php ... ?>`），运行期当文本输出；浏览器把未闭合的 `<?php` 当 PI 吞掉后续主内容。
- 实现：参照 `Icon::runtimeCallback`，为 `Theme\Taglib\Address` 增加运行期直接输出 `w-address` HTML；编译期路径不变。另修 header `$renderMenuItem` 闭包未 `use $headerEscDesc` 的 Warning。
- 验收：`AddressTaglibRuntimeCallbackTest`；分类页 HTML 无 Taglib PHP 泄漏，quick-add 正常输出 `data-w-address`。
- 残留观察：泄漏修复后主区仍缺席的问题已由同日「SlotRenderer 跨 header/content narrow 丢主内容」条目修复。

## 2026-08-25 — 预览 Token 粘着 locale 盖住 URL 语言切换

- 当前状态：`implemented`
- 问题：工具栏/预览内切 `en_US` 后 URL 已带 `locale=en_US`，但 iframe 仍中文；`html[data-lang]`/`LanguageSwitcher`/`Phrase` 跟 Cookie 或 Token 内旧 locale。
- 根因：`PreviewContextService::getCurrentContext` 在合并 request 后仍用 preview token 覆盖全部字段（含 `locale`），显式 query `locale` 被粘着 Token 语言压掉；`applyPreviewLocale` 拿不到英文 override。
- 修复：Token 仍锁定 theme/scope/target；token 合并后再次应用显式 `locale`（优先 raw query，WLS 剥掉 QUERY 时回退 request bag，含 `default`/空清空）。配合 `i18n.js` document/query 优先于 Cookie。
- 验收：`PreviewContextServiceTest` locale 覆盖用例；预览内 English↔中文后切换器与文案同步，Cookie 不变。

## 2026-08-25 — 预览内切语言后切换器仍钉中文（i18n.js Cookie 优先）

- 当前状态：`implemented`
- 问题：预览 URL/`html[data-lang]` 已是 `en_US`，但语言切换器文案与 `aria-checked` 仍像中文；用户以为「点了没切」。
- 根因：`WelineI18n.getCurrentLang()` 在无路径语言段时优先 `WELINE_USER_LANG` Cookie，`updateCurrentLanguageDisplay` 启动时把服务端已渲染的 current 盖回站外偏好语言。不是 Taglib 缺兼容。
- 修复：`getCurrentLang` 改为 path → `data-lang`/`lang` → query `locale`/`lang` → Cookie → 主题配置；预览切换仍不写 Cookie。
- 验收：预览内 English↔中文后切换器与 `html[lang]` 一致；Cookie 不变；`I18nJsAuthoritativeHrefBehaviorTest.js`。
