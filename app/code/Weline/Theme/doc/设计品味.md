# 设计品味（Design Taste）

> 技能：MCP `design_taste`（别称 `taste` / `weline-taste`）。
> 定位：**判断层**。定层级、密度、字号、强调预算、文案声音——不产出 CSS、不发明色板。
> 落地：`frontend_design`（构图/文案）→ `weline-theme-development`（Token 与主题）。
> 强制前置：`app/code/Weline/Theme/doc/theme-storefront-token-consumption.md`、`theme-css-variables-only.md`。

---

## 0. 一句话

界面不好看，通常不是颜色不够多，而是**层级不清、节奏不齐、强调太多、文案不像人话**。
品味 = 把有限的手段用在该用的地方，并且能说出为什么。

## 1. Token 法律（先于一切审美判断）

| 类别 | 只能取 | 禁止 |
|------|--------|------|
| 间距 | `--weline-space-1…12` | 裸 `6px`、`0.55rem`、`gap: 13px` |
| 字号 | `--weline-font-size-*` | 裸 `14px`、`clamp(13px,…)` |
| 圆角 | `--weline-theme-radius-sm\|md\|lg\|xl\|full` | `border-radius: 6px` |
| 阴影 | `--weline-shadow-*`、`--focus-ring` | 组件私写 `0 4px 14px rgba(...)` |
| 控件高 | `--weline-theme-control-height*` | `min-height: 48px` |
| 颜色 | 语义 Token（`--color-*` / `--weline-theme-*`） | 私有 hex/rgb、第三方 UI 默认色 |

审美建议**不能**成为新增字面量的理由。需要新刻度 = 先补主题全局盘，再使用。

## 2. 三视线法（先定层级，再谈装饰）

每屏只允许一个第一视线：

| 视线 | 内容 | 约束 |
|------|------|------|
| 第一视线 | 页面主对象（商品图 / 列表 / 表单首字段 / 关键数字） | 全屏唯一；尺寸或位置明显领先 |
| 第二视线 | 主操作、核心数据、筛选 | ≤2 处；不与第一视线同权重 |
| 第三视线 | 说明、辅助信息、次要操作 | 弱化：小一号字、低对比、收起 |

判定：眯眼看截图 3 秒，能说出"这页是干什么的"→ 通过；说不出 → 层级失败，先改层级再改颜色。

## 3. 字号阶梯

- 至少 3 级：**标题 / 正文 / 辅助**；营销页可加展示级，后台页不超过 4 级。
- 相邻级差要看得出来（同屏两级字号相同 = 没有层级）。
- 字重只做辅助强化，不能替代字号差。
- 正文行高 ≥1.5；标题行高 1.2–1.35；中文行长 ≤ 42 字（桌面）。

## 4. 间距与密度

- 8pt 基线：一切间距取盘内刻度，禁止 3/5/7/9/11 这类私造值。
- 组内同间距；组间距 = 组内间距 ×2（视觉分组靠距离，不靠边框）。
- 一屏只保留一种卡片密度；列表与详情不要混用两套 padding。
- 留白是结构：删掉一条分割线，用间距分组；删掉一个边框，用底色分组。

## 5. 强调预算（最常被违反）

| 项 | 预算 | 理由 |
|----|------|------|
| 强调色 | 每屏 ≤1 | 两个强调 = 没有强调 |
| 主按钮 | 每屏 ≤1 | 多个 primary 等于没有主操作 |
| 圆角体系 | ≤2 套（控件 md / 卡片 lg） | 混用显得廉价 |
| 阴影层级 | ≤2 级 | 层层叠影 = 脏 |
| 图标风格 | 一套（线性或面性） | 混用 = 拼装感 |
| 字体家族 | ≤2（含等宽） | 第三套开始失控 |

## 6. 状态完整性（比"好看"更影响信任）

每个交互面必须设计：**默认 / hover / focus / active / disabled / loading / empty / error / success**。
其中至少要有：

- 空态：说明为什么空 + 下一步动作（不是空白页）。
- 错误态：原因 + 可执行出口（重试 / 返回 / 联系），不写"出错了"。
- 加载态：骨架或进度，不用整屏 spinner 遮住布局。
- 禁用态：说明为什么禁用（tooltip 或辅助文字）。

## 7. 文案声音（文案是界面的一部分）

| 位置 | 写法 | 反例 |
|------|------|------|
| 按钮 | 动词 + 对象：`保存地址`、`生成报价单` | `提交`、`确定`、`操作` |
| 空态 | 发生了什么 + 下一步：`还没有收货地址，先添加一个` | `暂无数据` |
| 错误 | 原因 + 出口：`图片超过 5MB，请压缩后重试` | `操作失败` |
| 标题 | 名词短语：`订单明细` | `这里是订单明细信息` |
| 提示 | 一句话，不写教程 | 三段式说明文 |

中文标点用全角；中英混排加空格；不出现"亲""哦"等口语尾巴。

## 8. 动效

- 只做**状态变化**的过渡，不做装饰性入场；时长 120–200ms，`ease-out`。
- 一个页面只允许一种过渡语义（淡入 / 位移 / 高度展开，选一）。
- 必须尊重 `prefers-reduced-motion`；大位移与视差默认关闭。
- 禁：弹跳、无限循环呼吸灯、超过 300ms 的等待动画。

## 9. 响应式检查点

| 宽度 | 必查 |
|------|------|
| 375px | 无横向滚动、无一字竖排、按钮不被挤压、表格可横滑或转卡片 |
| 768px | 两栏不塌、侧栏可收、触控目标 ≥44px |
| 1280px+ | 版心不无限拉伸（见 `theme-layout-content-width.md`）、留白均匀 |

## 10. 六问自检（交付必须附结果）

1. 第一视线只有一个焦点？
2. 字号 ≥3 级且来自 Token？
3. 间距全部落在 8pt 刻度？
4. 强调色 ≤1、主按钮 ≤1？
5. 空态与错误态都有可执行出口？
6. 删掉装饰后信息仍完整？

6 问全 pass 才可交给 UI/主题席落地；任一 fail → 先改，不解释。

## 11. 反模式 → 改法

| 反模式 | 症状 | 改法 |
|--------|------|------|
| 装饰堆砌 | 渐变、大阴影、多色图标 | 保留一个强调色，其余降为中性 |
| 卡片地狱 | 卡片套卡片，每块都描边 | 用间距分组，去掉内层边框 |
| 层级扁平 | 全是 14px，靠加粗区分 | 建 3 级字号阶梯 |
| 强调通胀 | 3 个彩色按钮 | 只留 1 个 primary，其余 secondary/text |
| 假丰富 | 无信息量插画、图标满屏 | 删除，留白即呼吸 |
| 文案说明书 | 按钮写"提交" | 改成用户动作 |
| 状态缺失 | 只有成功态 | 补齐 empty/error/loading/disabled |
| 假优化 | 只换配色不改层级 | 先重排层级，再谈颜色 |

## 12. 与其它技能/流程的关系

```
prototype  →  design_taste  →  frontend_design  →  weline-theme-development
(信息架构)     (判断/验收)        (实现/构图)          (Token 落地)
                     ↓
                  审图（dev/ai-command/theme/审图.md）
```

- `审图` 判 E（人性化）/ F（规范美观）时，用本文件第 10 节的 6 问。
- 主题开发工程师负责 Token 叶子与表面角色；本技能**不得**替代主题判断。
- 内容运营（产品图/详情/文章）不适用本文件，走各自技能。
