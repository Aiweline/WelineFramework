# 规格：快捷购买 = 页内立即结账（非分享）

## 澄清记录

| # | 问题 | 结论（用户原话/纠偏） |
|---|---|---|
| 1 | 快捷购买成功态是否应出链分享？ | **否**。「快捷购买是立即弹出窗口快速当前页面就可以结账。而不是分享」 |
| 2 | 与「找朋友代付 / 分享给朋友」关系？ | 代付/纯分享仍走出链双形态；快捷购买主路径是本人结账 |
| 3 | `/q/{token}` 是否保留？ | 保留为本人付款页；跨设备链接/二维码仅次要入口 |

## 非目标

- 不改帮我付 / 纯分享的出链双形态主路径
- **已纠偏（2026-09-14）**：快捷购买主路径改为弹窗内地址→物流→支付闭环，见 `helppay-quick-pay-popup-checkout.md`；禁止主路径 `location.assign(/q/)`。`/q/` 仅跨设备次要入口。

## 用户故事

作为零售买家，我想在商品页点「快捷购买」后在弹窗里确认地址并立刻进入付款，而不是先拿到一份「发给朋友」的分享链接。

## EARS

1. When 用户在可售零售态点击「快捷购买」，the system shall 立即打开 HelpPay 弹窗并进入地址确认步（可编辑，同结账地址）。
2. When 用户在地址步确认且地址完整，the system shall 创建 `quick_pay_self` token，并**进入本人付款**（导航至 `/q/{token}` 或等价付款入口），**不得**把「链接分享 / 扫码分享 / 发给朋友」作为结果主界面。
3. When 用户停留在 `/q/{token}` 付款页，the system shall 以「立即支付」与应付金额为主；跨设备链接/二维码仅作次要折叠入口。
4. If 地址不完整或禁运，the system shall 留在地址步提示，不得跳转到分享结果态。

## 用例

### UC1 主成功路径

1. PDP 点「快捷购买」→ 弹窗地址步。
2. 确认地址 → 短暂「正在进入付款…」→ 进入 `/q/{token}`。
3. 付款页可见金额与「立即支付」；主区域无「发给朋友」分享文案。

### UC2 地址不全

1. 确认时地址不全 → 留在地址步提示完善。

### UC3 与代付区分

1. 「找朋友代付」仍出链分享；「快捷购买」不进入分享结果网格。

## 验收

- UT：快捷购买确认路径不再调用 `renderShareResult(..., 'quick')` 作为成功主路径。
- e2e：确认后进入 `/q/` 或付款 CTA；弹层结果不得出现「发给朋友 / 分享当前规格」。
- Browser：禁缓存验收上述主路径。
