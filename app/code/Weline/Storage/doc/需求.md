## `REQ-STORAGE-0001` 发布安全的数据化目录管理契约

- 来源：用户要求 MediaManager 的整目录编辑、重命名和删除对接提供者，供 OSS 等扩展统一管理。
- 公共接口：`StorageDirectoryManagerInterface` 只暴露 capability、目录列表、新建、移动/重命名和删除，不返回驱动、配置或凭据。
- 适配器约束：所有驱动继续实现 `StorageInterface`；本地驱动支持目录移动；OSS/S3 用目录标记表示空目录。
- 安全规则：路径只能是规范化相对路径；禁止根目录写操作、控制字符、`.`、`..`、移动到自身子目录和覆盖已有目标。
- 故障策略：对象存储目录先复制后删除。目标复制未完成则清理目标；源清理失败则保留已完成的目标副本，避免删除唯一副本。
- 非目标：不把驱动实例暴露给调用模块；不在本批次增加远端上传、下载或签名 URL UI。
- 兼容/迁移：无 Schema 变更；当前不修改安装版本。
- 验收：本地目录生命周期测试通过；外部存储命令由 MediaManager provider 路由验证；真实 UI 由 MediaManager 页面验收。

## `REQ-STORAGE-0002` Provider 驱动的统一对象存储与 URL 解析

- 来源：用户于 2026-08-22 确认完整实施方案，并指定 `disk_code` 为 `type::vendor::instance`，例如 `local::filesystem::media`、`oss::aliyun::media_public`。
- 公共契约：`StorageManagerInterface`、`StorageDiskInterface`、`StorageDriverProviderInterface`、`StorageUrlAdapterInterface`、不可变对象/统计/URL/配置快照 DTO，以及可显式关闭的读写 Handle。
- 解析规则：前两段选择编译 Provider，第三段选择数据库配置实例；旧名称只作为读取别名，新保存必须规范三段式；显式磁盘故障不得静默回退本地。
- WLS：磁盘配置按 `config_revision` 冻结在单次请求；Driver、URL Adapter、SDK Client、流和 multipart 状态是 Request/Fiber 资源；请求结束由资源注册表和 `request_resetter.Weline_Storage` 幂等清理。
- URL：公开、临时签名和图片变体 URL 均由资源所属磁盘 Adapter 生成；临时 URL 不得持久化或进入共享缓存、日志与诊断。
- 运行控制：Provider 只从编译注册表发现；进程缓存有界且可回收；只读诊断只输出计数和最近清理失败，不输出对象路径、Secret 或完整 URL。
- 迁移：旧磁盘名保留只读别名；StorageConfig 增加配置版本；本地默认实例固定为 `local::filesystem::media`。
- 验收：解析、无回退、流式读写、URL Adapter、配置快照、Fiber 隔离、资源归零、cleanup 故障 drain 和真实 WLS 并发路径通过。
