# 媒体项选择 UI 与项内字段统一

用户原话（需求，不改写产品）：

> 类似这种选择多张多文件的 UI 和单个的 UI 组件统一起来，避免以后类似的部件设置类似的情况不统一。还有每个文件项可以拓展信息，比如 Banner 上可以灵活设置其他标题、副标题、按钮等信息。都装载 item 里面配置多语言翻译。可以在用 UI 组件的时候指定 item 的字段的 UI。

触发事实（不是已拍板架构）：主题编辑器里「轮播图片」打开已有项时图片不回填。单图与多项目前不是同一套选择界面。用户要的是组件统一，不是再补一处预览回填。

## 目标

- 多文件选择与单文件选择使用**同一套**选择 UI，以后同类部件设置不再各做一套。
- 每个文件项可以声明额外信息（例如标题、副标题、按钮），这些信息装在 **item** 上。
- 装在 item 上的这些信息要能配置**多语言翻译**。
- 使用该 UI 组件时，调用方可以指定 item 上各字段用哪种字段 UI。

## 非目标

- 不把「只给某一处补上已选文件的预览回填」当作本需求完成。
- 不在本规格选定实现落点、类、补丁步骤或跨模块调用方式。
- 不在关键澄清未回答前，把前台展示改版、历史数据迁移步骤、或「只改某一种轮播」写成已承诺范围。
- 不新造第二套选图/选文件界面来绕开现有选择能力。

## 角色

- **部件作者**：使用选择组件时，声明 item 有哪些字段、每个字段用什么 UI。
- **配置者**（主题编辑或部件设置中的操作者）：选择一个或多个文件，并在对应 item 上填写可扩展信息与多语言内容。
- **阅读规格的后续席位**：只消费本文件的 what；架构选型不在本席。

## 成功标准

1. 配置者在「选一个文件」和「选多个文件」时，看到的是同一套选择 UI（选中态、已选回填方式一致），而不是两套互不相关的表单。
2. 调用方能为 item 声明额外字段及该字段的 UI；未声明的字段不出现。Banner 一类场景至少能声明标题、副标题、按钮这类信息。
3. 已声明且需要翻译的字段，其各语种内容跟该 item 走，而不是只挂在参数根上或与该项脱节。
4. 打开已保存的项时，该项已选文件在这套统一 UI 里回填可见。完成定义是统一组件下的回填，不是单独打补丁。

## 用户故事

**US-1**  
As a 配置者, I want 多文件选择和单文件选择用同一套 UI, so that 以后类似部件设置不会再各长一套。

**US-2**  
As a 配置者, I want 每个文件项上填写标题、副标题、按钮等信息并配置多语言, so that 这些内容装在该项里、能按语言区分。

**US-3**  
As a 部件作者, I want 使用该组件时指定 item 各字段的 UI, so that 不同部件可以声明不同字段，而不必绑死同一种表单。

### 验收标准（EARS）

1. WHEN 配置者编辑一个允许多个文件项的设置 THEN 系统 SHALL 使用与单个文件选择相同的选择 UI 展示每一项的文件选择，而不是另一套独立表单。
2. WHEN 配置者打开已保存的文件项 THEN 系统 SHALL 在该统一选择 UI 中回填该项已选文件，并显示该项上已保存的已声明字段。
3. IF 调用方为 item 声明了额外字段及其字段 UI THEN 系统 SHALL 只按该声明渲染这些字段，且这些字段的值属于该 item。
4. IF 调用方未声明某字段 THEN 系统 SHALL 不在该项上显示该字段。
5. IF 某 item 字段需要多语言 THEN 系统 SHALL 按语种保存该字段内容，且内容装在对应 item 上。
6. WHEN 调用方指定了某 item 字段的 UI THEN 系统 SHALL 用该指定的字段 UI 编辑该字段，而不是忽略指定、改用固定表单。

## 用例

### UC-1 打开已有轮播项并用统一 UI 编辑项字段

| 字段 | 内容 |
|------|------|
| id | UC-1 |
| 名称 | 已有多项的文件与项内字段走同一套选择 UI |
| 角色 | 已登录、可编辑主题部件的配置者 |
| 前置 | 默认站存在一条已保存的轮播类多项配置：至少一项已选图片，且该项上已有标题或按钮类文案（若当前数据没有文案，则本用例只断言文件回填，文案留空为合法） |
| 主成功步骤 | 1. 打开主题编辑器中带该项配置的部件设置。2. 展开或打开已有项。3. 查看文件选择区域。4. 查看该项上已声明的标题、副标题、按钮等字段。5. 修改其中一个已声明可译字段的当前语种文案并保存。6. 再次打开同一项。 |
| 备选/异常 | 见 UC-1a |
| 期望结果 | 文件选择区域与单个文件选择是同一套 UI；已选图片可见（回填）；已声明字段出现在该项上，未声明字段不出现；再次打开后，修改后的该语文案仍在该项上 |
| 映射 acceptance | 计划中的 `type=e2e` 主路径，以及 Browser WB-OP：同一 URL 上完成「打开已有项 → 看见回填 → 改一项字段 → 再打开仍在」。探活 URL 与交付 URL 须为同一条本机验收地址（实现阶段再填，本规格不编造 URL） |

### UC-1a 已选项缺少可预览文件

| 字段 | 内容 |
|------|------|
| id | UC-1a |
| 名称 | 已存项没有可显示的文件时不得假装已选中 |
| 角色 | 同 UC-1 |
| 前置 | 某一项的文件引用为空，或引用已无法解析出预览 |
| 主成功步骤 | 1. 打开该项。2. 看选择 UI 与项内已声明字段。 |
| 备选/异常 | 无进一步分支 |
| 期望结果 | 选择 UI 仍是与单文件相同的那一套；不显示一张假的已选预览；项内已声明字段仍可编辑；不因缺文件把整项其它字段丢掉 |
| 映射 acceptance | 计划中的 `type=e2e` 异常路径，或同一 Browser WB-OP 会话中的空文件项断言 |

## 隐形需求摘要

对齐仓库里已经有的能力，不新发明类型名，也不把下列名字写成实现步骤。

- **选图 / 选文件**：既有选图入口是 `WelineMedia` / `file-picker`（`value_mode=file-image`）以及标签侧的文件管理选择（`<w:file-manager>`）。统一后的选择 UI 应复用这套，而不是再做一个平行选择器，也不要用裸图片标签代替选图。
- **ParamSchema**：主题侧已有多项语义声明，例如 `banner_items`（项上已有图片、标题、副标题、链接、按钮文字等）、以及同目录的 `site_gallery_items`、`brand_logo_items`、`sidebar_ad_items` 等 `*_items`。本需求要能覆盖「项上再声明字段」这种已有语义，而不是只服务其中一种名字。
- **参数 UI**：用户已选边：项外壳只留部件数组项契约；主题编辑器不再自绘第二套卡片。选择 UI 复用现有 file-picker。
- **i18n**：可译字段沿用现有「按字段打开多语言」面板，译文装在对应 item 上，不在项上平铺全部语种。语种范围按默认网站已启用语种，不把「只做中英」写成需求。
- **待纠偏（留给框架审视，本席不选边）**：若方案仍是单图一套、多项另一套、编辑器再补回填，与用户「组件统一」字面冲突。统一也不得靠跨模块直接调用对方 Service / Model 来完成。

## 澄清记录

### 已确认

- 要统一多文件与单文件选择 UI。
- 项内可声明额外字段（标题、副标题、按钮等）。
- 这些字段装在 item 上，并走多语言。
- 调用组件时能指定 item 字段的 UI。
- 完成标准不是「再补一处图片预览回填」。
- 2026-09-19 用户确认外壳：项外壳只留 Widget 数组项。主题编辑器不再自绘第二套卡片。单文件和多文件都用现有 file-picker。用组件时在参数声明里指定 item 字段 UI。
- 使用面：以后同类部件设置都走这一套，不限主题编辑器里的某一处 Banner。
- 单文件：选择 UI 与多项里的每一项相同，都是现有 file-picker。扩展字段只出现在调用方为该项声明了字段的时候。单个文件参数仍是一个文件选择，不强制改成「最多 1 项的数组」。
- 多语言：沿用字段级多语言面板，译文保存在该 item 的对应字段上，不在项上把全部语种平铺开。
- 选什么：不写死只图片。调用方在参数声明里指定字段类型；图片和其它文件选择都走同一个 file-picker。
- 字段 UI 只在参数声明里指定，不另开第二套调用通道。

### 未回答

无。前台是否按 item 上的多语言字段改展示，用户原话未覆盖，仍不在本需求范围。

## 前后端范围

`fe_be_scope=both`。设置界面要收成同一套数组项与 file-picker；item 字段与多语言要按参数声明保存。不改前台展示。
