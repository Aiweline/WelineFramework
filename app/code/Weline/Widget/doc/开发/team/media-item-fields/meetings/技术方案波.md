# 技术方案

- 席位：架构师
- 规格：`app/code/Weline/Widget/doc/开发/spec/media-item-fields.md`（status=ready-for-plan，用户已确认）
- 决议意向：接口可冻结。数组项只有一个 HTML 来源，现有渲染边界接得上，不必新建跨模块 Service。

## 背景

配置者要的是同一套选择 UI，以及装在 item 上、按参数声明指定字段 UI 的可译扩展字段。范围是以后同类部件设置：`Theme/Ui/ParamSchema/*_items.php` 经 `ParamSchemaScanner` 收入注册表，再由 `ParamSchemaRegistry::expandParams` 把语义 type 展成 `base_type=array` 并带上 `item_schema`。不是只改 `banner_items`。

现在两套卡片并存。主题编辑器 `generateWidgetConfigForm` 优先走本地 `generateWidgetConfigFormFallback`；数组分支调用 `renderFallbackArrayItem`，外壳是 `.array-item` 和「第 N 项」。这条路径按 `item_schema` 的 type 画字段，媒体字段已调用 `Weline.Widget.Params.renderMediaLibraryPickerHtml`，但没有 `renderTranslatableWrap`。本地 HTML 一旦成功，已有的 paramrender 就不会被用上。

Widget 侧外壳已经存在。`ArrayType::getHtml` 输出 `.w-param-array` / `.w-param-array-item`。项内字段只看 `item_schema` 的 `type`：`media_image` / `image` / `image_picker` / `file_image` 走 `AbstractParamType::renderMediaLibraryPickerHtml`（与 `MediaImageType::getHtml` 同一函数，file-picker，`value_mode=file-image`）；文本、链接、选择等走 `ArrayType` 已有分支。可译字段走 `renderTranslatableWrap`，复合键 `{参数键}.{项下标}.{字段键}`。`WidgetConfigService::renderForm` / `renderField` 在渲染前已经 `expandParams`。主题侧 `ParamRender` 已通过 `Weline_Widget::query` 的 `getConfigForm`、`renderField` 取这段 HTML。前端 `Weline.Widget.Params.mount` 只挂载 `.w-param-array`，新增项克隆 PHP `<template>`，不另画卡片。

因此停掉 `renderFallbackArrayItem` 之后，主题编辑器不是没有数组 HTML。来源就是上述已有接口。这不是「两套扩展点都成立且现有接口接不上」的矛盾。

## 方案

数组项唯一渲染入口是 `ArrayType::getHtml` 产出的 `.w-param-array`。主题编辑器对展开后 `type` / `ui_type` 为 `array` 的参数，不再调用 `renderFallbackArrayItem`，也不再输出 `.array-item`。该字段整段 HTML 只从已有参数渲染边界取得：优先 `renderField`（单字段，返回值就是这一项外壳）；整表已走 `getConfigForm` 时，其中的数组字段同样只能是这段 HTML。插入 DOM 之后只调用已有 `Weline.Widget.Params.mount`。

不新增客户端数组卡片函数。`renderMediaLibraryPickerHtml` 只负责选图控件，不负责项外壳。`Params.mount` 只消费 ArrayType 已经写出的 DOM 和 template。

允许的耦合只有这两条，Theme 不得 `new` Widget 的 Service 或 Model：

- 已有参数渲染接口：`ParamFormRendererInterface::renderForm`，以及主题已在用的 query 操作 `getConfigForm` / `renderField`。
- 已有前端 `Weline.Widget.Params`：`mount`、`renderMediaLibraryPickerHtml`、`updateMediaPreview`。

单个文件参数仍是一个文件选择，渲染入口保持 `MediaImageType`（内部仍是同一个 `renderMediaLibraryPickerHtml`），不改成最多 1 项的数组。多项才是数组，每一项里嵌同一个 file-picker。

## 细节

- 判定数组：只认展开后的 `base_type=array`（`type` / `ui_type` / `input`）。`schema_type`（如 `banner_items`）只标明语义来源，不单独开 UI。`banner_items`、`site_gallery_items` 等同目录 `*_items` 都走这一入口。
- 项字段 UI 只由 `item_schema` 里该字段的 `type` 决定。未声明的字段不出现。媒体类 type 用现有 file-picker；标题、副标题、按钮文字等文本 type 用 ArrayType 已有输入。不另开第二声明通道，不新建 ParamType，不新建选图组件。
- 可译包装只在这条入口上生效。`ParamDefinition::isTranslatable` 为真时，`ArrayType` 调用 `renderTranslatableWrap`，按钮与面板带 `data-array-key`、`data-array-index`，字段键是复合键。不在项上平铺全部语种。译文跟该 item 字段走。JS fallback 没有这一层；停用后，已有项和 template 克隆出的新项都带着包装。`Params` 重排时已按同一复合键改写下标。主题编辑器已有的 `.w-param-btn-i18n` 委托，以及按点路径读取配置的逻辑，对准这个复合键即可，不新开多语言协议。
- 主题编辑器里凡仍调用 `renderFallbackArrayItem` 的表单生成（含同一函数的页面脚本副本）都改为消费这一入口，避免副本把第二套卡片带回来。非数组字段可以继续用本地表单生成；数组字段必须整段换上 ArrayType HTML，不得再套一层 `.array-editor-wrapper`。
- 已保存 file-image 打开时的回填仍走现有解析：`hydrateFileImagePickerPreviews` 查找 `.w-param-media-image[data-w-param-media="file-picker"]` 的 hidden 值，经现有 `resolve-file-image-previews` 得到预览地址，再交给 `Weline.Widget.Params.updateMediaPreview`。不另造预览协议。统一渲染覆盖到这些节点之后，这一步可以留着，但不是本需求的完成定义。
- 明确不做：前台展示、新 ParamType、新选图组件、把单文件参数改成数组、Theme 直接实例化 Widget Service。

接口冻结：数组项 HTML 只许 `ArrayType`（`.w-param-array`）；主题编辑器数组分支只消费已有 `renderField` / `getConfigForm` 的这段 HTML，然后 `Params.mount`；项内媒体与单文件共用 `renderMediaLibraryPickerHtml`；可译只走 `renderTranslatableWrap` 复合键。
