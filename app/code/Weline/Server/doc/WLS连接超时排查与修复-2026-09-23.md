# WLS 本机连接超时排查与修复（2026-09-23）

## 现场与复现

本机 `default`，Darwin / PHP 8.4.22 / direct shared_fd，访问 `https://p05113ef3.test.weline.com:9555/`。

- 域名解析为 127.0.0.1；9555 端口被 Master 持有，但没有业务 Worker，直连也无法建立连接。
- `var/log/wls/default/error-2026-09-23.log` 在 UTC 07:19:21 记录 `reload_wait` 没有终态回执；随后持续报告期望 4 个 READY、实际 0。
- IPC 状态显示 `tls_serving_quarantined=true`，最后操作为 `ssl_serving_quarantine`。因此紧急拉起即使反复执行，也不能启动 TLS Worker。
- 退役任务的实际结果显示：3 条历史记录仍待处理，共享网关未注册/无法确认；本地 TLS 更新也失败后，协调器执行隔离。

## 两条故障链

1. **异步子进程回收重入数据库。** 完整启动后再次热重载，Master 卡在第一批 Worker 排水。对 PID 50645 的系统采样显示 `pcntl_signal_dispatch → PDOStatement_nextRowset → zend_fetch_debug_backtrace`，该进程同时持有 `master_child_credentials.lock`。`reapExitedChildren()` 在 SIGCHLD 中调用翻译函数及日志，可能打断原本的数据库、锁或 Fiber 操作并重新进入运行时。
2. **后台证书退役与重载竞争。** 修复信号回调后再跑真实重载，仍出现证书退役触发隔离、Worker 消失。后台重试未参与 CLI 已有的实例生命周期互斥；重载期间同步 SSL 更新收到 `control_plane_busy`，退役协调器随后停用整个 TLS 实例，抢占重载。

## 修改

- `Service/MasterProcess.php`：SIGCHLD 回收仅执行非阻塞 `pcntl_waitpid(..., WNOHANG)`；不在异步信号上下文中做翻译或日志。正常 IPC 退出原因记录仍保留。
- `Service/SslCertificateService.php`：后台退役重试先按实例名排序获取现有 `ServerLifecycleOperationLock`，再进入证书事务。遇到启动、停止或等待式重载占锁，沿用已有 `deferred=true` 返回；部分获取、成功、异常均释放已持有锁。
- 未修改证书吊销内容、证书校验、隔离规则、网关信任或业务页面。
