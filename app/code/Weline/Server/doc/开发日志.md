- 兼容与回退：WLS 1.x 保持 legacy 直到显式 promote；WLS 2.0 使用 LKG、A/B slot、重引导 journal 和项目纯 WLS 降级。

### 审查与整改

- 架构：反向代理数据面仅 Nginx，纯 WLS 是独立 adapter；宿主 native Launcher/Broker 只负责恢复与权限边界。
- 缺陷：唯一审查周期已通过并关闭；此前实际复现的 late-port-race 5/6 参数、derived-state `trust` canonical order 与 TEST-134 Guardian 确认夹具缺口均已定向闭合。
- 安全：继续以 fail-closed、no-follow、OS peer identity/ACL、HMAC journal/receipt/marker、PID/binary/generation 绑定为复审主线。
- 用户批准延期：无。所有未闭合项仍为发布阻断。

### 测试与验收

- 当前源码本地运行门已闭合：macOS、Linux Kali/Orb、Windows 11 ARM64 QEMU guest 的 x64 兼容执行均完成纯 WLS 直接 HTTP/2 100 万请求，三端都是 `1,000,000 / 1,000,000`、0 error；报告摘要与 SHA-256 见 [WLS 当前能力与验收状态](WLS当前能力与验收状态.md)。
- Windows 证据只覆盖 QEMU/x64 兼容运行，不覆盖物理 Windows、MSVC、SCM 自动恢复、冷重启或专用容量 Runner。macOS 本轮也未执行 root system-domain LaunchDaemon 冷重启。
- 纯 WLS HTTP/3/QUIC 与 HTTP/2 SSE DATA-frame 流式明确为未实现；managed Gateway HTTP/3、纯 WLS TLS Session Ticket/跨 Worker 恢复等只能标记“已实现，待验证”。
- 公网 CA/DNS 与真实 443 首签按用户决定延后到上线测试环境，状态为“外部环境延期”。
- Freeze A/B 的聚合数字、旧分类和任务编号继续保留在历史记录中，不再作为当前完成度。非 WLS 模块问题只记录，不扩大本模块实现范围。
