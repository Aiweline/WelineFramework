# Visitor 开发面板访问契约

Visitor 的面板 API 和前台注入只依赖 Framework 公开的
`DeveloperAccessProviderInterface` / `DeveloperAccessPolicy`。Visitor 不得直接实例化
`DeveloperWorkspace` 的 Service。

## 运行规则

- Framework 策略通过编译 Provider 注册表查找可选实现。
- 安装并启用 `Weline_DeveloperWorkspace` 时，其 Runtime Provider 保持原有 Token、Cookie 与开发模式判定。
- 未安装或未启用 Provider 时，策略默认拒绝 API 访问且不注入面板脚本。
- REST 保护仍返回原有 `403`；不得因可选模块缺失而类加载失败。
- 「访问事件」Tab 脚本由 `VisitorPanelBootstrapObserver` 在
  `Weline_Framework::telemetry::request_collected` /
  `Weline_Framework::App::run_after` 上与 DevToolPanel **同链路全局注入**；
  不经由主题 body-end、PageBuilder 或 `PixelBootstrapHtmlService`。
- 注入实现仅读取 `shouldInjectBootstrap()`，不做模块存在性分支或动态类名调用。
- 面板数据读取走 `/api/visitor/rest/v1/**`（浏览器原生 `fetch` 直打 REST；**禁止**
  `Weline.Api.resource/call`、`adminRequest` 或 `auth=backend` 的 `visitor.*` worker query；
  无后台 Session 会触发 `Operation authorization requirements are not satisfied.`）。
- **双层鉴权**：
  1. **Api 软层**：`PublicApiAuthRouteMatcher` guest 前缀含
     `visitor/rest/v1/analytics`、`visitor/rest/v1/statistics`、`visitor/rest/v1/panel`；
     guest 路径不因缺业务 API Token 返回 `__('Missing authentication token.')`。
  2. **面板硬闸**：控制器内 `PanelProtectedTrait::guardVisitorPanelApi` →
     `DeveloperAccessPolicy::canAccessApi`；拒绝时 HTTP 403，文案
     「访问面板数据需要有效的开发面板 Token」。
- **路径约定**：面板 JS 默认 canonical 为 `/analytics/*`；`/panel/*` 为兼容入口（同等 guest + 同硬闸）。
- **DEV 语义**：DEV 下 `canAccessApi` 通常恒 true；生产依赖面板 Cookie / Bearer /
  `X-Weline-Panel-Token`。本契约不以非 DEV Browser 验收生产 403 为必过项。
- 游客打开「访问事件」概览时，不得再出现 Api 层 `Missing authentication token.`。

## 验证

在同一运行配置下，Framework 策略与 DeveloperWorkspace 实现的
`shouldInjectBootstrap()`、`canAccessPanel()` 和 `canAccessApi()` 结果必须一致。
去除可选 Provider 后，三个入口必须 fail closed。
HTML 响应在允许注入时必须含 `data-weline-panel-visitor-bootstrap`，且与
`data-weline-panel-bootstrap` 同源策略。
打开「访问事件」Tab 时不应出现 Weline.Api 红色 toast；指标应通过 REST 加载。
