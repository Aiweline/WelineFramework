# Weline_Visitor::event_chain_collect

高级事件链模块注册事件：业务模块可向 Visitor 像素 runtime 贡献漏斗定义。

## 触发时机

`EventChainService::getBundle()` → `EventChainCollector::collect()` 组装前台 `eventChains` 时。

## 事件数据

```php
[
    'website_id' => int,
    'chains' => [], // Observer 只能追加，禁止清空他人贡献
]
```

## 链结构

与后台事件链发布一致：

```php
[
    'id' => 'checkout_express_pay',          // 稳定唯一
    'name' => '快捷支付结账',
    'owner' => 'Weline_Checkout',            // 可选，贡献模块
    'complete_event' => 'express_pay_checkout_success', // 凑齐后上报；禁止与普通 checkout_success 同名
    'steps' => [
        ['type' => 'track', 'event' => 'express_pay', 'label' => '快捷支付'],
        ['type' => 'track', 'event' => 'express_pay_started', 'label' => '已拉起支付'],
        ['type' => 'track', 'event' => 'checkout_success', 'label' => '结账成功'],
    ],
]
```

`type`：`page` | `track` | `click` | `input` | `submit`。

## 合并规则

- 后台已发布包 + 本事件贡献 + Extends `EventChainProviderInterface`
- 同 `id`：**模块注册优先于**后台存储
- runtime `version` 由存储 version + 合并内容指纹计算，定义变更后前台 localStorage 自动换代

## 扩展方式

1. **推荐（事件）**：在模块 `etc/event.xml` 监听 `Weline_Visitor::event_chain_collect`，Observer 向 `chains` 追加。
2. **可选（Extends）**：实现 `EventChainProviderInterface`，放入 `extends/module/Weline_Visitor/EventChainProvider/`。

## 闭环注意

`complete_event` 须带 `__event_chain_complete` 才允许入库；前台 `pixel-event-chains.js` 在步骤凑齐后自动带标上报。不要把通用 `checkout_success` 设为 `complete_event`（会阻断普通结账成功直报）。
