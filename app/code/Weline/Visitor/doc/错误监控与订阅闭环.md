# 错误监控与订阅闭环

> 模块：`Weline_Visitor`  
> 状态：已实现（一期）

## 目的

全站「出错才上报」的事故包：页面、步骤路径、脱敏表单、框架/主题版本、错误类型；入库后按类型 `w_msg`，运营/技术在「我的订阅」中按 topic 订阅（backend / email / webhook→AI 工作流）。

## 事件

- 像素事件：`site_error`（`etc/event_dictionary.json`，`skip_gtm_push: true`）
- 表：`w_pixel_error_incident`（模型 `PixelErrorIncident`）
- 邮箱仅存事故表，不进营销像素 / GTM

## 错误类型（= Msg topic）

见 `Extends/NotificationTopicProvider` 与 `Service/PixelErrorIncidentClassifier`：

- 技术：`pixel_incident_js|promise|network|resource|stale_client|unknown`
- 业务：`pixel_incident_stock|checkout|payment|auth|business`

## 版本

- 框架：`deployVersion` / `workerBuildId`（header runtime 已有）
- 主题：`themePublishedVersionId` / `themePublishedVersion`（可空；`ThemePublishedVersionRuntimeResolver` 注入）
- stale 以框架版本为主；主题空值不阻断上报

## 前台

- `pixel.js` / taglib：`WelinePixel.reportIncident()`、自动 `error` / `unhandledrejection` / 资源 / `weline:api:error`
- QueryBin / `Weline.Api`：`Frontend/view/statics/js/weline-api.js` 的 `notifyApiFailure()` 在 HTTP/业务失败、worker 超时与崩溃路径**始终**向 `window` 派发 `weline:api:error`（与 Toast 成败无关）；跳过 `visitor.trackPixel` 防递归。像素在 `window`+`document` 双绑监听，读取 `detail.code` / `error_code` / `provider` / `operation`
- 店面 `assetVersion` 附加 `weline-api.js` 的 mtime，避免本地 `deploy_version=dev` 时懒加载仍命中旧 Api 脚本
- 环形步骤缓冲 + 表单脱敏快照 + 节流

## 后台

- 菜单：像素分析 → 错误监控  
- 路由：`visitor/backend/pixel-error-monitor/index`（详情为列表内 `w-dialog` 弹层；旧 `detail?id=` 重定向到 `index?open=`）  
- 处置：`open` / `ignored_stale` / `resolved`（弹层内提交，回列表）
- 弹层一眼全貌：严重度 + 中文类型标题 + 消息；四格（谁/何时/在哪/版本）；轨迹 chips；表单/堆栈/原始字段折叠在 `<details>`
- 重要程度色彩：`severity` → `w-badge` tone（`info` 蓝 / `warning` 黄 / `error|urgent` 红）；列表行左侧色条；结账/支付为 `urgent`

## 订阅

运营在 Backend「我的订阅」勾选对应 `pixel_incident_*` topic 与渠道（webhook 外接 AI）。

## 后续（不做）

基于已识别邮箱的发券/挽回营销模板。
