## 当前有效需求

### `REQ-CAPTCHA-0006` Google Enterprise 保护文案展示信任徽章

- 来源与确认：用户要求「此表单受 Google reCAPTCHA Enterprise 保护」旁加 Google 标签提升信任度。
- 目标：渲染 Google 四色 G 标 +「受 Google 保护」+ 原文案 + Privacy/Terms；样式用主题 token。
- 验收：`grecaptcha.enterprise.ready` 之后才可见 `data-testid="google-recaptcha-trust-badge"`；SDK 未就绪或加载失败时徽章保持 `hidden` 并降级本地图码；契约测覆盖。
- 补充（2026-09-10）：用户审图箭头指出未就绪仍显示徽章不合理——信任声明不得早于 SDK 可用。

### `REQ-CAPTCHA-0005` 删除旧 Google v2/v3 与兼容迁移，仅保留 Enterprise

- 来源与确认：用户确认不需要旧版兼容迁移，只用最新 Enterprise，旧实现全部删除。
- 目标：移除 v2/v3 Provider、legacy 配置组与 upgrade 迁移观察者；运行时仅 Enterprise 或本地图码。
- 验收：配置页无旧版分组；源码无 `GoogleRecaptchaV2/V3` 与 `LegacyConfigMigrator`。

### `REQ-CAPTCHA-0004` 后台以手填 Enterprise 密钥 + 开发者指南配置 Google

- 来源与确认：用户确认一键授权因 Google Redirect URI 环境差异无法稳定走通，要求去掉一键授权，改为指南 + 手填。
- 目标：SystemConfig 首组为「使用指南（开发者）」外链与步骤；主路径手填 Project ID / Site Key / API Key；无授权/选 Project/测试/撤销入口。
- 验收：配置页无「授权 Google」；指南指向 reCAPTCHA 控制台与凭据页；手填三项后可启用 Google。

### `REQ-CAPTCHA-0003` 后台配置以 Google 一键授权为最推荐路径（已取消）

- 状态：`cancelled`（由 `REQ-CAPTCHA-0004` 替代）。

### `REQ-CAPTCHA-0002` FPC 下验证码 lazy 打洞由模块根源提供

- 来源与确认：用户确认采用「页壳可 FPC + 挑战独立拉取」方案，并要求在 Captcha 模块根源支持，而非各业务页各自实现。
- 目标：`captcha="lazy"` 注入占位后由模块运行时自动加载/刷新；`required`/`auto` SSR 继续 forbid 共享缓存；挑战接口不可缓存。
- 验收：无业务定制 JS 时 lazy 表单可出图并刷新；FPC 命中页 HTML 不含一次性 `captcha_token`。
