# 异步索引管道（Async Schema Index Pipeline）

> 适用版本：`Weline_Database 1.2.9+`、`Weline_Framework 2.5.434+`
> 目标：升级时只记录索引变更，由 cron/queue 在低峰窗口增量执行 `CREATE/DROP INDEX CONCURRENTLY`，避免全量重建索引和升级请求长时间 DDL。

## 1. 链路

```text
Model #[Index] / SchemaDiff
  └─ SchemaMigrationExecutor（升级时）
       └─ SchemaIndexChangeSink
            ├─ 非唯一普通索引 ADD/DROP → 记录 weline_schema_index_job，源变更标记已处理
            └─ UNIQUE / 主键 / 外键 → 仍同步执行
  └─ Cron: schema_index_auto_apply（每分钟，受窗口/负载/冷却/预算约束）
       └─ Queue: schema_index_apply
            └─ IndexApplier
                 ├─ CREATE INDEX CONCURRENTLY
                 ├─ DROP INDEX CONCURRENTLY
                 └─ REBUILD：先建临时索引 → 删旧 → ALTER INDEX RENAME
```

- `weline_schema_index_job`：待执行/运行中/完成/失败任务。
- `weline_schema_index_state`：声明索引的物理状态（applied/running/drifted/removed/failed）。
- `schema_index_watchdog`：运行中任务在负载超阈值时 `pg_cancel_backend` 并回退 pending。
- 后台页：`数据库管理 → 索引管理`（`database/backend/schema-index`），支持自动开关、待索引、状态和「立即索引」SSE 进度。

## 2. 默认配置（系统配置 → 异步索引）

| key | 默认 | 说明 |
|---|---|---|
| `index/auto_apply` | 1 | 系统级自动索引开关，默认启用 |
| `index/defer_on_upgrade` | 1 | 升级仅记录普通索引变更 |
| `index/window` | `01:00-05:00` | 允许自动构建窗口，`*` 表示不限 |
| `index/max_concurrent` | 1 | 全局并发 |
| `index/cooldown_seconds` | 300 | 同表两次构建冷却 |
| `index/max_per_table_window` | 1 | 每表 24h 构建预算，避免集中打单表 |
| `index/load_threshold` | 3 | load average 阈值，超过则暂停/看门狗取消 |
| `index/maintenance_work_mem` | 256MB | 构建内存，过大会挤占缓存 |
| `index/max_parallel_workers` | 0 | 降低 CPU 峰值 |
| `index/retry_limit` | 3 | 失败重试次数 |

手动「立即索引」优先入队并跳过窗口等待，但仍受 applier 的表锁、同表串行和看门狗负载取消保护。

## 3. 运维命令

```bash
# 执行一条/下一条待索引任务（手工排障）
php bin/w index:apply --job=123
php bin/w index:apply --pending

# 物理漂移巡检；--fix 为漂移项入队修复任务
php bin/w index:verify
php bin/w index:verify --table=w_i18n_locale_dictionary --fix
```

- 首次安装/升级：`php bin/w setup:upgrade --model -m Weline_Database` 建表并注册任务；不要用 `index:reindex` / `REINDEX TABLE` 代替建索引。
- cron/queue 进程需运行；后台页能看到任务但长期 `pending` 时先检查 cron/queue 与 `system.maintenance`。

## 4. 性能与安全边界

- `CONCURRENTLY` 不阻塞读写，但会消耗 I/O；默认窗口 + 单并发 + 同表冷却 + 每表预算 + 负载看门狗共同限制峰值。
- 同一张表同时只允许一个索引构建（`pg_try_advisory_lock(hashtext(table))`）。
- invalid index：构建前发现同名 invalid 索引先清理；构建后回读 `indisvalid`，无效则清理并重试。
- rebuild 先建新索引并校验有效，再删旧索引并 rename，缩短无索引窗口；失败时尽量清理临时索引。
- `index:verify` 明确跳过 `pending/running` 状态，不把异步积压误报为 schema 漂移。

### 已知基线（I18n 原始问题）

`w_i18n_dictionary`（约 4.3 万行）anti-join `w_i18n_locale_dictionary`（约 174 万行）：
- 新增 `idx_locale_word(locale_code, word)` 前：单页约 1.95s；计数分页 1.38–2.11s。
- 索引 + keyset 分页 + 单次聚合计数后：页面约 54ms；计数 28–49ms。

## 5. 发布与回滚

发布：
1. 升级 Database/Framework 模块，执行 `setup:upgrade --model -m Weline_Database`（维护窗口）。
2. 确认 `weline_schema_index_job/state` 存在，cron `schema_index_auto_apply`/`schema_index_watchdog` 和 queue `schema_index_apply` 已注册。
3. 后台确认自动索引开关默认开启；必要时设置窗口/负载阈值。
4. 观察 `索引管理` 页的 pending/running/failed/drifted；用 `index:verify` 复核。

回滚：
1. 系统配置关闭 `index/auto_apply`，避免新增任务。
2. 停止 cron/queue 对本管道的消费（不影响其他队列）。
3. 将模块版本回退到旧版；已建索引可保留（通常无数据风险）。
4. 如需删除新索引：在低峰执行 `DROP INDEX CONCURRENTLY`；不要用事务包裹。
5. 任务/状态表可保留供审计；确认无 pending 后可归档。
