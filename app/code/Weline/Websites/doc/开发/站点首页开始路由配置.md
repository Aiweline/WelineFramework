# 站点首页开始路由配置

## 背景

框架已有全局开始路由配置：

- module: `Weline_Backend`
- key: `start_page_path`
- area: `backend`

上述键名与模块名由公开契约 `Weline\Backend\Api\Config\KeysInterface` 提供；
不要跨模块引用旧的 `Weline\Backend\Config\KeysInterface`。

`Weline_Frontend::start_page_plugin` 会在前台根路径请求时读取该配置，并把 `/` 映射到配置的前台路由。

## 站点级覆盖

站点后台表单的“首页入口路由”字段复用上述配置，不在 `website` 表新增字段。

- 选择具体路由时，保存为 `system_config` 的站点 scope 配置。
- scope 使用网站代码，由 `SystemConfig::normalizeScope()` 归一化为站点 scope。
- 留空时删除站点 scope 配置，继续继承全局 `start_page_path`。

保存入口：

- `Weline\Websites\Controller\Admin\Website::add()`
- `Weline\Websites\Controller\Admin\Website::edit()`
- `Weline\Websites\Controller\Admin\Website::quickSave()`

读取入口：

- WLS：`Weline\Websites\Integration\Backend\FrontendStartPageRouteProvider`
- 兼容路径：`Weline\Frontend\Plugin\StarPage::beforeGetUrlPath()`

站点 scope 读取会优先使用当前请求的网站代码；没有站点覆盖时，由 `SystemConfig` 的 fallback 机制回落到全局配置。

## AI 建站域名级首页

AI 发布还会额外写入域名哈希键（全局 scope）：

- key: `frontend_start_page_path_domain_{sha256(host)}`（由 `Weline\Websites\Api\DomainStartPageConfig` 生成）
- module: `Weline_Websites`
- area: `frontend`
- scope: `default.default.default`

同时镜像写入该站点的 `frontend_start_page_path`（website code scope）。

`FrontendStartPageRouteProvider` **必须先按请求 Host 读取域名哈希键**，再回退到 website scope 的 `frontend_start_page_path`。只写域名键、不读，会导致本地域名根路径 `/` 仍显示框架默认首页，表现为“发布一次不生效”。

写入入口：`Weline\Websites\Service\AiSiteStartPageService::configure()`（发布后同步 `cacheClearAndWait`）。

## 路由来源

可选项来自 `generated/routers/frontend_pc.php` 中的前台 PC 路由：

- 无显式方法的路由可作为开始路由。
- `::GET` 路由可作为开始路由。
- 其他方法路由不会出现在选择项中，避免把 POST 等非页面入口设为首页。

## 维护注意

- 修改开始路由机制时，应优先保持 `start_page_path` 配置键兼容。
- 站点级配置不要写入 `website` 模型字段，避免与 SystemConfig scope 机制形成两套来源。
- AI 域名哈希键与 website scope 键必须成对写入、成对可读。
- 如果新增前台路由后选择项未出现，先确认路由已生成到 `generated/routers/frontend_pc.php`。
