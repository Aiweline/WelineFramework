# 网站删除与孤儿清理（抽象流程）

> 权威流程正文。技能 / MCP 指令只指路，不另写第二套 SOP。  
> **禁止**在本文或技能里写死某一商户站名、域名、SSH 别名、公网 IP 或某一 `website_id` 当默认目标。

## 1. 输入

| 参数 | 必填 | 默认 | 说明 |
|------|------|------|------|
| **目标站** | 是 | — | 用户给出的站身份：优先 `code`，其次显示名 / `website_id`。禁止猜站。 |
| **位置** | 否 | **本地** | `本地` / `local` = 本机运行库与 `pub/media`；`线上` / `生产` / `online` / `production` = 该站柜 README 声明的生产 SSH Host。未明示线上时**禁止**连生产。 |

解析规则：

1. 用目标库的 `Website` 表（或等价 Catalog）把用户词解析成唯一 `(website_id, code, scope)`。
2. 0 条 → 停止并回报；多条 → 列出候选项，禁止擅自挑选。
3. **默认站不可删**：`website_id = 0` 或 `code = default` → 立即失败（与后台删除门禁一致）。
4. 位置=线上时：先 Read 该目标对应站柜 `websites/<cabinet>/README.md` 的「主用 SSH Host」；**禁止**套用其它站柜或其它 SSH profile。

## 2. 与后台「删除网站」的关系

后台 `Website::deleteDelete` / Model 删除边界：

- 会删：域名绑定、站货币、站语言、网站行（及缓存失效）。
- **拒绝**：仍有 Store / SalesChannel 引用时的物理删；默认站。
- **不会自动做**：站分片表、孤儿 SystemConfig / Theme 作用域行、无交叉引用静态资源。

本流程 = **受控全量清理**：在官方删除边界之上，补齐分片 / 配置孤儿 / 静态孤儿；能走官方备份与删除入口时优先走，不足部分按下列阶段补齐。

## 3. 阶段（必须按序）

### 3.0 只读清点

对目标站统计并回报（未写库）：

- 子 Store / SalesChannel（未清则不能物理删父站）
- 域名 / 货币 / 语言
- `website_id` 作用域的 SystemConfig / Theme 应用与 scope 行
- 表名含站分片模式的表（如 `*_ws_{website_id}_*`，以实际 schema 为准，禁止写死某一业务表清单当唯一真相）
- 媒体侧：`file_asset` 行数与 `pub/media` 体量（若可估）

### 3.1 备份（写入前硬门禁）

- **优先**：官方网站备份（`WebsiteBackupService` / `manageWebsiteBackup` / 后台备份），类型按「完整」或至少「仅站点数据」。
- **线上另加**：带时间戳、不覆盖已有路径的库表 dump（至少覆盖本回合将突变的表：网站图谱相关 + `file_asset` / `file_asset_locale` / `file_asset_reference` 等）；`gzip -t`（或等价）+ sha256（或大小）校验。
- 未备份成功 → **禁止**任何 DELETE / DROP / 删文件。
- 向用户回报备份路径与校验结果。

### 3.2 结构删除（网站图谱）

受控顺序（抽象；以当前 Model 门禁为准）：

1. 先处理子 SalesChannel / Store（tombstone 或受控 purge，禁止留下指向已删站的活引用）。
2. 域名、站货币、站语言、主题应用等站级绑定。
3. 网站行本身（优先官方删除事务）。
4. 仅属于该 `website_id` 的分片表 / 分片数据（确认表名模式后再动；禁止误伤其它 `website_id`）。

### 3.3 孤儿配置清理

删除**作用域身份仅属于已删站**的配置与主题产物，例如：

- SystemConfig 行的 scope / 键路径绑定该 `website_id` 或 `code`
- Theme scope / release / patch 等仅服务该站的行

**禁止**删除 global / 默认站 / 其它存活站的配置。

### 3.4 无交叉引用静态资源清理

**判定「无交叉引用」必须走引用图，禁止只看 `file_asset_reference` 为空。**

保留（任一命中即保留）：

| 来源 | 匹配 |
|------|------|
| 商品媒体 | `asset_id` / 非 `asset://` 的 path |
| 品牌 / 供应商 | logo / image 类 `*_asset_id` |
| 文件引用表 | `file_asset_reference.asset_id` |
| 下载权益等 | 业务表上的 `asset_id` |
| 评论媒体 | path |
| 博客 | `cover_image`、正文中的 `/pub/media/…` 或 `asset://` |
| 主题 JSON | patch / release / chrome / layout snapshot / widget 等载荷中的 path 或 `asset://` |
| SystemConfig | `v`（或等价值列）中的 media path / `asset://` / 站柜媒体相对路径 |
| 运行时字体子集 | `font-subset/**`（常由 CSS 哈希引用，无 DB 行也视为在用） |
| 仍被配置引用的站柜媒体前缀 | 如 `websites/{scope}/…` 下仍出现在配置中的文件 |

可删：

- 上述图中零命中的 `file_asset`（及 locale）行 + 对应磁盘文件
- 磁盘有文件、库无行、且路径也不在引用图中的对象
- 无引用的临时目录名模式（如 cleanup / quarantine / e2e / prototype / 明显测试前缀）——仍须先确认引用图零命中

**禁止**：

- 因「没有 `file_asset_reference`」就清空 catalog / blog 在用图
- 删仍被配置引用的店面音乐 / 品牌柜文件
- 把某一历史商户的目录名写进技能当「永远可删」黑名单

### 3.5 验收

- 目标 `(website_id, code)` 在 Website Catalog 中不存在
- 存活站：商品媒体 ⋈ `file_asset` 缺失数为 0
- 存活站博客封面等路径引用仍在磁盘（抽样或全量）
- 配置仍引用的站柜媒体仍在
- 汇报：删除前/后行数、释放体积、备份路径、位置（本地/线上）

## 4. 批量变体（仍抽象）

用户说「只留默认站 / 清掉其它站」时：

1. 列出全部非默认站（只读）。
2. **逐个**套用本流程（每站独立清点 → 备份 → 删 → 孤儿清理）。
3. 禁止一次 SQL 无差别 `DELETE` 扫全库；禁止把「默认站」写进可删列表。

## 5. 安全与抽象硬规则

1. 默认本地；未明示线上不碰生产。
2. 线上写入前必须备份并校验。
3. 技能 / 指令 / 本文 **禁止具象默认目标**（某一店名、域名、SSH、IP、固定非 0 的 `website_id`）。
4. 站柜路径、SSH Host、应用根 **只从用户指定站 + 该站柜 README** 解析。
5. `preserve_dirty_workspace`：本流程不 `git restore` / `clean` 清工作区。
6. 查询运行状态默认本机（与 `runtime_status_query_local_first` 一致）。
