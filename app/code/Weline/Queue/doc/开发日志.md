## `1.2.12` — queue.result 只存过程摘要

- 目标版本：`1.2.12`
- 问题：即便有字节上界，`prependResultMessage` 仍把 worker stdout 拼进 `result`，页面仍出现 `[truncated 65536 bytes…]`。
- 变更：`prependResultMessage` 只追加简短过程消息，忽略 `$output`；`RESULT_MAX_BYTES` 收紧为 8KB。
- 验收：`QueueDispatchServiceTest::testQueueResultAndProcessOutputAreByteBounded`

## `1.2.11` — queue.result / 进程日志字节上界

- 目标版本：`1.2.11`
- 问题：`prependResultMessage` 反复整文件前置进程日志，`getManagedProcessOutput` 无界 `file_get_contents`，导致单条 `result` 膨胀到数十 MB，AI 翻译后台页触发 WLS capture_limit，调度器 OOM。
- 变更：`RESULT_MAX_BYTES` / `PROCESS_OUTPUT_MAX_BYTES`（64KB）；append/prepend/完成与失败收口路径统一 `boundResultText`；日志改为尾部有界读取。
- 验收：`QueueDispatchServiceTest::testQueueResultAndProcessOutputAreByteBounded`

## `1.2.10` — 假 running 死 PID 收口 finished=1

- 目标版本：`1.2.10`
- 问题：`reconcileRunningQueues` 将死 PID 标为 `error` 时未写 `finished=1`，与 `failQueueWorkerSafely` 不一致；假 `running`/半终态占并发槽，cron 难以再派发。
- 变更：非可恢复死 worker 的 error 收口补 `finished=1`；控制单测与源码契约覆盖。
- 验收：`QueueDispatchServiceControlTest::testReconcileDeadWorkerMarksFinishedErrorTerminal`；`QueueDispatchServiceTest::testReconcileDeadWorkerErrorPathMarksFinishedTerminal`

## `1.2.9` — 失败收口 finished=1，避免幂等槽半终态卡死

- 目标版本：`1.2.9`
- 问题：`failQueueWorkerSafely` 只写 `status=error` 未标 `finished=1`，与 reconcile 失败终态不一致；`error+finished=0` 半收口导致翻译等幂等槽难以稳定重开。
- 变更：失败与成功一样写 `finished=1`；控制单测断言；README 对齐「失败写 error+finished=1」。
- 验收：`QueueDispatchServiceControlTest::testWorkerFailureClearsFenceAndExactLeaseImmediately`

## `1.2.4` — 批消费消费者类级单飞行调度

- 基线版本：`1.2.3`
- 目标版本：`1.2.4`
- 需求 ID：`REQ-QUEUE-0003`
- 问题：高频小任务（如 Search 投影）每行 `queue:run` 冷启，并发 createIfAbsent 可同时 spawn 多个 Worker。
- 变更：新增 `BatchDrainingQueueConsumerInterface`；`QueueDispatchService` 对实现类默认 `max_concurrent_by_class=1`，`startQueueProcess` 用类级 flock 串行 claim+spawn；支持 `queue.cron.max_concurrent_by_class.<FQCN>` 覆盖。
- 验收：`QueueDispatchServiceTest::testBatchDrainingClassesAreSingleFlightOnDispatch`。
