# Weline Queue 模块 - 队列停止事件

## 概述

`Weline_Queue::stop` 是队列**成功暂停后的通知事件**。后台 `queue_admin` 单条和批量
操作都先调用 `QueueDispatchService::stopQueueSafely()`；只有服务确认当前
执行代次已经释放，并以条件更新把 Queue 写成 `stop` 后，才会派发该事件。

该事件不是“停止前”拦截点，观察者不能用它阻止停止。权限、业务校验或前置约束应在
调用安全控制服务之前完成。

## 基本信息

- **事件名称**：`Weline_Queue::stop`
- **事件类型**：成功后的队列操作通知
- **触发位置**：`Weline\Queue\Service\QueueAdminService` 的 `action()` / `batchAction()` confirmed 分支
- **配置文件**：`app/code/Weline/Queue/etc/event.xml`

## 成功边界

以下条件全部满足后才会派发事件：

1. Queue 要么无 active/dirty attempt，要么精确活动代次已安全释放；
2. `running + pid=0 + token` 启动窗口可由同快照 CAS 取消；若 Worker
   attach 抢先，只重载一次并跟随同 token 代次；
3. `pid>0` 的活动 Worker 只有在 PID、Queue ID、规范名、launch-id 与 token
   共同确认并释放后才可继续；
4. Queue 按完整快照 CAS 变为 `stop`，PID 与 dispatch fence 已清空。

遇到进程身份未知、未携带 dispatch token 的存活旧 Worker、自我终止、终止未确认，
或并发条件更新失败时，操作返回失败且**不派发** `Weline_Queue::stop`。
状态确认写入后若观察者失败，后台响应仍保持成功并返回 warning，不把已完成暂停伪装成回滚。

## 事件数据

```php
[
    'queue' => $queue,
]
```

`queue` 是已经重新加载的 `Weline\Queue\Model\Queue`，其成功状态应为 `stop`。

## 监听示例

在模块的 `etc/event.xml` 中注册观察者：

```xml
<?xml version="1.0"?>
<config xmlns:xs="http://www.w3.org/2001/XMLSchema-instance"
        xs:noNamespaceSchemaLocation="urn:Weline_Framework::Event/etc/xsd/event.xsd"
        xmlns="urn:Weline_Framework::Event/etc/xsd/event.xsd">
    <event name="Weline_Queue::stop">
        <observer name="Your_Module::queue_stop"
                  instance="Your\Module\Observer\QueueStopObserver"
                  disabled="false"
                  shared="true"
                  sort="100"/>
    </event>
</config>
```

适合在观察者中记录审计日志、清理停止后的业务资源或发送通知。不要在观察者中再次
终止 PID，也不要按队列名批量清理进程记录。
