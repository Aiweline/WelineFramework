# Weline Queue 模块 - 队列删除事件

## 概述

`Weline_Queue::delete` 是 Queue 行被**条件删除成功后的通知事件**。后台 `queue_admin`
单条/批量操作和 `w_query('queue', 'delete', ...)` 都先调用
`QueueDispatchService::deleteQueueSafely()`；只有服务确认当前执行代次可安全释放，且
删除仍命中同一份 fence 快照后，才会派发事件。

该事件不是“删除前”拦截点，观察者不能用它阻止删除。需要保留记录或拒绝删除的业务
约束应在调用安全删除服务之前完成。

## 基本信息

- **事件名称**：`Weline_Queue::delete`
- **事件类型**：成功后的队列操作通知
- **触发位置**：
  - `Weline\Queue\Service\QueueAdminService` 的 `action()` / `batchAction()` confirmed 分支；
  - `Weline\Queue\extends\module\Weline_Framework\Query\QueueQueryProvider`
    的 `deleteQueue()` 成功分支。
- **配置文件**：`app/code/Weline/Queue/etc/event.xml`

## 成功边界

- 只有 `status!=running + pid=0 + token/until=NULL` 的无 active/dirty attempt 行
  可非 force 删除；任一 running/PID/fence 证据都默认拒绝。
- 显式 `force=true` 也只尝试安全释放精确受管代次。tokenless 存活 Worker、
  `UNKNOWN`、自身 PID，以及 non-running + token-only + pid=0 无法证明退出的行
  仍 fail closed。
- 主表删除使用完整 Queue 快照 CAS，并与 Queue EAV entity 的全部属性值清理
  置于同一 write-intent 事务；过去 type 留下的属性值也在清理范围。主表 CAS
  未命中或任一属性清理失败会回滚全部变化，且**不派发**事件。
- 安全删除拒绝嵌套在已有数据库事务中，避免外层 rollback 与已释放的
  Worker/lease 副作用失配。
- 删除 commit 后观察者失败不会恢复已删除行；后台响应保持 `success=true` 并携带 warning，
  避免用户重试已完成的删除。

## 事件数据

```php
[
    'queue' => $queue,
]
```

`queue` 是删除前的 `Weline\Queue\Model\Queue` 快照，供审计和关联数据清理使用；事件
触发时权威 Queue 行已经不存在，观察者不应再对该模型调用 `save()` 或 `delete()`。

## 监听示例

在模块的 `etc/event.xml` 中注册观察者：

```xml
<?xml version="1.0"?>
<config xmlns:xs="http://www.w3.org/2001/XMLSchema-instance"
        xs:noNamespaceSchemaLocation="urn:Weline_Framework::Event/etc/xsd/event.xsd"
        xmlns="urn:Weline_Framework::Event/etc/xsd/event.xsd">
    <event name="Weline_Queue::delete">
        <observer name="Your_Module::queue_delete"
                  instance="Your\Module\Observer\QueueDeleteObserver"
                  disabled="false"
                  shared="true"
                  sort="100"/>
    </event>
</config>
```

适合在观察者中记录审计日志、清理 Queue 外部的关联数据或发送删除通知。
